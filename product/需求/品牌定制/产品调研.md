# 换成我们的 Logo，第一版怎么做？

> 2026-09-08 · 原产品讨论与竞品依据保留，未登录商业版实测。
> 2026-09-09 · 首版已完成用户验收，实际范围以[验收记录](../../../workbench/cases/Logo品牌设置/期1/验收记录.md)和[功能指南](../../docs-zh/04-开发指南/08-Logo品牌设置.md)为准。

我们要解决的事情很简单：打开网关时，登录页和控制台显示我们的 Logo。以后需要换图时，管理员自己就能操作。

## 竞品怎么做

| 产品 | 用户怎么换 | 对我们有什么参考价值 |
|---|---|---|
| **LiteLLM** | 打开 Settings → UI Theme，填写 Logo 图片地址并保存，侧栏和登录页随之更换。还可以单独设置深色模式的 Logo；不填就沿用同一张图。 | 换 Logo 可以是一个很小的设置页面，深色素材可以选填。见[官方说明及页面截图](https://docs.litellm.ai/docs/proxy/ui/ui_edit_logo)。 |
| **Bifrost 上游企业版** | 支持替换 Logo 和小图标，并在控制台显示。发布说明还提到侧栏保留 Powered by Bifrost。公开仓库没有完整企业版表单，不能据此断言它的上传和预览交互。 | 已经考虑了大 Logo 和小图标两种展示位置。见[上游发布说明](../../../docs/changelogs/ent-v2.0.0.mdx)。 |
| **Grafana Enterprise**（管理控制台参考） | 由运维在配置中填写登录 Logo、菜单 Logo 等图片地址，也能另配产品标题和浏览器图标。 | 适合由运维统一维护品牌；不同位置可以分别配置，不必一次做齐。见[官方品牌配置](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/enterprise-configuration/#white_labeling)。 |

这里真正值得借鉴的是两点：**管理员能够自己换图；同一张图在不同位置、不同背景上要看得清。**

原稿对 One API／New API 的描述混用了两个产品，缺少逐项核实；Portkey 的具体设置流程也没有足够证据，因此不把它们作为本次方案的依据。

## 我们现在缺什么

控制台已有 **Settings → Branding** 入口，但打开后还是联系销售的占位页，不能真正换图。前端已经留了展示自定义品牌的位置，需要把设置和保存功能补上。

所以，这次要做的是：**把这个入口变成一个能用的 Logo 设置页。**

## 建议第一版这样用

管理员打开 Branding，看到当前 Logo，选择一张本地图片，预览效果后点击“保存”。保存成功，登录页和控制台显示新图；其他用户刷新后也能看到，重启服务后仍然保留。换错了，可以恢复默认。

页面只需要这些内容：

| 页面内容 | 用来做什么 |
|---|---|
| **Logo** | 选择、替换图片，用于登录页和展开的侧栏。 |
| **小图标（选填）** | 用于折叠后的侧栏。横向带字的 Logo 缩小后可能看不清，这时再单独提供。 |
| **效果预览** | 看展开、折叠和浅色／深色背景下的效果，避免保存后才发现看不清。 |
| **保存、恢复默认** | 保存当前选择，或恢复原来的图。图片不合适、保存失败时给出清楚的提示。 |

**不要求一开始就准备两份素材。** 先拿现有 Logo 看效果；如果没有填写小图标，建议尝试按比例使用同一张图，在预览中让管理员判断是否需要另配。深色背景下确实看不清时，再考虑增加选填的深色 Logo。

这里推荐本地上传，而不是只填图片地址：我们的私有化部署用户不必先找地方托管图片，也不必依赖外部图片网站。这是我们的产品选择，不是所有竞品的统一做法。

## 这次做到哪里

第一版先让登录页和控制台的 Logo 换得方便、显示正常、能恢复。产品名称、浏览器标签图标和整体配色，等有具体需求时再分别增加。

修改入口只给管理员使用，沿用当前管理端认证，之后再接入用户权限功能。预览、素材格式和大小提示由开发时处理，不需要现在逐项让用户拍板。

接下来先用现有素材看一次页面效果，再确定是否需要独立小图标；本文的页面和交互仍是建议，尚未开始实现。
