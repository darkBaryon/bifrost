## 当前功能范围

2026-09-15 用户确认 D1/D4/D5 做、D6–D9 不做；2026-09-16 确认 D3 做、D2 首期暂缓。当前范围如下：

| 状态 | 功能 |
|---|---|
| 确认做 | D1 违规与有害内容、D3 密钥与凭据泄漏、D4 提示词攻击、D5 自定义业务规则 |
| 确认不做 | D6 恶意链接、D7 恶意文件、D8 模型幻觉、D9 受保护内容 |
| 首期暂缓 | D2 个人与企业敏感信息 |

**D3 纳入依据**：针对代码或配置进入模型上下文时的凭据泄漏风险。BF 的本地 Gitleaks 检测路线可供借鉴，专门规则库可减少管理员维护各种密钥格式的工作；具体依赖版本和接入设计后续确定。[BF 密钥检测](https://docs.getbifrost.ai/enterprise/guardrails/secrets-detection)

**D2 暂缓边界**：首期不建设独立的通用敏感信息识别能力。零散固定格式需求可由 D5 自定义规则承载；预置中国手机号/身份证模板及广泛 PII 覆盖未纳入范围。BF 自带 PII 模板主要含美式标识，不能直接作为完整中文方案。[BF 正则与 PII 模板](https://docs.getbifrost.ai/enterprise/guardrails/custom-regex)

做 D3 不代表默认开启脱敏、返回还原或日志原文恢复；动作与默认值后续单独确定。数字水印仍为历史相邻能力记录，未被批准纳入开发。

## 三、旧盘点需要重新验证的判断

依据详见[竞品调研第三至六节](竞品调研.md)。

1. **Higress 只绑定阿里云审核服务**：范围过宽，现有官方材料另有自托管 Qwen3Guard 路径，但需要区分可构建实现与正式插件快照。
2. **只查最后一条 user 即可**：不同产品处理范围不同，对工具返回和长上下文必须单独验证。
3. **所有异常默认放行**：只确认到部分检测器的行为，不能泛化为本产品默认规则。
4. **护栏类型直接复用即可完成日志/UI**：当前本仓元数据结构与旧笔记不同，需要验证适配。
5. **流式可以简单后补一周**：整段回放、分段检查、实时观察的保护能力和体验不同，现阶段不能据此排期。

## 四、后续研究方式

2026-09-15 后续讨论中，用户确认：网关层主要明确哪些内容送检、检测后如何处理，用一张行为规则表整理；研究重点转到检测能力、配置方式及中文业务适用性。该聚焦方式已落实到[功能对照](阿里云与Bifrost功能对照.md)，不再把网关前后置流程展开成多个独立的大专题。

阿里云和 Bifrost 企业版能力并集 D1–D9 保留为来源目录，后续按“当前功能范围”推进 D1/D3/D4/D5；D2 首期暂缓，D6–D9 不再继续开发研究。本轮不接输出流检查；后续若支持流式，再确定完整检测后交付的协议与异常细节。

按已选检测项目细化时，每次研究交付：竞品行为对照、固定版本源码证据（可获得时）、正常/命中/异常的样本实验、可复用能力和未决事项。没有真实检测 API 或企业版环境时，文档事实、模拟行为和实测效果分别标注。

本轮采用本地检测、显式失败策略；实际检测算法、上线启用范围和对外拒答契约尚未确认。当前框架通过代码注入配置和测试检测器验证，不自动启用生产流量策略。
