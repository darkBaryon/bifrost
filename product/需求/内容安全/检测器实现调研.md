# 检测器实现调研：阿里（Higress）与 Bifrost 企业版

> 2026-09-17。核对两家 D1/D3/D4/D5 分别由什么实现，并实测 DeepSeek 判官。检测方式的决策见[调研总结](调研总结.md)。
> 框架层（提取、送检、处置、流式）见 [Higress 源码研究](Higress源码研究.md)，文档层见[功能对照](阿里云与Bifrost功能对照.md)。

## 一、两家分别怎么实现

| 检测项目 | 阿里（Higress） | Bifrost 企业版 |
|---|---|---|
| D1 有害内容 | 判定在阿里云端；另有自托管 Qwen3Guard | 本地无，用模型判官或外部服务 |
| D3 密钥凭据 | 无 | 本地嵌入 Gitleaks v8.30.1，默认 222 条规则 |
| D4 提示词攻击 | 阿里云端；Qwen3Guard 的越狱类别，仅输入 | 本地无 |
| D5 自定义规则 | 云端自定义服务；本地词库与正则 | 本地正则；语义规则用模型判官 |

**两家 D1/D4 的判定实现都拿不到**：阿里在云端，BF 企业版闭源（源码与镜像均不公开，镜像只在私有仓库）。公开的只有网关侧代码、文档宣称的能力，以及规则类检测。

## 二、可复用的部分

- **Gitleaks**（BF 密钥检测的基础，MIT，Go 库）：关键词预筛 → 正则 → 香农熵 → 白名单 → 通用规则去重。222 条规则中 221 条带关键词、130 条带熵阈值。本机实测：40KB 文本约 0.3ms；中文“密钥是…/密码：…”零召回；国内厂商只有阿里云两条。
- **Higress 敏感词库**：6.4 万条（来源 houbb/sensitive-word-data，Apache-2.0），无分类无等级，jieba 分词后精确匹配，不做变体归一化。
- **Qwen3Guard**（Apache-2.0，0.6B/4B/8B）：输出 `Safety/Categories/Refusal` 三行，9 个类别。Higress 插件只用 Safety 等级，类别弃之不用，调用失败即放行。
- **BF 模型判官**：待检内容编码为 JSON 单独发送，输出 `{action: ALLOW|BLOCK, reason}`，超时或解析失败时放行，默认提示词不公开。

我方检测结果有低/中/高三级，而两家本地规则只有命中与否，BF 判官只有二元结果；给出等级的只有阿里云端和 Qwen3Guard。

## 三、DeepSeek 判官实验

材料与原始结果见 [判官实验/](判官实验/)。做法：借 ai_house 的 DeepSeek 适配器调 `deepseek-v4-flash`（关 thinking、JSON 输出、温度 0），43 条中文样本各调 2 次，`medium` 及以上算拦截；同批样本用两个词库对照。

| 方式 | 该拦的 | 误拦 |
|---|---|---|
| DeepSeek 判官 | 22/22 | 0/21 |
| ai_house 词库（1150 词） | 3/19 | 2/18 |
| Higress 词库（6.4 万词，子串匹配） | 6/19 | 6/18 |

- 词库分母少 6 条业务规则样本。19 条里有 7 条提示词攻击、3 条变形写法，词库全部漏掉；命中的部分还有一半靠“客服”“政府”这类与风险无关的词，它们同时造成误拦。Higress 实际用分词精确匹配，本机无 jieba，子串匹配是其命中上限。
- 判官 86 次调用全部返回合法 JSON，拦截决定两次一致。耗时 p50 约 670ms、p90 约 890ms。每次约 350 token，按 ai_house 配置的单价估算约 0.0004 元。
- **ai_house 那一行只是它的第一层**：其完整流程是词库 → LLM 规划节点判断意图（跑题判为 `OFF_TOPIC`），实际防护效果高于表中数字。它的 LLM 判断的是“是否属于租房业务”，通用网关不能把跑题当风险。
- **样本偏简单**：样本与提示词出自同一人，意图明显。未覆盖长文本、多轮铺垫、隐晦表达、政治敏感边界、大批量误报率和流式。
