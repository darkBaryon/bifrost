## 一、先分清调研对象

| 层次 | 主要职责 | 本轮对象 |
|---|---|---|
| 网关安全功能 | 选择业务流量、调用检测、执行处置、记录结果 | Bifrost 企业版、Higress、阿里云 AI 网关、LiteLLM、Portkey |

## 二、阿里云：网关与检测服务分别做什么

### 2.1 AI 网关：统一管理模型、工具与 Agent 的访问

阿里云 AI 网关覆盖模型代理、MCP 工具访问和 Agent 访问。与本次有关的能力包括：消费者鉴权、模型密钥管理及 KMS 接入、网络入口防护、内容检查、数据脱敏，以及按消费者观察调用和拦截情况。MCP 工具级授权也属于其功能；授权能力不能直接等同于工具参数内容检测。[官方产品概述](https://help.aliyun.com/zh/api-gateway/ai-gateway/product-overview/what-is-an-ai-gateway)

### 2.2 网关中的安全配置流程

文档路径为：实例 → Model API → 目标 API → 策略与插件 → AI 安全防护。先开通护栏服务，再选择检测 Service；按消费者配置输入/输出检查及拦截等级。消费者支持全体、精确、前缀、正则匹配，处置包含观察模式。只开启开关而未开启检查策略不生效；检查与拦截是两个配置层次。该接入页限定文本生成和图片生成场景。[网关接入操作说明](https://help.aliyun.com/zh/document_detail/2980055.html)

### 2.3 AI 安全护栏：检测能力与运营工作台

阿里云文档将安全护栏、内容安全增强版、内容安全 1.0 列为不同产品系列。本轮以 AI 安全护栏为主；旧内容审核接口的能力与新版护栏不能混用。[产品系列入口](https://help.aliyun.com/zh/product/28415.html)

安全护栏产品介绍覆盖内容合规、个人/企业敏感信息、提示词攻击，以及恶意文件、恶意 URL 等风险。它提供的是检测能力，业务侧如何阻断仍取决于接入方式和策略。[产品概述](https://help.aliyun.com/zh/document_detail/2873209.html)

管理员在“防护配置 → 模型防护”选输入或输出 Service，按维度和细分标签启停检测。防护配置页将恶意 URL、模型幻觉标为公测；敏感内容与提示词攻击提示单独计费。当前页列有 `_pro` Service，而网关接入页仍展示普通及 `_hp` Service，不能据此假定所有网关实例均可使用同一列表。[防护配置](https://help.aliyun.com/zh/document_detail/2878231.html)

| 运营功能 | 管理员能做什么 |
|---|---|
| 词库 | 维护自有风险词及过滤词 |
| 代答库 | 为命中内容配置替代回答 |
| 在线测试 | 提交样本查看检查效果 |
| 结果查询 | 查看送检内容的判定及返回参数 |
| 风险报表 | 查看调用趋势与风险分布 |

以上来自[功能集](https://help.aliyun.com/zh/document_detail/2873210.html)。误报漏报 FAQ 还描述了自定义检测提示词、测试后发布、样本反馈和日志排查；日志分析需单独开通，部分定制能力存在地域限制。[误报漏报排查](https://help.aliyun.com/zh/document_detail/289095.html)

### 2.4 已发现的文档边界

- **流式行为需要核实到接入产品。** 网关操作页写明“检查响应”会改变流式交付；同页又提供面向流式的 `_hp` 检测服务。护栏优势页则介绍全链路流式审核。检测引擎能力不能直接证明网关前端仍逐段收到内容。[网关说明](https://help.aliyun.com/zh/document_detail/2980055.html)、[护栏技术说明](https://help.aliyun.com/zh/document_detail/2873212.html)
- **维度清单存在差异。** 网关总览与具体接入页展示的检测维度并不完全一致；文件、水印、幻觉等能力是否在指定 Model API 可用，需要按地域、版本、Service 及实际控制台核实。[网关总览](https://help.aliyun.com/zh/api-gateway/ai-gateway/product-overview/what-is-an-ai-gateway)、[网关接入](https://help.aliyun.com/zh/document_detail/2980055.html)
- **产品宣传不作为效果验收。** 当前没有中文误拦率、漏检率、延迟和单位业务成本的实测证据。

## 三、四家网关的主要安全功能

### 3.1 Bifrost 企业版：规则选择流量，档案定义检测

官方当前页面支持 LLM 与 MCP 两种规则目标。Rules 选择阶段及业务条件，Profiles 配置检测器，可复用；控制台分 Configuration 与 Providers。它包含正则、密钥检测、模型判官及外部检测服务。MCP 规则覆盖执行前参数和执行后结果；输入历史轮数也可配置。这些是上游商业版说明，不是本仓 EE 已实现能力。[护栏总览](https://docs.getbifrost.ai/enterprise/guardrails)

值得单独看的两个子功能：

- **脱敏范围**：运行时脱敏、仅日志脱敏、运行时脱敏并保留可授权查看的日志映射。查看原值需要 `Logs:Reveal`；“日志可还原”不等于自动把原值还给调用方。[脱敏模式](https://docs.getbifrost.ai/enterprise/guardrails/redaction)
- **自然语言策略**：选择判官模型、填写业务规则、验证后绑定。Verify 主要验证配置、连通性及结构化结果，不证明业务判定准确。该检测器运行异常时放行，每个检测阶段增加模型调用。[Prompt Guardrails](https://docs.getbifrost.ai/enterprise/guardrails/prompt-guardrails)

### 3.2 Higress：不同插件分别完成审核和数据保护

`ai-security-guard` 对接阿里云审核服务，按路径抽取输入输出，可配置拒答状态码与文案。文档示例以最后一条消息为默认输入抽取对象，支持在域名/路由/服务配置检测服务，并提供拦截指标和风险 Trace 字段。[内容安全插件](https://higress.cn/docs/latest/plugins/ai/api-provider/ai-security-guard/)

`ai-data-masking` 负责敏感词拦截、正则/Grok 替换、哈希和部分返回还原，可处理对话字段、指定字段或原始正文。文档明确承认：跨流式片段可能导致部分敏感词已返回，或脱敏词不能还原。[数据脱敏插件](https://higress.cn/docs/latest/plugins/ai/api-consumer/ai-data-masking/)

官方另有 Qwen3Guard 插件说明：调用独立部署的 Qwen3Guard-Gen，覆盖输入、输出及 SSE 分段审核。它不是直接集成 Qwen3Guard-Stream；当前主要按整体风险级别决策，尚不支持按类别分别配置动作。[官方接入文章](https://higress.cn/blog/higress-mmse_awbbpb_yafyyrc3t5wh0u55)

**交付状态**：v2.2.4 官方更新文章注明，该插件可自行构建，但未进入该版本官方插件快照。本轮该文章搜索结果可读，全文打开失败；发布状态需在后续固定 tag/插件镜像时复核。[版本说明](https://higress.cn/blog/higress-mmse_awbbpb_qwo0xq9sf9bc9i21)

### 3.3 LiteLLM：检测器接入与可复用策略

配置检测器后，可选择调用前、调用后、与模型并行检测或仅日志等模式，并支持默认启用。`during_call` 会与模型调用同时开始，等待检查完成再返回；由此不能把它当作“敏感输入尚未发出”的保障。另有 system/tool 消息是否参与检测的配置。[快速入门](https://docs.litellm.ai/docs/proxy/guardrails/quick_start)

Policies 将检测器组成可复用策略，支持继承、增加与移除。页面将该功能标为 Beta，团队/Key 策略绑定明确要求企业许可证；控制台存在 Policies/Attachments 配置流程。[策略说明](https://docs.litellm.ai/docs/proxy/guardrails/guardrail_policies)

### 3.4 Portkey：检查、动作与请求配置组合

操作路径为创建 Checks → 设置 Actions → 放入 Config → 应用到请求。检查包括正则、结构验证和模型判定，并可接外部服务；动作可同步阻断或异步记录，结果进入日志。总览明确称只检查请求体最后一条消息，不能据此宣称覆盖全部历史。不同检查类型按套餐开放，本文不将 SaaS 管理能力归为开源免费能力。[护栏文档](https://portkey.ai/docs/product/guardrails)

已有企业检测服务可通过 webhook 接入，由检测服务返回判断或修改后的内容，再由网关执行动作。[自定义护栏接入](https://portkey.ai/docs/integrations/guardrails/bring-your-own-guardrails)

## 四、检测引擎的补充地图

本节只辨认候选能力，没有完成选型。

| 对象 | 官方资料可确认的主要职责 | 本轮仍未确认 |
|---|---|---|
| 腾讯云 LLM-WAF | 提示词攻击、内容检测、敏感数据、Tool Call 防护等大模型安全能力 | 工具意图检测的实际协议范围与效果；与普通文本审核的差异 |
| 腾讯云审核/代答 API | 可直接送检，按服务策略判定；风险命中后可另调接口生成安全替代回答 | 网关适配成本、超时行为、真实流式阻断时机 |
| 百度内容审核 | 文本按 `strategyId` 送检，返回审核结论及风险信息 | 提示词攻击及 Agent 特定能力不能由普通文本审核接口推定 |
| Qwen3Guard | Gen 整体判定与 Stream 增量监测两条路线；不同模型规模 | 中文业务效果、算力成本、模型许可证及部署版本 |
| Presidio | 个人信息识别与去标识化，可扩展识别器与转换方式 | 中文实体覆盖、误识别及与现有 Go 服务的运行方式 |

腾讯云还有 TokenHub 与 LLM-WAF 集成：业务侧管理能力开关，细粒度规则进入 WAF 控制台配置，可作为另一种“网关配置与检测配置分开”的产品参照。[TokenHub 内容安全](https://cloud.tencent.com/document/product/1823/134506)

## 五、“支持流式”必须再细分

| 产品/功能 | 本轮官方资料描述 | 不能直接推出的结论 |
|---|---|---|
| Bifrost 可阻断的输出规则 | 完整生成与检测结束后，允许则回放；可设置回放间隔 | 有 SSE 格式不等于低首字延迟 |
| Bifrost 运行时脱敏 | 缓冲文本段，检查并处理后释放；仅日志模式不延迟客户端 | 脱敏模式与整段阻断不是同一种执行方式 |
| 阿里云网关响应检查 | 接入页说明改变流式交付，另列流式检测 Service | 检测服务支持流式不等于网关链路已保持流式 |
| Higress 数据脱敏 | 明确列出跨片段泄漏和无法还原的限制 | “支持替换”不能等同于零泄漏 |

来源：[Bifrost 流式行为](https://docs.getbifrost.ai/enterprise/guardrails#streaming-output-guardrails)、[Bifrost 脱敏](https://docs.getbifrost.ai/enterprise/guardrails/redaction)、[阿里云网关](https://help.aliyun.com/zh/document_detail/2980055.html)、[Higress 脱敏限制](https://higress.cn/docs/latest/plugins/ai/api-consumer/ai-data-masking/)。

这些机制对首字延迟、跨段上下文、已发出内容、取消和缓冲上限的影响，需专项实验。本轮不对各家的保护效果排名。
