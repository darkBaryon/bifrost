# 国内模型定价

> 2026-09-13 起草，同日用户确认第五节全部决策，本文即需求文档，可作为工程方案输入。依据：[现有功能盘点 B4](../../竞品调研/03-现有功能盘点与开发候选.md)、[路线图](../../路线图.md)、本机 `config.db` 与 `logs.db` 实测、上游 `framework/modelcatalog/datasheet` 源码（基线 `f371548b5`）。

## 一、背景与目标

网关按每次调用的 token 数乘以单价计算费用，费用用于控制台展示、预算扣减和限流。单价来自上游维护的定价表，启动时从 getbifrost.ai 下载，每天同步一次。定价表以美元计价，覆盖海外厂商较全，国内厂商的官方端点大量缺价。

本需求的目标是：**通过国内厂商官方端点调用的模型，费用计算正确。** 做到这一点，预算和限流才有意义，控制台的花费统计才能看。

本期不引入人民币。费用继续以美元为基准，价格文件里的单价带币种标注，导入时按基准货币换算。人民币作为基准货币的切换见第八节，另立需求。

## 二、现状事实

以下为实测与源码核实结果，非推测。

**定价表对国内厂商的覆盖不完整。** 本机同步的定价表共 4673 行，国内厂商官方端点的情况：

| 厂商键 | 行数 | 有价行数 | 说明 |
|---|---|---|---|
| dashscope（阿里百炼） | 45 | 25 | qwen3-max、qwen3-coder-flash 等新模型无价 |
| moonshot（Kimi） | 26 | 26 | |
| deepseek | 11 | 11 | |
| volcengine（火山、豆包） | 12 | 2 | |
| minimax | 10 | 6 | |
| 智谱 | 0 | 0 | 完全没有 |

**自定义厂商查不到任何价。** 上游只内置了 DeepSeek 一家国内厂商，Qwen、Kimi、智谱等都要以"自定义厂商"方式接入，由管理员自己起名。费用计算按"厂商名 + 模型名"查定价表，厂商名取管理员起的名字。本机把阿里百炼命名为 `qwen`，定价表里对应的行在 `dashscope` 下，两者对不上，结果是本机 qwen 的 20 次调用费用全部为零，而内置的 deepseek 调用有费用。这意味着：**即使定价表补齐了国内厂商的行，自定义厂商仍然算不出费用。**

**上游已提供覆盖机制。** 管理员可以在控制台"自定义定价"页或 config.json 里声明定价覆盖：指定作用范围（全局、某厂商、某厂商的某把 key、某虚拟密钥），指定模型名（精确或通配），给出单价。覆盖优先于定价表；定价表里没有的模型，只有覆盖也能算费用。覆盖存在配置数据库的 `governance_pricing_overrides` 表。

**上游正在内置国内厂商。** 上游 issue #6053 在把 Qwen、Kimi、智谱做成内置厂商。完成后这三家会有固定厂商名，定价表可能补齐官方行。时间未定。

## 三、功能范围

1. **维护一份国内官方端点价格文件。** 一行一个模型：厂商、模型名、输入单价、输出单价、缓存命中单价（如有）、来源链接、核对日期。只收录定价表缺的、错的，以及自定义厂商需要的行。文件放在 ee 仓库，随版本发布。
2. **启动时把价格文件导入覆盖表。** ee 启动时读取价格文件，写入或更新覆盖表中由本功能管理的行，管理员手工创建的覆盖不受影响。导入是幂等的，重复启动不产生重复行。
3. **按接入地址自动识别厂商。** 价格文件按厂商的固定标识组织（如阿里百炼、Kimi、智谱），每家附官方接入域名。导入时读取本部署的厂商列表，自定义厂商的接入地址落在哪家域名下，就把那家的价格写成该厂商名作用域的覆盖，管理员不需要按固定名字起名。识别不出的厂商（如自建代理地址）可在 ee 配置里手工指定对应哪家作为兜底。
4. **更新方式是改文件。** 厂商调价后修改文件、发布新版本。不做在线拉取，不做自动同步。

### 非目标

- 不做人民币展示与按人民币填预算（见第八节，另立需求）。
- 不修改上游定价表的下载与同步机制，不修改上游的费用计算逻辑。
- 不做控制台页面。管理员查看和临时修改覆盖仍用上游现有的"自定义定价"页。
- 不做海外厂商的价格修正。
- 不承诺定价表与官网价格实时一致，以文件的核对日期为准。

## 四、业务规则

- 覆盖表中由本功能写入的行带有固定的命名标记，导入时只增改这些行，不删改管理员手工建的行。
- 管理员手工建的覆盖若与本功能的行作用范围相同，以上游覆盖机制的优先级规则为准，本功能不额外处理冲突。
- 价格文件里的模型在部署中不存在时，照常导入，不报错。费用计算按请求时的模型名匹配。
- 价格文件解析失败时，启动继续，记录错误日志，不导入任何行，也不删除上次导入的行。
- 上游定价表将来补齐某模型的官方价后，本功能的覆盖仍然优先。文件维护者负责在核对时删掉已多余的行。

## 五、决策记录

- 2026-09-13：价格文件里的单价带币种标注，官网标什么币就写什么币；导入时按系统基准货币换算，汇率是 ee 配置里的一个数。本期基准货币是美元，人民币价乘汇率导入。将来切换基准货币时价格文件不用动。

- 2026-09-13：首版覆盖阿里百炼（Qwen）、DeepSeek、Kimi、智谱四家；每家只收官网价目表上在售的对话模型，不收下线版与预览版；火山、MiniMax 及嵌入、语音等类型后续按需追加（用户：之后加也简单）。

- 2026-09-13：自定义厂商与价格文件的对应采用"按接入地址自动识别，手工对应表兜底"（用户：最符合直觉）。管理员若恰好按定价表键名起名（如 `dashscope`），定价表行与覆盖同时命中，覆盖优先，结果一致。

## 六、验收标准

1. 部署里以任意名字的自定义厂商接入阿里百炼（接入地址为官方域名），不做额外配置，调用一次价格文件中收录的模型，请求日志里的费用等于该模型的输入单价乘输入 token 数加输出单价乘输出 token 数。
2. 同一模型的费用与控制台"自定义定价"页显示的覆盖单价一致。
3. 重启两次，覆盖表中本功能管理的行数不变。
4. 管理员手工建一条覆盖后重启，该覆盖仍在。
5. 把价格文件改成非法内容后重启，服务正常启动，日志有明确错误，上次导入的行仍在。
6. 调用价格文件未收录的模型，行为与本功能上线前一致。
7. 自定义厂商的接入地址不是任何已知官方域名时，不写入覆盖，日志提示可用手工对应表指定。

## 七、留给开发阶段的提醒

- 覆盖表结构与作用范围枚举在上游 `framework/configstore/tables/pricingoverride.go` 与 `framework/modelcatalog/datasheet/types.go`；费用查找与"仅覆盖"回退在 `datasheet/cost.go` 的 `resolvePricing`。
- 上游把覆盖行同步到内存目录的入口是 `ModelCatalog.UpsertPricingOverrides`；导入后要走这个入口或等价路径，不能只写表。
- 单价字段是每 token 的美元数，官网价目通常按每百万 token 标价，录入时换算。
- 上游定价表由 LiteLLM 仓库的 `model_prices_and_context_window.json` 转出（2026-09-13 逐行比对 215 行 208 行一致，2 行为 LiteLLM 更新后的新价），价格文件的字段名照它的用，便于日后向 LiteLLM 提 PR 补国内价。提 PR 是并行的补充路径，不替代覆盖文件。
- 竞品对照（2026-09-13）：Higress 开源版无费用概念，阿里云 AI 网关商业版用 Credits 由管理员在实例内手填每模型系数；One API 倍率写死在 Go map、人民币价按固定汇率折美元基准；New API 三层倍率、未配价报错；LiteLLM 用仓库内 JSON。没有任何一家提供权威国内价格源。
- 按[数据代码分离](../../../workbench/规范/项目/编码规范.md)要求，价格文件是数据文件，不写成 Go 字面量。

## 八、后续需求：人民币作为基准货币

2026-09-13 用户选定方案：不给上游加币种字段，也不在展示层换算，而是**让系统里的数字全部变成人民币**。上游只认数字不认货币，喂给它的数字换成人民币即可。涉及三处：

- **定价表。** ee 定期下载上游定价表，所有单价乘汇率写成本地文件，把上游的定价表地址指向该文件。与离线部署的镜像机制合做。
- **国内价格文件。** 本需求已带币种标注，切换基准后人民币价不再换算，美元价乘汇率。
- **前端符号。** 美元符号换成人民币符号。上游前端有一个集中的格式化函数（24 处调用）与 33 处写死的美元符号，用 UI 覆盖层或中文化字典机制处理，不改上游文件，具体做法待核实。

汇率改动后定价表自动重新生成，历史日志不回算，预算按人民币填。对外接口费用字段含义变为人民币，需在文档说明。因涉及前端，另立需求排在本需求之后。
