# 产品文档约定

本目录负责产品资料、竞品调研和需求方案；工程设计与交付遵循独立的 `../workbench/` 约定。

- 先读 `README.md` 和对应需求资料，避免另起一份重复文档。
- 新产品需求按“竞品调研 → 总结 → 产品方案”推进。调研阶段只陈述竞品事实与证据，不能提前把自己的建议写成确认规则。
- 开源实现核对记录仓库、commit 和代码出处；区分运行验证、源码阅读、官方说明和推断。
- 产品方案引用调研依据，区分沿用、适配和未确认事项；用户未确认的建议不得作为已批准需求交给开发。
- `竞品调研/` 放公共背景；`需求/<中文名称>/` 放具体需求；`docs-zh/` 放参考资料，不再向其中添加需求和产品路线图。
- 小需求可合写，复杂需求再拆；产品文档不规定代码文件、类和函数的实现细节。
- Workbench 引用产品方案，不复制另一套业务规则；实施发现需求缺口时反馈产品侧。
- 每份文档说明用途、确认情况及必要的适用版本。当前有效内容与历史证据分开，旧方案被替代时明确链接接替文档。
- 移动文档时修复相对链接；功能 worktree 中同源文档先比较再整合，不覆盖并行修改。
