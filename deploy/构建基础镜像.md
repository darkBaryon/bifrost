# 构建基础镜像

需求：将原 Dockerfile 中每次可能重新执行的编译工具安装提前完成，业务镜像复用专用 AMD64 构建环境。

镜像：`registry.cn-hangzhou.aliyuncs.com/yxdocker/ai-gateway:buildbase-go1.27-node25-v1-amd64`。

已推送 digest：`sha256:291a045df1c1d656583d3b2717bd74a05992183d3cbdca0d56d9355025105e20`。根 Dockerfile 已固定该摘要。镜像未压缩大小约 596 MiB；只有构建阶段使用，完整工具链不会复制进业务运行镜像。

包含 Go 1.27.0、Node 25、npm、bash、make、gcc、musl-dev、git 和 CA 证书，开启 CGO，沿用 GOPROXY=https://goproxy.cn。项目源码、npm 依赖、Go 模块依赖仍由业务构建处理。最终运行阶段的小型 Alpine 镜像仍安装运行库。

在项目根目录执行：

```bash
docker build --platform linux/amd64 \
  -f deploy/Dockerfile.buildbase \
  -t registry.cn-hangzhou.aliyuncs.com/yxdocker/ai-gateway:buildbase-go1.27-node25-v1-amd64 \
  deploy

docker image inspect \
  registry.cn-hangzhou.aliyuncs.com/yxdocker/ai-gateway:buildbase-go1.27-node25-v1-amd64 \
  --format '{{.Os}}/{{.Architecture}}'

docker push registry.cn-hangzhou.aliyuncs.com/yxdocker/ai-gateway:buildbase-go1.27-node25-v1-amd64
```

架构必须为 linux/amd64。升级工具或重新安装更新的软件包时，请更换版本标签（如 v2），不要覆盖正在使用的版本。基础镜像不包含 Jenkins 每次注入的构建标签；应避免清理脚本直接删除该基础镜像。Jenkins 仍在 node2 构建，预装工具不会修复 master 上旧 Docker 的系统调用兼容问题。

推送新版后，使用该次 push 输出的 digest 更新根 Dockerfile 的 FROM。平时只构建业务镜像，无需重复执行上述基础镜像制作命令。

镜像使用现有 ai-gateway 仓库中的独立 buildbase 标签，不需要新建仓库；不要将这个工具镜像部署为业务应用。

回滚时，将根 Dockerfile 的构建阶段恢复为独立 Go、Node 基础镜像及原来的 apk 工具安装命令即可。无需修改数据库或集群资源。
