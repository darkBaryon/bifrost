## 五个战略级判断

**1. "160+ 网关"是幻觉,活着的全开源重量级只有 5 家**
LiteLLM、Higress、Envoy AI GW、Bifrost、New API。Portkey 被收购后冻结(纸面开源、实际停摆),Kong 的 AI 能力实为商业产品,One API 已死。选型和对标都只需要看这五家。

**2. Bifrost 的性能牌正在被瞄准**
LiteLLM 官方 Rust 重写(2026-06 起 beta):p99 0.7ms、6.8k RPS/实例——虽然还没 GA、流式未完善,但"Go vs Python"的代差窗口可能只剩 6-12 个月。Bifrost 需要在窗口期内把差异化转移到治理深度和交付体验上。

**3. MCP 网关已从差异化变成标配**
七家里五家有 MCP 能力,Envoy AI GW 甚至做到了 v1.0 GA 级(工具聚合+OAuth+CEL 授权)。2026 的竞技场已经移到 **MCP 治理的深度**(按用户凭证、工具级 ACL、调用计费)和 **Agent 流量**(Kong 已支持 A2A)。

**4. "中国合规缝隙"假设修正:缝还在,但变窄了**
- Higress 已占据"国产模型+内容安全"主阵地——但**内容安全绑死阿里云付费服务**,且 Istio+Envoy 栈对中小企业过重
- New API 有敏感词表——但只是关键词黑名单,无 PII/提示注入防护;AGPL 传染性 + 定位是"站长计费分发",企业治理(RBAC/审计/追踪)全是空白
- **真正的剩余空白**:轻量单二进制 + 企业级治理 + 不绑阿里云的内容安全(私有化审核引擎/多引擎适配)+ 信创国产数据库适配。这恰好是"Bifrost 底盘 + 中国合规层"能填的形状
- 风险提示:这个空白 Higress 一个迭代就能填(加个通用审核引擎接口),窗口不稳定

**5. 商业模式对开源活性的影响已有实证**
- 被安全巨头收购 → 冻结(Portkey)
- 免费版做诱饵 → 薄核心(Kong)
- 母体养着 → 持续活跃(Bifrost/Higress)
- 社区自养+商业授权 → 活跃但许可证收紧(New API: Apache→AGPL)
选依赖底座时,"谁在养它"比"现在功能多少"更重要。
