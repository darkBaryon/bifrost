# 阅读路线图:如何读懂这 40 万行代码

> 核心思路:**别按目录顺序读,跟着一个请求的生命周期读**。网关的一切代码都为"一个请求穿过去"服务,抓住主动脉,其余都是挂在上面的分支。不需要读完 41 万行——14 万行 Provider 适配器和大部分 handler 都是模式重复,读一个样本即可。

## 第 0 步:先跑起来再读(半小时)

```bash
make dev          # 或 npx -y @maximhq/bifrost
```

控制台配一个 Provider 的 Key,curl 一条 `/v1/chat/completions`,到 Logs 页面看这条记录。先建立黑盒行为,读代码就是在给行为找解释。配合[总体架构](../02-架构/01-总体架构.md)建立地图。

## 第 1 步:读协议契约,拿到"词汇表"(1-2 天)

读 `core/schemas/`(挑着读):请求/响应主结构(`BifrostRequest`/`BifrostResponse`)、`plugin.go`(五种 Hook 接口)、Provider 接口。这是全项目的中间表示(IR),读懂后 80% 的函数签名都能望文生义。

## 第 2 步:跟一个请求走完全程(3-5 天,核心投入)

1. **启动装配**:`transports/bifrost-http/main.go` → `server.Bootstrap()`——见[源码精读/01](../03-源码精读/01-入口与启动装配.md)
2. **HTTP 入口**:`handlers/` 的 completions handler——HTTP 如何变成 `BifrostRequest`
3. **引擎本体**:`core/bifrost.go`(8800 行,只读主链路)——PreRequestHook → 入队/worker → Key 加权选择 → PreLLMHook(可短路) → Provider 调用 → PostLLMHook(LIFO) → fallback 循环。**读透这个文件,项目就通了**
4. **一个 Provider 适配器**:只读 `core/providers/openai/`,其余 22 家是同一模式的变奏
5. **流式回程**:`framework/streaming/` 的 accumulator——SSE 分片如何重组

技巧:调试器在请求入口打断点,curl 一条单步走一遍,比干读快十倍。

## 第 3 步:按兴趣挑子系统(每个 1-2 天,可跳过)

| 想懂什么 | 读什么 |
|---|---|
| 插件机制 | `plugins/mocker`(最小)→ [插件体系](../02-架构/04-plugins-插件体系.md) |
| 治理/虚拟密钥/预算 | `plugins/governance`(最大),对照 UI 的 governance 页面 |
| 语义缓存 | `plugins/semanticcache` + `framework/vectorstore` |
| MCP 工具网关 | `core/mcp/` |
| 存储层 | `framework/configstore/tables/`(约 40 张表,表结构即功能清单) |
| SDK 兼容层 | `transports/bifrost-http/integrations/` |

## 三个加速器

1. **AGENTS.md**——仓库给 AI 编码代理写的说明书,全是约定和踩坑记录,等于官方"新人须知"
2. **拿测试当文档**——29 万行测试是最准确的行为说明;想知道某 Provider 的 wire 格式,直接看测试夹具
3. **docs/architecture/**——官方英文架构文档,与本中文文档互补
