# 10 · 开发指南（含 IDE 报错排查）

## 环境要求

- Go ≥ 1.26.5（本机低版本也行：`GOTOOLCHAIN=auto` 会自动下载所需工具链）
- Node.js（UI 与 npx 包）
- Docker（framework/E2E 测试的后端服务）

## ⚠️ 第一步：生成 go.work（不做 IDE 必定大面积报错）

本仓库是 15+ 模块的 Go workspace，但 `go.work` **被 .gitignore 忽略**，克隆下来没有。缺失时 framework/transports 会去解析**已发布的旧版** core/插件模块，而本地 `dev` 分支代码用了未发布的新 API，于是 gopls/编译到处报 `undefined`、`missing go.sum entry`。

```bash
make setup-workspace   # 官方方式：重建 go.work，纳入 cli、core、framework、transports、全部插件、tests/cmd/*
```

完成后重启 gopls（VSCode：命令面板 → "Go: Restart Language Server" 或直接 Reload Window）。

### 第二个常见报错：`pattern all:ui: no matching files found`

`transports/bifrost-http/main.go` 用 `//go:embed all:ui` 嵌入前端产物，目录不存在时报此错。两种解法：

```bash
# 轻量占位（make dev 内部也是这么干的）
mkdir -p transports/bifrost-http/ui && touch transports/bifrost-http/ui/.tmp

# 或真正构建一次前端
cd ui && npm install && npm run build
```

## 常用命令

```bash
make dev                 # 完整本地开发：UI 热更新(3000) + API 热更新(8080, air)
make build               # 构建 bifrost-http 二进制
make lint / make fmt     # 代码检查 / 格式化
make mod-tidy [MODULE=core|framework|transport|plugins|cli|tests]  # 按模块 tidy
make work-clean          # 删除 go.work（还原为发布版解析）
```

测试命令见 [09-测试体系.md](09-测试体系.md)。

## 工作区规则（来自 AGENTS.md）

- `go mod tidy` 要在**具体模块目录**跑，不要在仓库根跑。
- 跨模块 import 本地靠 workspace 解析，但发布时必须在 go.mod 写明 `require`。
- 版本发布顺序遵循 core → framework → plugins → transports 层级（有 `/changelog-writer` 技能辅助）。

## 常见开发任务速查

**加一个新 Provider**：`core/providers/<name>/`，OpenAI 兼容的走极简委托模式，非兼容的实现完整转换器（`types.go`/`errors.go`/`chat.go`…）；转换函数必须纯函数；记得配 `streamingClient`（否则流 30s 被掐）。

**给 API 响应加字段**：`core/schemas/` 加类型 → Provider 响应转换器映射 → 流式聚合器（`framework/streaming/`）处理 → 必要时 HTTP handler 序列化 → 可配置的话更新 `transports/config.schema.json`。

**加插件**：`plugins/<name>/` 独立 go.mod → 实现 `LLMPlugin`/`MCPPlugin`/`HTTPTransportPlugin` → 加进 go.work → transport 层注册 → Makefile 加测试目标。

**改 UI**：`ui/app/workspace/<feature>/` → 保留/补充 `data-testid` → `make run-e2e FLOW=<feature>` 验证。

## 核心禁忌（Gotchas）

1. **池化对象归还前必须清零全部字段**（`pool.Put` 不会自动重置，脏数据会串请求）。
2. **BifrostContext 里不放大数据**——只放 ID/布尔/指针；随流增长的缓冲放 RequestID 键控的管理器。
3. 插件 Post-hook 是 LIFO，逻辑不要假设执行顺序与 Pre 相同。
4. Provider 转换函数保持纯净：无 HTTP、无日志、无副作用。
5. 流式路径一律用 `streamingClient`，一元路径用 `client`。

## 本次环境排查记录（2026-08-18）

当时 IDE 大量报错的三个根因与处置：

| 报错 | 根因 | 处置 |
|---|---|---|
| framework 里 `accResult.ServiceTier undefined` 等 | 缺 go.work，解析到已发布的 core v1.7.11，缺少 dev 分支新字段 | `make setup-workspace` ✅ |
| `missing go.sum entry for go.mod file`（semanticcache→mocker） | 同上（模块缓存解析）+ 依赖未下载 | 同上，workspace 内改用本地模块 ✅ |
| `pattern all:ui: no matching files found` | 前端产物未构建，embed 目录不存在 | 建占位目录 `transports/bifrost-http/ui/.tmp` ✅ |

处置后 `core`、`framework`、`transports` 全部 `go build ./...` 零错误。若 IDE 仍显示旧红线，重启 Go 语言服务器即可。
