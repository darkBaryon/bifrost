# UI 中文化层(zhLocale)

> 本 fork 的第一个差异化功能:不改任何组件源码,把控制台界面中文化。

## 方案与取舍

三个候选方案里选了 **DOM 字典翻译层**——核心约束是本 fork 需要持续 merge 上游,任何触碰 `ui/` 组件源码的改动都是永久性同步税:

| 方案 | 触碰文件 | merge 上游冲突 |
|---|---|---|
| 改源码 i18n(react-i18next) | 569 个 tsx 全动 | 永久大面积冲突 |
| **DOM 字典层(本方案)** | **新增 1 个 + 改 2 行** | 几乎为零 |
| 浏览器翻译 | 0 | 0(但无法产品化) |

## 实现

- **[ui/lib/zhLocale.ts](../../ui/lib/zhLocale.ts)**:词条字典 + MutationObserver。页面任何位置渲染出英文文本节点(及 placeholder/title/aria-label 属性),立即按字典替换为中文。
- **[ui/app/main.tsx](../../ui/app/main.tsx)**:`import { installZhLocale }` + `installZhLocale()` 两行注入——应用最顶端,登录页也覆盖。

关键设计:

1. **未收录词条保持英文**——上游新增页面永不白屏,补字典即可
2. **大小写兜底查表**——UI 大量用小写枚举 + CSS `capitalize` 显示(如状态筛选器的 `success`),查表同时登记原键与全小写键,否则这类文案全部漏翻
3. **翻译后的中文不会再命中字典**,MutationObserver 不会死循环
4. 跳过 `SCRIPT/STYLE/CODE/PRE/TEXTAREA` 与 Monaco 编辑器,技术内容不翻
5. 逃生门:`localStorage.setItem("bf-lang","en")` 后刷新即回英文

## 维护

- **补词条**:逛界面发现英文 → 在 `DICT` 对应分区加一行 `"English": "中文"`。注意先搜索避免重复键(TS 会报 1117 错)
- **动态拼接句**(如 "3 keys found")当前不翻,需要时在 `translateRaw` 里加正则规则层
- merge 上游后唯一可能的冲突点是 `main.tsx` 那两行,重新加上即可

## 已知边界

- React 重渲染会瞬间闪一下英文再被替换(肉眼几乎不可见,可接受)
- 图表 SVG 文本可翻,但轴刻度数字/日期格式暂未本地化
- 生产构建(`npm run build`)自动包含本层,无需额外步骤
