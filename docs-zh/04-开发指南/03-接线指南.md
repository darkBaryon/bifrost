# 接线指南:二次开发时在哪儿动手

> 想给系统加东西时,对号入座找到正确的接线位置。原理背景见 [源码精读/02-依赖注入模式](../03-源码精读/02-依赖注入模式.md)。

## 速查表

| 你要加的东西 | 接线位置 | 参考样本 |
|---|---|---|
| 请求处理逻辑(拦截/改写/计费/审计) | **写插件**(首选!) | `plugins/mocker`(最小)、`examples/plugins/` 模板 |
| 新管理 API 的 Handler | `RegisterAPIRoutes`(server.go:2021 起) | 任意现有 Handler 的构造 + `RegisterRoutes(r)` |
| 启动时要跑的后台服务 | `Bootstrap()` 按依赖顺序插入 | `WebhookDispatcher`(server.go:2435) |
| 新的持久化后端/外部客户端 | `lib.LoadConfig`,挂到 `lib.Config` | 现有 Store 的初始化 |
| core 需要的新能力 | 先在 `core/schemas` 定义接口,transport 实现后经 `BifrostConfig` 注入 | `MCPHeadersProvider` |
| 新的 Provider | `core/providers/` 新目录 | 抄 `deepseek/` 结构 |
| 控制台页面 | `ui/app/workspace/` | 相邻功能页面 |

## 黄金原则:能用插件就不改 core

插件是官方设计的扩展点:PreHook/PostHook 能拦截、改写、短路每一个请求,独立成模块、不碰上游代码。收益在同步上游时兑现:

| 改动方式 | `merge upstream/dev` 时 |
|---|---|
| 新增文件(新插件/新 Provider 目录/文档) | **零冲突** |
| 现有文件里加几行(handler 注册等) | 偶尔小冲突,几分钟解决 |
| 大改 core/bifrost.go 逻辑 | 每次同步都可能撞车 |

## 注册新插件的两步

1. 实现 `core/schemas/plugin.go` 里的接口(按需选 LLMPlugin/MCPPlugin/HTTPTransportPlugin);
2. 在 `transports/bifrost-http/server/plugins.go` 注册,选好 `Placement`(pre_builtin/builtin/post_builtin)和 `Order`——内置 8 插件的固定顺序是 telemetry → prompts → logging → governance → otel → semanticcache → compat → maxim。
