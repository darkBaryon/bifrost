# 09 · 测试体系

仓库有多层互相独立的测试套件，入口统一在根 Makefile。

## 分层总览

| 层 | 位置 | 说明 | 运行 |
|---|---|---|---|
| core 集成测试 | `core/internal/llmtests/` | **打真实上游 API**（需要各家 Key），48 个文件、场景化组织 | `make test-core [PROVIDER=openai] [TESTCASE=TestSimpleChat] [PATTERN=...] [DEBUG=1]` |
| MCP/Agent 测试 | `core/internal/mcptests/` | 全 Mock，无真实 API | `make test-mcp [TYPE=agent\|tool\|connection\|codemode]` |
| framework 测试 | `framework/*/` | 需要本地后端服务 | 先 `docker compose -f tests/docker-compose.yml up -d`（postgres、clickhouse、weaviate、qdrant、pinecone、4 种 redis），再 `make test-framework` |
| 插件测试 | `plugins/*/` | 各插件自带完整测试 | `make test-plugins` / `make test-governance` |
| UI E2E | `tests/e2e/features/` + `tests/e2e/core/` | Playwright，按功能分 spec（providers、virtual-keys、dashboard、logs、mcp-*、routing-rules、governance、mobile……），依赖组件 `data-testid` | `make run-e2e [FLOW=providers]` |
| API E2E | `tests/e2e/api/` | Newman/Postman 集合：**provider-harness**（回归主力）、inference-features、auth-matrix、rate-limit、mgmt-flows、async-webhooks、mcp-auth、model-catalog-wiring 等；自研 reporter（cache-parity、dbverify、token-parity） | `make run-provider-harness-test` 等 |
| CLI 测试 | `tests/e2e/clis/` | Go 套件，跑 CLI/harness 矩阵 | `make run-cli-harness-test` |
| 专项 Go 套件 | `tests/governance/`、`tests/async/`、`tests/semanticcache/` | 预算/限流/用量、异步生命周期、语义缓存 | 对应 make 目标 |
| SDK 兼容 | `tests/integrations/{python,typescript}` | 验证 OpenAI/Anthropic 等官方 SDK 直连 Bifrost | `make test-integrations-py` / `-ts` |

## 辅助设施

- `tests/cmd/`：`seed`、`e2eseed`、`seedvks` 种子数据工具（已包含在 go.work 中）。
- `tests/scripts/`：负载与迁移工具（`1millogs` 百万日志压测、`migration-checker`）。
- 代码质量：`make lint`、`make fmt`。

## 约定与坑

- UI E2E 依赖 `data-testid`：改 UI 必须保留；新交互元素要补。E2E 断了可用仓库技能 `/e2e-test sync` 同步。
- `make test-core` 会产生真实 API 消费，跑之前确认环境变量里的 Key。
- provider-harness 集合（`tests/e2e/api/collections/provider-harness.json`）是给已合并 PR/issue 补回归用例的地方，仓库有 `/harness-test-writer` 技能协助。
