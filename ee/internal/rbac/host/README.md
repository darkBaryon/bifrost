# Bifrost接口的角色权限接入

让已有管理接口按账号角色开放，并隐藏账号无权读取的敏感内容。登录由`ee/internal/host`检查；本包调用rbac根包查询权限，包装Bifrost原有的请求处理函数。

| 文件 | 职责 |
|---|---|
| [authorization.go](authorization.go) | 当前请求的权限检查、前后处理及失败日志 |
| [routes.go](routes.go) | 读取路由规则，核对实际注册，拒绝未知接口和异常路径 |
| [routes.txt](routes.txt) | 明确列出每个方法、路径及其权限规则，同一规则的接口集中放置 |
| [request.go](request.go) | 导出密钥等额外操作检查，以及保存厂商配置前的回调 |
| [response.go](response.go) | 隐藏配置中的敏感字段，检查响应结构，保留可以展示的内容 |
| [providers.go](providers.go) | 厂商地址和请求头隐藏，以及更新时保留原值 |

修改前要知道：

- 只有`managed`接口使用本包角色授权；`legacy-admin`仍只允许初始化管理员。协议与自有接口由原来的处理器检查。
- 新增接口必须在清单登记，启动时发现遗漏就报错；不根据GET/POST猜权限。
- 请求检查必须先于业务写入；无法理解的敏感响应不能直接返回原文。
- `<redacted>`是保留原值的标记，不能当成新密钥保存；没有旧值时拒绝更新。
- 当前开放厂商、虚拟密钥、治理、路由、MCP和提示词；日志、Webhook、插件、设置、通知及WS仍保留初始化管理员限制。
