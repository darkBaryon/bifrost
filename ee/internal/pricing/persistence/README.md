# 国内定价存储适配

## 解决什么问题

`pricing` 根包要读厂商列表、增删改覆盖行、更新内存目录，但它不认识数据库和上游类型。
本包是这三件事的翻译层，把根包声明的接口接到上游的两个对象上：

- `ConfigStore` 是上游的配置数据库访问层，厂商、密钥、定价覆盖这些表都经它读写。
- `ModelCatalog` 是上游在内存里维护的模型与价目表，算费用时查的就是它，进程重启即重建。

由 `app` 在启动时构造并注入根包。

## 文件

| 文件 | 内容 |
|---|---|
| `store.go` | 三个适配器，以及业务行与上游表行之间的双向转换 |
| `store_test.go` | 转换往返与错误映射 |
| `cost_test.go` | 费用闭环：装入生成的覆盖行，验证上游真的据此算出费用 |

## 要改这里时该知道的

- **上游的错误要翻译成根包的哨兵**。行已存在、行不存在这两种情况，根包据此决定转更新还是当作删除成功，
  多节点同时启动的幂等就靠它。其余错误原样上抛，保留原因。
- **内存目录只做增量**，不用上游的全量替换接口，否则会清掉管理员手工建的覆盖。
- **落库和更新内存的先后由根包决定**，本包不自作主张。

费用闭环测试放在这里而不是根包，是因为它要导入上游的定价模块，而根包连测试都不依赖上游。
