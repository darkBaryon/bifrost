# 国内定价

## 解决什么问题

网关按「厂商名 + 模型名」查定价表算费用。国内厂商大多要以自定义厂商接入，名字由管理员自己起，
和定价表里的官方键名对不上（管理员起名 `qwen`，定价表里叫 `dashscope`），于是费用一律算成零。
定价表本身每天从上游重新下载，改它没有意义。

本包在启动时把随版本发布的国内官网价格，写成上游自己的「定价覆盖」行，按厂商作用域精确匹配模型名。
覆盖压过定价表；定价表里没有的模型，只有覆盖也能算出费用。

不新建表、不改上游代码、不做页面、不在线拉价、不监听运行期厂商增删（新增厂商需重启一次）。

## 代码在哪

只有启动期这一条路径，没有 HTTP 入口、定时器或后台任务。

```
cmd/bifrost-http/main.go
└── app/bootstrap.go            上游 Bootstrap 之后、Start 开始监听之前接入
    └── app/pricing.go          读三个环境变量，构造依赖，调用一次 Sync
        ├── pricefile.go        解析嵌入的或 EE_PRICING_FILE 指定的价格文件
        ├── vendors.go          按接入地址主机名认出自定义厂商，手工对应表优先
        ├── overrides.go        换算单价，算出稳定 UUID，组装成覆盖行
        └── sync.go             与库内现状对差，增删改，再推进内存目录
            └── persistence/    翻译成上游的 ConfigStore 与 ModelCatalog 调用
```

另有 `model.go` 放业务模型与币种，`data/cn-prices.json` 是随版本发布的价格目录。
三个窄接口由 `sync.go` 定义、`persistence/` 实现，所以根包连测试都不依赖数据库和上游类型；
费用闭环测试因此放在 `persistence/cost_test.go`，其余测试与被测文件同名对应。

## 失败怎么处理

| 情形 | 行为 |
|---|---|
| 部署配置错误：汇率非法、手工对应表引用未知厂商、一个厂商命中多家 | 包装 `ErrConfig`，`app` 拒绝启动 |
| 价格文件解析或校验失败 | 记 error，跳过同步，不删旧行，服务照常启动 |
| 读厂商、覆盖增删改、更新内存目录失败 | 记 error，继续启动，已提交的行保留，下次启动继续收敛 |

## 取价规则

官网的阶梯计价、分时段价、思考与非思考价，在上游的覆盖表里只能写成一个单价，所以收录时要挑一档。
本期按 Gate 1 拍板的 A1 挑：**取最低档、取默认模式、不取需要客户端改造才生效的价**。
具体到每类价目怎么挑、未取的写在哪里，见[使用说明](../../docs/国内定价.md)的同名小节，两处口径必须一致。

改价格文件时记住两条：单价一律填官网币种的每百万 token 价，导入时统一折成美元每 token；
每条都要写来源与核对日期，费用的准确性以那个日期为限。

## 同步边界

- **只动自己的行**。覆盖表是共享的，管理员也能在页面上手工建行。本功能写的行，名称以 `ee-pricing: `
  开头（模型名不变，例如名称 `ee-pricing: dashscope/qwen-plus`、模型 `qwen-plus`）。但名称可以被模仿，
  所以归属还要求行的 UUID 等于用它自己的厂商名与模型名重算的值。两道都过才改或删；只对上名称的留一条
  告警，不碰。
- **多节点共享一张表是安全的**。创建撞上唯一约束转为更新，删除时行已不在视为成功。
- **换价升级要所有节点滚动重启**。表是共享的，内存目录是每个节点自己的，不重启就会新旧价并存。
- **不拥有数据库与宿主的生命周期**，也不做在线拉价和运行期监听。

环境变量、运维、回滚与单价近似带来的误差见[使用说明](../../docs/国内定价.md)。
