# 国内定价

## 解决什么问题

网关按「厂商名 + 模型名」查定价表算费用。国内厂商在上游只内置了 DeepSeek，其余要以自定义厂商接入，
厂商名由管理员自己起；定价表里对应的行却挂在官方键名下（管理员起名 `qwen`，定价表里叫 `dashscope`），
两者对不上，于是这类调用的费用一律算成零，预算、限流和花费统计全部失去意义。上游的定价表还每天重新
下载，直接改它没有意义。

本包在启动时把一份随版本发布的国内官网价格，写成上游自己的「定价覆盖」行，让费用重新算得对。覆盖行
按厂商作用域精确匹配模型名，压过定价表；定价表里没有的模型，只有覆盖也能算出费用。

不做的事：不新建表、不改上游代码、不做页面、不在线拉价、不监听运行期厂商增删（新增厂商需重启一次）。
管理员查看和临时修改覆盖仍用控制台的自定义定价页。

## 架构

一条启动期调用链，没有 HTTP 入口、定时器或后台任务：

```
app.assemblePricing  读环境变量、装配依赖、调用一次 Sync
  └── pricing.Service.Sync   认厂商 → 生成期望行 → 与库内现状对差 → 增改删 → 推进内存目录
        ├── overrideStore    覆盖行的增删改查
        ├── catalog          本节点内存目录
        └── providerLister   本部署的厂商清单
```

三个窄接口由本包按实际需要定义，`persistence` 子包适配到上游的 `ConfigStore` 与 `ModelCatalog`，
依赖方向指向本包。根包（含测试）只依赖标准库与 `google/uuid`，不认识数据库和上游类型，因此同步逻辑
可以不连数据库直接测试。

失败分三类：部署配置错误（汇率非法、手工映射未知、厂商多命中）包装 `ErrConfig` 交由 `app` 拒绝启动；
价格文件无效记录错误并跳过同步，服务照常启动；存储与目录操作失败记录错误后继续启动，已提交的行保留，
下次启动继续收敛。

## 文件

| 文件 | 职责 |
|---|---|
| `model.go` | 无 JSON/数据库标签的价格业务模型与币种、取价口径 |
| `pricefile.go` | 独立 JSON DTO、嵌入文件、解析及整份校验（主机归一后须非空且首尾无点）、共享汇率判定 `ValidRate` |
| `data/cn-prices.json` | 随版本发布的价格目录；2026-09-13 官网核对，收录情况见使用说明 |
| `vendors.go` | 按接入地址主机名认出官网厂商（忽略大小写及单个末尾根域点），手工映射优先，保留原始厂商名 |
| `overrides.go` | 美元/token 换算、UUID v5 稳定 ID、精确匹配覆盖行的组装 |
| `sync.go` | 窄接口与 `Service`；`Sync` 及其四个步骤函数、所有权判定、逐行幂等与失败分类 |
| `persistence/` | 上游 `ConfigStore` / `ModelCatalog` 适配，错误映射为本包哨兵 |

测试与被测文件同名对应，均只用标准库与内存夹具；费用闭环测试在 `persistence/cost_test.go`，
因为它需要导入上游的 `datasheet`。

## 取价规则

文件头固定 `pricing_rule: lowest-tier-standard-rate`，按方案 v2 §9 的 A1 裁定：

- 输入长度取最低档；最低输入档内再按输出长度分档时，取最低输出档。
- 思考/非思考有不同价格时取非思考价；只有思考模式的模型取其唯一价。每条 `note` 记未取的思考价与其他阶梯价。
- 分时段取标准（高峰）价；限时折扣、Batch 折扣、赠送额度不取；真正免费模型填 0。每条 `note` 记未取的优惠。
- 缓存只有一种命中价时直接填；分显式/隐式时取自动生效的隐式命中价，显式命中及创建价不填，`note` 记未取比例。官网未公开、仅控制台显示的缓存价不填 `cache_read_input_cost`，不得按通用比例推算。未明确列出的快照不沿用别名缓存价。
- 在售以官网模型概览/模型列表的可用标注核实，历史价格行不能单独证明在售；不收预览与下线版。名单和公开价目交叉核对，疑点与未收录项见核对记录。
- Kimi 动态页读不到时仅收录官网静态内容能核实价格的模型；其余跳过并记实施偏差，不引入浏览器自动化。

这是单价近似：长上下文、较长输出子档和较贵的思考请求可能少算；折扣时段或活动价请求可能多算。它不等于厂商实际账单。输入/输出/缓存字段保存官网币种的每百万 token 价格，导入时统一换成美元/token。

## 同步边界

覆盖行的所有权同时核验保留前缀 `ee-pricing: ` 与 UUID 自洽，两者都对才动；管理员手工建的行一律不改，
只对上前缀的留一条告警。创建撞上唯一约束转为更新，删除时行已不在视为成功，因此多个节点共享同一个库
同时启动是安全的。价格目录与来自 `ParseVendorMap` 的映射在服务使用期间只读，`New` 只拷贝需要被环境
变量覆盖的汇率。

模块不拥有数据库与宿主的生命周期。多节点共享同一张表但各有内存目录，换价升级需要所有节点滚动重启，
否则新旧价格并存。环境变量、运维、回滚与单价近似带来的误差见[使用说明](../../docs/国内定价.md)。

`sync_test.go` 围绕同一同步服务共享内存夹具，保持单文件便于对照生命周期与失败路径；场景分组增长
明显时按职责评估拆分，并遵守编码规范的文件行数上限。嵌入的价格 JSON 超过 500 行是逐模型来源与核对
数据，不是业务代码，按方案 §5 保留单一完整文件，避免分片改变外部替换文件的契约。
