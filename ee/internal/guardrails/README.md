# 本地内容安全框架

本包把“运行哪些检测、风险达到什么等级、命中或失败后怎么办”集中到一个规则执行器。检测器通过构造函数注入，`plugin` 子包提供 BF Chat 前后置 Hook。实际检测算法、配置管理和生产注册尚未接入，不能据本包存在认定网关已开启防护。

参考 [Higress 固定提交研究](../../../product/需求/内容安全/Higress源码研究.md)的职责拆分、阈值判断和处置流程，按本项目的本地检测契约实现；不依赖 HG 的运行时或云调用代码。

| 文件 | 职责 |
|---|---|
| `rules.go` | 检测阶段、D 项、风险等级、动作、检测器接口及事件 |
| `engine.go` | 配置快照、按序执行规则、超时和失败处置 |
| `engine_test.go` / `rules_test.go` | 规则语义、配置校验、取消、边界及并发测试 |
| `plugin/plugin.go` | BF Hook、错误短路、不含原文的事件日志 |
| `plugin/text.go` | 全历史纯文本、逐候选输出提取及未知载体拒绝 |
| `plugin/*_test.go` | Hook 边界与真实 BF 管线中的模型替身测试 |

## 核心约束

- 根包 `New` 接收规则、本地检测器注册表和完整文本字节上限。根包只依赖标准库，BF 类型留在 `plugin`。D1/D3/D4/D5 常量不代表已经实现检测算法。
- `Check` 接收完整 UTF-8 文本，按阶段和规则顺序执行；达到阈值才命中，观察继续，阻断停止。空文本仍送检，空规则不执行检测。
- 每条规则明确超时、命中动作和失败动作。检测失败允许或阻断均记为失败；取消、非法输入和超限返回框架错误，调用方不能忽略。
- 检测同步执行，实现必须并发安全并响应 context 取消；框架不会启动超时后遗留的 goroutine，也不能强杀不响应取消的算法。
- 规则及注册表复制，检测器实例不复制，其生命周期归装配方。事件不保留正文、命中原文或检测器异常文本。

## BF 接入边界

`plugin.New(engine, options, logger)` 返回可加入宿主插件链的 `schemas.LLMPlugin`。错误状态码（400–599）与拦截文案必须显式指定；安全错误设置 `AllowFallbacks=false`。当前没有往 `app` 注册空策略或测试检测器。

输入检查全部历史纯文本；非流式输出逐个检查候选回答，所有候选共享文本总字节预算。原始正文、未知参数、工具、多模态和推理等未覆盖结构明确拒绝。开启输出检查时拒绝流式请求；仅输入检查允许规范化 Chat 流式请求。上游错误保持原样，本包不审核错误正文。

生产装配前须确定改写插件的顺序、缓存及 Provider 行为：本轮只验证独立 Hook 和 BF 测试管线，不保证任意组合中的后续改写受保护。检查完成后不能再被其他插件或旁路改写正文。生产默认状态码、检测算法及启用范围尚未确定。

验证：在 `ee/` 执行 `GOWORK=off go test -race ./internal/guardrails/...`。检测器和模型替身仅存在于测试文件；集成测试实际运行 BF 插件管线，不调用外部服务。
