# 角色权限接口

这些接口管理角色、分配角色，以及查询账号能做什么。账号创建、停用和密码操作见[账号认证接口](账号认证接口.md)。前端页面不在本次后端交付范围。

## 请求约定

下表路径均以 `/api` 开头，全部使用 POST、JSON 对象、`ee_session` Cookie 和同源 Origin。请求体最大 16 KiB；拒绝未知字段、重复 JSON 键、显式 null 和多份 JSON。未登录返回 401，强制改密会话返回 403。成功默认 200，创建角色返回 201。

| 路径 | 请求字段 | 所需权限 | 成功响应 |
|---|---|---|---|
| `/permissions/list` | `{}` | Users.View | `{modules}`，按功能分组的权限目录 |
| `/permissions/me` | `{}` | 正常登录即可 | 本人的账号权限结果 |
| `/roles/list` | `{cursor?,limit?}` | Users.View | `{items,next_cursor}` |
| `/roles/get` | `{role_id}` | Users.View | `{role}` |
| `/roles/create` | `{name,description?,permission_codes}` | Users.Manage | 201 `{role}` |
| `/roles/update` | `{role_id,name,description,permission_codes}` | Users.Manage | `{role}`，完整替换名称、说明和权限 |
| `/roles/delete` | `{role_id}` | Users.Manage | `{message}` |
| `/accounts/get-roles` | `{account_id}` | Users.View | 指定账号的权限结果 |
| `/accounts/set-roles` | `{account_id,role_ids}` | Users.Manage | 替换后的账号权限结果 |

`?` 表示字段可省略，不表示允许 null。更新角色时四个字段全部必填；`permission_codes: []` 清空权限。分配角色也是完整替换，`role_ids: []` 清空分配，最多提交 64 个编号（去重前计数）。不能修改自己的角色分配；不能移除最后一个启用的主管理员。

角色编号是 1 到 9007199254740991 的 JSON 整数，不接受字符串、小数或指数形式。账号编号是 UUID。角色名去掉首尾空白后不能为空、不能包含控制字符，最多 64 个字符；说明最多 512 个字符。权限必须来自目录，多角色权限取并集，Manage 不自动包含 View 或敏感权限。

## 返回字段

- `role`：`id`、`name`、`description`、`system_code`、`permission_codes`、`account_count`、`created_at`、`updated_at`。时间为 UTC RFC3339；自建角色的 `system_code` 为 null，预置角色为 chief/developer/readonly。
- 账号权限结果：`account_id`、`roles`、`permissions`、`matrix`。`roles` 每项包含 `id/name/system_code`；`permissions` 每项包含 `code/role_ids`，说明权限来自哪些角色；`matrix` 是功能名到操作开关的映射，供前端显示入口和按钮，不能代替后端判权。
- 权限目录：`modules` 每项包含 `code/name/permissions`；权限项包含 `code/name/available`。没有角色或权限时返回空数组。
- 分页：默认 20 条，显式 limit 必须在 1–100；按创建时间及编号倒序。下一页原样传回 `next_cursor`；末页为 null，空页 `items: []`。

三个预置角色不能删除。主管理员始终拥有整个目录的权限，其权限列表不能修改；开发者和只读角色的权限可以修改。关联了账号的角色不能删除，包括已停用账号的关联；冲突响应的 `details.account_count` 给出关联数量。

## 当前范围

目录中 `ModelProvider.RevealKey`、`Settings.AuthConfig`、`Settings.ImportConfig` 为预留项，`available: false`，当前没有开放入口。`available` 只说明功能是否开放，不是服务端授权开关。账号支持停用，没有删除账号接口。

已有 Bifrost 管理接口保留原方法和路径，按各自权限检查；敏感字段会被隐藏。通知需要 Notifications.View，并按当前角色筛选受众；长连接每次发送前重新检查会话和权限。具体边界见[宿主接入说明](../internal/rbac/host/README.md)。

## 错误

错误体为 `{"error":{"code":"…","message":"…"}}`，必要时包含 `details`。自有角色接口使用 400 invalid_input、401 unauthorized、403 forbidden、404 not_found、405 method_not_allowed、409 conflict、503 unavailable。错误方法同时返回 Allow，响应禁止缓存。

经过角色适配的上游接口保留原 HTTP 错误状态；当前对未单独映射的状态（例如 500/422/429）使用 `unavailable`，因此不能仅凭这个 code 认定 HTTP 状态一定为 503。此项已登记 FIND-022，前端接入时统一口径。

## 凭据发送地址的敏感权限

权限目录新增安全模块下的 `Security.ChangeCredentialDestination`，名称为“允许将已有凭据用于新地址”。主管理员自动拥有，开发者、只读和已有自建角色不自动获得；管理员可通过角色更新接口授予，撤回后下一次操作重新检查。目录共30项，不需要数据库迁移，也不覆盖用户已有角色设置。该权限不产生matrix开关，前端可从permissions读取；后端在保存时检查权限组合。

修改已有厂商、单Key及别名地址、代理、Webhook认证头、OTEL/遥测上报配置时，若保留旧凭据并改变地址或TLS信任，需要该权限和所属模块的管理权限。普通名称、超时更新不额外要求；全部换为自己提供的新凭据时仍按原模块权限处理。厂商配置接口总会保留已有Key，换请求头不等于换掉全部凭据。地址按完整值比较，含路径、查询及默认地址回退。

MCP连接地址本身不可通过更新接口修改；可变的TLS和OAuth目的地遵守同一规则。用户令牌、云端服务器身份、同一env/vault引用也属于已有凭据。令牌交换还携带调用者身份令牌，所以仅换client_secret不能免除目标变更权限。此权限不允许读取密钥明文，也不代替各模块的管理权限。
