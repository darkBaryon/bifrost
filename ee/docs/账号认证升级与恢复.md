# 账号认证升级与恢复

本期交付认证后端；认证页面、项目操作日志页面与完整RBAC后续接入。以[接口文档](账号认证接口.md)及[批准方案](../../workbench/cases/账号认证/期1/方案v2.md)为准。

## 部署

| 环境变量 | 规则 |
|---|---|
| EE_PUBLIC_ORIGIN | 浏览器访问的完整origin，例如https://gateway.example.com；非回环必须HTTPS。回环监听未设置时按host/port推导本机HTTP |
| EE_INITIAL_PASSWORD | 默认123456，仅管理员建号和重置使用，可覆盖；不能为空、必须UTF-8且≤72字节。所有节点一致配置 |
| EE_SESSION_TTL_HOURS | 默认24，1–168整数；签发时固定到期，修改部署值不延长已发会话 |
| BIFROST_SETUP_TOKEN | 复用宿主初始化密钥；空实例没有此密钥不能创建首个管理员。通过受保护的部署环境注入，不打印/写入脚本历史 |

支持现有SQLite/PostgreSQL配置库，禁用config_store或迁移失败则拒绝启动。PG所有节点连同一权威库，不能鉴权时查询只读副本。使用数据库会话，无Redis和进程认证缓存。会话表与WS票据表只保留未到期行：写入新会话/票据时顺带删除已到期的行（含已撤销、已消费），运维无需定期清理；行数自查见ee/internal/identity/persistence/README.md。身份表和hash不得输出到应用日志；网关/反代访问日志须避免记录认证头、Cookie、密码请求体和ticket查询值。

生产HTTPS通常在反代终止，应用EE_PUBLIC_ORIGIN仍配置外部HTTPS，并只允许可信反代访问内部端口；不要依靠客户端X-Forwarded-*推断安全属性。登录按真实TCP peer IP限流，反代用户共享IP桶，这是首版限制。

独立BIFROST_PPROF_* profiling端口有自己的凭据和回环规则，不受控制台Cookie保护，不应反代为公开入口。主Router的/api/dev/pprof仍要求chief。

## 升级

1. 停止全部旧节点、关闭流量，备份完整配置库及部署配置，记录版本；SQLite使用备份API/一致性快照，不能只复制正在写入的主文件。PG使用一致备份并验证恢复。
2. 整体切换新EE，禁止新旧二进制共库混跑。迁移ee_identity_v1原子建立六张身份表及版本记录；后续事务创建唯一chief。
3. 完整有效的旧用户名/bcrypt快照迁移为chief，开关原先关闭也会强制开启EE认证。旧用户名、短密码原样保留，新登录后使用个人会话；旧Cookie/Basic/Bearer/ticket无效。
4. 若文件密码超过bcrypt上限而宿主回退到有效旧DB凭据，迁移采用已解析的DB快照；日志给出无凭据来源提示，必须用原DB密码登录。残缺、空外部引用或不支持的hash拒绝启动，修正配置后再启。
5. 原先没有旧账号的空实例调用initialize，部署密钥正确才可建首个管理员；不能凭默认123456初始化。创建后初始化接口409。
6. 验证新登录、成员强制改密、配置读写及密码事件查询，再恢复流量。EE初始化后不会从旧文件/旧AuthConfig重新覆盖账号；改密后回改旧配置不能恢复旧密码。

默认初始密码在用户修改前可能被其他人使用；管理员重置日志可追查但不能阻止代登录。仅把账号交付给相应人员，优先配置更合适的初始密码。数据库/主机操作者可以修改日志，本期不是防篡改存证。

## 忘记主管理员密码

停止所有使用该库的实例，保留备份，在同一部署环境（数据库配置及必要环境变量）运行：

```bash
./bifrost-http identity recover-admin --app-dir /path/to/app-data
```

终端隐藏输入新密码；自动化可从受保护stdin输入。禁止将密码放命令行参数。命令读取app-dir/config.json确定原库；未配置config_store时要求现存config.db，不创建首个管理员、不更换chief。需使用原实例相同的工作目录处理相对数据库路径。

恢复新密码须符合新密码规则。事务更新chief密码/状态、撤销全部会话，写入actor=operator/action=admin_recovery事件；失败非零退出。成功后重启实例并登录查询事件。该命令不替你停止运行中的实例，没有常驻HTTP恢复后门。

## 降级回滚

优先前向修复。不能只替换旧二进制：旧AuthConfig可能保留过时密码甚至关闭认证。

关闭流量并停全部新节点 → 导出保留EE密码事件 → 恢复升级前完整一致备份及配置 → 显式开启旧管理员认证并清空旧sessions → 使用旧版本在隔离回环监听确认无凭据401、正确密码可管理 → 才恢复流量。备份之后的账号/配置变化可能丢失，需列明并接受。不得自动drop生产EE表或让新旧版本共用恢复中的库。

开发验收提供`ee/scripts/identity-upgrade-smoke.py --binary <新EE> --legacy-binary <基线EE>`，在合成SQLite上实际运行旧→新→备份恢复→旧；包含旧开关关闭、短密码、文件超长密码回退、配置修改不覆盖EE、启动失败与无setup密钥。基线为3e15a640d89902772445d3fb4c04023e58828eba。

## 验证命令

从ee模块使用GOWORK=off go test -race ./...；设置专用IDENTITY_TEST_POSTGRES_DSN可额外执行PG身份事务测试，每次独立schema。仓库根的identity-smoke.py --database postgres要求专用libpq格式DSN并创建自己的测试数据库，启动两节点，仅清理自己的进程/数据库；缺DSN直接失败。SQLite模式独立临时目录。测试证据保留于脚本输出目录，不包含对外输出的密码或token。

数据库故障日志包含operation、stage、incident_id、kind及driver码，不包含SQL或driver原文；HTTP故障关联X-Request-ID。SQLite迁移对busy/locked最多重试3次，每次完整回滚后重开事务，其他失败立即中止启动。PG冒烟成功才删自有库，失败保留库及证据目录并输出显式清理说明。
