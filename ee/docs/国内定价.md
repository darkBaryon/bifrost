# 国内定价

EE 启动时为按官方域名接入的自定义厂商写入官方模型价格覆盖，解决任意厂商名查不到基础定价、费用为零的问题。使用上游“自定义定价”页面查看覆盖。

当前内置目录核对日期为 **2026-09-13**：阿里百炼 65 个、DeepSeek 2 个、智谱 19 个；Kimi 保留厂商识别但暂无可核实的模型价格。来源、筛选和未收录项见[价格核对记录](../../workbench/evidence/国内定价-期1-价格核对.md)。默认汇率为部署参数 **1 USD = 7.20 CNY**，沿用方案示例，不是实时外汇牌价。

## 取价规则

文件头固定 `pricing_rule: lowest-tier-standard-rate`，按方案 v2 §9 的 A1 裁定：

- 输入长度取最低档；最低输入档内再按输出长度分档时，取最低输出档。
- 思考/非思考有不同价格时取非思考价；只有思考模式的模型取其唯一价。每条 `note` 记未取的思考价与其他阶梯价。
- 分时段取标准（高峰）价；限时折扣、Batch 折扣、赠送额度不取；真正免费模型填 0。每条 `note` 记未取的优惠。
- 缓存只有一种命中价时直接填；分显式/隐式时取自动生效的隐式命中价，显式命中及创建价不填，`note` 记未取比例。官网未公开、仅控制台显示的缓存价不填 `cache_read_input_cost`，不得按通用比例推算。未明确列出的快照不沿用别名缓存价。
- 在售以官网模型概览/模型列表的可用标注核实，历史价格行不能单独证明在售；不收预览与下线版。名单和公开价目交叉核对，疑点与未收录项见核对记录。
- Kimi 动态页读不到时仅收录官网静态内容能核实价格的模型；其余跳过并记实施偏差，不引入浏览器自动化。

这是单价近似：长上下文、较长输出子档和较贵的思考请求可能少算；折扣时段或活动价请求可能多算。它不等于厂商实际账单。输入/输出/缓存字段保存官网币种的每百万 token 价格，导入时统一换成美元/token。

## 配置与使用

只识别上游自定义厂商（`custom_provider_config` 非空），不改变内置 DeepSeek 等厂商。默认按 `base_url` 的主机名匹配下表，支持等于或真实子域；无 scheme 时先补 `https://`。`dashscope-intl.aliyuncs.com` 不匹配北京域名。

`base_url` 主机名与白名单均忽略大小写，并各去掉一个末尾根域点（`dashscope.aliyuncs.com.` 等价）；`base_url` 带多个末尾点时不匹配该厂商，按未识别处理。

白名单本身另有校验：`endpoint_hosts` 归一后为空、以点开头，或去掉一个末尾点后仍以点结尾（如 `.`、`a.com..`、`.a.com`），整份价格文件判为无效，按下文「价格文件解析/校验失败」处理，即本次所有厂商都不同步。

| 厂商 ID | 默认主机 | 说明 |
|---|---|---|
| `dashscope` | `dashscope.aliyuncs.com` | 北京模型价格 |
| `deepseek` | `api.deepseek.com` | 厂商直连价 |
| `moonshot` | `api.moonshot.cn` | 本次无可核实价格，不生成覆盖 |
| `zhipu` | `open.bigmodel.cn` | 国内开放平台直连价 |

| 环境变量 | 用途 |
|---|---|
| `EE_PRICING_USD_CNY` | 1 美元对应的人民币数，有限正数；覆盖文件内 CNY 汇率 |
| `EE_PRICING_VENDOR_MAP` | 例如 `myqwen=dashscope,glm2=zhipu`；部署厂商名到文件厂商 ID，优先于域名；键小写归一 |
| `EE_PRICING_FILE` | 用完整外部 JSON 替换嵌入文件；不与嵌入目录合并，未设置时使用内置文件 |

例如设置 `EE_PRICING_USD_CNY=7.2` 后启动 EE。外部文件可从[内置 JSON](../internal/pricing/data/cn-prices.json)复制，保留 `pricing_rule`、单位与来源。人民币每百万 token 单价除以 1,000,000 再除以汇率；USD 只除以 1,000,000。不修改历史请求日志。

在上游自定义定价页中，可按原始厂商名查看 `ee-pricing: <vendorID>/<model>` 的 provider 作用域行。模型名必须与请求完全相同；流式/非流式的 Chat、Responses、Text Completion 均使用对应单价。未收录模型回到原上游查价路径，基础定价也没有时仍可能为零。

## 同步与失败处理

同步发生在完整宿主 Bootstrap 之后、开始监听之前，每次启动执行一次。运行期新增/删除厂商、修改域名或换价文件后需要重启；不在线拉官网价格，不监听文件。日志示例：

```text
pricing sync: created=2 updated=0 deleted=0 unchanged=0 unrecognized=[mystery]
```

覆盖 ID 是厂商原始名和模型名生成的固定 UUID v5。仅操作同时满足保留名称前缀 `ee-pricing: ` 和 UUID 所有权核验的行；普通手工行保持原样，伪装前缀而 UUID 不符的行只 warn 不动。管理员仍应避免使用保留前缀，且不要手改本功能管理的行，它们会在下次启动被同步恢复。手工行与本功能同作用域同模型时按上游优先级叠加，本功能不处理这种冲突。

- 非法汇率、有效文件下手工表引用未知厂商、主机多命中都包装 `pricing.ErrConfig`，装配用 `errors.Is` 判断并拒绝启动。
- 价格文件解析/校验失败：记 error，不同步、不删除原行，跳过映射校验并继续启动；环境汇率始终先独立校验。
- 厂商列表、覆盖 CRUD、目录 Upsert 失败：记 error，继续启动；已成功的表操作保留，下次启动继续收敛。表操作未全成功时不更新内存；目录失败后可能暂时保留启动时加载的价格。
- 对应表的键不是当前自定义厂商时 warn 并忽略；未识别域名则 info 记录厂商和主机并跳过。目录未装配时 warn 并跳过。

存储逐行提交，整批不是事务。双节点同时创建同一 ID 遇存在错误会转 Update；删除已不存在的行视为成功。多节点共享表但各自有内存目录，换价升级必须让所有节点滚动重启，避免节点间新旧价格并存。

若使用 `source_of_truth: "config.json"` 且显式声明 `governance.pricing_overrides`，上游加载配置会清理文件外的行，随后 EE 在监听前重建，无对外费用为零窗口，但每次启动可能再次记 `created=N` 并重置创建时间。

## 更新与回滚

维护价格时重新核对官网模型列表及标准价，更新 `version`、`checked_at`、每模型 note 和来源；升级时重启全部节点。价格准确性只保证到核对日期。

若要清理全部本功能管理的行，临时将 `EE_PRICING_FILE` 指向以下完整有效文件，清空 `EE_PRICING_VENDOR_MAP`，重启全部节点一次：

```json
{"version":"rollback","pricing_rule":"lowest-tier-standard-rate","vendors":[]}
```

空目录产生空期望集，仅删除本功能拥有的覆盖。保留此配置可停止自动导入；撤掉后再次启动会恢复嵌入目录。仅撤掉装配调用会停止同步，但已经落表的行仍需在上游页面删除。

## 验证

`make -C ee smoke-pricing` 会构建二进制并使用临时 SQLite、随机端口、虚假 key 和小价格文件验证完整 HTTP 管理链路。夹具关闭厂商模型发现，不执行真实推理；原 identity/branding 冒烟脚本未修改。费用引擎闭环在 `pricing/persistence/cost_test.go` 验证三种请求类型、流式与缓存。

真实 key 请求、日志费用与页面单价的人工核对属于方案 Gate 2 验收，本次实施不自行发起真实计费调用或评审。
