# 账号认证接口

支持本地个人账号；账号管理按角色权限授权，角色和分配接口见[角色权限接口](角色权限接口.md)。页面、SSO和完整操作审计另期实现。密码事件已有持久化及查询接口，现有操作日志占位页尚未接入。

## 请求与登录状态

自有接口全部POST、Content-Type: application/json、JSON对象最大16KiB，拒绝未知字段、重复键和多份JSON。请求必须携带与EE_PUBLIC_ORIGIN完全相同的Origin；缺Origin可用同源Referer，两个头冲突拒绝。读取型POST也遵守该规则。浏览器同源部署，fetch使用credentials:"same-origin"；不读取或保存登录token。

登录成功由Set-Cookie设置ee_session：HttpOnly、SameSite=Lax、Path=/，HTTPS部署附Secure，不设Domain。有效期默认24小时、绝对到期，无滑动续期。响应不返回session token。服务端只保存随机token的SHA256摘要，每次从权威数据库验证；不依赖Redis。密码使用独立盐bcrypt。

前端流程：status判断是否初始化 → initialize或login → 检查must_change_password；为true仅提供本人改密和登出 → 改密200后重新登录。接口401清理前端身份状态并转登录；403表示账号无权限或来源不合法，不等于登出。数据库错误503应提示稍后重试，不视为匿名放行。

账号响应字段：id(UUID)、username、display_name、status(active/disabled)、must_change_password、last_login_at(UTC RFC3339或null)。last_login_at 仅在成功登录提交时更新，精度为微秒；从未登录和升级前的未知历史值为null，失败登录不更新。不含密码、hash、权限版本。新建username为3–64位，首位字母/数字，其余字母/数字/下划线/点/@/连字符，大小写敏感；历史用户名原样保留。display_name可空，最多128字符。

## API

下表路径均以/api开头；除注明201外成功200。

| POST路径 | 请求 | 成功响应与限制 |
|---|---|---|
| /identity/status | {} | initialized、auth_type=password、is_auth_enabled=true、has_valid_session、must_change_password；兼容字段has_valid_token |
| /identity/initialize | {setup_token,username,password} | 201 {account}；仅空实例，核对部署初始化密钥；不自动登录 |
| /identity/login | {username,password} | {account,must_change_password,expires_at,message}及Cookie；错误账号/密码/停用统一401 |
| /identity/logout | {} | {message}并撤销当前会话、清Cookie；重复及无Cookie也成功 |
| /identity/me | {} | {account}；受限会话也可调用 |
| /identity/change-password | {old_password,new_password} | {message}并清Cookie；旧密码错误400；撤销本人所有会话，须重新登录 |
| /accounts/create | {username,display_name?} | 201 {account}；需要 Users.Manage，初始密码取部署默认值，响应不返回密码 |
| /accounts/list | {cursor?,limit?} | {items,next_cursor}；需要 Users.View |
| /accounts/set-status | {account_id,status} | {account}；需要 Users.Manage，不能停用自己或最后一个启用的主管理员；同状态幂等。停用撤销全部会话，启用不恢复 |
| /accounts/delete | {account_id} | {}；需要 Users.Manage；不存在404，自己或固定恢复账号403，最后一个启用的主管理员409 |
| /accounts/reset-password | {account_id,operation_id} | {event_id,result:"success"}；需要 Users.Manage，不能重置自己。重置为部署初始密码并强制改密，不启用停用账号 |
| /identity/password-events | {target_id?,cursor?,limit?} | {items,next_cursor}；有 Users.Manage 可查全量，其他账号仅本人，受限会话403 |
| /identity/ws-ticket | {} | {ticket,expires_in:30}；正常会话且有 Notifications.View，一次性、30秒 |

删除账号同时解绑角色、清理会话与WS票据；已建立长连接在下次发送前重新判权。历史密码事件保留，新建同名账号获得新编号，不继承旧角色。

新密码至少8字符、最多72字节、合法UTF-8，不等于当前密码或部署初始密码；不自动trim或截断。管理员创建/重置的默认初始密码是长度政策例外。初次及重置登录是受限会话，不能查看事件或任何管理设置。服务层同样执行限制。

重置operation_id必须为调用方生成的UUID。网络断开时使用原ID重试；同actor/target原样返回原结果，不重复改密或踢掉后来登录的会话。ID复用于其他actor/target返回409；失败事件同样占用ID，再次尝试使用新ID。409也可能表示权限在服务端两次判定之间发生变化，此时未写入任何事件，用同一ID重试即可。

事件字段：id、operation_id、actor_id、target_id、actor_name、target_name、action、result、reason_code、occurred_at（UTC RFC3339）。action为password_change、password_reset、admin_recovery；result为success/failure。离线恢复actor_id/name=operator。查询只读，账号名是操作时快照，记录不会因账号停用或删除而清除。没有密码、hash、Cookie、token或请求体。

分页按时间及ID倒序；limit省略时默认20，显式给出须在1–100之间，0或越界返回400。空页items=[]、next_cursor=null；后续请求原样传入next_cursor。游标非法400。没有 Users.Manage 的账号不传target_id则限定自己，传别人的ID返回403。

X-Request-ID用于关联安全故障诊断与访问日志，由服务端生成；错误内容不包含数据库原文。

错误统一为{"error":{"code":"…","message":"…"}}。400 invalid_input，401 unauthorized，403 forbidden，404 not_found，409 conflict，429 rate_limited（Retry-After:60），503 unavailable。每账号5次/分钟、真实TCP来源IP30次/分钟；未知账号也计数，不信任X-Forwarded-For，反代后用户共享IP桶。

## 兼容与WebSocket

旧POST /api/session/login、logout、ws-ticket委托新服务；logout/ws-ticket可空body，同源检查仍必需。GET /api/session/is-auth-enabled保持登录页状态形状并追加initialized、must_change_password。旧Cookie token、Basic、Bearer和/ws?token=全部不能管理EE；脚本改为先登录，再携带Cookie与Origin。

GET /ws使用ee_session Cookie，或先申请ticket，再以/ws?ticket=…握手；握手必须携带精确Origin。票据只消费一次，持有它不能访问其他管理路由。每次推送/心跳前重验原会话和 Notifications.View；推送还按当前账号角色匹配通知受众。撤回通知权限或重置/停用/删除/登出/过期后拒绝下一次验证并关闭连接。应用访问日志对/ws只记录路径，票据仍由认证处理者实际消费；外层提前拒绝也不记录查询凭据。日志系统和反向代理也应避免记录Cookie、Authorization及URL票据。

GET /api/config的auth_config是只读投影，client_config.whitelisted_routes=[]；完整响应不修改auth_config后原样PUT可以更新普通设置。改变认证字段或加入非空白名单，整请求409且不写普通字段。新认证配置使用部署环境变量，旧security页不能更改EE密码。

品牌公开读、OAuth协议及精确MCP临时令牌流程保持；品牌写及已有管理路由要求正常会话和各自对应的角色权限。个人Cookie不能作为推理VK。更多部署规则见[升级与恢复](账号认证升级与恢复.md)。
