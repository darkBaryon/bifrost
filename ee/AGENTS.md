# ee/ — 自有 EE 应用

本目录由我们自己维护，编码与评审遵循 [workbench/规范/项目/编码规范.md](../workbench/规范/项目/编码规范.md)，架构遵循 [product/架构/EE后端架构.md](../product/架构/EE后端架构.md)。`ee/` 以外的上游代码不按这套规范修改。

## Code Review Rules

实施与评审都按下列规则逐条核对（详见编码规范「硬规则」一节）：

- 对外枚举（状态、动作、结果、操作者标识）必须是业务根包的类型化常量，不用裸字符串。
- 业务限制各有命名常量并注明来源；派生值用表达式从源值算出。
- 同一条规则只在一处实现，需要复用就抽包内函数。
- 业务类型、HTTP 请求/响应结构、数据库行分开定义，业务类型不带 `json`/`gorm` 标签。
- 导出符号必须有用途注释；"未找到视为未认证""同状态幂等""失败事件仍提交"之类的特殊语义写进注释。
- 依赖通过构造函数显式注入；包外无使用方的符号不导出；`app` 负责装配，`bifrost` 只做宿主接入。
- 每个包有中文 README，逐文件说明职责；改代码同步改注释与 README。
- 自有接口统一 POST，路径为 `/api/功能/动作`；上游已有接口保持原样。

## 构建与测试

在 `ee/` 下以 `GOWORK=off` 运行：`go vet ./...`、`go test -race ./...`、`go build -o tmp/bifrost-http ./cmd/bifrost-http`。真实 HTTP 冒烟见 `scripts/`；本期检查清单见 workbench 各案 `checklist.yaml`。
