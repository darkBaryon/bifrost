## 背景

[内容安全框架](内容安全框架.md)已合入 develop，只有开发用假检测器。产品侧已确认检测方式（[调研总结](../../product/需求/内容安全/调研总结.md)「检测方式调整」）：D3 密钥用规则；D1 有害内容、D4 提示词攻击、D5 自定义业务规则由 DeepSeek 判官检测，网关直接调用；不内置通用敏感词库。依据见[检测器实现调研](../../product/需求/内容安全/检测器实现调研.md)与[密钥格式核实](../../product/需求/内容安全/密钥格式核实.md)。

## 目标

1. 密钥规则检测器：Gitleaks 规则数据 + 自写扫描，补中文关键词、国内外厂商规则，`sk-bf-` 白名单。
2. 判官检测器：通过网关内已配置的 provider 调判官模型，内置 D1/D4 提示词与 D5 规则模板，解析等级，失败重试后按规则策略处置。
3. 同阶段规则并行执行，遇拦截取消其余。
4. 显式配置装配：每个检测项目一个判官实例、每条 D5 规则一个实例；默认不启用。

## 非目标

管理 API 与持久化配置、脱敏与代答、输出流检查、MCP/多模态、判官调用的计费与日志落库、真实流量准确率保证。

## 定档提议

标准级（L2）：多模块（检测器、检查器、装配），引入判官调用这一新的运行期外部依赖；不改公开 HTTP 契约、不动数据表、无权限与迁移风险。

**用户裁决**：标准级，2026-09-19 随 Gate 1 放行确认。

## 验收口径

EE vet/race/build 与预飞全绿；密钥检测器对真假样本的单测通过；判官检测器用替身模型验证等级解析、重试与失败策略；并行执行有竞态测试；用真实 DeepSeek 跑一遍[判官实验](../../product/需求/内容安全/判官实验/)样本作独立验证记录（需要 key，不入必过）。
