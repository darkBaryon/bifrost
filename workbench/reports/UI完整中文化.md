## 背景

控制台原生纯英文。已建立 zhLocale DOM 字典层(252 词条,含大小写兜底),覆盖侧边栏/仪表盘/筛选器等主要界面,但仍是"逛到哪补到哪"的部分翻译:大量页面存在英文残留,带变量的动态句(如 "3 keys found")完全不处理。作为 fork 的首个差异化功能,需要从"演示级"推进到"可交付级"。

## 目标

1. **覆盖率工具**:脚本扫描 ui/ 全部 JSX 字符串字面量与关键属性,与字典 diff,输出未翻译清单——把覆盖从"碰运气"变成"可收敛的清单"
2. **正则规则层**:在字典精确匹配之后增加规则匹配,处理带变量的动态句(数量类/时间类/分页类),首批规则覆盖清单中出现的全部动态句式
3. **字典补齐**:按清单批量补词条,直至清单(除白名单)清零
4. 巡检验证:主要功能页(侧边栏全部入口 + 仪表盘/日志/供应商/虚拟密钥/MCP/设置)人工巡检无英文残留

## 非目标

- 不改任何组件源码做 i18n(维持 DOM 层方案与最小 merge 税)
- 不翻译:Monaco 编辑器内容、日志正文、模型名/技术标识、Dev Profiler(开发态组件)、品牌名
- 不做多语言框架(仅中文,不设语言切换 UI;逃生门维持 localStorage)
- 不翻译 docs/ 与代码注释

## 定档提议

标准级——单期可完成;有独立工具产物(覆盖率脚本)但不动系统结构、不跨模块;判据见规范「三档分级」。

**用户裁决**:待填

## 验收口径

- `覆盖率脚本` 可执行,输出未翻译清单为空(白名单条目除外)
- 动态句样例(至少:N keys found / N items / N minutes ago / 分页 Showing X of Y)在页面上翻译正确
- `cd ui && npx tsc --noEmit` 全绿;`npm run build` 成功
- 人工巡检目标 4 所列页面,无用户可见英文残留(白名单除外)
