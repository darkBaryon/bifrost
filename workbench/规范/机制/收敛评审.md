# 收敛评审

[← 返回规范主页](../../规范.md) · [流程](../流程.md)

代码评审回答"这个 Change 有没有**做对**"；收敛评审回答"做完之后整个系统**还健不健康**"。前者看功能对不对得起方案，后者看代码库对不对得起未来——两者读同一份 diff，互相独立，可并行。每个 Change 必经收敛评审，重量随[风险分级](../风险分级.md)。

## 第一原则

**机械检查产事实，判断只属于评审 agent，任何指标不得直接构成结论。**

- 脚本与命令（依赖 diff、文件增长、契约 diff、重复搜索）只产出事实，作为证据喂给评审；
- "文件超过 N 行""重复率超过 N%"这类指标**永远不允许**直接判定结论——指标只指路，判断靠读代码；
- 反过来，评审的每条判断必须落在具体证据上（`文件:行号`、diff hunk、git 历史），并给出**反证条件**——一个能推翻该提议的具体事实。

## 重量分级（成本与改动规模成比例）

六维是**责任清单，不是操作步骤**——它规定评审者"看过之后不能说没注意到"，不要求六次独立扫描。小 diff 一次通读就同时覆盖全部六维，正如人扫一眼 diff 就同时看见了重复和越界；评审耗时显著超过"人看一眼"的量级，就是在错误的深度上工作。

| 级别 | 执行方式 | 产物 |
|---|---|---|
| **L1** | 由独立复核者在复核时顺带完成，一次通读 | 交付摘要里一两句话（默认"无碍"），**不建单独文档** |
| **L2** | 可与代码评审同一独立 agent：先评正确性，再评结构 | 单独收敛评审记录，六维表可收束为段落 |
| **L3** | 必须独立于代码评审的干净上下文 agent，高配模型 | 逐维留痕的完整记录 |

## 独立性

不变量只有一条：**评审者与本 Change 的实施上下文隔离**——不能是写代码的那个会话自评。是否再与代码评审分开，按上表级别决定；L3 的结构判断没有事实表托底，不降档。

## 输入

1. 基线..HEAD 的完整 diff；
2. 存量代码（读被改文件的**完整现状**，不只读 diff 行；`git log` 看被改文件的历史，判断本次是否在惯性恶化点上又踩了一脚）；
3. [Finding 台账](finding台账.md)与豁免记录（不重提已裁决的问题）。

## 六个必看维度

这是**注意力清单，不是打分表**——保证每个维度被看过，不规定每个维度必须有产出，也不规定分维度调查（见"重量分级"）。

| 维度 | 核心问题 |
|---|---|
| **重复** | 新代码是否已有等价实现？是否出现第二套业务规则、重复转换 / 错误处理 / 工具类、同概念不同命名？ |
| **膨胀与职责** | 被改文件 / 模块的职责是否变多？是否继续往大 Service 里塞？函数、类、依赖是否失控？ |
| **架构边界** | 是否绕过既有接口、直接摸别的模块的数据、引入反向依赖或循环、违反分层？ |
| **契约一致性** | 前端类型、后端 Schema、SDK、OpenAPI、Enum、Error Code 是否同步？ |
| **测试健康** | 新规则有没有测试？fixture 是否重复？测试是否过度绑定实现？测试准备是否越来越复杂？ |
| **非功能**（按风险） | 性能、并发、幂等、安全、可观测性、数据一致性、部署与运维成本。 |

## 结论与四个出口

| 出口 | 判据 | 去向 |
|---|---|---|
| **无碍** | 本次没有让系统变差 | 正常走 Gate 2（默认结论） |
| **Blocking** | 本次引入的损伤，且现在修远比合入后修便宜：第二套业务规则、循环依赖、契约漏同步、数据一致性风险 | 阻塞 Gate 2，交用户裁决 |
| **REF Case** | 变差了，但事后治理不比现在贵 | 照常交付；立 REF 需求（`triggered_by: [<本case>]`）进队列 |
| **Finding** | 问题可能存在，证据还不足 | 记入 [Finding 台账](finding台账.md)，达到触发条件再转 Case |

记录模板：[`templates/收敛评审.md`](../../templates/收敛评审.md)。

## 校准（防噪音，最重要）

1. **默认结论是无碍**。只提值得用户专门拍板的问题；"命名可以更好"这类不值得拍板的，不写。
2. **Blocking 高门槛**：绝大多数 Change 应该以无碍或立债收束，功能交付不被审美人质化——但每一笔债都被看见、被记账。
3. **不重提已豁免的问题**，除非本次改动使其显著恶化。
4. **不越界**：功能对不对是代码评审的事，方案该不该做是 Gate 1 已决的事。

## 闭环

结构改善的唯一诚实证据是后续开发不再被绊住：REF Case 完成后，其效果由**后续 Change 的收敛评审**验证（同一双眼睛再看一遍），不用指标断言验证。
