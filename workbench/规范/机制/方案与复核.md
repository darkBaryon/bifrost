# 方案与复核

[← 返回规范主页](../../规范.md) · [流程](../流程.md)

方案的作用是把意图变成可检查的实施边界。写不出明确接口、失败路径或验收标准,通常说明需求仍不够清楚,不应直接编码。重构方案还必须同时描述"现在是什么""要变成什么"和"怎样证明行为没有丢失"——只有目标目录图不构成可执行方案。

## 方案必备内容

1. **给用户的摘要**:十行以内说明当前状态、完成后的变化和拍板项;
2. **精确起点**:基线 commit SHA(非 Git 工作记录文件清单/版本/时间戳);
3. **现状与约束**:可复用能力、调用方、只读边界、敏感数据和不碰的范围——**重构另须**:现状盘点事实,含**全部生产调用方**(盘点清单见 [差异/重构.md](../差异/重构.md));
4. **目标与非目标**:本次交付白名单;重构写明"结构要改变什么、行为必须保持什么";
5. **设计**:公共签名、数据结构、正常/失败/空值路径、模块边界和依赖方向;重构给终态结构与依赖方向;
6. **实施步骤**:顺序明确,每步可独立检查——重构每步须保持可编译、可测试、可回滚;
7. **验证策略**:单元/组件/集成/端到端或演示,写清输入与预期——**重构另须**:行为保护(表征测试、金样、语义等价口径、已知盲区)与**公共接口白名单**(允许增删改的符号逐项列名);
8. **验收标准**:可观察行为描述,机械项写明命令(落 checklist.yaml,与预飞同源);
9. **风险、禁止事项和回滚方式**。

## 蓝图与分期(蓝图级)

蓝图只定义整体目标、非目标、模块边界、公共契约、分期、依赖、终态验收和回滚策略,不提前猜后期实现细节:

- 第一期应是能证伪关键假设的**垂直切片**,不是横切的基础设施层;
- 每期独立走标准级流程;上一期未验收(阻塞未关闭),不开始下一期实施;
- 后续期方案在前期结论稳定后再细化;
- 关键假设被证伪时,修订蓝图并重新复核和 Gate 1。

## 方案复核

复核职责必须重新读取需求、基线和相关代码,亲自确认:

- 是否重复建设已有能力;目标、非目标和调用方是否完整;
- 接口能否表达正常、失败、空值和兼容路径;数据所有权和依赖方向是否明确;
- 每个步骤是否可测试、可回滚——重构另查:目标结构是否解决**已经证明**的问题;迁移顺序是否避免长时间双轨和危险大爆炸;
- 测试是否覆盖主要风险——重构另查:表征测试是否断言业务语义而非碰巧的源码形态;公共接口白名单是否完整;
- 是否混入"顺手优化"或没有验收价值的抽象。

**意见必须可被事实证实或推翻**("缺少输入时实际返回什么"是有效问题,"建议更健壮"不是)。首轮覆盖完整方案;判「需修改」创建 v+1 新版本,旧版冻结不覆盖;后续轮次核对上轮意见、声明变化及影响范围——再小的修订也不能由设计者自检直通。复核记录至少含:结论、范围、逐项意见、阻塞与建议之分、亲核证据、剩余风险。新需求只记入建议,不直接扩进当前方案。

## Gate 1:允许实施

方案复核通过后向用户提供:放行的任务、方案版本和基线;已确认的目标/范围/非目标;需要用户决定的业务取舍、风险或成本(无则写"无");1-3 个抽查入口;最大剩余风险;通过和不通过分别发生什么。条件触发规则见 [流程.md](../流程.md)。用户负责业务方向和风险接受,不需要逐文件检查;没有明确的 Gate 1 决策,不进入标准级或蓝图级实施。

## 敏感信息

记录和证据不得包含 token、密码、完整身份信息、合同全文或生产客户数据;必要原始证据放受控位置,规范记录只留脱敏引用。
