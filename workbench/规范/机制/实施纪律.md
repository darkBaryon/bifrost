# 实施纪律

[← 返回规范主页](../../规范.md) · [流程](../流程.md)

## 固定起点

实施前重新确认当前目录、分支、基线 commit、未提交修改(逐项确认归属,不覆盖或夹带他人工作)和生成物状态;本机 SDK、环境地址、凭据和打包配置不得混入功能提交。所有后续 diff、评审和验收都以该起点为参照;**基线变化时必须重新判断方案和验证范围是否仍然成立**。

## 标准执行方式

1. 按方案顺序实施,不提前做后续步骤;
2. 每一步控制在可独立理解、检查和回滚的范围;
3. 每步相关检查通过后再形成 commit;提交时只暂存明确的业务文件;
4. 持续记录步骤、commit、结果和偏差。

## 偏差即停

目标、接口、范围、步骤、测试对象或验收口径发生变化都属于偏差;**漏做已确认条目(方案声明但没有实施)同样属于偏差**。

| 级别 | 情形 | 动作 |
|---|---|---|
| 小偏差 | 实现/迁移细节变化,目标和契约(重构:目标结构和行为口径)不变 | 记录原因与影响,交代码复核确认 |
| 中偏差 | 步骤、接口、范围或验证方式变化 | 停止实施,修订方案,差量复核并由用户确认 |
| 大偏差 | 目标、终态或关键假设被证伪 | 中止当前阶段,重新设计(蓝图级修订蓝图)并重新 Gate 1 |

**"无偏差"是需要负责的事实结论,不是默认填空**。不得先按自己的理解做完再补写理由。外部环境故障写清复现、影响、替代核验和解除条件;未解除的强制项不能包装成通过。

## 实施记录(完成实施后落在方案尾部)

- **实施记录**:每一步对应的 commit、一句话说明和验收自查;
- **实施偏差记录**:所有偏差及其裁决,无则明确写"无";
- **蓝图验证备忘**:蓝图级分期记录接口表达力、关键假设和是否需要修订;其他任务写"不适用"。

有效交接还应包含任务来源、范围、基线、当前版本、已执行检查、阻塞和下一步——聊天历史可辅助理解,不能作为唯一事实源。

## 预飞自检

交评审前运行项目规定的机械检查并生成事实表(本仓:`tools/preflight.py` + 期内 checklist.yaml)。按项目能力选择:

- 格式和静态分析;单元、组件和相关集成测试;构建、部署或可运行演示;
- 必要文件和必含符号;临时日志、断点、测试后门等禁留标记;
- 生成物重建与零漂移;实际 diff 与方案范围对账;
- **重构另须**:旧符号与临时兼容层清理、公共接口签名 diff 与白名单对账、架构禁区和依赖方向、重复代码与死代码扫描(工具缺某项扫描能力时给替代核验或明确盲区,不能静默省略)。

脚本只能证明命令结果,不能证明业务设计正确或结构合理。红项必须先修复或明确记录为阻塞;**事实表不全绿时不能用"看起来没问题"进入正式复核**。

## 并行与共享资源

- 一条工作线对应一条分支、一个 Worktree、一个实施上下文;每次 Git 操作前确认目录和分支;
- 按项目集成点汇合,后合者先吸收最新基线;多条线共用的契约改动优先独立落地;
- 改动足迹高度重叠时排队,不伪装并行;生成文件冲突通过生成器重建,不手工拼接;
- 分期任务:上一期阻塞未关闭不开始下一期(见 [方案与复核.md](方案与复核.md) 蓝图节);
- 共享模拟器/真机/数据库/外部账号服从项目资源协议:短操作窗口串行,编辑代码、等待反馈和普通构建期间不默认长期持有;确需连续调试用明确的限时独占,不得擅自抢占或破坏其他会话。
