# 3. 实施、偏差与预飞

[← 上一章：方案与 Gate 1](02-plan-and-review.md) · [开发规范](README.md) · [下一章：测试与交付 →](04-test-and-delivery.md)

## 开始实施

实施前重新确认当前目录、分支、基线和未提交修改。新 Worktree 或本机配置按业务项目规则准备；本机 SDK、环境地址、凭据和打包配置不得混入功能提交。

标准执行方式：

1. 按方案顺序实施，不提前做后续步骤；
2. 每一步控制在可独立理解、检查和回滚的范围；
3. 每步相关检查通过后再形成 commit；
4. 提交时只暂存明确的业务文件；
5. 持续记录步骤、commit、结果和偏差。

## 偏差即停

目标、接口、范围、步骤、测试对象或验收口径发生变化都属于偏差；漏做已确认条目同样属于偏差。

| 级别 | 情形 | 动作 |
|---|---|---|
| 小偏差 | 实现细节变化，目标和契约不变 | 记录原因与影响，交代码复核确认 |
| 中偏差 | 步骤、接口、范围或验证方式变化 | 停止实施，修订方案，差量复核并由用户确认 |
| 大偏差 | 目标、终态或关键假设被证伪 | 中止当前阶段，重新设计并重新 Gate 1 |

“无偏差”是需要负责的事实结论，不是默认填空。不得先按自己的理解做完，再补写理由。外部环境故障也要写清复现、影响和解除条件；未解除的强制项不能包装成通过。

## 实施记录

完成实施后记录：

- **实施记录**：每一步对应的 commit、一句话说明和验收自查；
- **实施偏差记录**：所有偏差及其裁决，无则明确写“无”；
- **蓝图验证备忘**：蓝图级分期记录接口表达力、关键假设和是否需要修订；其他任务写“不适用”。

有效交接还应包含任务来源、范围、基线、当前版本、已执行检查、阻塞和下一步。聊天历史可以辅助理解，但不能作为唯一事实源。

## 预飞自检

交代码复核前，先运行项目规定的机械检查并生成事实表。按项目能力选择：

- 格式和静态分析；
- 单元、组件和相关集成测试；
- 构建、部署或可运行演示；
- 必要文件和必含符号；
- 临时日志、断点、测试后门和禁留标记；
- 生成物重建与零漂移；
- 实际 diff 与方案范围。

脚本只能证明命令结果，不能证明业务设计正确。红项必须先修复或明确记录为阻塞；事实表不全绿时不能用“看起来没问题”进入正式复核。

## 并行开发

多条功能线并行时：

1. 一条功能线对应一条分支、一个 Worktree 和一个实施上下文；
2. 每次 Git 操作前确认目录和分支；
3. 按项目规定的集成点汇合，后合者先吸收最新基线；
4. 多条线共用的契约改动优先独立落地；
5. 改动足迹高度重叠时排队，不伪装并行；
6. 生成文件冲突通过生成器重建，不手工拼接。

共享模拟器、真机、数据库或外部账号必须服从业务项目的资源协议。等待资源、编辑代码或构建期间是否释放占用，以项目规则为准，不能让一个开发任务默认长期独占共享资源。
