# 测试(类型差异)

[← 返回规范主页](../../规范.md) · [流程](../流程.md) · 分级与最低测试组合见 [风险分级.md](../风险分级.md)

测试 = 对一个**精确的软件版本**建立可信结论,覆盖开发自测、独立测试、缺陷复测和发布准入;模拟器、真机、浏览器、API、数据库和自动化只是不同执行平台。测试流程原则上不修改被测代码:发现缺陷后固定失败证据,交回修复职责形成新版本,再复测。(原 playbook 测试套的 03 缺陷复测/04 发布准入两页在 vendor 时即缺失;其要点已并入本页「三个事实」与「证据与历史」。)

## 职责(测试特有细分)

| 职责 | 主要责任 | 不得做的事 |
|---|---|---|
| 开发 | 提供测试计划初稿、自动化测试、自测、精确版本和已知盲区 | 把自测写成独立测试通过 |
| 测试 | 独立核对版本和环境、执行用例、补充反例、记录证据并给结论 | 修改被测代码、采信口头结论、把未执行/阻塞判成通过 |
| 修复 | 根据失败证据修复、补回归测试、提供新版本 | 覆盖旧记录或混入无关改动 |
| 决策 | 用户确认档位、授权测试条件、接受剩余风险并业务验收 | 重复测试职责已完成的机械检查 |

同一主体实现并执行的测试标记为"开发自测";独立测试必须重新核对对象与运行条件并亲自执行,结论不能继承开发者判断。

## 最小交测包

需求/缺陷来源与一句话目标;基线、分支、完整 commit 或版本;构建/部署方式、产物标识和内容哈希;风险档位、必测用例、回归范围和非目标;开发自测事实表和已知盲区;环境、账号、脱敏数据和外部依赖准备说明。

## Gate T0:测试准入

进入执行前确认:测试对象已提交可获取、不在持续变化;commit/构建标识/产物哈希与计划一致;构建输入和工作区可解释、无未声明改动;必要静态检查、自动化测试和构建已完成;实际运行环境/设备/平台与计划一致(**核实际运行态,不只看配置文件期望值**);账号、数据和外部依赖已备或阻塞已明确;用例写明前置/单步/期望/回归/证据要求。T0 只证明"可以正确开始测试";对象、环境或关键数据在 T0 后改变,受影响结论失效,重新准入。

## 分层执行

按风险选层,通常依次:差异核对 → 机械检查(存量基线错误单列)→ 构建/部署(记录命令、产物、哈希)→ 运行态确认 → 主路径(按真实业务顺序)→ 反例与边界(取消/返回/重复触发/空数据/失败响应/权限拒绝)→ 回归(公共组件、调用方、相邻业务)→ 结果核对(**高风险操作查真实数据或后续状态,不以提示消息代替结果**)。不能因为某个平台难用就静默降低测试范围。

## 用例写法

每个用例:编号、优先级、前置条件、单步操作、每步期望、实际结果、证据、结论。一步只做一个动作,随后确认页面/状态/数据结果,不把多次点击串成无法定位失败的大步骤。结论只能用:`通过 / 未通过 / 阻塞 / 不适用 / 未执行`——未执行不计入通过率,阻塞不能写成通过。

## 最小证据

版本(分支/commit/基线/diff 摘要)、产物(构建方式/标识/哈希)、环境(实际运行态证据)、平台(设备/系统/运行时版本)、自动化(命令/退出码/统计)、行为(关键步骤截图/日志/状态,失败附稳定复现)、数据(脱敏可追踪标识)、结论(覆盖统计/遗留风险/职责/时间)。

## 证据与历史(含缺陷复测要点)

原始证据按轮次保存,能对应精确测试对象;新轮不覆盖旧轮,复测记录引用上轮失败和本轮变化。缺陷修复形成新版本后,**失败项复测 + 影响面回归**,不沿用旧版本结论。环境/设备故障记录复现、影响、解除条件;未解除保持"阻塞"。

## 测试状态

```text
待测试 → 准备中 → 执行中
  ├→ 阻塞 → 准备中/执行中
  ├→ 未通过 → 修复中 → 待复测 → 执行中
  └→ 已通过 → 待业务验收 → 已验收 → 可发布 → 已归档
```

"已通过"只表示当前精确版本的规定范围通过(Gate T1,独立测试职责结论);"已验收"表示用户接受业务结果(Gate T2);"可发布"还要满足项目自己的合并、审批和发布规则。**T1 与 T2 是两个独立结论**;"已推送""可安装""已建 MR"不得写成"可发布"。
