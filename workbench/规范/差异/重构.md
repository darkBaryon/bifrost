# 重构(类型差异)

[← 返回规范主页](../../规范.md) · [流程](../流程.md) · 共享机制见 [机制/](../机制/方案与复核.md)

重构 = 调整既有结构、边界、依赖或公共接口。**默认目标是保持可观察行为**;确需改变行为时,必须把允许变化写进方案并单独验收,不能借重构暗中改变功能。本页只写重构独有的纪律;方案要件中标注「重构另须」的条目详见此页。

## 先证明问题存在

起点是结构问题、技术债或设计缺陷,**而不是"这段代码看起来不舒服"**。立案记录至少包含:问题在哪;当前造成的维护成本、错误风险或扩展障碍;文件/接口/依赖或测量证据;希望的终态;本轮不解决什么;**可证伪的成功口径**。

## 现状盘点(方案第 3 项的重构实体)

所有盘点、diff、测试和验收绑定完整 commit SHA。至少覆盖:相关文件、模块和公共符号;依赖方向和边界;**全部真实生产调用方**(向外追到真实使用者——零调用者需说明保留理由,否则按死代码候选处理);当前正常/失败/空值/兼容行为;现有测试、生成代码和架构规则;已知重复、死代码和临时兼容层。**不能只根据名称、局部搜索或设计文档推断现状**。

## 行为保护与接口白名单

- 关键行为要有表征测试、金样或明确的替代证据;表征测试必须断言业务语义,不是碰巧的源码形态;
- 公共接口变化逐项列白名单(允许新增/删除/改变的符号列名),复核与终扫对账;
- **新旧结构不得无期限并存**——旧接缝、临时兼容层按计划退出。

## "碰巧同形"

扫描发现相似代码不代表必须抽象。业务本质不同但结构相似的代码可以带证据留存;判断依据必须能被事实证伪。**没有证据的"以后可能复用"不能成为抽象或保留理由**。

## 阶段终扫(在通用预飞之上)

项目支持时,阶段结束至少执行:

1. 格式、静态检查、测试和构建;
2. 重复代码与基线逐组对账(新增、消除、位移、留存);
3. 死代码与基线对账,确认没有新增不可达内容;
4. 公共接口签名 diff 与白名单逐项核对;
5. 调用方、旧符号、兼容层和过渡开关清理;
6. 生成代码重建零漂移;长期架构文档回填。

工具不支持某项时给替代证据或明确剩余盲区。

## 结构问题状态

结构问题(finding 台账条目之外的独立立案)可用:`观察中 → 待计划 → 执行中 → 已处理`。
