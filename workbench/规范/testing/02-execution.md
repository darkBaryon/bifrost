# 2. 分层执行、用例和证据

[← 上一章：测试准入](01-readiness.md) · [测试规范](README.md) · [下一章：缺陷与复测 →](03-defect-and-retest.md)

## 分层执行

按风险选择必要层级，通常依次进行：

1. **差异核对**：确认测试对象与计划一致，阅读相对基线的变化和影响面；
2. **机械检查**：格式、静态分析、单元和组件测试，存量基线错误单列；
3. **构建或部署**：记录命令、模式、产物和哈希；
4. **运行态确认**：核对实际环境、版本、设备或平台；
5. **主路径**：按真实业务顺序逐步执行；
6. **反例与边界**：取消、返回、重复触发、空数据、失败响应、权限拒绝等；
7. **回归**：覆盖公共组件、调用方和相邻业务；
8. **结果核对**：高风险操作检查真实数据或后续状态，不以提示消息代替结果。

模拟器、真机、浏览器、API、数据库或第三方端只是执行平台。工具选择必须服务于风险和证据，不能因为某个平台难用就静默降低测试范围。

## 用例写法

每个用例包含：编号、优先级、前置条件、单步操作、每步期望、实际结果、证据和结论。

一个步骤只做一个动作，随后确认页面、状态或数据结果。不要把多次点击、长时间等待和取证串成无法定位失败位置的大步骤。

结论只能使用：

- `通过`：全部步骤符合期望且证据充分；
- `未通过`：能够执行，但实际结果不符合预期；
- `阻塞`：外部条件导致无法执行；
- `不适用`：测试计划已经明确裁决不属于本轮；
- `未执行`：尚未执行，不计入通过率。

## 最小证据

- **版本**：分支、完整 commit、基线和 diff 摘要；
- **产物**：构建方式、文件或部署标识、内容哈希；
- **环境**：实际运行环境证据；
- **平台**：设备、系统、浏览器或运行时版本及关键模式；
- **自动化**：命令、退出码和结果统计；
- **行为**：关键步骤的截图、日志或状态，失败时附稳定复现；
- **数据**：脱敏且可追踪的标识；
- **结论**：覆盖统计、遗留风险、测试职责和时间。

机械脚本生成事实表，但脚本只能证明命令结果。业务行为是否正确、风险是否可接受仍需测试职责和用户分别作出判断。

## 证据与历史

原始证据按测试轮次保存，名称或记录中能够对应精确测试对象。新的截图、日志或结论不能覆盖旧轮；复测记录引用上轮失败和本轮变化。

环境或设备故障需要记录复现、影响、解除条件和已尝试的安全检查。没有解除的强制条件保持“阻塞”，不能写成通过。
