# 风险分级

[← 返回规范主页](../规范.md) · [流程](流程.md)

**本页是分级的唯一权威**(原先散在 change/开发/重构/测试四处的分级表合并于此)。两个原则,分别解决"流程太重"的两个来源:流程重量与风险匹配;Gate 条件触发(见 [流程.md](流程.md))。

## 三级分级(判据只看风险,不看感觉)

| 级别 | 判据 | 必需产物 | 流程 |
|---|---|---|---|
| **L1 快速**(≈轻量级) | 局部修改、小 bug、小功能;不动公共接口、不动数据、错了看 diff 就能回滚 | 需求摘要(几句话)+ 交付摘要(一页内) | 摘要 → 实施 → 机械检查 → 独立复核(含收敛评审一段话版)→ 用户看摘要/diff 点头 |
| **L2 标准**(≈标准级) | 多模块;API / Schema / 状态变化;普通复杂度业务 | + 正式方案、方案复核、收敛评审记录 | L1 基础上:方案 → 方案复核 → [Gate 1 条件] → 实施 → 代码评审 ∥ 收敛评审 → Gate 2 |
| **L3 严格**(⊇蓝图级) | 支付、权限、Migration、高风险数据写入、大规模重构、跨系统 | + 完整影响预估、独立测试、逐维收敛评审、回滚预案 | 完整流程,所有 Gate 必现,实测验收 |

L3 与蓝图级的差别:除结构尺度(跨子系统、多期交付)外还包含**风险域**——支付/权限/Migration/高风险数据写入即使只动一个模块也按 L3 走(取 L3 的证据要求,流程步骤可按标准级执行)。frontmatter `tier` 与级别的映射同表(另见 [SCHEMA.md](../SCHEMA.md))。

## 两根保险丝

- **就高不就低**:判据落在两级之间取高级;未知情况不得按低风险处理;行数和文件数只能作经验锚点。
- **升级不降级**:实施中发现实际风险超出定级(碰到公共接口、动到数据、失败后果或验证难度超出原判断),立即停、登记偏差、重新定级;不允许"悄悄按低级做完"。**多个相关小改动不得拆开分别走 L1 来规避整体风险**,按整体影响定档。

## 定档程序

1. 设计职责提出档位,用一句话说明命中的风险判据;
2. 用户确认或调高;
3. 裁决和理由写回需求记录(`tier` 字段 + 处置历史);
4. 降档必须说明哪项风险已被**事实**排除并由用户确认。

## 测试组合(测试分级看失败后果,不看代码行数)

| 档位 | 判据 | 最低测试组合 |
|---|---|---|
| 轻量级 | 纯文案/样式、纯函数小修,失败易发现、易回滚且不改业务数据 | 相关静态检查 + 单元/组件测试或精确人工检查 + diff 复核 |
| 标准级 | 页面/API 交互、状态流转、普通数据解析或兼容性变化 | 轻量级全部 + 可运行产物 + 主路径 + 相关回归 + 独立测试记录 |
| 高风险级 | 支付、合同、身份、权限、关键数据写入、不可逆操作、跨系统链路 | 标准级全部 + 有效数据端到端 + 失败/取消/重试 + 结果状态核对 + 业务验收 |

缺账号、数据、服务或平台条件时记为**阻塞**,不能用低层测试替代高层结论。
