## 三个不同的事实

开发自测、推送供打包和独立测试通过互不等价:

- 开发自测 = 实现者认为可以交测;
- 推送分支 = 测试对象可以被获取;
- 独立测试通过 = 规定范围在**指定版本和环境**中得到验证。

标准级和高风险行为通常还需按 [差异/测试.md](../差异/测试.md) 对精确 commit 或产物独立测试。测试发现缺陷后,记录失败版本和证据,修复形成新 commit,再对新版本复测;**不得把旧版本的通过结论沿用到新版本**。

## 代码复核

复核职责对照需求、最终方案、基线和 commit 亲自检查:

- 实际功能是否满足验收标准;方案声明、实施记录、偏差记录和 diff 是否一致;
- 多出的功能、公共接口、抽象或依赖是否构成范围偏差(只对照方案声明判偏差,是否必要归收敛评审);
- 失败、空值、取消、重复触发、并发、事务边界和兼容路径是否正确;输入上限与校验顺序、鉴权边界、敏感信息是否处理;
- 失败是否可观测:服务端能否追溯原因,对外是否泄露内部原文,脚本与测试失败时现场是否保留;
- 自动化测试是否验证业务行为而非碰巧的实现形态;失败信息能否定位;fixture 是否依赖个人环境;mock 结果是否越界成真实环境结论;
- 是否存在调试残留、本机配置、未使用代码或无关改动;
- **重构另查**:基线行为和调用方盘点是否仍然准确;公共签名变化是否全落白名单;调用方是否完整迁移;旧接缝、临时兼容层和废弃代码是否按计划退出(另见 [差异/重构.md](../差异/重构.md) 的阶段终扫与"碰巧同形")。

首轮覆盖完整范围;修改后差量复核(只核上轮意见、声明修改和受影响区域),无法证明未修改区域不受影响时恢复全量。**复核者不能以实施者提供的"已测过"代替亲核**。架构一致性、组织、命名常量、重复与契约同步属于 [收敛评审](收敛评审.md)，本评审不审；看到写进「转收敛评审」栏，不出结论。操作步骤与起手表见 [代码评审审查方向.md](代码评审审查方向.md)。

**转交闭环**：两份评审记录返回后，实施者把对方记录的「转交」条目原样交给本侧的差量复核处理（同一 agent 兼任两侧时直接归入本侧记录）；每条转交项的处置结果（修复 / 撤回 / 挂账）写进 Gate 2 请求，不得静默丢失。

意见注明具体位置、影响及最小修正。当前授权范围内的「本轮修复项」由实施者直接处理，定向复核关闭后才能给「通过」；未关闭时为「需修改」。是否需要用户裁决按流程的 Gate 条件另判，不因修复问题小就省略，也不把每条意见都变成用户审批。

## Gate 2:交付验收

请求 Gate 2 时提供:

- 本次验收的精确 commit 或产物;需求和验收标准覆盖情况;
- 自动化、构建、运行态和独立测试结论;收敛评审结论;
- 两侧评审「转交」条目及处置结果;
- 未执行、阻塞和遗留风险;需要用户决定的事项;
- 通过后如何集成,不通过后回到哪个阶段;
- 重构另附:原行为、允许变化和实际结果对账,目标结构、调用方和公共接口完成情况。

用户可按风险选择看事实表、抽查一个入口或亲自操作关键路径。**没有明确通过 Gate 2,不得把"代码已完成""分支已推送""MR 已创建"解释为获准集成**。

## 集成和清理

Gate 2 通过后按业务项目规则创建/更新合并请求、进入集成分支并执行最小冒烟(规范不预设直接推送、MR、squash 或分支名)。收口:

- 确认集成对象仍是已验收版本;
- 清理临时日志、测试后门和不再使用的代码;删除已完成分支和 Worktree;
- 保留方案、评审、事实表、测试和验收记录;
- 按 [流程.md](../流程.md) 知识沉淀表回填长期口径;状态流转"已交付/已归档"。

集成后冒烟失败或出现行为差异:停止后续发布,记录新的精确版本,回到缺陷修复和复测流程,不覆盖原结论。
