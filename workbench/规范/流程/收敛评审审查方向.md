# 收敛评审：操作指引

[← 返回规范主页](../../规范.md) · [收敛评审](收敛评审.md) · [编码规范](../项目/编码规范.md) · [启动提示词模板](../../templates/收敛评审提示词.md)

[收敛评审.md](收敛评审.md) 定义目的、输入、四维、出口与校准；本页只讲**怎么执行**：步骤、每个维度必须过一遍的信号、意见怎么写。测试与非功能不在本评审范围，见 [代码评审审查方向](代码评审审查方向.md)。规则以 [收敛评审.md](收敛评审.md) 为准，本页不重述。测试代码作为代码仍按四维看重复与组织；测试是否可信归代码评审。

## 工作程序

按顺序执行，每步有产出；跳步的评审视为未完成。

1. **读规则与裁决**：[收敛评审.md](收敛评审.md)、[编码规范](../项目/编码规范.md)、[findings.md](../../findings.md)、本案方案的「Gate 决策结果」与「实施偏差记录」。产出：哪些偏离算问题、哪些已被裁决或豁免。不读旧评审的意见。
2. **核对范围**：`git status --porcelain`、`git diff --stat <基线>`；未跟踪文件必须在清单里。产出：实际文件清单。
3. **通读全文**：范围内每个文件读完整现状，diff 只用来定位新旧。产出：每个文件一句话职责。
4. **找同类实现**：对每类新代码 grep 上游与 ee 里做同样事的位置（相邻 handler、同类迁移调用、同目录组件、同包测试 fixture），读它们。产出：本案与同类的对照。
5. **核实关键假设**：结论依赖"上游会/不会做 X"或"删掉 Y 无影响"的，到代码里找到证据行。产出：带行号的证据。
6. **逐行执行起手表**（下表）：每一行都执行，每行记一个结果——发现 / 无 / 不适用（说明为什么不适用）。只记有证据的发现；范围外的问题记到「转代码评审」。
7. **开放式复读**：放下表，以"半年后要改这里的人"的身份把范围内代码再读一遍，对每个文件回答一个问题——**第一眼会让维护者皱眉的是什么**。产出：表外发现清单，可以为空，但必须写明"已做开放式复读，无表外发现"；表外发现与表内发现同等对待。
8. **写结论**：按"意见写法"输出，最后列实际阅读范围与未执行项。

## 四维：起手表

[收敛评审.md](收敛评审.md) 给出每维的**核心问题**，那才是要回答的东西；下表是回答它时必须过一遍的信号。用法：**每一行都执行**，结果记为发现 / 无 / 不适用；怎么查由评审者自己决定。做完回到核心问题再问一次"还有什么"；表外的发现照样按五要素提出，不因为"表里没有"而略过。表会随后续评审补充，但不追求穷尽，也不是发现的边界。

| 维度 | 信号 |
|---|---|
| 重复 | 同一数字或限制多处出现 |
| | 同一规则多份实现且互不注明 |
| | 重造已有 helper |
| | 派生常量无推导 |
| 职责与实现质量 | 魔数（锁键、端口、ID、阈值） |
| | 状态码、错误码裸数字 |
| | 无名的错误形状（以元组表示失败） |
| | 紧凑但绕的控制流（捕获外部状态的闭包、多层三元、一次调用做两件事） |
| | 一个文件多个独立修改理由 |
| | 多余状态或守卫（判重复前先核实是否防同一对象） |
| | 同一效果做两次（响应头、注册、初始化） |
| | 注释与现状矛盾（尤其鉴权、边界、装配处） |
| 架构与项目一致性 | 接缝形状与同类不同（对照本案已确认的接入约定和对应上游接口，逐项写一致/不一致） |
| | 反向依赖 |
| | 绕过既有出口（存储、迁移、响应、鉴权；只看是否走既有出口的形状，路由实际是否受保护归代码评审） |
| | 把上游现状当契约 |
| 契约一致性 | 后端类型、前端类型、开发指南三方不一致（手维护契约；生成物与源的漂移归代码评审） |
| | 状态码口径不一 |
| | 省略、空、值三态语义不对应 |

## 意见写法

每条意见五要素，缺一条不算意见：**位置**（绝对路径 + 行号）、**代码事实**（一句话，不加形容词）、**维护影响**（说不出代价的不提）、**最小修正**、**反证条件**（取舍项必带）。

输出分三档，对应记录模板的出口：

| 档 | 判据 | 落到模板 |
|---|---|---|
| 本轮修复项 | 范围内、无需裁决、必须修 | 「本轮修复项」 |
| 建议取舍项 | 有反证条件，由实施者决定采纳或撤回 | 涉及范围/契约/风险 → 「需用户裁决的 Blocking」；事后治理不贵 → 「立债 REF」；证据不足 → 「挂账 Finding」 |
| 有理由保留项 | 写出理由，让下一轮不再重提 | 「台账对账」或结论 |
| 转代码评审 | 正确性、测试、非功能问题，一行一条，不出修复意见 | 「转代码评审」 |

结论末尾附两项：**起手表覆盖**（每行的结果：发现 / 无 / 不适用，可用紧凑表格）；**实际阅读范围与未执行项**：读了哪些文件与同类实现、跑了什么命令、什么没做，以及开放式复读的结果（有表外发现，或明确为空）。

## 自查：常见漏审

- 只读 diff 不读全文；只看 `基线..HEAD` 漏掉工作树。
- 不 grep 同类实现，凭印象说"与上游一致/不一致"。
- 用行数、重复率、文件数直接下结论。
- 把"测试通过"当"质量合格"，把"没有大问题"当"无碍"。
- 只报大问题，不报常量、注释、断言这类小修，实施者没有修复出口。
- 提建议不给反证条件，把偏好当问题。
- 删守卫、删检查前不核实两处防的是否同一对象。
- 报告里出现自己没读过的文件或没跑过的命令。
- 起手表挑顺手的行做，其余行没有结果记录。
- 只做表内动作就收工，没有开放式复读；或表外发现因"表里没有"被丢掉。
