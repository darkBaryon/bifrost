# 代码评审：操作指引

[← 返回规范主页](../../规范.md) · [交付](交付.md) · [收敛评审审查方向](收敛评审审查方向.md) · [启动提示词模板](../../templates/代码评审提示词.md)

[交付.md](交付.md) 的"代码复核"定义范围与判据；本页只讲**怎么执行**：步骤、每个方面必须过一遍的信号、意见怎么写。代码评审管**对不对**：对照方案、行为正确、失败可观测、测试可信、无残留。架构、组织、命名常量、重复、契约同步不在本评审范围，见 [收敛评审审查方向](收敛评审审查方向.md)。

## 工作程序

按顺序执行，每步有产出；跳步的评审视为未完成。

1. **读规则与方案**：[交付.md](交付.md) 代码复核节、本案需求的验收口径、方案的接口设计与实现步骤、「Gate 决策结果」「实施偏差记录」、本期预飞事实表、[findings.md](../../findings.md)。产出：验收标准清单、方案声明的接口面、已裁决事项、预飞里需要亲核的判断项。
2. **核对范围**：`git status --porcelain`、`git diff --stat <基线>`；未跟踪文件必须在清单里。产出：实际文件清单。
3. **三方对账**：方案说要做的、实施记录说做了的、diff 里实际有的，逐项对；实际新增的对外符号 ⊆ 方案声明。产出：偏差清单（多做 / 少做 / 未登记）。
4. **通读全文并追每条失败路径**：范围内每个文件读完整现状；对每个 error return、catch、超时、取消，追到它最终去了哪（响应、日志、状态回滚、被吞）。产出：失败路径表。
5. **亲核测试**：读每个测试的断言，对应到被测行为；确认失败路径有测试；以本期 `checklist.yaml` 的必过命令为准实际运行测试与构建，记录命令与结果。**运行边界**：允许构建与测试命令，包括产物写入 gitignore 目录、测试脚本自行拉起并回收的子进程（如自包含的 smoke）；二进制等产物写到 scratchpad 而非仓库。禁止启动 dev server、连接或操作任何已有实例、修改被 git 跟踪的文件。跳过某条命令必须写明原因，不得以"会写文件"为由跳过自包含的 smoke；交付物在未提交工作树时，同时记下 `git status --porcelain` 与 `git diff --stat` 快照，使结果可绑定版本。产出：验证记录。
6. **逐行执行起手表**（下表）：每一行都执行，每行记一个结果——发现 / 无 / 不适用（说明为什么不适用）。只记有证据的发现；范围外的问题记到「转收敛评审」。
7. **开放式复读**：放下表，以"上线后半夜被叫醒的人"的身份把范围内代码再读一遍，对每个文件回答一个问题——**它出问题时我怎么知道、怎么恢复**。产出：表外发现清单，可以为空，但必须写明"已做开放式复读，无表外发现"。
8. **写结论**：按"意见写法"输出，最后列验证记录、实际阅读范围与未执行项。

## 五个方面：起手表

交付页给出判据；下表是核对时必须过一遍的信号。用法：**每一行都执行**，结果记为发现 / 无 / 不适用；怎么查由评审者自己决定。做完回到判据再问一次"还有什么"；表外的发现照样提出。

| 方面 | 信号 |
|---|---|
| 对照方案 | 验收标准有未覆盖项 |
| | 方案、实施记录、diff 三方不一致 |
| | 多出的功能、公共接口、抽象或依赖 |
| | 偏差未登记在实施偏差记录 |
| 行为正确性 | 失败路径被吞或降级成假成功 |
| | 空值、空集合与非空走同一路径且无分支 |
| | 取消或超时后仍产生写入或副作用 |
| | 同一请求重发两次产生两份副作用 |
| | 事务外写后读；多方写入只有一方回滚 |
| | 开关关闭、旧数据或旧客户端路径无处理 |
| | 昂贵检查先于廉价检查（先解码再限长）；校验缺层 |
| | 路由实际是否受保护、认证关闭时的行为（是否走既有鉴权出口的形状归收敛评审） |
| | 敏感信息进日志或响应 |
| | 热路径新增 I/O、无界缓冲或无上限循环 |
| | 新增配置项、环境依赖或部署步骤未登记 |
| 失败可观测 | 服务端无法追溯失败原因 |
| | 对外泄露内部错误原文 |
| | 脚本、工具失败时现场（日志、临时目录）被清理 |
| 测试可信 | 新规则或失败路径无测试 |
| | 断言绑定实现而非行为 |
| | 失败信息无法定位是哪个条件 |
| | 返回值、错误未检查 |
| | fixture 依赖个人环境（本机路径、个人数据库、固定端口） |
| | mock 或替代环境的结果被写成真实环境结论 |
| | 整体替换模块的 mock |
| 残留 | 调试输出、临时后门、本机配置 |
| | 未使用代码、无关改动 |
| | 生成物与源不一致（手维护契约的同步归收敛评审） |

重构类 Change 另按 [差异/重构.md](../差异/重构.md) 的终扫与"碰巧同形"检查。

## 意见写法

每条意见四要素，缺一条不算意见：**位置**（绝对路径 + 行号）、**代码事实**（一句话）、**触发条件与后果**（什么输入或状态下会出什么错，不能复现的写"静态推断"）、**最小修正**。

输出分档，对应记录模板：

| 档 | 判据 | 落到模板 |
|---|---|---|
| 本轮修复项 | 范围内、无需裁决、必须修；未关闭时 verdict 为需修改 | 「可证伪质疑」 |
| 需用户裁决 | 涉及范围、契约、风险接受 | 「可证伪质疑」并标注 |
| 有依据撤回 | 核实后不成立，写出证据 | 「可证伪质疑」并标注 |
| 挂账 Finding | 范围内、经裁决本轮不修但需记账的问题 | 「挂账」，并登记 [findings.md](../../findings.md) |
| 转收敛评审 | 架构、组织、命名常量、重复、契约同步，一行一条，不出结论 | 「转收敛评审」 |

结论末尾附三项：**验证记录**（实际跑了什么、看到什么，含命令）；**起手表覆盖**（每行的结果）；**实际阅读范围与未执行项**，以及开放式复读的结果。

## 自查：常见漏审

- 采信实施记录或"已测过"，没有自己跑。
- 只读 diff 不读全文；只看 `基线..HEAD` 漏掉工作树。
- 追失败路径只追到 `return err`，没看调用方把它怎么了。
- 把"测试通过"当"行为正确"，没读断言到底断了什么。
- 起手表挑顺手的行做，其余行没有结果记录。
- 只做表内动作就收工，没有开放式复读。
- 把架构或风格意见写成修复项，而不是转收敛评审。
- 报告里出现自己没读过的文件或没跑过的命令。
