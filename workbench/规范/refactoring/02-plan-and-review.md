# 2. 终态方案、方案复核与 Gate 1

[← 上一章：基线与分级](01-baseline-and-classification.md) · [重构规范](README.md) · [下一章：分期迁移 →](03-migration.md)

重构方案必须同时描述“现在是什么”“要变成什么”和“怎样证明行为没有丢失”。只有目标目录图，没有行为与迁移证据，不构成可执行方案。

## 方案必备内容

1. **给用户的摘要**：现状、目标结构、可观察变化和拍板项；
2. **精确基线**：完整 commit SHA；
3. **现状事实**：文件、公共符号、依赖方向和全部生产调用方；
4. **目标与非目标**：结构要改变什么，行为必须保持什么，本期不解决什么；
5. **终态结构和依赖方向**；
6. **迁移步骤**：每步保持可编译、可测试、可回滚；
7. **行为保护**：表征测试、金样、语义等价口径和已知盲区；
8. **公共接口白名单**：允许新增、删除或改变的符号逐项列名；
9. **验收和机械检查**：旧符号、公共签名、架构红线、重复、死代码和生成物；
10. **风险、禁止事项和回滚口径**。

标准方案使用 [`templates/refactoring/plan.md`](../templates/refactoring/plan.md)，跨期任务使用 [`templates/refactoring/blueprint.md`](../templates/refactoring/blueprint.md)。

## 蓝图与分期

蓝图定义终态、接口契约、分期和最终验收，不提前展开所有期的实现细节。

- 第一期选择能证伪关键假设的垂直切片；
- 每期按标准级走完整的方案、实施、复核和 Gate；
- 上一期阻塞未关闭，不开始下一期实施；
- 后续期在前期结论稳定后再计划；
- 关键假设被证伪时停止，修订蓝图并重新 Gate 1。

## 方案复核

复核职责重新读取基线和生产代码，验证：

- 现状事实和调用方是否完整；
- 目标结构是否解决已经证明的问题；
- 允许变化与必须保持的行为是否明确；
- 迁移顺序是否避免长时间双轨和危险大爆炸；
- 表征测试是否断言业务语义，而非碰巧的源码形态；
- 公共接口白名单是否完整；
- 每期是否可独立验证、回滚并给出真实结论。

意见必须可证伪。首轮覆盖完整方案；修订创建新版本，旧版冻结。后续轮次复核上轮意见、声明变化和影响范围，再小的修订也不能由设计者自检直通。

## Gate 1：允许迁移

Gate 卡片向用户说明：放行的基线和方案版本、目标结构、允许变化、迁移范围、拍板项、抽查入口、最大剩余风险以及通过/不通过后的动作。

用户负责结构方向、业务行为变化和风险接受。方案复核通过但没有明确 Gate 1，不能开始标准级或蓝图级迁移。

记录不得包含凭据、完整身份信息、合同或生产客户数据。必要原始证据放入受控位置，规范记录只保留脱敏引用。
