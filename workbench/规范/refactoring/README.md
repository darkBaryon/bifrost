# 重构规范

[← 返回仓库首页](../README.md)

重构规范用于调整既有结构、边界、依赖或公共接口。默认目标是保持可观察行为；确需改变行为时，必须把允许变化写进方案并单独验收，不能借重构暗中改变功能。

如果主要目标是新增业务能力，使用[开发规范](../development/README.md)；如果只需要验证一个固定版本，使用[测试规范](../testing/README.md)。

## 完整流程

```text
1. 固定行为和结构基线
   盘点现状、调用方、依赖和真实问题
        ↓
2. 定档与制定迁移方案
   定义终态、行为口径、白名单和分期
        ↓
3. 方案复核与 Gate 1
   用户确认方向、范围和允许变化
        ↓
4. 分步迁移
   每一步保持可编译、可测试、可回滚
        ↓
5. 预飞、代码复核和终扫
   对账行为、调用方、公共接口和旧结构
        ↓
6. Gate 2
   用户确认行为结果和最终结构
        ↓
7. 按项目规则集成、回填和归档
```

## 不可省略的底线

- [ ] 基线行为和全部生产调用方已经盘点；
- [ ] 目标结构、非目标和允许变化已经明确；
- [ ] 公共接口变化有逐项白名单；
- [ ] 迁移步骤可独立验证和回滚；
- [ ] 关键行为有表征测试、金样或明确的替代证据；
- [ ] 任何计划外变化都先停下并登记；
- [ ] 新旧结构没有无期限并存；
- [ ] 最终行为、调用方、死代码、重复和生成物已经对账；
- [ ] Gate 2 通过后才按项目规则集成。

## 状态参考

结构问题可以使用：`观察中 → 待计划 → 执行中 → 已处理`。

蓝图或方案可以使用：`草拟中 → 待评审 → 需修改 → 已通过 → 已实施 → 已归档`。

状态表示已经完成的事实。正式方案、评审和验收必须绑定版本，修订不得覆盖历史。
