## A. 保留现有页面，先验证业务请求的实际影响

保留现有 Dashboard、providers、plugins、custom-pricing、logs、MCP、治理、路由规则、品牌等业务页面，使用已有权限接口控制可见和可用能力。撤回两页开放名单及其直链拦截，不以未完成逐页审计作为隐藏页面的理由。账号/角色、内容安全等新业务页仍不在本期开发范围。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。

## B. bootstrap 的后端候选契约与所有权

本轮保留此候选设计：ClientLayout 的完整配置失败有toast及FullPage阻断路径，Sidebar/Topbar也订阅完整config；这与业务Sheet的附属403不同。三字段投影用于消除外壳对Settings.View的依赖，不能给普通账号放开完整配置。保留候选不表示已经实施或重新复核通过。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。

新增 `ee/internal/host/console_bootstrap.go`，只负责 HTTP 宿主投影，不新建账号/权限业务服务。构造依赖窄接口：

```go
type bootstrapSessions interface {
    Authenticate(context.Context, string) (identity.Principal, error)
}
type bootstrapOrigin interface { SameOrigin(*fasthttp.RequestCtx) bool }
type ConsoleBootstrap struct {
    IsDBConnected bool
    IsLogsConnected bool
    EnvLabel string
}
type ConsoleBootstrapReader func(context.Context) (ConsoleBootstrap, error)
func NewConsoleBootstrapHandler(bootstrapSessions, bootstrapOrigin, ConsoleBootstrapReader) *ConsoleBootstrapHandler
func (*ConsoleBootstrapHandler) RegisterRoutes(*router.Router, ...schemas.BifrostHTTPMiddleware)
func (*ConsoleBootstrapHandler) OwnsRoute(method, path string) bool
```

- `OwnsRoute` 只认完整 `POST /api/console/bootstrap`，不认前缀。内部 DTO 单独定义且只有三个 json 字段；EnvLabel 空字符串映射 null，不 omitempty。
- `app/console_routes.go` 的固定组合 `consoleRoutes{rbac, bootstrap eehost.AdditionalRoutes}` 依次注册并原样传递中间件；OwnsRoute 为二者的精确 OR。`app/identity.go` 仍只调用一次 WithAdditionalRoutes，不能覆盖掉已有 RBAC 注册。
- app 注入每次读取的闭包：宿主 Config.ConfigStore != nil、Config.LogsStore != nil、Config.EnvLabel；Config nil 返回 ErrUnavailable。与上游 getConfig 一样表示持有存储，不宣称实时健康探测；不读取完整 HTTP config 响应再删字段。闭包避免 Bootstrap 时过早冻结未初始化状态。
- `rbac/host/routes.go` 增加 console-service 类别，仅接收无权限、none guard、protocol projection；`routes.txt` 精确登记这一个 POST。不是 public，不伪装成 identity-service，不放进要求权限的 managed。RootGuard 和 VerifyRoutes 算法不改，所有注册完成后照常对账。新增类别不能增加允许未登记路径的通配逻辑。
- AuthAdapter 现有 AdditionalRoutes 分支将请求交给自管 handler，因此不进入 managed Prepare；认证责任明确在该 handler，不能空跳过。无须修改 AuthAdapter.APIMiddleware。

handler 顺序：设置 no-store → 建立 console.bootstrap context → 缺依赖503 → SameOrigin失败403 → 非空Authorization头401 → Cookie Authenticate（匿名/过期/停用/撤销401，存储故障503）→ 严格解析空对象400 → 窄投影读取503 → 固定 DTO 200。错误使用已有 identity HTTP 映射，内部 error 不原样输出。

在 `identity/http/protocol.go` 增加 `DecodeJSON(c *fasthttp.RequestCtx, value any) error`，仅调用已有 `decode(c,value,false)`；不改原函数语义。bootstrap 传 `&struct{}{}`，复用16KiB、媒体类型、UTF-8、重复键、单对象、未知字段规则。不是仅调用 ValidateJSONObject 后宽松解码。

路由测试验证 `/identity/me`、`/permissions/me`、bootstrap 同时注册；manifest 有而 Router 无仍拒绝。GET 等错方法405/Allow POST、尾斜杠及编码别名按既有 RootGuard400、未知路径404。`TestRouteSourceDigest` 对新条目的完整分类单独断言并剔除后检查旧摘要，不简单重算摘要掩盖变化。

## C. 外壳候选接入与业务页复用边界

以下外壳签名保留为已证实缺口的候选设计，不扩展到业务页面协议。类型位于候选 `ui/lib/types/consoleExtensions.ts`；`ReactNode`/`ComponentType`为React类型，Config的restart类型引用既有BifrostConfig。fallback位于 `ui/app/_fallbacks/enterprise/console/`，EE同路径覆盖。会话、表单和通知各自维持现有职责。业务页新policy已撤回，导航/直接URL受影响部分待诊断收敛与复核。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。

|---|---|---|---|

`AppContent` 的原模式判定可抽出小型 ShellSelection 以将判定移到 Session/RBAC 前，保持既有 auth-probe skip 和 fragment 快照语义。不要复制两份模式判定。`FullPage` 仅依赖 DB/log 布尔条件，其类型改为对应 Pick，不再要求完整 BifrostConfig。无权限工作台仍有账号菜单，不能因为页面为空把它一起卸载。

### 账号菜单、onboarding 与通知

```ts
type NotificationSyncOptions = { enabled: boolean; scope: string };
type TicketDecision =
  | {kind: "connect"; ticket: string}
  | {kind: "stop"}
  | {kind: "retry"};
type ManagedConnection = {
  enabled: boolean;
  scope: string;
  requestTicket: (signal: AbortSignal) => Promise<TicketDecision>;
};
// console/useConsoleControls.ts；只组合当前账号与权限能力，不拥有改密表单
function useConsoleControls(): {
  AccountMenu?: ComponentType;
  onboardingEnabled: boolean;
  notifications?: NotificationSyncOptions;
  connection?: ManagedConnection;
};
// 上游公开 props/参数新增可选项
function Topbar(props: {AccountMenu?: ComponentType; notificationsEnabled?: boolean}): ReactNode;
function useNotificationSync(options?: NotificationSyncOptions): void;
function WebSocketProvider(props: {
  children: ReactNode;
  path?: string;
  connection?: ManagedConnection;

```

执行位置与默认矩阵：

- `useConsoleControls` 在已认证且权限就绪的完整工作台子组件内调用。fallback：AccountMenu/notifications/connection均 undefined，onboardingEnabled=true。EE：AccountMenu为身份模块组件，onboardingEnabled=false，notifications.enabled=Notifications.View，scope为账号 UUID；连接 scope 为账号 UUID + 本地会话/权限代次，不含 Cookie/token。
- Topbar 无 AccountMenu 时才挂 `LegacyAccountMenu`，把原 getCoreConfig、getUserInfo effect、logout及菜单一起搬入该子组件，旧逻辑不改；提供 AccountMenu 后只挂它，父 Topbar 不再有这些 legacy hook。标题、品牌、ThemeToggle保留。通知 enabled 缺省 true；false 时整个 NotificationCenter 不挂载，避免其内部查询。
- ClientLayout 以 onboardingEnabled 控制 Widget 挂载；Sidebar 的既有 `useOnboardingChecklist` 传 `skip: !onboardingEnabled || !isDbConnected`。hook本身无需改。
- StoreSyncInitializer 传 notifications 给 useNotificationSync；undefined走现有 local-admin/OAuth 作用域与订阅；显式 disabled 时跳过HTTP、订阅、定时器及偏好回写。新 scope 先清旧通知再 hydrate；不能把旧账号偏好写入新账号。顶部中心与 sync 启用条件一致。
- WebSocketProvider 未提供 connection 时独立走原 Legacy 分支，仍保留全局连接、现有票据失败 Cookie 回退及原重试。不要把 EE策略改成 OSS默认。
- 提供 connection 时进入独立 Managed 分支：实例级 socket/handlers；disabled 仍提供空 Context（subscribe返回空退订、send无操作），不 fetch、不建WS、不设重试。StoreSync消费者不会因此 throw。
- EE requestTicket 通过现有个人 ws-ticket 请求：2xx且合法非空ticket返回connect；401通知统一会话失效并stop；403触发权限刷新一次并stop；网络/5xx返回retry，其他4xx或无效成功体stop并显示可重试连接错误。授权HTTP错误不依赖RTK wrapper，因为这是原生fetch。中止不显示故障。
- Managed分支有AbortController和递增代次。enabled/scope变化、卸载时先失效代次、abort请求、移除回调、清心跳/退避、关闭旧socket、清订阅。每个 await 后和 onopen/onmessage/onclose前检查代次；迟到结果不能打开连接或重新排队。票据仅进入一次握手，不缓存复用。
- retry采用现有上限32秒退避且每次取新票据；403保持停机，不形成“403→刷新→403”的自动循环；只在后续显式重试、窗口聚焦完成权限重查或身份变更后新代次重启。权限移除立即disabled。跨账号切换先卸载整个业务树/清内存，再进入新树。

## E. 自动化断言与记录要求

1. bootstrap候选继续经完整RootGuard/Router验证方法、路径、Origin、Authorization、Cookie、空对象、字段白名单及no-store；失败不泄露内部错误，不改变旧路由规则。
2. 已有诊断记录路由列表空/非空、分页及team详情的403表现，未出现本次观察的整页阻断，观察时toast为0。customer/VK详情、编辑选择器及提交未测，保持未知；如后续修复需要再针对性验证，不扩展成全仓审计。区分源码判断与实际浏览器观察，不以403本身判定全页故障。
3. 根据诊断选择最小修复，再补对应正负权限和请求断言；优先复用useRbac/query skip。不预设全部附属请求必须为零，不以新增的ModelProvider/Governance/VirtualKeys整页门槛作为正确性标准，不限制原有scope操作能力。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。
