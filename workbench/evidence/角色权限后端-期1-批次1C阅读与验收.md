## 阅读顺序

先看HTTP请求的共同入口，再挑一个接口沿着Service走到已确认的业务层。数据库实现不用重读。

| 入口 | 用途 | 要求 |
|---|---|---|
| POST /api/permissions/list | 返回可分配的权限目录 | Users.View |
| POST /api/permissions/me | 返回自己的角色及权限 | 正常登录会话 |
| POST /api/roles/list、get | 查看角色列表或详情 | Users.View |
| POST /api/roles/create、update、delete | 创建、修改或删除角色 | Users.Manage |
| POST /api/accounts/get-roles | 查询某个账号的角色和权限来源 | Users.View |
| POST /api/accounts/set-roles | 替换某个账号的角色 | Users.Manage |

文件入口：`rbac/http/handler.go`注册九个路由和共同认证；`roles.go`读参数并调用Service；`dto.go`整理响应；`protocol.go`约束输入JSON；`errors.go`将业务错误转HTTP状态。`app/rbac.go`组装已确认的业务与存储，`app/identity.go`连接迁移和HTTP，`app/recovery.go`连接离线恢复。宿主适配器只对精确匹配的角色端点交回接口自己鉴权。
