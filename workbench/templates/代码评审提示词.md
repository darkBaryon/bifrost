# 代码评审启动提示词（模板）

> 复制到新会话（干净上下文，非实施会话）。尖括号处替换。配套：[审查方向](../规范/流程/代码评审审查方向.md)、[记录模板](代码评审.md)。

```text
请在 <仓库绝对路径> 进行独立代码评审：不要创建/修改任何文件或报告，不修改代码/索引，不操作服务，不暂存、不提交、不推送。允许运行 checklist.yaml 里的构建与测试命令以亲核，包括产物写入 gitignore 目录、测试脚本自行拉起并回收的子进程（自包含 smoke 要跑）；二进制等产物写到 scratchpad。禁止启动 dev server、连接或操作任何已有实例、修改被 git 跟踪的文件。跳过某条命令须写明原因。

目标：判断这次改动对不对——是否满足方案与验收标准、失败路径是否正确且可观测、测试是否可信、有无残留。架构、组织、命名常量、重复、契约同步归收敛评审，看到只记一行"转收敛评审"，不出结论。

先读：根 AGENTS.md、workbench/AGENTS.md、workbench/规范/流程/交付.md、workbench/规范/流程/代码评审审查方向.md、workbench/规范/流程.md、<需求路径> 的验收口径、<方案路径> 的接口设计/实现步骤/「Gate 决策结果」/「实施偏差记录」、workbench/findings.md。按审查方向页的"工作程序"逐步执行；起手表每一行都要执行并记录结果；最后做开放式复读。

风险等级 <L1/L2/L3>。分支 <分支>，基线 <基线 commit>。代码在 <未提交工作树 / 某 commit>；必须包含新增未跟踪文件，不能只看 基线..HEAD。以 git 状态验证范围。

评审范围仅本次改动：
<逐文件列出路径>

产品范围与验收口径：<一段话，或指向需求文件>

不采信实施记录里的"已测过"：关键验证自己跑，命令与结果写进验证记录。不要读旧代码评审、旧收敛评审或先前会话的意见（差量复核轮除外：对方记录的「转交」栏会原样贴给你，按本侧规则处置）；已裁决/豁免的问题不重提。

直接在聊天中返回最终结果，按以下结构：
1. 总体判断（一段，含 verdict）；
2. 对照方案与接口面对账：三方不一致、多做/少做、未登记偏差；
3. 本轮修复项：每条含 绝对路径+准确行号、代码事实、触发条件与后果、最小修正；
4. 需用户裁决 / 有依据撤回：分别列出并说明；
5. 转收敛评审：范围外发现，一行一条（可为空）；挂账：范围内但裁决本轮不修的（可为空）；
6. 开放式复读的表外发现（可为空，须明写）；
7. 起手表覆盖：审查方向页表中每一行的结果（发现 / 无 / 不适用）；
8. 验证记录：实际跑的命令与结果；实际阅读范围及未执行的检查。
只报告有证据的判断。不需要输出文件。请适时汇报阅读进展。
```

## 使用说明

- 验收口径要给，代码评审的第一问是"做完了没"，没有口径就没法对账。
- 允许它跑测试，但要求命令与结果落在验证记录里；"已测过"三个字不算证据。
- 修复后的差量复核用同一会话继续，只核上轮意见、声明修改和受影响区域；把收敛评审记录的「转代码评审」栏原样贴给评审者，要求逐条处置（修复 / 撤回 / 挂账）。
