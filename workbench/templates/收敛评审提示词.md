# 收敛评审启动提示词（模板）

> 由 [tools/convergence_review.py](../tools/convergence_review.py) 按本模板与 checklist.yaml 机械填参，在新的 Claude Code 会话中启动；实施方不手工复制、不改写。尖括号是脚本替换的占位符，改动占位符须同步脚本。配套：[审查方向](../规范/流程/收敛评审审查方向.md)、[编码规范](../规范/项目/编码规范.md)、[记录模板](收敛评审.md)。

```text
请在 <仓库绝对路径> 进行独立收敛评审，只读：绝对不要创建/修改任何文件或报告，不修改代码/索引，不运行会写文件的测试/构建，不操作服务，不暂存、不提交、不推送。

工具限制：工作目录已经是仓库根。Bash 只放行以 git diff / git show / git log / git status / git ls-files / git rev-parse / git merge-base / git grep 起头的单条命令；不要加 cd 前缀，不要用管道或 && 串联，否则整条命令会被拒绝。文件阅读与搜索用 Read / Grep / Glob。

目标：像一个有成熟工程判断、审美优良的长期维护者通读代码，既看架构和原项目是否一致，也看实现细节是否脏、是否需要优化。无需凑问题，不机械抽象或打分。

先读：根 AGENTS.md、workbench/AGENTS.md、workbench/规范/流程/收敛评审.md、workbench/规范/流程/收敛评审审查方向.md、workbench/规范/项目/编码规范.md、workbench/规范/流程.md。按审查方向页的"工作程序"逐步执行；起手表每一行都要执行并记录结果，不是每维挑一行；最后做开放式复读。

涉及 EE 后端时必读 product/架构/EE后端架构.md，分别记录「架构符合性」「依赖关系」的核对结果，引用对应章节与实际代码证据。文件粒度按编码规范判断：核实拆分是否减少阅读和修改成本，不把架构示例或现有文件布局当成必备清单。检查模块边界、职责、装配与 Bifrost 集成，以及 import、窄接口、显式注入、跨模块数据访问和资源所有权；不能只看目录名或以上游风格为标准，也不因历史布局尚未迁移要求本次全量搬迁。

风险等级 <L1/L2/L3>（决定阅读深度，见收敛评审.md 重量分级）。分支 <分支>，基线 <基线 commit>。代码在 <未提交工作树 / 某 commit>；必须包含新增未跟踪文件，不能只看 基线..HEAD。以 git 状态验证范围。

评审范围仅本次改动：
<逐文件列出绝对/仓库相对路径>
规范文档变化、历史评审及原调研不是本次被评对象。

产品范围：<一段话：做什么、不做什么>

独立阅读实际代码和相关同类实现后形成判断；不要读旧代码评审、旧收敛评审或先前会话的意见（差量复核轮除外：对方记录的「转交」栏会原样贴给你，按本侧规则处置）。但必须读 workbench/findings.md 与 <方案路径> 的「Gate 决策结果」「实施偏差记录」，已裁决/豁免的问题不重提。需要核对约束时再查 <方案路径> 与 <开发指南路径>。

关注：架构一致性、职责、文件与包组织、命名/常量、控制流/状态、规则重复、抽象必要性、契约三方同步；但不要扩大到无关旧债。正确性、失败路径、测试、性能/并发/安全/可观测性属于代码评审，看到只记一行"转代码评审"，不出结论。凡是结论依赖"上游会/不会做 X"的，去上游代码里找到那几行证实后再下结论。

最终回复只输出一份完整的收敛评审记录（Markdown），结构按 workbench/templates/收敛评审.md，含 frontmatter，verdict 只取 无碍 / 仅立债挂账 / 有Blocking，不附加其他文字。记录须覆盖以下内容，分别落入模板对应章节：
1. 总体判断（一段）；
2. 本轮修复项：每条含 绝对路径+准确行号、代码事实、维护影响、最小修正；

5. 开放式复读的表外发现（可为空，须明写）；
6. 转代码评审：范围外发现，一行一条（可为空）；
7. 起手表覆盖：审查方向页表中每一行的结果（发现 / 无 / 不适用）；
8. 实际静态阅读范围及未执行的检查。
只报告有证据的判断。你不写文件，启动脚本会原样保存你的最终回复。
```

## 使用说明

- 启动：预飞全绿并提交候选后，实施方在项目根执行 `python3 workbench/tools/convergence_review.py start --config <checklist.yaml> --round <R>`，脚本在后台运行；用 `status` 查看进度，或用 `wait` 等到结束。先用 `--dry-run` 可只打印提示词。
- 参数来源：checklist.yaml 的「收敛评审」段给出风险等级、基线与开发指南；文件清单取 `git diff --name-only`（排除 workbench/）；产品范围取方案「给用户的摘要」。工作树不干净时拒绝启动。
- 首轮整包；修复后提交新候选，加 `--since <上一轮候选 commit>` 启动差量复核轮，脚本自动附上上一轮记录和最新代码评审的「转收敛评审」栏原文，要求逐条处置。每轮都是新会话。
- 实施方不撰写、增删或改写提示词，不限定范围，评审期间不与评审者通信。评审原文由脚本落盘为 `收敛评审<R>.md`，实施方不改写；有异议在下一轮或交用户裁决。落盘后照常跑 `build_views.py`。
