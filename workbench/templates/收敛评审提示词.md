# 收敛评审启动提示词（模板）

> 复制到新会话（干净上下文，非实施会话）。尖括号处替换。配套：[审查方向](../规范/流程/收敛评审审查方向.md)、[编码规范](../规范/项目/编码规范.md)、[记录模板](收敛评审.md)。

```text
请在 <仓库绝对路径> 进行独立收敛评审，只读：绝对不要创建/修改任何文件或报告，不修改代码/索引，不运行会写文件的测试/构建，不操作服务，不暂存、不提交、不推送。

目标：像一个有成熟工程判断、审美优良的长期维护者通读代码，既看架构和原项目是否一致，也看实现细节是否脏、是否需要优化。无需凑问题，不机械抽象或打分。

先读：根 AGENTS.md、workbench/AGENTS.md、workbench/规范/流程/收敛评审.md、workbench/规范/流程/收敛评审审查方向.md、workbench/规范/项目/编码规范.md、workbench/规范/流程.md。按审查方向页的"工作程序"逐步执行；起手表每一行都要执行并记录结果，不是每维挑一行；最后做开放式复读。

风险等级 <L1/L2/L3>（决定阅读深度，见收敛评审.md 重量分级）。分支 <分支>，基线 <基线 commit>。代码在 <未提交工作树 / 某 commit>；必须包含新增未跟踪文件，不能只看 基线..HEAD。以 git 状态验证范围。

评审范围仅本次改动：
<逐文件列出绝对/仓库相对路径>
规范文档变化、历史评审及原调研不是本次被评对象。

产品范围：<一段话：做什么、不做什么>

独立阅读实际代码和相关同类实现后形成判断；不要读旧代码评审、旧收敛评审或先前会话的意见（差量复核轮除外：对方记录的「转交」栏会原样贴给你，按本侧规则处置）。但必须读 workbench/findings.md 与 <方案路径> 的「Gate 决策结果」「实施偏差记录」，已裁决/豁免的问题不重提。需要核对约束时再查 <方案路径> 与 <开发指南路径>。

关注：架构一致性、职责、文件与包组织、命名/常量、控制流/状态、规则重复、抽象必要性、契约三方同步；但不要扩大到无关旧债。正确性、失败路径、测试、性能/并发/安全/可观测性属于代码评审，看到只记一行"转代码评审"，不出结论。凡是结论依赖"上游会/不会做 X"的，去上游代码里找到那几行证实后再下结论。

直接在聊天中返回最终结果，按以下结构：
1. 总体判断（一段）；
2. 本轮修复项：每条含 绝对路径+准确行号、代码事实、维护影响、最小修正；
3. 建议取舍项：每条附反证条件；
4. 看似可改但有理由保留：写出理由；
5. 开放式复读的表外发现（可为空，须明写）；
6. 转代码评审：范围外发现，一行一条（可为空）；
7. 起手表覆盖：审查方向页表中每一行的结果（发现 / 无 / 不适用）；
8. 实际静态阅读范围及未执行的检查。
只报告有证据的判断。不需要输出文件。请适时汇报阅读进展。
```

## 使用说明

- 文件清单要逐个列，不写"ee/ui 下全部"；范围越具体，弱模型越不跑偏。
- 产品范围一段话决定评审者对"应该做/不该做"的判断，别省。
- 评审返回后，由实施者按"本轮修复项"修复并定向复核；独立性规则见 [收敛评审.md](../规范/流程/收敛评审.md)。
- 差量复核轮：把代码评审记录的「转收敛评审」栏原样贴给评审者，要求逐条处置（修复 / 撤回 / 挂账）。
- 评审结束用 [收敛评审.md](收敛评审.md) 模板建档，frontmatter `verdict` 三态。
