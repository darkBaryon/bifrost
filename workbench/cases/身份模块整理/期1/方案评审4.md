## 建议（不扩进本期方案，不构成阻塞）

1. **`test_guard.sh` 的「允许集合为空」分支不可达**。第 13 行 `grep -vE '^[[:space:]]*(#|$)' "$ALLOWED_FILE" > "$tmp/allowed"` 在 `set -eu` 下：若允许文件只有注释与空行，`grep` 以 1 退出，脚本**当场终止**，第 14 行的提示与 `exit 2` 永远不会执行。实测：喂一个只含注释的文件，输出为空、rc=1。虽然仍是非零（预飞照样判红），但拿不到原因。补 `|| true` 即可。
2. **第 7 条模式建议钉到具体 import 路径**。`^[-+][[:space:]]*"[^"]+"$` 在语法上放行任何「整行只有一个带引号字符串」的行（实测样本 m 通过守卫）。本期这四个文件真正会变的 import 只有 `.../ee/internal/identity/hasher` 一条（`service_test.go` 与 `auth_test.go` 各一），可以直接写死成 `^\+[[:space:]]*"github\.com/darkBaryon/bifrost/ee/internal/identity/hasher"$`，守卫就从「形状对」升级为「内容对」。
3. **多条模式是双向的，守卫只证明"没多改"，不证明"改对了"**。第 10、11、12、13、18–21、26–29 都写成 `(旧|新)` 的并联，所以把新形态改回旧形态同样放行（实测样本 l、以及把 `return services{...}` 改回 `return s` 均 rc=0），只能靠编译器兜底。若把旧形态钉在 `^-`、新形态钉在 `^+`（第 22–24 条已经是这个写法），守卫单独就能证明这些替换确实做了、而且只做了一次方向。
4. **重申上轮建议 4：两个新护栏测试仍无机械守护**。`accounts_page_test.go`、`dto_test.go` 是本期唯一的新增行为保护，步骤 3b「不改一行」与步骤 6「`dto_test.go` 零改动」目前只能人工看。脚本已支持多参数与逐文件基线路径，步骤 2 提交后把这两个文件按「基线 = 引入它们的提交」再加一条 `test-guard-new` 即可闭环。
5. **`^[-+]\)$` 仍放行任意顶格 `)` 行**（不止 import 收尾）。本期这四个文件里顶格 `)` 只出现在 import 块，风险很低；若采纳建议 2 把 import 行钉死，这条也可一并收紧为只允许与 `import (` 成对出现。
6. **§5 步骤 5 的自检 ERE 漏掉行尾形态**。`grep -rnE 'identity\.Service[^sA-Za-z]|identity\.NewService' ee` 实测 11 处命中，但**漏掉** `ee/internal/bifrost/auth.go:28` 与 `ee/internal/identity/http/handler.go:26` 两个以 `*identity.Service` 结尾的字段声明；补上 `|identity\.Service$` 后是 13 处。checklist 的禁留标记本来就是两条一起（`identity\.Service[^sA-Za-z]` + `identity\.Service$`），所以最终预飞不会漏，只是步骤 5 当场的自检会给出假绿。把步骤 5 的表达式与禁留保持一致即可。
7. **守卫自证结果建议进实施记录**。§6 已写入 v4 起草时的正/反样本结论；本轮我独立复现并扩到 11 个样本，建议步骤 9 的实施记录把「修改后复跑正样本 + 至少 a/b/c/d/e/g/k 七个反样本」列为一项，避免日后有人放宽允许文件时守卫悄悄失效。

## 剩余风险

1. **守卫的效力取决于允许文件不被放宽**。它现在是本期唯一能机械证明「61+4 处调用点的替换没有顺手改掉断言」的手段；一旦实施中为了过关而往允许文件里加宽模式，绿就退回弱绿。建议 7 的实施记录要求是针对这一点的最低成本对冲。
2. **两个新护栏测试自身的正确性仍无人预审**（建议 4）。`accounts_page_test.go` 与 `dto_test.go` 在步骤 2 一次写成，是 3b 的唯一回归探测器；代码评审阶段应把这两个文件排在最前。
3. **守卫不覆盖生产代码**。四个既有测试文件零逻辑改动只证明「保护没被削弱」，不证明「行为没变」——后者仍靠 `go test -race`、四个冒烟脚本与白名单终扫。这是设计如此，不是缺陷，但 Gate 1 时值得让用户知道绿的边界。
4. 前三轮的剩余风险（步骤 5 的 diff 规模、`hasher` 搬包时 `bcryptHashPattern` 正则逐字一致、`Account` 增字段的其他序列化出口）依然成立，v4 未改变其性质。
