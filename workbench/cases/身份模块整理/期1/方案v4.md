## 给用户的摘要

账号认证后端已交付，这次只整理内部结构，不改任何对外行为：把一个大 `Service` 拆成会话、账号、密码三个服务共用一个核心；HTTP 层的端点按线分三个文件，请求/响应结构仍是一个文件、按线分三段；宿主适配只依赖它用到的五个方法；`Credential` 改名为 `AccountRecord`，账号列表不再携带密码哈希；bcrypt 适配从存储包移到 `identity/hasher`；`internal/bifrost` 改名 `internal/host`。唯一的行为变化是 FIND-020：写入新会话或票据时顺手删除已过期的行。

拍板项：(a) 标准级 / L3 证据；(b) 名称 `host`、`AccountRecord`、`SessionService`/`AccountService`/`PasswordService`、`hasher.Bcrypt`；(c) FIND-020 口径"到期即删、含已撤销"，且**不加索引**（理由见 §4.6）；(d) 期 1 已归档的 checklist 更新必存产物路径、历史事实表不改。用户已明确选择「同包三类型 + core」（B），不选「单类型 + 窄接口」（A）或「三层分包」（C）。最大剩余风险：账号列表分页此前零覆盖，本次先补表征测试再动它。

## 4. 设计

### 4.1 `identity` 包终态

```
model.go       Credential → AccountRecord；CreatedAt 移到 Account（AccountRecord 只保留 UpdatedAt）；
               Repository.CredentialByName → RecordByName；Repository.Accounts 返回 []Account；
               AuthRecord.Credential 字段 → AuthRecord.Account（类型 AccountRecord）
core.go        由 service.go 改名而来，保留：Options 与 Validate；type core struct{repo, hasher, policy, options, hashSlots, dummyHash}；
               now / randomID / randomToken / digest；withHashSlot / hash / compare / validPassword；
               verify / resolve / current / fullSession / authorize / manager；
               page / encodeCursor（自 accounts.go 移入，两条线共用）；
               导出方法 State、RequireAccountManager（挂在 *core，经嵌入提升到三个服务）
session.go     type SessionService struct{ *core }   Authenticate ValidateSession Me Login Logout IssueTicket ConsumeTicket
accounts.go    type AccountService struct{ *core }   BootstrapLegacy Initialize CreateAccount SetAccountStatus ListAccounts
passwords.go   type PasswordService struct{ *core }  ChangePassword ResetPassword RecoverAdmin ListPasswordEvents
```

构造：`identity.New(repo Repository, hasher PasswordHasher, options Options, policy AccountPolicy) (*Services, error)`；`type Services struct{ Session *SessionService; Account *AccountService; Password *PasswordService }`。三个服务共享同一个 `*core`（同一个哈希槽 channel、同一个假哈希）。三条线互不调用（方案评审1 逐方法核对通过）；跨线动作全部经 `Tx` 或 `core`。

`CreatedAt` 归属：`Account{ID, Username, DisplayName, Status, MustChangePassword, CreatedAt}`；`AccountRecord{Account; PasswordHash; AuthVersion; UpdatedAt}`。只有一个 `CreatedAt`，无遮蔽；`rows.go` 的转换给 `Account.CreatedAt` 赋值。`accountDTO` 不加 `created_at`，接口输出不变（步骤 2 的表征测试与冒烟核对字段集合）。

### 4.3 `internal/bifrost` → `internal/host`，依赖收窄为窄接口

`git mv`，包名 `host`，import alias 沿用 `eehost`。按"接口由使用方定义"，host 侧声明：

```go
// consoleSessions 是管理鉴权需要的会话能力，由 identity.SessionService 满足。
type consoleSessions interface {
    Authenticate(context.Context, string) (identity.Principal, error)
    ValidateSession(context.Context, string) (identity.Principal, error)
    RequireAccountManager(context.Context, identity.Principal) error
    ConsumeTicket(context.Context, string) (identity.Principal, error)
    Me(context.Context, identity.Principal) (identity.Account, error)
}
// legacyImporter 是导入旧管理员需要的能力，由 identity.AccountService 满足。
type legacyImporter interface {
    State(context.Context) (identity.State, error)
    BootstrapLegacy(ctx context.Context, username, passwordHash string) error
}
// identityRoutes 是接入身份 HTTP 层需要的能力，由 identityhttp.Handler 满足（用户在预飞 2 后追加，见实施偏差 6）。
type identityRoutes interface {
    Origin() string
    SameOrigin(*fasthttp.RequestCtx) bool
    RegisterRoutes(*router.Router, ...schemas.BifrostHTTPMiddleware)

func NewAuthAdapter(h *server.BifrostHTTPServer, sessions consoleSessions, handler identityRoutes) *AuthAdapter
```

`host` 包整体只能触及这十个方法；建号、启停、列表、重置、恢复对它不可见。`Handler` 的导出方法恰好就是 `identityRoutes` 的三个，收窄不改变可达面，只让三处依赖遵守同一条"接口由使用方定义"。

### 4.4 bcrypt 适配 → `identity/hasher`

判定规则：`identity` 根包只依赖标准库；`identity/<子包>` 是把根包定义的接口适配到某个**库**（`persistence`→GORM，`http`→fasthttp）；`host` 是触及**运行中宿主对象**（`*server.BifrostHTTPServer`、handlers 上下文键、`TempTokens` 服务）的代码。`framework/encrypt` 是库不是宿主对象，故 bcrypt 适配归 `identity/hasher`：

```go
package hasher   // ee/internal/identity/hasher/bcrypt.go
type Bcrypt struct{}   // 实现 identity.PasswordHasher；Hash / Compare / ValidHash 实现不变
```

文件末尾加 `var _ identity.PasswordHasher = Bcrypt{}`（这是 §4.7 中 `hasher → identity` 这条边的来源）；`bcryptHashPattern` 正则原文照搬，不改一字。`app/identity.go` 与 `app/recovery.go` 注入 `hasher.Bcrypt{}`；离线恢复不因此依赖 `host`。`persistence/service_test.go` 改 import `identity/hasher`（兄弟包，无反向边）。

### 4.5 `app` 装配

`newIdentityService` 改为 `newIdentity(db, options, log) (*identity.Services, error)`；`assembleIdentity` 传 `svc.Session` 给 `NewAuthAdapter`、`svc.Account` 给 `ImportLegacyAdministrator`、`svc` 给 `identityhttp.NewHandler`；`RecoverAdmin` 用 `svc.Password.RecoverAdmin`。`bootstrap.go` 不变。

### 4.6 FIND-020：过期行清理

`transaction.InsertSession` 前执行 `DELETE FROM ee_identity_sessions WHERE expires_at < ?`；`transaction.InsertTicket` 前执行 `DELETE FROM ee_identity_ws_tickets WHERE expires_at < ?`。删除与插入同一事务，在既有 state 写锁内，两节点串行（方案评审1 核对：不引入新加锁顺序；删行后 `AuthByHash` 走 `ErrNotFound` → 401，`Logout` 对已删行返回成功，票据消费条件本就含 `expires_at > ?`，对外状态码不变）。

**索引取舍**：`expires_at` 在两张表都无索引，DELETE 为全表扫描。接受，理由：表的大小由这条清理本身封顶——会话行数 ≈ TTL 窗口内的登录次数（默认 24h，内部控制台为十位数），票据行数 ≈ 30 秒内的 WS 建连次数（个位数）；对这种规模的表，扫描代价在微秒级，低于同一事务里已有的 `UPDATE state` 与 `INSERT`。加索引要出 `ee_identity_v2` 迁移，与非目标冲突，本期不做；若日后会话表超过万行再评估。

口径：**到期即删，已撤销但未到期的行保留到到期**。会话表不承担审计职责，密码事件表才是。`model.go:139` 的注释"撤销通过 RevokedAt 标记，记录不删除"同步改为"撤销通过 RevokedAt 标记；到期行在下次写入时清理"。与账号认证期1 方案v2 §4.3 的"保留记录"承诺无冲突（该句只管 `password_events`，方案评审1 已核）。
