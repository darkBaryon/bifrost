## 给用户的摘要

账号认证后端已交付，这次只整理内部结构，不改任何对外行为：把一个大 `Service` 拆成会话、账号、密码三个服务共用一个核心；HTTP 层的端点和请求/响应结构跟着三分；宿主适配只拿它需要的服务；`Credential` 改名为 `AccountRecord`，账号列表不再携带密码哈希；bcrypt 适配从存储包搬到宿主接入包；`internal/bifrost` 改名 `internal/host`。唯一的行为变化是 FIND-020：写入新会话或票据时顺手删除已过期的行。

拍板项：标准级 / L3 证据；上述四个新名字；过期行"到期即删、含已撤销"的口径。最大剩余风险：搬动过程中漏改一处调用，由既有测试与三个冒烟兜底。

## 3. 目标与非目标

**结构要改变的**：上述 1–5。
**行为必须保持的**：全部 HTTP 契约（路径、方法、请求/响应字段、状态码、错误体）、Cookie 属性、`ee_identity_v1` 迁移与六张表结构、宿主接缝（`ConsoleAuthProvider` 实现、`IsLocalAdmin` 写法、WS 重验、`/api/config` 投影）、离线恢复命令的参数与输出、三个冒烟脚本不改一行。
**允许的行为变化**：仅 FIND-020（见 4.6）。
**非目标**：RBAC；`Repository/Tx` 接口收窄（GPT 第 4 点，记为观察项）；`RequireAccountManager` 兼任控制台准入的改名（RBAC 时一并处理）。

## 4. 设计

### 4.1 `identity` 包终态

```
model.go       不变（Credential 改名 AccountRecord；Account 增 CreatedAt）
core.go        type core struct{ repo, hasher, policy, options, hashSlots, dummyHash }
               共享判定：verify / resolve / current / authorize / manager / hash / compare / validPassword
               导出：State、RequireAccountManager（三线都用，经嵌入提升）
session.go     type SessionService struct{ *core }   Login Authenticate ValidateSession Logout Me IssueTicket ConsumeTicket
accounts.go    type AccountService struct{ *core }   BootstrapLegacy Initialize CreateAccount SetAccountStatus ListAccounts
passwords.go   type PasswordService struct{ *core }  ChangePassword ResetPassword RecoverAdmin ListPasswordEvents
```

构造：`identity.New(repo Repository, hasher PasswordHasher, options Options, policy AccountPolicy) (*Services, error)`，`type Services struct{ Session *SessionService; Account *AccountService; Password *PasswordService }`。三个服务共享同一个 `*core`（同一个哈希槽 channel、同一个假哈希）。三条线互不调用；跨线动作全部经 `Tx`（如改密调 `tx.RevokeSessions`）或 `core` 判定函数，与现状一致。

`Repository.Accounts` 改为返回 `[]Account`；`Account` 增加 `CreatedAt time.Time` 供游标分页使用（`accountDTO` 不加该字段，接口输出不变）。

### 4.2 `identity/http` 终态

```
handler.go     Handler{svc *identity.Services, origin, secure}；路由表；serve；OwnsRoute；RegisterRoutes
session.go     status login logout me wsTicket
accounts.go    initialize createAccount listAccounts setStatus
passwords.go   changePassword resetPassword passwordEvents
protocol.go    不变
dto.go         → dto_common.go（error/message/page/optional/pageLimit）+ dto_session.go + dto_accounts.go + dto_passwords.go
```

路由表、`serve`、`protocol.go` 一字不改；端点函数只是搬家并把 `h.service.X` 改为 `h.svc.Session.X` 等。

### 4.3 `internal/bifrost` → `internal/host`

`git mv`，包名 `host`，import alias 沿用 `eehost`。`AuthAdapter` 依赖收窄为：

```go
func NewAuthAdapter(h *server.BifrostHTTPServer, sessions *identity.SessionService, handler *identityhttp.Handler) *AuthAdapter
func ImportLegacyAdministrator(ctx, h *server.BifrostHTTPServer, accounts *identity.AccountService, log Logger) error
```

`config.go` 的 `projection` 用 `sessions.Me`。适配层不再能触及建号、重置、恢复。

### 4.4 bcrypt 适配

`persistence.Passwords` 移为 `host.Bcrypt`（文件 `host/bcrypt.go`），实现不变（含 `ValidHash` 的完整哈希形状校验）。它包装的是上游 `framework/encrypt`，属宿主接入。`app/identity.go` 与 `app/recovery.go` 改注入 `eehost.Bcrypt{}`。

### 4.5 `app` 装配

`newIdentityService` 改为 `newIdentity(db, options, log) (*identity.Services, error)`；`assembleIdentity` 与 `RecoverAdmin` 共用；`bootstrap.go` 不变。

### 4.6 FIND-020：过期行清理

`transaction.InsertSession` 前执行 `DELETE FROM ee_identity_sessions WHERE expires_at < ?`（当前时间）；`transaction.InsertTicket` 前执行 `DELETE FROM ee_identity_ws_tickets WHERE expires_at < ?`。与 `login_limits` 的既有做法同形（写入时顺带清理，不起后台任务）。

口径：**到期即删，已撤销但未到期的行保留到到期**。会话表不承担审计职责；密码事件表才是审计记录。删除与插入在同一事务，失败一起回滚。

### 4.7 依赖方向（终态）

```
app → host, identity, identity/http, identity/persistence, 上游
host → identity, identity/http, 上游
identity/http → identity
identity/persistence → identity
identity → 标准库
```

与现状唯一差别：`host` 不再需要 `persistence`（bcrypt 已在本包）。
