## 给用户的摘要

现在只有共享管理员登录。完成后，每个账号独立登录，由分配的多个角色共同决定可执行操作。
新增角色、配置权限、分配账号都提供后端接口，前端以后接入。
多角色权限取并集已确认；旧共享管理员作为首个主管理员，保留用户名密码、要求重新登录；未配置管理员的实例先初始化。
当前是接入草案，还没有通过方案复核，也没有开始修改业务代码。

## 2. 现状与复用

- `ee/transports/bifrost-http/server/bootstrap.go` 的 attach 可复用 ConfigStore.DB() 建立 `ee_` 表、增加路由和包装全局处理器。
- 上游 `handlers/session.go` 的登录只验证 AuthConfig 的共享管理员，会话表没有账号 ID，不能直接表达多账号。
- 上游 `handlers/middlewares.go:1154` 的认证逻辑会把普通有效会话标为本地管理员；认证关闭还有匿名管理员路径。不能让 EE 只检查新增角色接口，旧业务接口仍走原来的放行逻辑。
- 上游 `server/server.go:2733` 的企业模式会跳过管理认证；同一开关在 2782 行还会跳过推理认证，并影响插件装配。不能仅为替换登录而直接打开这个开关。
- fasthttp router 有 List/Lookup，可用于运行期路由覆盖核对。API 不全在 `/api/`，管理 WebSocket、监控和调试入口需要独立分类。
- 前端用户、角色、登录和 rbacContext 都有 enterprise 覆盖入口。实现源码可放 `ee/ui/`，本轮不修改它们。

## 3. 目标与边界

产品事实引用本分支的[角色权限产品方案](../../../../product/需求/角色权限/产品方案.md)，竞品证据见[竞品产品调研](../../../../product/需求/角色权限/竞品产品调研.md)。只有明确确认的条目是实施输入。

## 4. 接口与数据设计草案

以下是待复核的技术契约，尚未发布。

| 数据 | 内容 |
|---|---|
| ee_users | 账号 ID、唯一登录名、密码哈希、启用状态 |
| ee_roles | 角色 ID、唯一名称、说明、内置保护标记 |
| ee_role_permissions | 角色 ID、权限 ID，联合唯一 |
| ee_user_roles | 账号 ID、角色 ID，联合唯一 |
| ee_sessions | 会话凭据哈希、账号 ID、到期时间；不把权限快照写进会话 |

权限目录由服务端按实际操作定义。创建角色只能引用目录内权限，未知权限返回 400；无角色的账号没有业务权限。修改授权关系采用事务，后续请求读取当前权限，避免等待重新登录或本地缓存过期。

| 拟定 API | 用途 |
|---|---|
| GET /api/ee/permissions | 权限目录 |
| GET、POST /api/ee/roles | 列出、创建角色 |
| GET、PATCH、DELETE /api/ee/roles/{id} | 查看、改名/说明、删除角色 |
| PUT /api/ee/roles/{id}/permissions | 整体替换角色权限集合 |
| GET、POST /api/ee/users | 列出、创建账号 |
| PATCH /api/ee/users/{id} | 停用/启用账号；密码维护契约另行细化 |
| PUT /api/ee/users/{id}/roles | 整体替换账号角色集合 |
| GET /api/ee/me | 当前账号、角色、有效权限及权限来源 |

登录保持已有 username/password 请求形式；成功建立绑定账号的新会话。无效凭据返回 401，无权限返回 403，被引用角色删除返回 409；不返回密码哈希和会话哈希。

认证装配仍需确定最小接入点：优先在 EE 内完成；如上游缺少管理认证替换接口，应增加明确、默认不改变上游行为的扩展入口，不能借用 API Key 标记伪装 EE 用户，也不能把所有账号标成管理员。接入点未落实前本方案不能进入实施。

## 5. 实现步骤

1. 依据已确认的首次启用与旧管理员衔接规则，确定认证扩展入口；盘点实际注册路由、敏感字段与业务操作，形成权限映射。
2. 实现 EE 数据表、事务服务和多角色权限计算。
3. 实现账号会话及角色/账号接口。
4. 接入已有管理操作；核对旧登录、Basic、Bearer、Cookie、匿名模式、WebSocket 与临时凭据路径，防止旁路。
5. 完成接口契约、运行说明和验证；单独评审代码与整体影响。

## 6. 测试策略

- 两个角色分别允许改路由、读费用，账号同时持有时二者可用，预算修改仍返回 403。
- 移除一个角色后，仅它独有的权限消失；其他角色仍提供的权限保留。
- 编辑角色后同一会话的下一次请求采用新权限。
- 普通账号直接请求授权管理接口不能给自己提权；批量接口不能绕过权限。
- 账号停用、密码变更、登出、到期后的会话行为分别验证；首次迁移重启不重复创建或覆盖管理员。
- 并发修改不能移除最后一个有效主管理员；SQLite 与 PostgreSQL 分别验证事务行为。
- 未分类管理路由拒绝访问；查看列表不能意外返回密钥或请求正文；推理请求与原有凭证行为回归。
- 真实启动 EE 服务后用 HTTP 验证完整链路，不能只调用内存 handler。所有数据使用临时测试库。

## 8. 风险与禁止事项

最大风险是新旧认证叠加，造成绕过或把所有账号当管理员。主管理员保护、敏感字段、配置更新和长连接必须纳入同一授权边界。
本次不改品牌 worktree，不迁移真实业务数据。用户已授权本次文档汇总、提交推送和权限分支对齐；后续业务代码提交推送仍须遵循用户当时的授权。产品中未确认建议不得静默变成已确认规则。

## 9. 回滚口径

使用临时数据库开发验证；现有配置表和会话表不做破坏性改造。功能未上线前以切回基线二进制回退。真实环境启用前需明确：回退后原共享管理员入口会恢复，不能称为权限等价回滚。
