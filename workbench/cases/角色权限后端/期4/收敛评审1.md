## 结论

角色权限后端的整体架构适合交付，但本轮修复项关闭前不能按"无碍"交付。

**整体符合项目架构的部分**
- rbac 根包只依赖标准库。
- 存储、HTTP、身份策略、宿主接入四个适配层的依赖方向正确，没有循环依赖。
- `internal/host` 通过窄接口和 Option 注入使用角色能力，不导入 rbac。
- 上游改动都是可选的上下文回调，业务规则留在 EE。

**需要处理的问题**
- 过渡期留下的"固定恢复账号兜底"分支在最终装配下已经走不到，但注释仍把它写成生产行为。
- 身份 README、账号认证接口指南、EE 后端架构三份文档没有跟上最终授权模型。
- 有几处跨模块或同包的规则被重复实现：唯一键冲突判定、16 KiB 请求体上限、账号 ID 格式、`requirePermissions`、设置字段权限表。
- 少量导出符号缺少说明特殊语义的注释。
- 上游新增的错误类型带着无人读取的字段，还有一处不可达的守卫。

以上都是局部修正，不需要重新设计。修复并定向复核后，可按剩余的取舍项和挂账重新给出结论。

### 架构符合性（对照 EE 后端架构）

- **§4 模块内职责：符合。**
  - rbac 根包承载权限目录、角色与分配规则、判权和管理员保护。`roles.go` 的 import 块（第 4–16 行）等根包文件只引用标准库。
  - `persistence` 负责表结构、迁移和事务内读写（`rows.go`、`roles.go`、`migration.go`）。
  - `http` 负责解析、调用服务、映射响应（`api.go` 对名称长度等只做字段形状检查，业务校验在 `roles.go:138-163`）。
  - 业务类型不带 json/gorm 标签；DTO 在 `api.go:120-130`、`232-251`，行结构在 `rows.go`。
- **§5 事务：符合。** 业务服务通过 `s.write` 决定完整操作的边界（`assignments.go:66-101`）。`Store.Write` 委托身份存储的 `Within`，共用 state 写锁（`scope.go:96-99`）。`*gorm.DB` 没有进入业务层。
- **§5 模块之间：符合。** rbac 需要账号信息时，只通过 `identity.Queries` 窄接口读取（`access.go:29-35`），由 app 注入（`app/rbac.go:19-23`）。rbac 不写身份表：`CountActiveAccounts` 在身份持久化包内实现（`scope.go:51-66`），迁移取身份锁也由身份导出的 `LockView` 执行（`scope.go:87-94`）。
- **§1、§7 与内嵌 Bifrost 的关系：符合。**
  - 共享 Router：角色路由经 `RegisterSessionRoutes` 注册（`host/auth.go:188-193`）。
  - 共享 Server.Handler：EE 外层包装在 `bootstrap.go:47`。
  - 共享配置库：`identity.go:68-74`。
  - 离线恢复自己打开连接并自己关闭（`recovery.go:67-71`）。
  - 上游改动只增加可选回调，业务规则仍在 EE（`consolepolicy.go:25-59`、`request.go:133-151`），且已登记在 `product/上游改动/README.md:125-149`。
- **§7 集成归位：不一致（R4）。** §7 规定触及宿主对象的代码进 `internal/host/`（EE后端架构.md:114）。实际的 `rbac/host` 使用了 handlers 上下文键（`request.go:135-150`）和 `*lib.Config`（`settings.go:28-36`），这个位置由开发蓝图 §2/§4 确认。架构文档 §1 第 5、22 行和 §3 第 53 行仍写着"完整 RBAC 后续开发"。
- **§3 app 只做装配：符合。** `app/rbac.go` 共 26 行，`identity.go` 只做构造和迁移调用，`bootstrap.go:44-47` 只核对路由并包装 Handler，没有运行期业务编排。
- **§6 插件：不适用。** 本次没有新增插件。

### 依赖关系

依赖图如下，没有反向或双向依赖：

| 包 | 依赖 |
|---|---|
| rbac 根包 | 仅标准库 |
| rbac/identity | identity、rbac |
| rbac/persistence | identity、identity/persistence、rbac、rbac/identity |
| rbac/http | identity、identity/http、rbac、rbac/identity |
| rbac/host | identity、identity/http、rbac、rbac/http、rbac/identity |
| identity 各包 | 不导入 rbac 或 host（Grep 结果为空） |
| internal/host | 只声明 `ConsoleAccess`、`AdditionalRoutes` 两个接口（`host/auth.go:49-66`），不导入 rbac |

- **窄接口与显式注入**
  - `AccountPolicy` 由使用方 identity 定义，rbac/identity 实现（`policy.go:100`）。
  - 同一事务内的策略由 app 通过 `WithPolicyFactory` 注入（`app/rbac.go:19-21`）。
  - `rbachttp.NewHandler` 接收 `Sessions` 和 `OriginChecker` 两个窄接口（`handler.go:18-38`）。
- **具体类型**：`rbac/host.NewAdapter` 接收 `*rbac.Service` 与 `*lib.Config`（`authorization.go:27`）。前者是同模块依赖，与 identity/http 接收 `*identity.Services` 的先例一致；后者是宿主对象，放在宿主适配里合理。
- **存储适配之间的跨模块依赖**：rbac/persistence 依赖 identity/persistence 的 `LockView`、`RetrySQLiteBusy`、`Scope(*gorm.DB)`。原因是共享事务必须在存储层共用连接；依赖是单向的，锁的写入由 identity 执行。保留理由见 K2。
- **有维护影响的一点**：rbac 的适配包已经依赖 identity 的适配包，但仍各自复制了三条身份侧规则（R6）。
