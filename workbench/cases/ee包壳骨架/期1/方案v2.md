## 给用户的摘要

现状:企业级功能的落点(独立 `ee/`、不改上游)只是设想,没有一行代码验证过。做完:仓库里多一个 `ee/` 目录(内部路径镜像上游,骨架期只有 transports 一支),自己的可执行文件起在 8080,OSS 的页面和 API 行为不变,外加五样"证明":一条自己的路由、一张自己的表、一个自己注册的插件、一个 Bootstrap 前注入的 HTML 标记、控制台审计页显示我们自己的占位组件。

已拍板(2026-09-04):
1. UI 接法用覆盖层(复制上游占位再逐文件链上我们的文件)。
2. ee 的装配是"包着上游 Bootstrap 的 Bootstrap":prepare → `s.Bootstrap` → attach;全局中间件挂 `s.Server.Handler`,不走 ServerCallbacks(上游硬编码传 `s`,换不掉)。
3. go.mod 用 fork 路径,上游 13 个模块 + fasthttp 共 14 行 replace 到本地。
4. **接受控制台进入企业模式**:覆盖层存在即 `IS_ENTERPRISE=true`,侧栏多 Proxy/Branding 菜单、License/Branding 页可进、Security 页多一区块、onboarding 多企业步骤、每次加载请求 `/api/branding`。这些位置正是后续功能要填的;骨架期补一个返回默认值的 `/api/branding`,差异清单逐项人工核过。

### 4.2 Bootstrap 的契约(Go)

```go
// ee/transports/bifrost-http/server
func Bootstrap(ctx context.Context, s *bifrostServer.BifrostHTTPServer) error {
	prepare(s)                                  // Bootstrap 前:s.ShellRewriter = lib.EEShellRewriter
	if err := s.Bootstrap(ctx); err != nil { return err }
	return attach(ctx, s)
}
```
attach 顺序:① `s.Config.ConfigStore == nil` → 返回错误(ee 要求 DB 模式);`db.AutoMigrate(&lib.Probe{})`;② `s.SyncLoadedPlugin(ctx, "ee-probe", &probePlugin{}, nil, nil)`;③ `handlers.NewProbeHandler(db).RegisterRoutes(s.Router)`、`handlers.NewBrandingHandler().RegisterRoutes(s.Router)`;④ `s.Server.Handler = handlers.EEHeaderMiddleware(s.Server.Handler)`。任一步失败 main 退出非零。

- `GET /api/ee/ping` → 200 `{"ok":true,"probe_rows":<int>,"plugin":"ee-probe"}`;无鉴权(骨架探针,文档注明正式路由须包 `s.AuthMiddleware.APIMiddleware()`)。
- `GET /api/branding` → 200 `{"enabled":false,"has_logo":false,"has_icon":false}`;无鉴权(上游设计如此)。
- `EEShellRewriter(ctx, data)`:`bytes.Replace(data, "</head>", `<meta name="x-bifrost-ee" content="1"></head>`, 1)`;无 `</head>` 时原样返回。
- main.go 与上游差异仅两处:embed 路径;`server.Bootstrap(ctx)` 改为 `eeServer.Bootstrap(ctx, server)`。Version 默认 `"v2.0.0-ee.0"`,ldflags 可覆盖。
