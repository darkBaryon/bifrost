### 立债(REF:立 `triggered_by: [ee包壳骨架]` 的需求进 reports/)

提议合并为**一个 L1 REF「ee骨架对齐上游建表与构建约定」**,在 B1 审计日志立案前完成(B1 是第一张真实表、第一个照抄样板的人):

1. **建表走上游迁移体系**。`attach` ① 改为 `configstore.RunSingleMigration(ctx, nil, db, logger, &migrator.Migration{ID: "ee_probe_v1", Migrate: func(tx) { return tx.AutoMigrate(&lib.Probe{}) }, Rollback: ...})`;ID 一律 `ee_` 前缀与上游步骤 ID 隔开;07 文档插座表第一行改写。收益:与上游同一张迁移表、可回滚、多副本部署与上游同一套锁语义。**反证条件**:若用户裁定 ee 表的生命周期必须与上游迁移表解耦(担心上游 `pendingMigrationStepIDs` 逻辑被 ee 条目干扰——实测它按显式 ID 列表查,`ee_` 前缀不会撞),则改用 ee 自己的 `migrator.Options{TableName: "ee_migrations"}`,但仍不裸 `AutoMigrate`;此条只降为改法,不作废。
2. **构建脱钩 go.work**。Makefile 的 build/test/smoke 前缀 `GOWORK=off`,`workspace` 目标只留给 IDE/gopls 与 `dev`;07 文档"日常命令"节同步。**反证条件**:若用户明确要 ee 的可执行文件与上游 `make build LOCAL=1`(同样在 go.work 下)保持同一依赖图,则 build 保留现状,但 test/smoke 仍应 off 以对齐上游 CI;若 `GOWORK=off` 下 `make -C ee smoke` 因 UI 构建以外的原因失败,则提议整体作废改记 Finding。

### 挂账(Finding:登记 findings.md,带四要件)

1. **FIND-012** `attach` 是被指定的惯性点:bootstrap.go:32,39-64 与 middlewares.go:14 已预告 B1/B2 都往这里加;现 4 步 64 行不构成问题。convert_when:B1 第二次往 attach 加"表+插件+路由+中间件"四件套时,先评是否拆成按功能注册(每个功能一个 `Register(s)` 文件,attach 只剩一个列表)。
2. **FIND-013** 探针残留会随二进制进生产:`ee_probe` 表(每次启动建、永不删)、`ee-probe` 插件、`/api/ee/ping`(无鉴权)、`X-Bifrost-EE` 头、`x-bifrost-ee` meta,散在 5 个文件。convert_when:第一个 B 功能落地或第一次对外构建前,决定"保留为健康探针并包鉴权"或"整体删除并配 Rollback 迁移"(依赖立债 1 的迁移体系才能删表)。
3. **FIND-014** main.go 抄本的同步只靠包注释一句话,无机械护栏;上游 main.go 近期两次实质改动(pprof、计时)说明会漂。convert_when:下次合并上游时若 main.go 有改动,在 checklist 加一条"上游 main.go 与 ee 抄本 diff 只允许 4 处已知 hunk"的检查(约 10 行脚本)。
4. **FIND-015** smoke.sh 依赖本机状态(个人 config.db、固定端口、按端口 kill、sqlite3/python3/lsof),仅能单人本机跑。convert_when:第二个人要跑或要进 CI 时,改为脚本自建最小 config.json(至少一个 provider)+ 动态端口 + 只杀自己起的 pid。
5. **FIND-016**(方案 §8 明示由收敛评审登记)`ServerCallbacks` 参数与 `RegisterAPIRoutes` 内三处 `callbacks.(XxxProvider)` 断言不可从 ee 替换(上游硬编码传 `s`);03 文档已订正。convert_when:任一功能(集群广播、日志脱敏映射、治理路由整体替换)需要这条通路时,向上游提 PR 加导出字段,而不是在 ee 内绕。
