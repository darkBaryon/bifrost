## 给用户的摘要

现状:企业级功能的落点(独立 `ee/`、不改上游)只是一个设想,没有一行代码验证过。做完:仓库里多一个 `ee/` 目录(内部路径镜像上游,骨架期只有 transports 一支),自己的可执行文件起在 8080,行为和 OSS 一样,外加三样"证明":一条自己的路由、一张自己的表、一个自己注册的插件;控制台的审计页面显示的是我们自己的占位组件而不是上游的"联系我们"。

需要拍板的三件事:

1. **UI 接法用"覆盖层"而不是整目录符号链接**。上游 `@enterprise` 别名要么全指向 `ui/app/enterprise`,要么全指向 `_fallbacks`,不会逐文件回退。整目录链接意味着 ee/ui 得复制上游 46 个占位组件并跟着上游改。覆盖层 = 先复制 `_fallbacks` 再把 ee/ui 的文件链上去,ee/ui 只放我们真改的文件。代价是多一个同步脚本。
2. **ee 的装配是"包着上游 Bootstrap 的 Bootstrap"**:`ee/transports/bifrost-http/server.Bootstrap(ctx, s)` = prepare(上游装配前要设的开关,骨架期为空)→ `s.Bootstrap` → attach(建表、挂插件、加路由、包 Handler)。全局中间件挂在 `s.Server.Handler` 上,不走 ServerCallbacks:核实过上游 Bootstrap 把 `s` 自己当 callbacks 传给 RegisterAPIRoutes,包壳换不掉;03 文档 §1.4 那一行说错了,本案顺手改正。
3. **ee 的 go.mod 用 fork 路径 `github.com/darkBaryon/bifrost/ee`**,上游 13 个模块全部 replace 到本地相对路径。这样在 go.work 之外也能独立构建。反面是每次上游新增插件模块要补一行 replace。

### 4.2 Bootstrap 的契约(Go)

```go
// ee/transports/bifrost-http/server
// 取代上游 main 里的 s.Bootstrap(ctx) 调用;内部原样调用上游 Bootstrap。
func Bootstrap(ctx context.Context, s *bifrostServer.BifrostHTTPServer) error {
	ctx = prepare(ctx, s)          // 骨架期空函数;B2 起在此设 IsEnterprise / 可选字段
	if err := s.Bootstrap(ctx); err != nil { return err }
	return attach(ctx, s)
}
```
attach 顺序:① `s.Config.ConfigStore.DB().AutoMigrate(&lib.Probe{})`,ConfigStore 为 nil 则返回错误(ee 要求 DB 模式);② `s.SyncLoadedPlugin(ctx, "ee-probe", &probePlugin{}, nil, nil)`;③ `handlers.NewProbeHandler(db).RegisterRoutes(s.Router)`;④ `s.Server.Handler = handlers.EEHeaderMiddleware(s.Server.Handler)`。任一步失败 main 退出非零。

main.go 与上游的差异仅两处:embed 路径指向 ee 自己的 ui 目录;`server.Bootstrap(ctx)` 改为 `eeServer.Bootstrap(ctx, server)`。Version 默认 `"v2.0.0-ee.0"`,ldflags 可覆盖。

### 4.4 UI 覆盖层(sync.sh)

```

for f in $(cd ee/ui/app/enterprise && find . -type f); do
  mkdir -p ui/app/enterprise/$(dirname $f)
```

### 4.5 构建与运行

- `make -C ee ui-sync`:上文脚本
- `make -C ee build-ui`:ui-sync → `cd ui && vite build` → `rm -rf ee/transports/bifrost-http/ui/* && cp -R $(UI_DIST)/* ee/transports/bifrost-http/ui/`,其中 `UI_DIST ?= ../ui/out` 是构建参数:将来自研前端只需把它指向新前端的产物目录,后端与 embed 逻辑不变(前后端只经 /api 通信,ee 功能一律 API 优先,页面不承载逻辑)
- `make -C ee build`:build-ui → `go build -ldflags "-X main.Version=v2.0.0-ee.0" -o ee/tmp/bifrost-http ./transports/bifrost-http`
- `make -C ee dev`:ui-sync → 后台 `cd ui && npm run dev`(3000,上游 vite 代理到 8080)→ 前台 `go run ./transports/bifrost-http -app-dir $HOME/.config/bifrost -log-style pretty`
- `make -C ee smoke`:build → scripts/smoke.sh

## 8. 风险与禁止事项

- **ServerCallbacks 不可替换**(Bootstrap 硬编码 `s`):本案改走 `s.Server.Handler`;03 文档 §1.4 的对应行改为"不可用,需向上游提 PR",并在收敛评审时登记 Finding。
- SyncLoadedPlugin 若落库:OSS 二进制再读同一 config.db 会见到未知插件 `ee-probe`,上游对内置名以外的加载失败是记状态不阻断(plugins.go:286-342),风险低,T5 观察后定。
- 覆盖层用 `cp -R`:上游 fallbacks 更新后自动跟随,但 ee/ui/src 与 fallbacks 同名文件的接口签名漂移只能靠 `tsc` 兜底。
- 禁止:改上游文件(含上游 Bootstrap);`ee/` 内出现对 `IsEnterprise` 的设置;写任何非 `ee_` 前缀的表;在 ee/ 内发明与上游不同的目录名或包名。
