## 给用户的摘要

从当前提交重构整个 EE 后端，包含品牌、定价和内容安全，usage 除外。
现在业务依赖藏在认证适配、策略回调、共享 core 和辅助函数中；目标是业务入口直接写出查询、检查和写入的顺序。
保留正常 Store 接口与跨服务事务，删除不必要的策略转换和业务对象工厂。
本文给出具体模块、文件、接口和操作流程，整体仍为设计稿，尚未通过正式评审。用户另行授权的 BF 接入口及 EE 接线迁移已在工作区实施，范围见第 12、13、14 节；其余设计尚未实施。第 12 节保留第一批结束时的历史状态，当前接线以第 13、14 节为准。
已确认方向见 [整体架构](../../../../product/架构/EE后端架构.md)；本文补充建议及待确认项集中在第 11 节。

## 3. 模块与文件安排

### 3.1 文件按业务阅读顺序组织（本轮建议）

根包承载业务操作及其小型依赖接口，HTTP 和数据库实现单独放置。一个业务文件可以同时定义入参、小接口、相关错误和辅助函数；不建立每个模块都有的 `service/model/repository` 三层目录。

| 位置 | 建议放置内容 |
|---|---|
| `account/accounts.go` | 创建、列表、启停、删除；相关参数和 Store 能力 |
| `account/passwords.go`、`events.go` | 本人改密、管理员重置、密码事件查询 |
| `account/initialize.go`、`recovery.go` | 首次初始化、旧账号导入、离线恢复 |
| `account/http/`、`account/persistence/` | 账号和密码接口；账号、初始化状态、事件的数据库实现 |
| `auth/login.go`、`authenticate.go` | 登录全流程；会话与账号联合结果的身份验证 |
| `auth/http/middleware.go`、`handler.go` | 公共认证中间件、登录/退出/当前身份入口 |
| `auth/persistence/` | 登录限流和认证专用联合查询；只读账号/会话投影，不承担其写入 |
| `session/sessions.go`、`tickets.go`、`persistence/` | 创建/撤销/清理会话，签发/消费票据，各自数据库操作 |
| `rbac/roles.go`、`assignments.go`、`permissions.go`、`authorize.go` | 角色规则、角色分配、权限目录、权限判断 |
| `rbac/http/`、`rbac/persistence/` | 管理接口及公共权限中间件；角色数据存储 |
| `host/routes.go`、按 BF 业务命名的接入文件 | BF 路由权限声明、具体类型转换、控制台基础信息和 WS 接入 |
| `app/bootstrap.go`、各模块装配文件 | 启动依赖顺序、迁移、构造和注册 |

这是一份职责落点，不是必须提前创建的文件清单。内容很少的相邻操作可以在一个文件中；文件变大后按完整业务能力拆分。session 没有用户直接管理会话的既有页面，不为对称新增 session CRUD API。

### 3.2 Go 依赖和构造顺序（本轮建议）

```text
各模块 http/persistence → 对应业务包
auth                   → 认证联合查询、account 凭据/登录时间存储、session 签发能力
account                → session、rbac 的公开操作
rbac                   → 自己的 Store（含明确的账号存在性只读查询）
session                → 自己的 Store
app                    → 具体 Store、Service、HTTP 与 BF 接入实现
```

account 和 rbac 不 import auth。它们需要事务内复核会话时，在各自使用处声明小接口，由 auth.Service 隐式实现。auth 读取 account 数据和类型，不持有 AccountService。rbac 的只读账号投影只取存在性等实际需要的数据，不反向依赖 account.Service。

推荐构造顺序为：数据库与 Store → session → auth → rbac → account → 中间件/Handler → 注册。账号读写 Store 先于 AccountService 存在，auth 也不依赖 rbac（WS 授权在 host 的具名入口执行），因而不产生运行时构造环。各具体 Store 依赖业务包的模型和接口，业务包不反向 import 自己的 persistence 子包。

## 4. 接口和事务（普通 Store 与显式事务已确认，其余接口草图按批落实）

### 4.1 使用普通 Store 接口，显式传事务

建议允许业务入口接触 GORM 的事务句柄。以下仅表示接口形状；名称和完整方法集需随实施核对，不表示代码已经存在：

```go
// account 包：普通 Store 接口；persistence 实现它。
type Store interface {
    WithTx(tx *gorm.DB) Store
    Account(ctx context.Context, id string) (Record, error)
    UpdatePassword(ctx context.Context, id string, change PasswordUpdate) error
    DeleteAccount(ctx context.Context, id string) error
    InsertPasswordEvent(ctx context.Context, event PasswordEvent) error
    // 其余本模块确实需要的读写方法。
}

type PasswordUpdate struct {
    Hash               string
    ExpectedVersion    int64
    MustChangePassword bool
}

// account 消费方接口；auth.Service 实现。返回类型为小型会话身份值。
type SessionVerifier interface {
    ValidateSession(ctx context.Context, tx *gorm.DB,
        claimed session.Principal) (session.Principal, error)
}

// 参与调用者事务的方法不开始、提交或回滚另一个事务。
// session.Service
RevokeAccountSessions(ctx context.Context, tx *gorm.DB, accountID string) error
DeleteAccountSessions(ctx context.Context, tx *gorm.DB, accountID string) error

// rbac.Service
RemoveAccountRoles(ctx context.Context, tx *gorm.DB, accountID string) error
AssignAdminRole(ctx context.Context, tx *gorm.DB, accountID string) error
```

`session.Principal` 只承载账号 ID、会话 ID、认证版本和强制改密标志；认证结论由 auth 产生，session 不因此承担账号校验。复验同时核对声明的账号 ID、会话 ID、认证版本，强制改密状态以当前数据库为准。HTTP 上下文中的身份由服务器填充，不从请求 JSON 反序列化一个 Principal 当作认证结果。

`WithTx` 返回持有当前连接的 Store 副本，不改变共享 Store。事务参数不能为空，不能遇到 nil 自动改用全局连接。只绑定数据访问对象，不构造新 Service、不重新注入策略。纯读取方法仍可使用服务持有的普通 Store。

业务入口用常规 `db.WithContext(ctx).Transaction(...)` 表达开始/提交/回滚。只有该入口有提交权；参与者方法复用传入事务。HTTP Handler 不开启跨服务事务，`app` 也不成为运行期协调服务。

第三批已确认普通 Store 和显式事务，并同步放宽旧规范“业务层不得接触 GORM”的限制。业务方法明确依赖事务句柄，SQL 仍在持久化层。`database.Write` 只复用现有写锁与 SQLite 重试，不引入事务版服务或策略工厂。

### 4.2 业务入口如何读

以下为顺序伪代码，省略重复的错误返回和已列出的参数校验：

```text
account.DeleteAccount(ctx, claimedIdentity, accountID)
    参数检查
    开事务
        auth.ValidateSession（通过注入的小接口，同一 tx）
        rbac.AuthorizeInTransaction(UsersManage)
        校验本人删除限制与固定恢复账号限制
        AccountStore.Account(accountID)
        rbac.RemoveAccountRoles(tx, accountID)
        session.DeleteAccountSessions(tx, accountID)  // 明确包含该账号的票据
        AccountStore.DeleteAccount(accountID)         // 只删账号；保留事件
    提交
```

不再出现 `BeforeDelete`、`Tx.AccessPolicy()`、`policyFactory`。跨模块调用的返回错误就地处理，写入失败一起回滚。`DeleteAccountSessions` 的名称及注释明确会清理附属票据，不能继续由 account Store 偷做。

### 4.3 并发与一致读取

- 普通接口认证沿用一次 JOIN 读取账号和会话的做法，检查状态、过期、撤销和认证版本。事务本身不自动等于一致快照，不能以“两个查询在一个事务里”为由移除 JOIN。
- 登录在事务外比较密码，在事务内重新核对账号状态、版本和摘要，再创建会话；bcrypt 不长时间占用写事务。
- 密码和状态更新保留版本约束；与删除账号、分配角色、创建会话的并发一致性需有明确锁或条件更新。
- 首次替换默认保留现有数据库写锁及顺序，去掉最后管理员的业务检查；不把“取消管理员保护”误写成“所有锁都可删除”。后续缩小锁范围需独立证据。
- SQLite busy 重试只包围可安全重试的数据库事务，事务回调不得包含外连或内存发布。共享的少量重试工具建议放 `internal/database`，消除 guardrails 对 identity.persistence 的技术依赖；不扩为数据库框架。
- 密码哈希并发限制全进程只构造一份，供登录、创建、改密、重置和恢复复用。

## 5. 账号、认证、会话和权限的完整流程

### 5.1 操作归属与副作用

| 操作/所属模块 | 事务外准备 | 同一事务内的主要动作 |
|---|---|---|
| 登录 / auth | 输入和登录频率检查；读取凭据；未知账号使用假摘要比较；校验密码 | 重读状态/版本/摘要 → session 创建会话 → account Store 更新最近登录时间 |
| 创建账号 / account | 参数和权限预检；计算初始密码哈希 | 会话及权限复核 → 唯一性检查 → 插入需改密账号 |
| 启用/停用 / account | 状态参数检查 | 会话及权限复核 → 既有本人操作限制 → 读取目标 → 实际变化才更新状态/版本并撤销会话 |
| 本人改密 / account | 验证旧密码，计算新哈希 | 会话复核、确认旧摘要未变化 → 更新凭据 → 撤销会话 → 插入成功事件 |
| 重置密码 / account | 权限预检通过才计算哈希 | 会话复核 → 查询幂等事件 → 权限及目标校验 → 改凭据 → 撤销会话 → 写事件；失败分支见下一节 |
| 删除账号 / account | 参数检查 | 会话与权限复核 → 既有限制和目标检查 → 清理角色 → 清理会话/票据 → 删除账号 |
| 首次初始化 / account | 初始化令牌和输入校验，计算哈希 | 再确认未初始化 → 建账号 → 标记初始化 → AssignAdminRole |
| 导入旧管理员 / account | 读取 BF 旧账号和已有哈希 | 确认未导入 → 原样存账号与摘要 → 标记初始化 → AssignAdminRole |
| 离线恢复 / account | CLI 操作入口；读取恢复目标；计算哈希 | 恢复账号状态 → 改凭据 → 撤销会话 → 分配管理员角色 → 写恢复事件 |
| 分配角色 / rbac | 角色 ID 规范化 | 会话/权限复核 → 目标账号存在 → 角色存在 → 既有本人修改限制 → 更新角色关系 |
| 签发 WS 票据 / host 的 WS 入口 | 来源和协议检查 | auth 会话复核 → rbac 通知权限检查 → session 签发 |
| 消费 WS 票据 / host 的 WS 入口 | 票据形状和来源检查 | session 原子消费 → auth 联合查询复核 → rbac 通知权限检查；失败回滚 |

跨模块写入在入口逐项列出。本人改密、重置、恢复各有业务入口，不再共用一个暗中写事件/撤销会话的 replacePassword。共同凭据字段更新由 Store 保证，密码规则由明确的校验函数复用。

退出登录仍保持对失效/不存在会话的幂等处理。普通认证会返回强制改密标志；只允许改密、退出和获准的基础资料入口。需要完整管理会话的操作明确检查该条件，不能把 Authenticate 写成统一拒绝所有需改密账号。

### 5.2 重置密码失败事件

现状会保存部分业务失败事件，并按 `operation_id + 操作者 + 目标` 识别重放。简单在路由外新增一个直接返回 403 的授权中间件，会跳过这段业务，改变现有行为。

建议该路由使用公共认证和来源检查；需要留存失败事件的授权判断由 `account.ResetPassword` 直接调用同一个 RBAC 服务。路由权限声明明确标记由业务执行授权，不把它当成公开或免授权接口。这是针对既有事件语义的具名例外，不建设通用授权工作流框架。

```text
事务内
    验证会话，查是否已有相同操作结果
    调用 RBAC，校验目标账号及重置限制
    若是需要留痕的业务失败：只插入失败事件，保存待返回业务错误
    若成功：更新密码 → 撤销会话 → 插入成功事件
提交成功后，才向调用方返回保存的业务错误或成功
```

数据库故障回滚，不伪造失败事件已保存。哪些失败会记录、未认证请求如何响应，以及预检后权限变化但尚未计算哈希的冲突返回，都以基线行为测试核对，不能借重构默默更改。

### 5.3 RBAC 的边界

- `Authorize` 只处理真实权限码，不再经过 AccountAction 枚举。权限中间件与业务中的事务复核调用同一套权限计算逻辑。
- 角色管理、账号角色分配和当前权限查询继续是独立 HTTP 能力；业务权限与 HTTP 中间件不是同一个职责。
- 取消 `remainingChief` 和最后一个可用主管理员检查，不保留空的 BeforeDisable/BeforeDelete 钩子。
- 角色 ID 存在性、角色仍有关联时的删除约束、系统角色属性规则不是“最后管理员保护”的同义词，仍按现有规则处理。
- 账号删除必须显式清理角色关系。现有账号角色表没有指向账号的外键，不能靠删账号自动实现清理。
- 初始化和恢复直接调用 AssignAdminRole；不会把其他模块的业务注册到 rbac 或 auth 的 HTTP Handler 里。

### 5.4 API 归属和兼容建议

包拆分默认保持现有路径、字段、错误码和 Cookie 行为；路径中的 identity 不要求与 Go 包名同步改。旧 alias 在所属 Handler 显式注册，删除 OwnsRoute/AdditionalRoutes 分流协议。

| 现有入口 | 新代码归属 |
|---|---|
| `/api/identity/login`、`logout`、`me` 及既有 session alias | auth/http |
| `/api/identity/status`、`initialize`、`change-password`、`password-events` | account/http；状态聚合只返回所需配置/初始化字段 |
| `/api/accounts/*` | account/http |
| `/api/identity/ws-ticket`、既有 WS ticket alias、`/ws` | 明确的 WS 接入文件调用 auth/rbac/session；保留 BF 长连接实现 |
| 角色、权限目录、角色分配接口 | rbac/http；以基线路由表逐项登记，不借会话接口注册 |
| 工作台基础信息接口 | host/console；有效会话即可读取获准基本信息，完整配置仍需 Settings.View |

临时凭据、OAuth、VK 自服务与推理接口继续由对应协议负责。公开品牌读取不是全局匿名放行规则；受保护写接口仍声明权限。

## 6. 品牌、国内定价和内容安全

以下均为本轮新增的具体落法，尚待确认。它们属于本次范围，并非留待以后处理的保留区。

### 6.1 品牌：把图片业务放回模块

建议 `branding/settings.go` 定义 Service 和小 Store 接口，`image.go` 保留完整解码与图片规则，`http/` 负责 JSON 和响应，`persistence/` 负责单行部分更新。

```text
HTTP 解码（保留字段是否出现）
  → branding.UpdateSettings
      检查两张图片及大小/尺寸
      计算内容 hash
      一次原子写入本次修改
  → HTTP 转响应

GET 图片 → branding.GetAsset(slot, hash)
         → 确认当前资源存在且 hash 匹配
         → HTTP 处理 Content-Type / ETag / 304 / 缓存头
```

Service 拥有图片业务和资源选择，不是给 Store 再加一个空转发壳。业务 Settings、修改参数和图片结果归 branding 根包，数据库行留 persistence，Service 不返回 persistence.Settings。省略字段表示不变、空字符串表示清空、null 拒绝；两张图片校验全部成功才写入。保留 PNG/JPEG、base64/data URI、完整解码、体积尺寸限制和原图字节，不顺带重编码。

保持 SHA-256 资源地址、旧 hash 的 404、现有 ETag 和缓存语义。每次读数据库，不引入本地缓存改变多实例可见性。品牌迁移失败阻止启动；借用共享 DB，不新增运行时关闭对象。

### 6.2 国内定价：显式同步计划和副作用

保留根包的价格规则。将 `persistence/store.go` 中的覆盖行读写留在 persistence，provider 读取和本节点 catalog 更新移到 `pricing/host/providers.go`、`catalog.go`。app 注入这三种窄能力。

建议新增普通数据结构 `SyncPlan`：分别列出待创建、更新、保留、删除及受保护的覆盖记录。计算计划不修改调用方传入的 map；执行阶段不靠“前一函数偷偷删了 map 元素”推断要删除什么。

```text
pricing.Sync
    读取 provider 与现有覆盖
    匹配厂商、计算价格，形成明确 SyncPlan
    顺序执行覆盖行写入与删除
    全部数据库操作完成后
        更新本节点 catalog
    返回实际完成数量与未识别厂商
```

计划只是此次同步的数据结果，不引入通用任务或执行器。创建和更新按全部期望记录的统一 ID 顺序执行，然后删除；catalog Upsert 包含未变化的有效记录，排除受保护记录，不能只发布新增和更新项。保留确定性 ID、记录归属校验、完整字段比较、创建冲突后更新、删除不存在视为成功。只有名称前缀和 ID 都满足规则的记录归本功能管理。

现状允许数据库部分成功，下次启动继续收敛；本次不假装它具有跨数据库和内存的原子事务。启动策略也保持：非法汇率/映射和同步配置错误拒启；价格文件读取或校验失败、普通同步错误记录后继续；缺 catalog 跳过。核对原验证顺序，避免重排后改变失败结果。

只在启动同步，没有后台周期任务和 HTTP 管理入口；新增这些能力需要产品决定。

### 6.3 内容安全：配置管理与检测执行分开

根包继续承载规则和 Checker。现有 `guardrails/config` 是具体配置能力，建议在该包加入 `service.go`，提供 Get/Update/Reset；不再由 HTTP Handler 持有更新 mutex。

`config.Service` 依赖小 Store、Checker Builder、Publisher 接口。数据库实现返回配置能力的结果类型，Builder 的具体检测器/BF 装配位于 host，Publisher 由 plugin 实现。config 不 import plugin 或 persistence，避免循环；启动和在线更新共用构建逻辑，启动不伪装成一次带版本写入的 Update。

具体类型归属：`State`、未配置/版本冲突错误由 config 定义，persistence 负责数据库行转换；Publisher 草图为 `Publish(*guardrails.Checker, config.Deny) error`，接口在 config 内声明时直接使用 Deny。plugin/persistence/host 依赖 config，config 依赖检测根包；不得把现有 plugin.Options 或 persistence.Row 原样放入配置服务签名。

```text
配置 Handler → config.Service.Update(rawJSON, expectedVersion)
    校验配置并构建完整 Checker
    取得配置更新锁
        CAS 写库
        发布 Checker 与拒绝策略的完整快照
    返回配置和版本

BF 插件 → 请求前取得一次运行快照 → Checker 执行规则
        → 返回时使用同一快照；fallback 仍沿用该快照
```

配置 JSON 原文、版本、未配置及 Reset 幂等语义不变。构建失败、版本冲突或存储失败不改变运行状态；保存成功但发布失败如实返回“已保存、未激活”，不声称已回滚。Reset 先成功清除存储，再关闭运行配置；关闭失败返回“已清除、未停用”，不能返回成功。

现有开发假检测模式只禁止 update，reset 仍可停用；如要禁止全部写入，应作为额外行为改变。本机 mutex 只保证本进程更新顺序，CAS 保护数据库版本，不把它描述为所有实例同步热更新。

保留插件在缓存前执行、judge 子请求避免递归、拒绝不触发 fallback、输出检测启用时提前拒绝不支持的流式请求。判官与密钥检测的输入范围、推理文本合并和失败处置规则按现有行为迁移，不因拆包改变检测结论。

启动读取配置发生存储错误、已保存配置无法解析/构建、迁移或插件装配失败均拒启；假检测模式与已保存配置同时存在也拒启；只有确认未配置才透传。旧快照随请求引用结束回收，不增设管理所有模块的运行时框架。共用限制常量归到真正的共同类型/规则位置，减少“复制一份并注明保持同步”。
