## 4. 接口与数据设计

### 4.1 存储、迁移与并发

新增 `ee/framework/configstore/tables/branding.go`：`Branding` 单例，表名 `ee_branding`，主键 ID 固定为 1；Logo/Icon 的二进制数据、MIME、SHA-256 和 UpdatedAt。二进制使用 GORM 对 SQLite BLOB / PostgreSQL bytea 的映射，不写磁盘图片文件。
新增 `ee/framework/configstore/branding.go`：BrandingStore，Read(ctx)、Update(ctx, patch)、Reset(ctx)。字段省略/清空由指针区分；null 拒绝。Update/Reset 均在数据库事务内完成写入和返回状态读取；读失败回滚，提交失败返回错误，成功提交后只发送已取得的状态，不能再读库造成已写入但报读取失败。网络在提交后中断无法保证客户端收到响应，此时页面保留草稿，重试前重读当前状态；不承诺网络失败意味着数据库未改动。Upsert 只更新请求显式包含的槽位，避免两个客户端分别修改 Logo/Icon 时互相抹除；同槽位最后成功写入胜出。单条写语句原子更新两个槽位；两图先全部校验再写；Reset 更新为两个空槽位而非删除单例，幂等。
迁移 `ee_branding_v1` 位于 `ee/framework/configstore/migrations.go`，通过 ConfigStore.RunMigration 获取回调连接；回调对所有方言调用一次 `db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {...})`，外层是唯一事务所有者。复制 `opts := *migrator.DefaultOptions` 并显式 `opts.UseTransaction = false`，将同一个 tx 与 &opts 交给 RunSingleMigration，不修改全局默认。PostgreSQL 在此外层事务先 `SET LOCAL lock_timeout = '10s'`，再 `SELECT pg_advisory_xact_lock(8342761901)`，成功后才做版本检查、DDL、空单例插入和版本记录。SQLite 不执行 PG SQL，使用同一个外层事务和文件锁。所有错误返回外层统一回滚；只有外层提交成功才算迁移成功。锁超时、取消、SQLite busy 均启动失败，不监听，可重试。迁移只新增 ee_branding；同 ID 已成功时不重新种子或清空图片。
沿用 migrations 版本表。该专用锁只协调本功能，不宣称替代上游或其他功能的全局迁移锁。为本案新表进行首次迁移，不改运行时已查询的其他表；不额外刷新全局运行连接池。

Rollback 函数只定义删除本案表的能力，运行时不自动调用；实际回退优先旧程序忽略新表、保留图片，需删除数据时另获用户授权。

### 4.2 HTTP 契约

`NewBrandingHandler(store *BrandingStore)`；`RegisterRoutes(router, authMiddleware)` 要求非 nil 写鉴权中间件，启动装配确保它存在。

| 方法与路径 | 认证 | 成功行为 |
|---|---|---|
| GET /api/branding | 公开 | 200 BrandingState；未配置三项 false，省略 URL |
| PUT /api/branding | APIMiddleware | JSON BrandingPayload 合并更新，200 完整 BrandingState |
| DELETE /api/branding | APIMiddleware | 清空全部覆盖，200 默认状态，可重复执行 |
| GET /api/branding/assets/{slot}/{hash} | 公开 | slot 仅 logo/icon；当前内容与 hash 一致时 200 图片，否则 404 |

BrandingState 保持 `enabled/has_logo/has_icon/logo_url/icon_url/updated_at`；has_icon 指实际独立小图标，Logo 回退由 UI 完成，不伪造 has_icon。URL 是 `/api/branding/assets/logo/<sha256>` 等，hash 根据图片内容计算；同内容重传 URL 不变。公开 JSON `Cache-Control: no-store`；图片仅返回实际 PNG/JPEG 类型、`X-Content-Type-Options: nosniff`、ETag 与 `Cache-Control: public, max-age=0, must-revalidate`，先检查 slot/当前 hash 有效，再判断 If-None-Match 返回 304；清除或替换后旧 ETag 不得续用旧图片。清除后旧 URL 不再提供旧图（已存在浏览器内的历史副本无法回收）。不返回数据库字段/错误原文。

PUT 省略槽位保留、空字符串清除、非空 base64（或 data URI）替换；单独 MIME 无数据、null、未知字段、非字符串、额外 JSON 值、空对象均 400。MIME 可省略并从图像内容确定，若提供或 URI 声明则须与实测一致。支持 image/png、image/jpeg，拒绝 SVG/GIF/WebP；每图解码后 ≤1 MiB，JSON body ≤3 MiB；单边 ≤4096 像素，总像素 ≤400 万且非零。先限制请求/编码长度再 base64 decode，再 DecodeConfig 限制尺寸，最后完整 decode 确認有效图像；不信扩展名或 MIME。超限 413，格式/尺寸不合法 400，存储失败 500，失败前后旧图和版本保持一致。此 3 MiB 是 handler 解码前限制；上游 fasthttp 在进入 handler 前已按 ClientConfig.MaxRequestBodySizeMB 接收请求（基线默认 100 MiB），故不声称网络接收峰值仅 3 MiB。若运维设更小的全局限制，上游可能先拒绝；本案不改该全局配置。日志不含图片 base64 或管理员凭据。

读库失败返回 500，不冒充“未设置”；页面禁止保存/重置并提供重试。图片查不到返回 404，非法 slot/hash 同样 404；方法精确注册，不被 SPA HTML 兜底代替。
