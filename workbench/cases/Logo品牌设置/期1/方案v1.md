## 4. 接口与数据设计

### 4.1 存储、迁移与并发

新增 `ee/framework/configstore/tables/branding.go`：`Branding` 单例，表名 `ee_branding`，主键 ID 固定为 1；Logo/Icon 的二进制数据、MIME、SHA-256 和 UpdatedAt。二进制使用 GORM 对 SQLite BLOB / PostgreSQL bytea 的映射，不写磁盘图片文件。
新增 `ee/framework/configstore/branding.go`：BrandingStore，Read(ctx)、Update(ctx, patch)、Reset(ctx)。字段省略/清空由指针区分；null 拒绝。Upsert 只更新请求显式包含的槽位，避免两个客户端分别修改 Logo/Icon 时互相抹除；同槽位最后成功写入胜出。单条写语句原子更新两个槽位；两图先全部校验再写；Reset 更新为两个空槽位而非删除单例，幂等。
迁移 `ee_branding_v1` 位于 `ee/framework/configstore/migrations.go`，通过现有 ConfigStore.RunMigration 回调调用 RunSingleMigration，沿用 migrations 版本表、复制 DefaultOptions 后使用，不修改全局 Options。迁移创建表与空单例，事务失败向上传播，启动失败即不监听；重复启动不重置数据。只增 ee 表，不修改现有业务表。PostgreSQL 在该回调的同一连接/事务内取得本功能专用事务 advisory lock（固定 int64 常量 8342761901，锁超时 10s），再运行迁移，避免本功能并发建表；SQLite 依靠事务和文件锁，忙则启动失败后可重试。不宣称完成整个 ee 的共享迁移协调。
Rollback 函数只定义删除本案表的能力，运行时不自动调用；实际回退优先旧程序忽略新表、保留图片，需删除数据时另获用户授权。

### 4.2 HTTP 契约

`NewBrandingHandler(store *BrandingStore)`；`RegisterRoutes(router, authMiddleware)` 要求非 nil 写鉴权中间件，启动装配确保它存在。

| 方法与路径 | 认证 | 成功行为 |
|---|---|---|
| GET /api/branding | 公开 | 200 BrandingState；未配置三项 false，省略 URL |
| PUT /api/branding | APIMiddleware | JSON BrandingPayload 合并更新，200 完整 BrandingState |
| DELETE /api/branding | APIMiddleware | 清空全部覆盖，200 默认状态，可重复执行 |
| GET /api/branding/assets/{slot}/{hash} | 公开 | slot 仅 logo/icon；当前内容与 hash 一致时 200 图片，否则 404 |

BrandingState 保持 `enabled/has_logo/has_icon/logo_url/icon_url/updated_at`；has_icon 指实际独立小图标，Logo 回退由 UI 完成，不伪造 has_icon。URL 是 `/api/branding/assets/logo/<sha256>` 等，hash 根据图片内容计算；同内容重传 URL 不变。公开 JSON `Cache-Control: no-store`；图片仅返回实际 PNG/JPEG 类型、`X-Content-Type-Options: nosniff`、ETag 与 `Cache-Control: public, max-age=0, must-revalidate`，匹配 If-None-Match 返回 304。清除后旧 URL 不再提供旧图（已存在浏览器内的历史副本无法回收）。不返回数据库字段/错误原文。

PUT 省略槽位保留、空字符串清除、非空 base64（或 data URI）替换；单独 MIME 无数据、null、未知字段、非字符串、额外 JSON 值、空对象均 400。MIME 可省略并从图像内容确定，若提供或 URI 声明则须与实测一致。支持 image/png、image/jpeg，拒绝 SVG/GIF/WebP；每图解码后 ≤1 MiB，JSON body ≤3 MiB；单边 ≤4096 像素，总像素 ≤400 万且非零。先限制请求/编码长度再 base64 decode，再 DecodeConfig 限制尺寸，最后完整 decode 确認有效图像；不信扩展名或 MIME。超限 413，格式/尺寸不合法 400，存储失败 500，失败前后旧图和版本保持一致。请求体限制也须与 fasthttp 上游限制核对。日志不含图片 base64 或管理员凭据。

读库失败返回 500，不冒充“未设置”；页面禁止保存/重置并提供重试。图片查不到返回 404，非法 slot/hash 同样 404；方法精确注册，不被 SPA HTML 兜底代替。

### 4.3 UI

新增 `ee/ui/app/enterprise/components/branding/brandingView.tsx` 和该组件内部子组件（必要时同目录拆分）；共享 Zod schema 放 `ee/ui/app/enterprise/lib/schemas/branding.ts`，符合 ee 覆盖位置。复用现有 Button/Input/AlertDialog、react-hook-form、Zod、RTK mutation；不添依赖。
加载中显示加载状态；读取失败显示页内错误及重试。Logo、小图标有格式/大小提示、选择/替换/移除按钮和文件错误；文件选择失败保留原草稿。不同主题预览同份图，草稿显示不影响实际侧栏；异步读文件以递增请求号防旧回调覆盖新选择；取消选择不改变草稿；对象 URL 在替换/卸载后释放。
保存只发送脏槽位，未改动禁用；读文件/保存/重置期间禁用变更动作，避免旧请求覆盖新草稿；成功清草稿并使用返回状态与 Branding 标签刷新，失败保留草稿和旧已保存图。恢复默认确认取消不变，确认成功清除草稿；当前为空时禁用重置。离开页面未保存草稿丢弃，不承诺跨页面草稿恢复。所有新增交互带 branding-* data-testid，中文可读文案。
共享源修改白名单仅 `ui/lib/hooks/useBranding.ts` 的 iconSrc 回退：独立 icon → 自定义 Logo → 按主题的默认 icon，附相邻行为测试 `ui/lib/hooks/useBranding.test.ts`。不用复制整个 sidebar/hook 到 ee，不改展示布局；OSS 无 branding 数据时结果保持原状。此为旧骨架“不改上游文件”边界的明确例外，须 Gate 1 确认。
