## 可证伪质疑

### 代码阻塞项

无。

### Gate 2 验收阻塞（不以代码通过解除）

1. **PostgreSQL 未验证。** 实际 migrations_test.go 只构造 SQLite；没有 PG 双连接并发初始化、锁超时/取消释放、失败回滚及重试证据。方案 v2 §6 明确要求取得隔离实例完成验证，或由用户明确缩小交付范围、登记 PG 能力未交付；两者之一发生前仍阻塞 Gate 2。不能把源码上正确的事务顺序或 SQLite 成功视为 PG 已通过。
2. **浏览器上传主路径缺口。** 现有证据明确通过 API 预置图片，chooser.setFiles 被扩展拒绝；文件选择、有效图读入草稿、取消选择及损坏文件提示尚未通过真实交互验证。当前新增 Vitest 仅覆盖 hook，不覆盖 FileReader、表单和 RTK mutation 状态协作。补测这些验收项并保留证据后才能声称浏览器验收完成；本轮依照评审分工没有启动浏览器。

### 建议（不阻塞代码评审）

1. UI schema 允许 `file.type === ""`，readAsDataURL 的结果却直接作为上传值。建议补测无 MIME 的有效 PNG/JPEG：若浏览器生成 application/octet-stream data URI，服务端会按声明 MIME 不匹配拒绝。该边界应统一成明确拒绝，或让上传载荷省略未知 MIME；不要降低服务端真实图片校验。
2. hook 原有注释仍称图片使用 long max-age、首屏由服务端品牌重写覆盖，与本案 max-age=0 及已披露首屏边界不一致。这是基线注释旧债；本案不应为此扩大获批的共享源码白名单，但后续整合宜清理，开发指南已给出正确口径。
