## 4. 接口与数据设计

**zhLocale.ts 增量**(唯一改动的既有文件,三处):

```ts
// ① RULES:四字段对象,skeleton/sample 供 scanner 与 self-test 机械互证(评审2-3.1.1)
type ZhRule = {
  re: RegExp;        // 锚定 ^…$;禁止 (.+) 级全泛化捕获;上限 100 条
  out: string;       // 译文模板($1..$9);不得保留可再匹配的英文锚
  skeleton: string;  // scanner 侧骨架声明:与"模板字面量归一化"(所有 ${…} → ⟨x⟩)完全同构
  sample: string;    // 自测样例:必须命中 re 且恰中此一条
};
const RULES: ZhRule[] = [
  { re: /^(\d+) model budgets?$/, out: "$1 个模型预算",
    skeleton: "⟨x⟩ model budget⟨x⟩", sample: "3 model budgets" },
  // 首批规则输入 = 步骤1 清单第④类;skeleton 全表唯一
];

// ② translateRaw:精确 DICT → 小写兜底 → RULES 顺扫首中即停
//    收敛契约:任何路径 结果===输入 → null;固定点断言强制"输出再入必 null"

// ③ walk 属性通道(:313)改走 translateRaw;
//    observer.observe 增加 attributes: true, attributeFilter: ATTRS,
//    回调加属性分支(契约①天然防属性回写环)(评审2-N1)
```

### 独立代码复核(verdict:需修改,阻断 2 条)

复核代理对实际 diff、self-test、DICT/RULES 全量做了程序化复验,发现:

1. **[阻断] channel①(原①b)存在系统性提取盲区**:只处理"同行 `>text<`"与"紧邻单行独立文本"两种模式,遗漏"多行连续纯文本、被闭合标签终止"这一常见 JSX 写法——真实 DOM 会把跨行纯文本折叠为单个文本节点,但 scanner 只取第一行当 key,字典条目系统性截断。复核实测 5 处直接验证 + 71 处高度疑似,覆盖面广(安全设置/MCP注册表/可观测配置/供应商表单/虚拟密钥表单等几乎每个设置页)。
2. **[阻断] 实施偏差记录里"旗舰样例(`providerConfigCard.tsx:186`)已验证运行时正确"的结论经不起复验**:复核用 scanner 自带的 `parseZhLocale`/`makeTranslate` 直接对生产 32 条 RULES 求值 `"3 model budgets"`,结果为 `null`——**RULES 数组里根本没有覆盖这个骨架的规则**,此前记录的"已验证正确"是未经复验的错误结论。附带发现:self-test 的固定点/互证/sample 恰中三项断言只测了孤立硬编码的样板规则,从未触达真实 RULES,这个安全网此前是空转的。

复核判定 checklist 可执行、1988 词条抽样质量扎实(无重复键、无误译)、机制设计与方案接口一致——问题集中在"两处真实实现缺陷"而非架构性偏差。

### 阶段B:修复(commit `b1ebd61`)

针对复核发现,逐项修复并**回源码精确复验**(不满足于自证,每处结论都能用命令重放):

1. **channel①c 重写**:原"同行匹配 + 单行独立文本"改为状态机式多行聚合——起点为"上一行以 `>` 收尾(且排除 `=>` 误判)",逐行累积直到遇到 `<`/`{`/`}`/`` ` `` 边界字符,按 JSX 空白折叠规则(换行+缩进→单空格)拼接。
2. **回归修复**:重写过程中意外发现箭头函数 `onCopy={() =>` 末尾的 `>` 被误判为 JSX 标签闭合符,导致跨行聚合吞并整段多行 JS 表达式(`JSON.stringify(...)`)。改用 `(?<!=)>$` 排除,并把右花括号 `}` 补进边界字符集(原来只挡 `<{` `` ` ``,右花括号未被识别为边界)。加了专项回归防护断言。
3. **self-test 互证改为跑真实生产数据**:固定点/互证/sample 恰中一条三项断言,从"对局部硬编码样例做单例断言"改为"对 `parseZhLocale` 解析出的**全部**生产 RULES 做 `.every()` 遍历"——这才是真正接到生产数据上的安全网,以后谁改坏一条规则,self-test 会报错。
4. **补齐缺失的 model budget 规则**,并用 `makeTranslate` 直接对生产 RULES 求值验证:`"3 model budgets"` → `"3 个模型预算"`(程序化验证,非猜测)。
5. **修复后重新扫描**,清单从 0 变为 224 条(新逻辑捕获了之前完全提取不到的内容),逐条回源码精确判定截断处紧邻的字符:
   - **107 条**被闭合标签(`</...`)正常终止 → 真正完整的长句,批量翻译入字典
   - **62 条**被同行内联开标签(如 `<span>$0.00</span>`)打断 + **53 条**被 JSX `{expr}` 插值打断,合计 **115 条**属于"跨节点碎片"——这正是方案 §3 既定的非目标(不处理跨节点碎片句)。因无浏览器可视化核验条件,**保守处置**:即使部分看起来语义完整的短标题,也不做主观完整性判断,统一记入白名单 + Finding,理由标签 `[跨节点碎片-方案非目标]`,完整清单存档于 `workbench/evidence/UI完整中文化-期1-行级旁路分流.md`。

## 实施偏差记录

   **替代验证**:`npm run build` 已在预飞中验证通过;scanner 四类提取的正确性已用真实源码抽样 + 回源码精确判定复验(不是靠自证);self-test 22 项含对生产 RULES 的全量机械互证;用户本人在此 case 之前已多次在 `localhost:3000` 亲眼验证过阶段性效果。
   **遗留动作**:建议 Gate 2 前用户在 `localhost:3000` 花 3-5 分钟过一遍侧边栏全部入口 + 日志页(含流式更新观察),再放行。`/run-skill-generator` 建可复用驱动脚本的任务(本 case 中断过一次)值得作为独立后续处理。
