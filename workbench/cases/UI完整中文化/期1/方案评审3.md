## 一、3.1 三个子缺口逐个判定

**3.1.1(对账算法)→ 已闭合**(就算法本身;附 F2)。声明制对账消解了"朴素 `.test()` 骨架永 false":归一化(所有 `${…}` → `⟨x⟩`)对 :186 的双插值(含三元式)得 `⟨x⟩ model budget⟨x⟩`,与规则声明逐字符相等。但注意:该样例实际**永远不会运行到判定**——它被位置围栏挡在提取之外(见 F1);且互证的反推算法未定义(见 F2)。

**3.1.2(非数值插值通道)→ 已闭合。**multiSelect.tsx:614 全链路推演走通:announce 实参命中位置围栏 → 骨架 4 英文词过形态围栏 → 无排除上下文 → 无对应规则进清单标动态类 → 白名单**字面行**豁免(归一化骨架是确定性字面串,`(.+)` 禁令与金丝雀判定均不触碰)。微瑕:方案未明写"动态类白名单行匹配的是归一化骨架而非源文本",定稿补一句。

**3.1.3(提取围栏)→ 未真正闭合。**洪水已控(1356 行可压到数十),但围栏在方案自引的旗舰样例上把真句围了出去:providerConfigCard.tsx:186/:203 位于普通 const 赋值(`headerSummary = [...]`,:183-189),非 JSX children、非六 prop、非 toast/announce 实参——三条位置通道全不命中 → 不提取 → 规则不会诞生 → 运行时不译 → `--check` 绿灯下 UI 漏英文。"先算字符串再渲染"是 React 高频形态,是一类不是孤例。见 F1。

## 二、N1–N3 落地判定

- **N1 已落地**:attributes 观察 + 属性分支;回写环推演——译文再入规则(锚定英文)不可命中 → 契约① 返 null,环断。
- **N2 已落地**:行锚定计数与 v3 排版相容;残余排版敏感是响的失败,提醒实施加排版约定注释。
- **N3 已落地**:金丝雀主防线语义可执行(`/.*/` 类全命中金丝雀即败,锚定窄正则不命中即过);`#` 转义入格式;checklist tripwire 收窄到位。

## 三、新机制审查发现

**F1 [阻断] 位置围栏系统性排除"赋值位"模板字面量,自家旗舰样例即反例。**
后果链:清单看不见 → 规则不产出 → 运行时不译 → `--check` 绿灯漏英文——评审1-3.1 的"零证明力"在赋值位一类上原样复活;且 §4 演示四字段契约的那条规则(sample "3 model budgets")按方案自己的管线根本不会诞生。§4 承诺的聚合"排除计数"人工不可审。修法二选一写进方案:①位置围栏增设第四通道(赋值/return 位),须同时过形态+上下文围栏,以评审2 的 422 行基数复测洪水可控;②保持围栏,但"位置围栏外、形态围栏内"的行输出**行级**旁路报告随首份清单入库,人工一次性分流并入验收记录。

**F2 [重要] 互证断言的"由 sample 反推骨架"算法未定义,朴素实现对首条规则必败。**
捕获组替换法对 `s?`(非捕获)反推不出第二个 `⟨x⟩`,得 `⟨x⟩ model budgets` ≠ 声明 → self-test 规则#1 永红;删断言则 skeleton 沦为自由声明可骗绿 scanner。修法:互证写死为"**sample 必须是 skeleton 的代入实例**"——skeleton 字面段转义、`⟨x⟩` 展开为 `(.*?)`、锚定后 sample 必须命中,且 sample 同时命中 re;此定义对首条规则可验证通过。

**F3 [建议]** 上下文围栏按"所在行"整行排除,单行 JSX 同含 `className` 与 children 模板时误杀真句 → 排除判定以模板自身语法位置为准,入 self-test 负例。

**F4 [建议]** `${…}` 归一化对嵌套花括号未定义(`${fn({a:1})}`)→ 错切进清单(响的失败),self-test 补一例并写明口径,不得静默。
