## 给用户的摘要

现状:控制台汉化靠人工"逛到哪补到哪",252 个词条,覆盖不明,动态句("3 keys found")完全不翻。
做完:一条命令列出全部未翻译文案(清单可收敛至零),动态句由规则层处理,主要页面无英文残留。
Before:打开陌生页面 → 大概率见英文。After:`node scripts/zh-coverage.mjs --check` 通过 = 全站覆盖有证据。
拍板清单:①提取用正则启发式而非 TS AST(快、够用;误报靠白名单,漏报靠巡检兜底——AST 版记 Finding 后置)②规则层上限 100 条、必须 `^…$` 锚定(防误吞,性能可忽略)。其余无。

## 1. 起点

`起点=aae659b`(develop)——一切 diff、复测、对账以它为参照。

## 2. 现状与约束盘点

- `ui/lib/zhLocale.ts`(344 行):DICT 252 词条;`LOOKUP` 大小写兜底(:280);`translateRaw`(:291)目前仅精确/小写查表,miss 即返回 null;`walk`(:299)已处理文本节点 + placeholder/title/aria-label 三属性
- 动态句现状:零处理,页面直接显示英文
- `ui/scripts/` 不存在,将新建;ui 无单测基建(package.json 无 test script),自测走脚本内置断言
- **复用盘点**:词条数据与匹配逻辑全在 zhLocale.ts,可直接增量扩展,无需新抽象;扫描器无现成可复用(e2e 是 Playwright 行为测试,非静态扫描)
- 约束:不改任何组件源码(需求非目标);Monaco/日志正文/品牌名不翻;merge 税面维持"1 文件 + main.tsx 2 行"不扩大

## 3. 目标 / 非目标

**目标**:①覆盖率脚本(扫描→diff→清单,`--check` 空清单退出 0)②RULES 正则规则层接入 translateRaw ③字典补齐至清单清零(白名单外)④四类页面人工巡检通过

**非目标**:同需求页;另加:不做 TS AST 级提取(记 Finding)、不处理 React 碎片化跨节点句(记 Finding,按例外白名单处理)

## 4. 接口与数据设计

**zhLocale.ts 增量**(唯一改动的既有文件):

```ts
// 新增,置于 DICT 之后
const RULES: Array<[RegExp, string]> = [
  [/^(\d+) keys? found$/, "找到 $1 个密钥"],
  // …锚定 ^$;模板仅支持 $1..$9;顺扫首中即停;上限 100 条
];
// translateRaw 匹配顺序变更:精确 DICT → 小写兜底 → RULES 顺扫 → null
```

**新文件 `ui/scripts/zh-coverage.mjs`**(Node ≥20,零依赖,只读不写源码):

- 扫描范围:`app/ components/ hooks/ lib/` 的 .tsx/.ts,排除 `*.gen.ts`、`_fallbacks/`
- 提取三类:JSX 文本节点(`>文案<`)、六属性字面量(placeholder/title/label/description/aria-label/tooltip)、`toast.*("文案")`
- 判定:命中 DICT(含小写兜底)或任一 RULES 正则 → 已覆盖;命中 `zh-coverage-whitelist.txt`(支持 `/regex/` 行)→ 豁免;否则进清单
- 字典/规则读取:正则解析 zhLocale.ts 源文件(键值对 + RULES 字面量),不 import(避免 .ts 加载链)
- 输出:`词条 ⇥ 出现次数 ⇥ 首个文件:行号`,按次数降序;`--check` 清单非空退出 1;`--self-test` 内置断言(≥6 条:规则命中/漏配/白名单/属性提取样例)

**新文件 `ui/scripts/zh-coverage-whitelist.txt`**:品牌与技术标识(Bifrost、模型名模式、URL、SDK 名等)

## 5. 实现步骤

1. `feat(ui): add zh-coverage scanner + whitelist` — 脚本 + 白名单骨架 + self-test;跑出**首份清单存入本期目录**(基线事实)
2. `feat(ui): add RULES layer to zhLocale` — 规则层接入 + 从清单提取的首批动态句规则
3. `feat(ui): zh dictionary batch N` — 按清单分批补词条(预计 2-3 个 commit,每批后重跑 scanner 记录收敛数)
4. `docs+chore: coverage 清零收口` — 白名单终态、docs-zh/05-UI中文化层 增补"清单驱动维护流程"、巡检记录

每步独立 tsc 全绿可提交。

## 6. 测试策略

- 脚本正确性:`--self-test` 内置断言(固定样例字符串 → 期望分类)
- 规则层行为:self-test 覆盖"规则命中返回替换/未锚定拒绝/超上限告警";页面级由巡检验证
- 巡检用例(验收口径的目标4):侧边栏 21 入口逐个打开 + 仪表盘/日志/供应商/虚拟密钥/MCP/设置六页,记录于验收记录
- 盲区(明示):运行时才拼出的服务端文案(错误消息透传)不在静态扫描范围——巡检兜底,漏网记 Finding

## 7. 验收标准 + 检查清单 YAML

机械核验四条(详见同目录 `checklist.yaml`):tsc 全绿 / scanner self-test 通过 / `--check` 清单空 / RULES 符号落地。人工一条:六页+侧边栏巡检无英文残留(白名单除外)。

## 8. 风险与禁止事项

- 正则提取误报(把代码常量当文案)→ 白名单 + 人工过清单把关;漏报 → 巡检兜底
- 规则误吞正常文案 → 强制 `^…$` 锚定 + self-test 回归
- 禁止:触碰组件源码;翻译非目标清单内内容;规则层超 100 条(该拆字典就拆字典)

## 9. 回滚口径

feature 分支未合 develop 前直接弃;合入后回滚 = revert 对应 commit(新文件删除 + zhLocale 增量回退,无级联)。
