> v2 针对评审1 的 4 条阻断 + 6 条建议全部修订;逐项对应见 §10。

## 给用户的摘要

现状:汉化 252 词条靠人工补,动态句(`${n} keys` 模板字面量)完全不翻,属性翻译通道还和文本通道行为不一致。
做完:一条命令列出全部未翻译文案(含动态句形态),文本/属性统一走同一匹配管线,规则层带防死循环契约,清单可收敛至零。
拍板清单:①提取用正则启发式而非 TS AST(误报白名单兜底、漏报巡检兜底;AST 版记 Finding)②属性通道统一改走 translateRaw(+1 行既有文件改动,换来运行时与 scanner 口径一致)③动态句规则译文**禁止保留可再匹配的英文锚**(防循环的纪律代价)。

## 1. 起点

`起点=aae659b`(develop)。

## 2. 现状与约束盘点

- `ui/lib/zhLocale.ts`(344 行):DICT **252** 词条;`LOOKUP` 兜底(:280);`translateRaw`(:291)含防重入(`hit === trimmed → null`,:295);`walk`(:299)文本节点走 translateRaw,**但属性通道(:313)直查 `DICT[v.trim()]`,不吃兜底**——本期必须统一
- 动态句真实形态(评审1 亲核):JSX 表达式内模板字面量——`providerConfigCard.tsx:186,203,208,326`、`toolCallView.tsx:532-533`、`multiSelect.tsx:614-619`、`logDetailView.tsx:2106`;需求样例"N keys found"实际仅以静态串存在(`entityAssociationSelect.tsx:78,83`)
- `ui/scripts/` 不存在,将新建;ui 无单测基建,自测走脚本内置断言
- 复用盘点:词条与匹配逻辑集中于 zhLocale.ts 可增量扩展;扫描器无可复用现成件
- 约束:不改组件源码;Monaco/日志正文/品牌名不翻;merge 税面维持"zhLocale 1 文件 + main.tsx 2 行"

## 3. 目标 / 非目标

**目标**:①覆盖率脚本(四类提取,`--check` 空清单退出 0)②RULES 规则层(带收敛契约)统一服务文本+属性通道 ③字典/规则补齐至清单清零(白名单外)④主要页面巡检通过(含日志流式页性能观测)

**非目标**:同需求页;不做 TS AST 提取、不处理跨节点碎片句(均记 Finding)

## 4. 接口与数据设计

**zhLocale.ts 增量**(唯一改动的既有文件,两处):

```ts
const RULES: Array<[RegExp, string]> = [ /* 锚定 ^…$,禁止 (.+) 级全泛化捕获,上限 100 */ ];

function translateRaw(raw: string): string | null {
  // 匹配顺序:精确 DICT → 小写兜底 → RULES 顺扫(首中即停)
  // 收敛契约(防 MutationObserver 循环,对齐 :295 既有不变量):
  //   ① 任何路径下 结果 === 输入 → 返回 null
  //   ② 规则译文不得保留可再匹配的英文锚(self-test 固定点断言强制)
}

// walk 的属性通道(:313)改为:const t = translateRaw(v); —— 与文本通道完全同管线
```

属性口径说明:运行时翻译 placeholder/title/aria-label 三个 DOM 属性;label/description/tooltip 等 React prop 最终渲染为文本节点,由文本通道覆盖——scanner 对这六者统一按 translateRaw 全语义判定,与运行时一致(评审1-2.2 修复)。

**新文件 `ui/scripts/zh-coverage.mjs`**(Node ≥20,零依赖,只读):

- 扫描范围:`app/ components/ hooks/ lib/` 的 .tsx/.ts,排除 `*.gen.ts`、`_fallbacks/`
- **四类提取**:①JSX 文本节点 ②六属性/prop 字面量 ③`toast.*("…")` ④**模板字面量**——`${…}` 归一化为 `⟨n⟩` 占位符,与 RULES 做可命中性对账(评审1-3.1 修复)
- 判定:与运行时同口径——精确 DICT / 小写兜底 / RULES 试配;白名单豁免;否则进清单
- 字典/规则读取:正则解析 zhLocale.ts 源文件,**带对账自检**:解析出的 DICT 条数必须等于对同文件的机械 `": "` 计数、RULES 条数等于 `],` 项计数,不一致即退出 1(评审1-3.4 修复)
- `--self-test` 断言集(≥10):四类提取各 ≥1 例;规则命中样例**恰中一条**(冲突检测,评审1-3.3);**固定点断言:每条规则对其样例的输出再入 translateRaw 必须返回 null**(评审1-3.2);白名单豁免例;对账自检例
- `--check`:清单非空退出 1

**新文件 `ui/scripts/zh-coverage-whitelist.txt`**:支持字面行与 `/regex/` 行;**禁止全匹配行**(`/.*/`、`/.+/` 类,self-test 拒绝);终态逐条附理由(行内 `# 理由`),进验收记录(评审1-4.2 修复)

## 5. 实现步骤

1. `feat(ui): add zh-coverage scanner + whitelist` — 四类提取 + 对账自检 + self-test;跑出**首份清单存入本期目录**;同时定位需求四个动态句样例的真实形态,以真实句式替换验收样例并记录(评审1-1.2)
2. `feat(ui): unify attr channel + add RULES layer` — 属性通道改走 translateRaw + RULES 接入(含收敛契约)+ 首批规则(输入=步骤1 清单的第④类条目)
3. `feat(ui): zh dictionary batch N` — 分批补词条(预计 2-3 commit,每批记录收敛数)
4. `docs+chore: coverage 清零收口` — 白名单终态(逐条理由)、docs-zh/05 增补维护流程、巡检记录

## 6. 测试策略

- 脚本与规则:`--self-test` 断言集(§4);行为级由巡检验证
- 巡检:侧边栏全部入口(**以巡检当日运行时实际枚举为准**,评审1-5.2)+ 仪表盘/日志/供应商/虚拟密钥/MCP/设置六页;**日志页流式更新时观测 CPU/掉帧**(评审1-6.1)
- 盲区(明示):服务端透传的运行时文案不在静态扫描内,巡检兜底,漏网记 Finding

## 7. 验收标准 + 检查清单 YAML

机械核验**五条**(评审1-1.1 修复,详见 `checklist.yaml`):tsc / **npm run build** / self-test / --check / RULES 符号。人工两条:六页+侧边栏巡检无残留;流式页性能观测无肉眼可感劣化。

## 8. 风险与禁止事项

- **RULES 循环(冻死级)**:收敛契约①② + 固定点断言防护(评审1-6.1 入册)
- 属性口径分裂:本期统一后由 self-test 守护
- 性能:≤100 条锚定正则 × 短文本(节点文案通常 <80 字符),单次匹配微秒级;流式页实测观测点兜底
- 正则提取误报/漏报:白名单(带护栏)+ 巡检兜底
- 禁止:触碰组件源码;规则超 100 条;白名单全匹配行;规则译文留英文锚

## 9. 回滚口径

feature 分支未合前弃;合入后 revert 对应 commit(新文件删除 + zhLocale 单文件增量回退,无级联)。
