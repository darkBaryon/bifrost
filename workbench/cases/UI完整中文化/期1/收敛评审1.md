## 出口清单

### Blocking(阻塞 Gate 2,交用户裁决)

无。⑧ 的算法孪生虽系本次引入,但损伤面限于开发期扫描器的准确度(假绿风险),不触运行时,合入后修的成本与现在相当,不满足 Blocking 门槛。

### 立债(REF Case,triggered_by 本 Change)

**REF:收敛 TS/mjs 边界的三处文本级/抄写级共享**(预估半天~1 天):
1. 抽 `ui/lib/zhTranslate.mjs`(纯 JS:LOOKUP 构建 + translate 判定,约 25 行),zhLocale.ts 与 zh-coverage.mjs 各自 import,删除 makeTranslate 与 translateRaw 中重复的查表逻辑;
2. slug 标题化同法:把 `formatTitlePart`+slug 尾段抽入共享纯 JS 模块,topbar.utils.ts 与扫描器共用,parseTopbarMaps 只剩数据解析或一并删除;
3. (可选加码)RULES 改存数据文件(regex 源串 + flags 四字段),两侧各自 `new RegExp` 编译,parseZhLocale 整体删除——对账机器随之消失,是净减行的简化。
- **理想结构**:数据(zhDict.json、rules 数据文件)与算法(共享 .mjs)各一份,扫描器零依赖约束不破(node 原生 import .mjs),Vite 侧 import .mjs 无障碍。
- **反证条件**:若 ui 的 tsconfig/构建链实测无法从 .ts import 同目录 .mjs 并通过 typecheck+build,或 fork 策略明确禁止 topbar.utils.ts 结构性改动(upstream merge 税),则第 2、3 条作废,第 1 条仍可独立成立(zhLocale.ts 本就是自有文件)。

### 挂账(Finding)

1. **覆盖门禁未接入仓库级检查**:`zh-coverage --check`/`--self-test` 仅在 workbench preflight(checklist.yaml:7-8),ui/package.json 无脚本别名、CI 无 workflow;upstream merge 后新增英文文案静默存活直至下次手动跑 preflight。理想结构:ui/package.json 加 `"zh:check"` 别名(一行,merge 税极小),是否进 CI 由 fork 策略裁决。反证条件:若既定策略是「所有中文化检查只经 workbench preflight、且每次 merge 后必跑 preflight 已成纪律」,则作废。规模:10 分钟。
2. **zhDict.json「键按字母排序」仅靠注释承诺**(zhLocale.ts:7),parseZhDict 查重复键/值类型但不查序(zh-coverage.mjs:45-54);今日实测 3047 键 0 乱序,但无护栏,乱序插入会静默劣化 diff/merge 体验。理想结构:parseZhDict 加一行序检查(排序是既有事实,零迁移成本)。反证条件:若认为排序仅是便利而非契约、不值得响的失败,则作废。规模:15 分钟含自测。
3. **⑧ slug 合成算法孪生**(若 REF 第 2 条被反证条件击落则单独挂此账):deriveSlugTitle(zh-coverage.mjs:273-276)与 topbar.utils.ts:25-27,77 的算法漂移无护栏,数据漂移已有 parseTopbarMaps 兜底。反证条件:REF 落地即消。规模:随 REF。
