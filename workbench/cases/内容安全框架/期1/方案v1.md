## 给用户的摘要

当前只有竞品研究，完成后有可被 BF 调用的本地安全检测框架。参考 HG 的内容提取、阈值判定、处置职责，去掉云调用和 WASM 依赖。放行、拦截、仅记录与显式失败策略已获用户确认。通过测试检测器验证 BF Chat 文本的输入、非流式输出及完整流检测后交付；实际检测器、生产注册、配置管理和其他协议后续接入。没有待拍板的新增成本、依赖或公开 API。

## 1. 起点

基线 `7c81459aa0e62750f22f57b57c3c4a4750a98cfc`，分支 `feat/content-safety`。起始未提交内容均为本会话内容安全研究文档，不覆盖其他代码。HG 固定提交 `faccaad586a3cdc9e85dc7fa39358ff31a6453b2`，出处见 [源码研究](../../../../product/需求/内容安全/Higress源码研究.md)。

## 2. 现状与约束盘点

- `ee/AGENTS.md`：根包只用标准库；插件依赖业务根包；中文注释，文件超过 300 行评估拆分、500 行必须拆。
- `core/schemas/plugin.go`：普通 Go error 不阻断，须使用短路或响应错误；本轮安全错误禁止 fallback 绕过。
- `core/schemas/context.go`：已有 Pause/Resume/ClearPausedStreamBuffer/GetAccumulatedResponse；无真实 Tracer 时可能静默无效，必须验证暂停成功。
- `core/providers/utils/utils.go`：先累计 chunk，再执行 PostLLMHook，最后进入 gate；最终 chunk 标记由宿主提供。
- `framework/streaming/gate.go`：已有顺序回放、取消清理；EndStream 会先释放缓存，所以阻断前必须清空。上游缓存有 100 MiB 上限，本插件的显式流预算必须更小且在进入 gate 前检查。
- `ee/internal/app/bootstrap.go` 当前没有护栏装配。框架不注入空策略或假检测器，不修改上游文件。

## 3. 目标 / 非目标

目标：新增 `ee/internal/guardrails` 业务根包和 `plugin` 入口，支持按阶段运行本地检测、合并风险、生成不含原文的事件；测试真实 BF 流缓存能力。
非目标：真实算法、外部服务、配置 CRUD/持久化、HTTP 管理 API、脱敏/代答、多模态/MCP/Responses/TextCompletion 协议、生产启用及发布。Chat 入口只接受当前实现可完整提取的纯文本消息，未覆盖结构明确报不支持，不冒充已检测。

## 4. 接口与数据设计

- `Detector.Detect(context.Context, string) ([]Finding, error)`：本地同步调用，实现必须响应取消、支持并发；不另建适配器层。
- `Rule`：ID、检测器 ID、D 项、输入/输出阶段、风险阈值、命中动作 Block/Observe、失败动作 Allow/Block、超时；关键字段无默认值。规则按配置顺序运行，阻断短路，观察和允许失败继续后续规则。
- `New(rules, detectors, maxTextBytes)` 校验并复制规则/映射；`Check(ctx, stage, text)` 返回最终 Decision 与各规则 Event；空规则放行；空正文仍送检，避免将缺失与安全混同。
- 超限、非法输入、取消属于框架错误；检测器超时/错误/非法结果按该规则失败策略处理。检测事件不保留正文、命中原文或 detector error 文本。
- 插件 `New(engine, options, logger)`：选项明确拒答状态/文案及流缓冲预算；接 BF Chat 的 PreLLM/PostLLM。只在匹配阶段有规则时检查；输入包含全部历史纯文本消息，输出包含全部 choice 的纯文本。复杂 assistant/tool/multimodal 结构本轮拒绝处理。
- 流式输出在调用模型前暂停并验证 gate 能力。正文仍由宿主 accumulator 持有，ctx 仅存阶段开关、字节计数等固定大小状态。最终 chunk 用累计全文执行一次检测；通过立即恢复缓存，无播放延迟；阻断/流错误/超限先清空再终止。请求取消由宿主管理器清理。
- 插件只提供可注入的构造与 Hook 实现，无新增公开 HTTP 契约或默认启用；后续由 app 在真实检测器和配置到位后装配。

## 5. 实现步骤

1. 完成产品方向和工程记录；独立方案复核。
2. 业务规则执行和失败策略，编写语义单测。
3. BF Chat Hook、流式 gate、中文 README；使用测试检测器及真实宿主 accumulator 验证。
4. EE 全量检查、预飞、提交本地候选，启动独立代码与收敛评审；修复问题后交用户验收。

## 6. 测试策略

- 多规则：观察后继续；阻断停止；阈值边界；D 项、动作、失败策略缺失拒绝构造。
- 检测器：返回风险、失败、超时、非法严重度；配置快照不受调用方修改；并发无竞态。
- Hook：输入阻断返回 ShortCircuit，输出阻断替换结果，AllowFallbacks=false；无规则透明通过；不支持结构明确失败。
- 流：分两批危险词跨片段；最终判定前无任何客户端数据；通过按序释放；阻断不释放已缓存文本；无 Tracer、超限、上游错误、取消及清理。
- 真实算法、网关部署、所有 provider 协议与其他插件改写顺序均未验证，不作为本轮结论。

## 7. 验收标准 + 检查清单 YAML

按 `checklist.yaml` 执行 EE vet/race/build、文档检查及格式检查；所有新增 Go 文件不超过 500 行。预飞绿后做独立评审，Gate 2 由用户验收。

## 8. 风险与禁止事项

框架不等于识别能力；禁止默认启用、伪造生产检测器、隐式失败放行、把原文写日志、在 ctx 存流内容、改动上游或引入云依赖。独立测试不等于生产实测。

## 9. 回滚口径

未发布、无数据迁移；可回退本次 guardrails 新包和相关说明，既有启动行为不变。
