## 给用户的摘要

当前只有竞品研究，完成后有可被 BF 调用的本地安全检测框架。参考 HG 的内容提取、阈值判定、处置职责，去掉云调用和 WASM 依赖。放行、拦截、仅记录与显式失败策略已获用户确认。通过测试检测器验证 BF Chat 文本的输入和非流式输出；实际检测器、生产注册、配置管理和其他协议后续接入。没有待拍板的新增成本、依赖或公开 API。

## 1. 起点

基线 `7c81459aa0e62750f22f57b57c3c4a4750a98cfc`，分支 `feat/content-safety`。起始未提交内容均为本会话内容安全研究文档，不覆盖其他代码。HG 固定提交 `faccaad586a3cdc9e85dc7fa39358ff31a6453b2`，出处见 [源码研究](../../../../product/需求/内容安全/Higress源码研究.md)。

## 2. 现状与约束盘点

- `ee/AGENTS.md`：根包只用标准库；插件依赖业务根包；中文注释，文件超过 300 行评估拆分、500 行必须拆。
- `core/schemas/plugin.go`：普通 Go error 不阻断，须使用短路或响应错误；本轮安全错误禁止 fallback 绕过。
- `core/schemas/context.go` 提供流式 gate API，但完整正文累计依赖其他插件，本轮不接 gate。
- `core/providers/utils/utils.go`：先向 trace 记录 chunk 计数，再执行 PostLLMHook，最后进入 gate；此流程不保证全文已累计。
- `framework/streaming/gate.go` 的 EndStream 与无 final Hook 的 CloseStream 会释放暂停缓存，本轮不使用该路径实现输出保护。
- `ee/internal/app/bootstrap.go` 当前没有护栏装配。框架不注入空策略或假检测器，不修改上游文件。

## 3. 目标 / 非目标

目标：新增 `ee/internal/guardrails` 业务根包和 `plugin` 入口，支持按阶段运行本地检测、合并风险、生成不含原文的事件。框架始终接收完整文本。
非目标：真实算法、外部服务、配置 CRUD/持久化、HTTP 管理 API、脱敏/代答、多模态/MCP/Responses/TextCompletion 协议、生产启用及发布。Chat 入口只接受当前实现可完整提取的纯文本消息，未覆盖结构明确报不支持，不冒充已检测。

## 4. 接口与数据设计

- `Detector.Detect(context.Context, string) ([]Finding, error)`：本地同步调用，实现必须响应取消、支持并发；不另建适配器层。
- `Rule`：ID、检测器 ID、D 项、输入/输出阶段、风险阈值、命中动作 Block/Observe、失败动作 Allow/Block、超时；关键字段无默认值。规则按配置顺序运行，阻断短路，观察和允许失败继续后续规则。
- `New(rules, detectors, maxTextBytes)` 校验并复制规则/映射；`Check(ctx, stage, text)` 返回最终 Decision 与各规则 Event；空规则放行；空正文仍送检，避免将缺失与安全混同。
- 超限、非法输入、取消属于框架错误；检测器超时/错误/非法结果按该规则失败策略处理。检测事件不保留正文、命中原文或 detector error 文本。
- 插件 `New(engine, options, logger)`：选项明确拒答状态/文案；接 BF Chat 的 PreLLM/PostLLM。只在匹配阶段有规则时检查；输入包含全部历史纯文本消息，输出包含全部 choice 的纯文本。复杂 assistant/tool/multimodal 结构本轮拒绝处理。
- 流式调整（2026-09-16 用户选择 1）：本轮不接 BF 输出流缓存；匹配输出检查的 Chat 流式请求在 PreLLMHook 明确短路，不调用模型、不释放未经检查输出。只有输入规则时可正常检查输入并透传模型流。后续再修复输出流机制。
- Chat 输入/输出仅接受纯文本字符串或 text blocks；对多模态、tool、reasoning、refusal 等本轮未提取结构明确拒绝。拒绝 RawRequestBody、UseRawRequestBody、LargePayload passthrough、ExtraParams 和 ExtraContent 等绕过规范字段的路径；不将未知结构当空文本放行。
- 插件只提供可注入的构造与 Hook 实现，无新增公开 HTTP 契约或默认启用；后续由 app 在真实检测器和配置到位后装配。

## 6. 测试策略

- 多规则：观察后继续；阻断停止；阈值边界；D 项、动作、失败策略缺失拒绝构造。
- 检测器：返回风险、失败、超时、非法严重度；配置快照不受调用方修改；并发无竞态。
- Hook：输入阻断返回 ShortCircuit，输出阻断替换结果，AllowFallbacks=false；无规则透明通过；不支持结构明确失败。
- 流：有输出规则时 PreLLMHook 明确短路，不以普通 Go error 冒充阻断；仅输入规则时继续，PostLLM 不对 chunk 假装做完整输出检测。
- 真实算法、网关部署、所有 provider 协议与其他插件改写顺序均未验证，不作为本轮结论。
