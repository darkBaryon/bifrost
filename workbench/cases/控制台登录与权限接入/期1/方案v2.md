## 4. 接口与数据设计

### 4.1 改密提醒语义

- 身份业务字段采用 `PasswordChangeRecommended`；创建、重置后为 true，本人改密成功后为 false。
- 持久化继续使用已有 `must_change_password` 列，存储适配显式映射，旧数据无需批量更新。业务不再依据该字段拒绝正常登录账号的操作。
- status/login/account DTO 新增 `password_change_recommended: boolean`；兼容字段 `must_change_password` 保留并始终返回 false，表示本版本不强制改密。新前端只读取新字段，不推断密码值。
- identity 与 RBAC 移除“尚未改密”的拒绝条件；启停、会话版本、过期、角色检查、自我操作和最后管理员保护保持。无角色账号可读本人信息/权限及改密，仍不能管理其他账号。
- 改密请求继续 `{old_password,new_password}`；成功清 Cookie、撤销本人所有会话并记录密码事件，前端重新登录。重置仍使用部署初始密码且撤销旧会话，操作编号幂等不改。
- 不清空旧列来掩盖权限限制。新旧二进制混跑会对旧列 true 作不同解释，因此该行为切换要求同一部署滚动完成后再启用新前端；回滚旧后端会恢复强制改密。发布说明明确此限制。

### 4.2 最小工作台信息

建议新增 `POST /api/console/bootstrap`，请求严格为 JSON 空对象，沿用身份接口的来源校验、正文大小/重复字段规则及错误结构。

成功返回固定 DTO：`{is_db_connected:boolean,is_logs_connected:boolean,env_label:string|null}`。只读宿主已经持有的状态，不返回认证投影、完整设置、凭据、URL或数据库连接串；不接受任意字段选择。

要求有效且启用的个人会话，无额外 Settings.View；匿名/过期401、来源不合法403、正文非法400、读取失败503。尚未改密不影响读取。接口使用 no-store。

由独立 `ee/internal/host/console_bootstrap.go` 处理；`app/console_routes.go` 将其与现有 RBAC handler 固定组合成一个 AdditionalRoutes，仍只注入一次，不修改 AuthAdapter 的鉴权算法。增加 console-service 清单类别，精确登记 POST 路径；自身依次验证 Origin、拒绝 Authorization、认证 Cookie、严格解析空对象、读取投影。完整 Go 签名、注册顺序及 RootGuard 回归见附件 B。`GET /api/config` 的原 Settings.View 不变。

### 4.3 认证与表单

`ee/ui/app/enterprise/features/identity` 持有类型、RTK API、登录/初始化表单、改密表单与提醒状态；兼容入口 `components/login/loginView.tsx` 只组合视图。

状态查询失败显示重试，不能按未初始化处理。初始化成功回到登录，不自动签发会话。登录成功整页导航到经过现有 normalizeLoginGoto 校验的目标或 `/workspace`，重置本账号的提醒关闭记录；不得保存密码或 Cookie。

工作台最外层 SessionBoundary 在挂载 RBAC、bootstrap、通知、业务页面前验证本人身份。401 统一且去重地回登录；403 不登出，503/网络错误可重试。登录错误的401由表单处理；公共/临时令牌页面不经过该边界。

顶栏账号菜单公开当前显示名/登录名、修改密码、退出。改密 Dialog 自己持有 RHF/Zod 草稿和错误，不把字段塞进顶栏或会话 Context。中文提示，字符数与 UTF-8 字节数分开校验，不 trim 密码。

提醒关闭记录仅影响 UI。按账号隔离并在明确登录成功/退出时清理；同一浏览器标签页本次登录刷新不再弹，下一次登录再提醒。关闭、稍后、去修改有可访问标签和 data-testid。多标签页不承诺只弹一次，不新增服务端提醒已读接口。

退出/改密成功采用完整页面跳转清理内存查询与连接，账号敏感数据不持久化；退出失败显示重试，不能宣称服务器会话已撤销。跨标签页用不含凭据的会话变更信号触发本人身份/权限重查，切换账号时先卸载业务树、清理旧缓存再加载。清理包括 RTK Query 及 app/provider/plugin slice 中的选中实体、通知等账号相关状态；完整导航清理所有内存，跨标签账号改变也先完整导航，不只 resetApiState。

### 4.4 权限与路由

EE `rbacContext` 兼容现有全部导出，读取 `/permissions/me` 的 matrix；未知/加载/失败均默认拒绝，失败提供独立重试，不使用持久化权限决定初次放行。Manage 不自动包含 View，继续使用后端已有映射，不另造权限关系。

保留现有页面与导航结构，优先接通已有页面/布局/按钮的 useRbac。首页按已有导航中的授权入口选择；有效 goto 继续做原有安全校验，并遵守实际页面权限。无业务权限保留账号、改密和退出。父子布局、直接 URL 及首页是否还有缺口，通过相关页面的实际请求和显示验证后确定必要修改，不预建两页开放白名单或新的业务路由权限框架。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。

路由规则已完成的只读模拟HTTP诊断显示：附属403未阻断空/非空列表、分页和已检查详情，只缺团队名称且无scope_id回退；编辑选择器及提交仍未验证。区分 query.error、局部空选项、toast 和全页阻断。若证据表明需要跳过无权附属查询，优先在现有 query 的 skip 条件中复用 useRbac；不因为附属读取失败就为整个新增/编辑操作追加 ModelProvider/Governance/VirtualKeys 查看前置条件，不限制原有 scope 编辑能力。必要文件及回归范围按证据明确，不预设 RoutingRulePolicy 或一组新 props。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。

权限在登录/账号切换、窗口聚焦、相关拒绝时刷新；处理 permissions/me 自身错误时不循环刷新，403 不等于登出。权限撤回后按当前 matrix 更新界面并清理相关账号缓存，服务端始终最终裁决。尚未验证的敏感按钮、组合权限和附属请求明确记为待诊断；保留页面不等于宣称全站已适配。来源：2026-09-23 本轮用户裁决，见方案「Gate 决策结果」。
