## 可证伪质疑

### R1：只读路由账号是否仍会触发无权附属请求？

**亲核事实：**基线在编辑器关闭时仍挂载 Sheet，Sheet 的查询不受 open 控制；详情查名也没有读权限条件。只更换 RBAC Context 无法消除这些请求。

**本轮处置：**附件 A/C 要求空、非空列表均延迟挂载编辑器；详情必须同时满足 open 与实体读权限；选择器连同 LabelResolver 按 allowedScopes 挂载。四个必要接缝已纳入本期范围。

**可推翻条件：**实施后以仅有 RoutingRules.View 的账号进入空／非空列表，或打开无关联实体权限的详情，若出现 providers、keys、models、完整 config、team/customer/VK 附属请求，即推翻该项实现符合性。附件 E 已要求这些网络负向断言。

**结论：方案层面关闭，运行结果待实施验证。**

### R1：额外编辑门槛是否误伤本可执行的启停、删除？

**亲核事实：**后端 matrix 将 RoutingRules.Manage 映射为 Create/Update/Delete，不包含 View；现有表格启停为独立更新请求，不依赖厂商或实体选择器。

**本轮处置：**附件明确 View 是进页条件；编辑器另需厂商及相应实体读取权限，启停／删除保留独立条件。旧 user scope 只读及按授权启停／删除，不新增用户目录。

**可推翻条件：**有 RoutingRules.View+Manage、无 ModelProvider.View 的账号若不能启停／删除，或仍能打开完整编辑器，即违反方案。Manage 无 View 若能进入页面，也违反方案。

**结论：关闭。编辑门槛作为候选 UI 限制随范围取舍提交 Gate，不改变后端 Manage 契约。**

### R2：提供 EE 外壳后，旧配置订阅和旧 WS 是否仍会启动？

**亲核事实：**Topbar 配置查询发生在菜单渲染前；通知中心自身查询列表；旧 WS 请求票据失败后仍握手，卸载不关闭全局连接。

**本轮处置：**附件不再只约定展示替换，而是约定 LegacyAccountMenu 整体不挂载、通知中心与 sync 同步禁用、Managed/Legacy 独立分支。Managed 的请求中止与代次检查覆盖 await 返回和 socket 事件；401、403、网络/5xx 分别对应明确处置。

**可推翻条件：**EE 未提供 Settings.View 时外壳仍查询完整 config；通知禁用仍取票据；票据403后仍 Cookie 握手；旧代次迟到后建立连接或重排重试，任一发生即不满足方案。未提供 connection 时改变 OSS 原回退行为同样不满足兼容矩阵。

**结论：方案层面关闭。**

### R2：bootstrap 是否会挤掉 RBAC 注册，或借所有权分流绕过认证？

**亲核事实：**WithAdditionalRoutes 是赋值而非累加；AuthAdapter 对自管路由不执行 managed Prepare；RootGuard 使用实际已注册 Router 建匹配器，manifest 单独存在不足以放行。

**本轮处置：**附件规定只注入一次固定组合；bootstrap 精确拥有单个 POST，并自行验证 Origin、Authorization、Cookie、空对象及投影。console-service 无管理权限映射，但不属于 public。旧路由摘要须保持，新分类单独断言。

**可推翻条件：**`/permissions/me` 注册丢失；匿名 bootstrap 返回200；错方法进入成功 handler；仅登记 manifest 而未注册仍可达；新分类导致旧路由规则摘要改变，均构成失败。

**结论：关闭。**

## 建议栏（不立案）

1. **补齐已有契约的白名单索引。**附件 C 已明确给 RbacProvider 增加可选 skip，但 v2 §4.5 汇总表没有显式列出现有 fallback `ui/app/_fallbacks/enterprise/lib/contexts/rbacContext.tsx:65`。可增加交叉引用，避免实施时遗漏 OSS 类型兼容。规范性附件已经定义该变更，不作为新的契约阻塞。

2. **状态隔离验收留意树布局 Cookie。**`tree/views/positionPersistence.ts:3` 使用固定 `bf-routing-tree-positions`，内容含规则 ID/更新时间指纹及节点位置；`routingTreeView.tsx:114` 写入持久 Cookie。落实已有本地状态隔离承诺时应纳入盘点，不能把完整导航当作该 Cookie 已清除的证据。无需因此重写树视图或建立新的偏好服务。

3. **临时页面兼容用例明确两类访问者。**除匿名携带 fragment 的场景，也验证有效普通会话访问精确临时页面的既有路径。`clientLayout.tsx:44–72` 本来按访问者状态选择外壳；附件 C 已要求保留这一语义。这是既定兼容要求的测试落点，不是增加开放业务页面。

上一轮 S1 已修正引用，S2 已取消不必要的 onboarding hook 改动，S3/S4 已补入方案。上述建议不要求另开新的产品需求，也不构成本轮技术阻塞。

## 剩余风险与 Gate 边界

- **产品范围尚未裁决。**接受候选意味着管理员也暂时失去其他现有业务页面入口。若用户拒绝，须继续方案阶段，补充所需页面的调用链和验证边界后复核；不能直接扩大放行。
- **技术可行不等于实现正确。**真实同源浏览器、多标签切换、权限撤回、请求竞态、WS 清理及 OSS 默认兼容仍须实施后按附件 D/E 取得证据。
- **改密兼容与部署窗口仍有风险。**保留旧列使回滚可行，但新旧后端对 true 的解释不同；字段兼容策略、配套版本切换及统一初始密码可长期有效的风险须由 Gate 接受。
- **本次不批准额外能力。**账号／角色 CRUD、随机密码交付、完整个人中心、全站权限改造及全局错误协议重构均未扩入本期。

本轮可进入 Gate 1 的技术方案提交环节；本记录不代替 Gate 放行。
