**目标**：需求的五项目标作为同一个可运行切片。用户可用初始密码进入被授权页面，可以选择稍后或主动改密；服务端依旧逐请求按角色授权。

## 4. 接口与数据设计

### 4.1 改密提醒语义

- 身份业务字段采用 `PasswordChangeRecommended`；创建、重置后为 true，本人改密成功后为 false。
- 持久化继续使用已有 `must_change_password` 列，存储适配显式映射，旧数据无需批量更新。业务不再依据该字段拒绝正常登录账号的操作。
- status/login/account DTO 新增 `password_change_recommended: boolean`；兼容字段 `must_change_password` 保留并始终返回 false，表示本版本不强制改密。新前端只读取新字段，不推断密码值。
- identity 与 RBAC 移除“尚未改密”的拒绝条件；启停、会话版本、过期、角色检查、自我操作和最后管理员保护保持。无角色账号可读本人信息/权限及改密，仍不能管理其他账号。
- 改密请求继续 `{old_password,new_password}`；成功清 Cookie、撤销本人所有会话并记录密码事件，前端重新登录。重置仍使用部署初始密码且撤销旧会话，操作编号幂等不改。
- 不清空旧列来掩盖权限限制。新旧二进制混跑会对旧列 true 作不同解释，因此该行为切换要求同一部署滚动完成后再启用新前端；回滚旧后端会恢复强制改密。发布说明明确此限制。

### 4.2 最小工作台信息

建议新增 `POST /api/console/bootstrap`，请求严格为 JSON 空对象，沿用身份接口的来源校验、正文大小/重复字段规则及错误结构。

成功返回固定 DTO：`{is_db_connected:boolean,is_logs_connected:boolean,env_label:string|null}`。只读宿主已经持有的状态，不返回认证投影、完整设置、凭据、URL或数据库连接串；不接受任意字段选择。

要求有效且启用的个人会话，无额外 Settings.View；匿名/过期401、来源不合法403、正文非法400、读取失败503。尚未改密不影响读取。接口使用 no-store。

由 EE 宿主接入层提供窄投影，复用身份验证与同源检查，不让 identity 业务模块依赖上游 Config。注册/所有权/RootGuard 清单同时登记并测试；不能把接口列为 public，也不绕过会话验证。`GET /api/config` 的原 Settings.View 不变。

### 4.3 认证与表单

`ee/ui/app/enterprise/features/identity` 持有类型、RTK API、登录/初始化表单、改密表单与提醒状态；兼容入口 `components/login/loginView.tsx` 只组合视图。

状态查询失败显示重试，不能按未初始化处理。初始化成功回到登录，不自动签发会话。登录成功整页导航到经过现有 normalizeLoginGoto 校验的目标或 `/workspace`，重置本账号的提醒关闭记录；不得保存密码或 Cookie。

工作台最外层 SessionBoundary 在挂载 RBAC、bootstrap、通知、业务页面前验证本人身份。401 统一且去重地回登录；403 不登出，503/网络错误可重试。登录错误的401由表单处理；公共/临时令牌页面不经过该边界。

顶栏账号菜单公开当前显示名/登录名、修改密码、退出。改密 Dialog 自己持有 RHF/Zod 草稿和错误，不把字段塞进顶栏或会话 Context。中文提示，字符数与 UTF-8 字节数分开校验，不 trim 密码。

提醒关闭记录仅影响 UI。按账号隔离并在明确登录成功/退出时清理；同一浏览器标签页本次登录刷新不再弹，下一次登录再提醒。关闭、稍后、去修改有可访问标签和 data-testid。多标签页不承诺只弹一次，不新增服务端提醒已读接口。

退出/改密成功采用完整页面跳转清理内存查询与连接，账号敏感数据不持久化；退出失败显示重试，不能宣称服务器会话已撤销。跨标签页用不含凭据的会话变更信号触发本人身份/权限重查，切换账号时先卸载业务树、清理旧缓存再加载。

### 4.4 权限与路由

EE `rbacContext` 兼容现有全部导出，读取 `/permissions/me` 的 matrix；未知/加载/失败均默认拒绝，失败提供独立重试，不使用持久化权限决定初次放行。

维护 EE 可访问路由表：页面路径到所需资源/操作及可用功能的显式映射。用于首页选择、导航过滤、页面挂载前守卫，路径按规范化后的最长匹配，未登记业务页默认拒绝。覆盖 governance 子路由不能只依赖父层“有任一治理权限”的判断。

`/workspace` 进入首个可访问页面；没有业务权限时显示最小工作台说明，保留顶栏改密/退出。已授权例子首选 routing-rules：路由只读账号可进列表，无新增/编辑/删除按钮；直接打开设置页显示无权限且不发配置查询。

权限在登录/账号切换、窗口聚焦、相关拒绝时刷新；处理 permissions/me 自身错误时不循环刷新。角色变化后的后端检查始终权威，前端刷新完成后卸载无权内容并清理相关缓存。已有页面复杂组合权限逐模块完善，本期不能以此为由遗漏测试账号所用页面的按钮/请求控制。

### 4.5 外壳、通知与上游扩展白名单

`useConsoleConfigQuery` 是窄配置查询：OSS fallback 调用原 getCoreConfig，EE 调用 bootstrap。ClientLayout 和 Sidebar 使用窄字段；Topbar 从当前身份决定账号菜单。

上游已有文件仅允许下列增量接入，默认 fallback 保持原行为：

| 文件 | 可选扩展与必要性 |
|---|---|
| `ui/app/clientLayout.tsx` | SessionBoundary/RouteBoundary、窄配置 hook、可选 onboarding 与通知启用；EE生命周期没有现成覆盖点 |
| `ui/app/workspace/layout.tsx` | 可选工作台落点策略，未提供时仍跳 Dashboard |
| `ui/components/sidebar.tsx` | 窄配置、导航过滤、禁用不适用的 onboarding 查询 |
| `ui/components/topbar.tsx` | 可选账号菜单与通知显示；不改变旧菜单的默认实现 |
| `ui/hooks/useOnboardingChecklist.ts` | 仅必要的可选 skip 条件透传，EE 默认关闭旧共享管理员/SCIM引导 |
| `ui/hooks/useWebSocket.tsx` | 可选 enabled/账号作用域，撤权或切换关闭旧连接和计时器；默认沿用旧行为 |
| `ui/hooks/useNotificationSync.tsx` | 可选 enabled/账号作用域，无权限不查询；旧调用默认不变 |
| `ui/lib/utils/port.ts`、`ui/vite.config.mts` | 可选同源开发连接配置与 WS 代理；默认保持上游端口行为 |

上述扩展的 fallback 放 `ui/app/_fallbacks/enterprise/`，EE 实现在 `ee/ui/app/enterprise/`。新增 hook 默认使用原实现；所有拓展契约类型一处定义。其余 `ui/` 文件不在白名单，实施发现缺口先登记偏差、修订方案。不修改生成的 enterprise 覆盖目录或 routeTree。

通知只有 Notifications.View 才查询和建连接；票据403停止重试，401触发身份失效。禁用连接仍给消费者提供空上下文，避免 hook 报错；本地偏好按账号 UUID 隔离，不能复用 local-admin。EE HTTP wrapper只处理会话失效，不实现刷新令牌。

开发时 API/WS 经同源代理，EE_PUBLIC_ORIGIN 精确匹配浏览器地址；生产同源方式不变，不关闭来源校验解决开发问题。

## 6. 测试策略

- Go 单元/集成：初始密码账号有角色时按授权放行；无角色仍拒绝业务管理；旧数据库 true 被解释为建议；重置重新提醒且旧会话失效；本人改密撤销全部会话；WS未改密但有通知权限可用，撤权即拒绝下一次验证。
- bootstrap 真实 HTTP：未登录401、错误Origin403、合法普通账号200且字段恰好为三个白名单字段，非法JSON/重复键/未知字段400；/api/config 对同账号继续403。
- 前端单测：路由最长匹配、未知路由/权限加载失败默认拒绝、goto边界、密码字符/字节校验、账号间提醒隔离、错误分类。
- 浏览器隔离验收：新实例初始化、管理员正常登录、提醒稍后、刷新不重复、顶栏再次打开改密、输入错误保留表单、改密成功重新登录；只读路由用户正确落点和按钮、直接设置URL无权、无角色仍能改密退出；账号切换不显示前账号数据；无通知权限不请求通知/不重连；503保留错误而不匿名放行。
- 对真实临时 EE 服务运行浏览器，不只 mock fetch。复用现有 identity-smoke 的临时目录/随机端口思路和 Playwright 工具；测试不得碰个人业务数据库、真实上游厂商或已有服务端口。
- EE/OSS 两种构建单独在可控生成目录验证；品牌、公共/临时令牌页面回归，不能为测试删除其他工作树生成物。

## 8. 风险与禁止事项

- 本次是身份权限行为变化，按L3证据验收；不以已有后端测试代替新流程测试。
- 统一初始密码长期可用是允许跳过的直接影响；当前用户已知代码默认值，但正式方案仍需确认是否沿用部署初始密码。随机生成/一次展示是不同契约，未获确认不实施。
- 新旧后端混跑的改密语义不同；部署/回滚必须明确版本窗口，不悄悄清旧字段或角色记录。
- 禁止存储/记录密码或Cookie，禁止关闭Origin校验，禁止把403等同登出，禁止授予所有账号Settings.View来绕过外壳依赖。
- 本期不替用户合入develop、推送或发布。前端实施中需要额外上游改动按偏差规则处理。
- FIND-022 的 HTTP 状态/code 不一致纳入错误分类验证；本期以HTTP状态为准兼容原错误形状，是否统一整个上游转换另列方案复核意见，不能默默扩大为全局错误重构。
