## 摘要与起点

基线 `7ac06f8a13b8ed630830bae51b38dc2f54067ebc`，代码迁移开始前 EE Go 代码无未提交修改；此前产品、规范与权限工作文档的未提交修改保留。

从镜像上游的 transports/framework 目录迁到 cmd/internal，品牌增加业务服务与存储接口。依据 [EE 后端架构](../../../../product/架构/EE后端架构.md)，本次只迁移已有功能，不建空业务模块，不改变前端覆盖机制。

## 现状与调用方

- `ee/transports/bifrost-http/main.go` 调用 EE Bootstrap，后者装配品牌 Store/Handler、探针表/Handler/插件和全局标记。
- 品牌 Handler 直接依赖具体 Store，图片内容校验混在 HTTP 包；Store 同时声明业务输入与数据库模型。
- EE 路径的生产调用方为上述 Go 入口、`ee/Makefile`、UI schema 的校验说明；冒烟脚本使用 `ee/tmp/bifrost-http`，其中 OSS 对照入口仍为根 transports。
- 没有独立前端项目迁移；当前数据库、上游鉴权、Router、插件注册和生命周期均复用。

## 目标结构与接口范围

| 原位置 | 目标 |
|---|---|
| transports/bifrost-http/main.go、ui/ | cmd/bifrost-http/main.go、ui/（embed 产物） |
| server/bootstrap.go | internal/app/bootstrap.go：依赖装配与注册 |
| lib/shell.go、handlers/middlewares.go | internal/bifrost/：宿主 HTTP 接入 |
| 探针表、Handler、no-op 插件 | internal/bifrost/：现有宿主接入验证组件 |
| handlers/branding/ | internal/branding/http/：HTTP 解析与响应 |
| framework/configstore/branding/ | internal/branding/persistence/：表、迁移、事务读写 |
| 品牌模型、图片校验、操作规则 | internal/branding/：业务类型、Repository、Service |

业务包只依赖标准库；HTTP 和存储依赖业务包，app 注入具体实现。探针属于宿主集成验证，保留在 bifrost 适配包，不建立独立业务或额外服务层。

允许变更的 Go 内部接口：Bootstrap/Handler/Store 的 import 路径与包名；品牌新增 Settings、Asset、Patch、Repository、Service、ValidationError、DecodeAsset、ErrAssetNotFound，Handler 改为接收 Service；数据库行留在 persistence。数据库 Reset 简化为服务调用原有原子 Update，原图片 hash 计算仍是存储字段派生。HTTP 负责 JSON 类型与字段解析；业务包用 DecodeAsset 顺序解码和校验每张图片，返回字段私有的有效 Asset 值，服务负责空操作、重置与当前资源选择规则。

对外保持：全部路由/方法、读取公开与写入上游鉴权、缺字段/空串/null 语义、响应字段与缓存、413/400/404/500 错误类别；`ee_branding`/`ee_probe` 表、字段、`ee_branding_v1`、迁移锁键、图片 hash、插件名及响应标记不变。品牌两图校验完成后才写入，保留局部更新与事务回滚。

## v2 补充：接口与行为保护

- `Settings`：`Logo/Icon []byte`，`LogoMIME/IconMIME/LogoHash/IconHash string`，`UpdatedAt time.Time`；无 ID、ORM 标签或 TableName。persistence 的 `brandingRow` 保留原字段与 ID=1，显式转为 Settings。
- `Asset`：私有 `data []byte`、`mime string`，由 `DecodeAsset(encoded, mime string) (*Asset, error)` 校验后构造；零值表示清除。`Data() []byte` 返回副本，`MIME() string` 返回类型，调用方不能修改已验证内容。
- `Patch{Logo, Icon *Asset}`：nil 不修改，零值 Asset 清除，有效 Asset 替换；两者都 nil 由 Service 拒绝。
- `Repository`：`Read(context.Context) (Settings,error)`、`Update(context.Context,Patch) (Settings,error)`；Update 原子写入指定字段并回读。
- `NewService(Repository) *Service`；Service 提供 `Read(ctx) (Settings,error)`、`Update(ctx,Patch) (Settings,error)`、`Reset(ctx) (Settings,error)`、`Asset(ctx,slot,hash string) (Asset,error)`。Resource 先检查 slot/hash 形状，再读库比对当前 hash。
- `ValidationError{Message string, TooLarge bool}` 为业务校验错误，HTTP 映射为 400 或 413，并保留 logo/icon 前缀；`ErrAssetNotFound` 映射为 404；存储错误仍隐藏细节并返回 500。
- HTTP 仍先完整解析/校验 logo，再处理 icon；无效 logo + 超限 icon 仍返回 400。空串清除，`data:;base64,` 和只有 CR/LF 的编码均拒绝，不改变旧图。坏资源路径配故障库仍返回 404，合法形状路径配故障库返回 500。
- 其余允许搬移符号：`app.Bootstrap`；`bifrost.EEShellRewriter`、`EEHeaderMiddleware`、`EEHeaderName/Value`、`Probe`、`NewProbeHandler`、`ProbePluginName`、`ProbePlugin`；`brandinghttp.NewBrandingHandler(*branding.Service)` 与 RegisterRoutes；`persistence.NewBrandingStore`、`MigrateBranding`。旧 ee 非 internal import 路径停止使用，本仓搜索未发现其他生产调用方。
- ee/Makefile 的 workspace 目标补充 go.work 缺失时 `go work init ./ee`，已存在时 `go work use ./ee`；不调整依赖版本。
- 机械命令与产物见同目录 checklist.yaml。现有存储测试仍验证原子合并/回滚/锁行为，输入换为有效图片以适配有效 Asset；新增服务测试验证绕开 HTTP 时仍保持业务边界。
