## 2. 终态设计

### S1 SCHEMA(Change 模型原生)

- 过程文档表增行:`收敛评审 | case, phase, round | 无状态机,必填 verdict(无碍 / 仅立债挂账 / 有Blocking)`——**规范串以此三值为准,不设旧值兼容**(理由见 §3 取舍1);
- **视图定义表删 active.md/by-case.md 两行**;index.md 行保留,描述"站点首页 = 活跃工作台";build_views.py 模块 docstring(:5-11)同步;
- 新增「风险分级」节:tier ↔ Change 级别(轻量级=L1/标准级=L2/蓝图级⊆L3),声明 **case 名即账本主键,不设 CHG/REF 编号**;
- 需求 frontmatter 增可选字段 `triggered_by`(列表,元素为 case 名或需求 id)。

### S2 build_views.py + tests(闭合 B1/B2)

- **`render_active` 更名 `render_index`,保留**,专供 index.md;删除 views/active.md 的写出与 `render_by_case` 函数及其写出;views/ 仅剩 all.md;
- nav_model:工作台区删「过程文档全景」条目(nav 本无 active 条目);「全量索引」「需求报告」保留;SUMMARY/nav.js 管线不动(SUMMARY 现无消费方,保留为惯例产物,处置另案);
- **收敛评审并入 REVIEW_TYPES 语义**(is_active 排除、case 内时间线参与):verdict 校验**按 type 分集合**——方案评审/代码评审:{通过,需修改,驳回};收敛评审:{无碍,仅立债挂账,有Blocking};`phase_flat` 给收敛评审专属排序键(代码评审后、验收记录前);
- tests 补 4 条断言:①收敛评审 verdict 非法值(如「通过」)必炸;②含收敛评审的已归档 case 不出现在 index;③nav 不含 active/by-case;④时间线中收敛评审排代码评审后、验收前。
