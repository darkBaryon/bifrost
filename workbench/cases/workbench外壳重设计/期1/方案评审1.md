## 阻断项

1. **B1|S2 自相矛盾**:index.md 正是由 `render_active(docs, "")` 生成(build_views.py:403),"删除 render_active"与"index.md 保留"不能同时成立——照字面执行 index.md 沦为带哨兵、禁手改、无人再生成的死文件,站点首页(brand 链接/first_path 兜底,build_site.py:341,360)永久过期。处方:保留函数(更名 render_index),仅删 views/active.md 写出与 render_by_case;nav 描述改准确(nav 里删「过程文档全景」条目)。
2. **B2|新类型在生成器既有分支的行为未规定**:`is_active`(:114-117)不排除收敛评审 → 已归档 case 因收敛评审1 永久重现于 index;`VERDICTS` 单一集合(:106)会判「仅立债挂账」非法;`phase_flat`(:177-191)未知类型落 (500,0) 桶 → 时间线排到代码评审之前。S2 所列 tests 捕不到这三处。处方:收敛评审并入 REVIEW_TYPES 语义;verdict 按 type 分集合;phase_flat 给专属键(排代码评审后、验收前);tests 补「含收敛评审的已归档 case 不出现在 index」断言。
3. **B3|verdict 兼容「通过」与 S3 互相矛盾**:S3 把唯一一处「通过」改写为「仅立债挂账」,兼容项成为纯增量歧义入口;取舍1 的依据("已归档文档不再动")被 S3 自己推翻。另「仅立债挂账」vs「仅立债/挂账」写法不一。处方:枚举定为 无碍/仅立债挂账/有Blocking,删兼容;取舍1 重述为"S3 修改已获需求非目标条款明示豁免"。
4. **B4|checklist 与 §5 并非同源,关键项机器不可判**:四个"文件不存在"验收无对应命令;「findings ≥9 条」只有存在性检查;`禁留 gate-card` grep 的是文件内容,基线上实测**已经是绿**(空转);"build_site 全量渲染即验证死链"不成立(build_site.py 全文无链接校验)。处方:补 `test ! -e` ×4、FIND 计数命令、可执行的死链 grep;删不可判条款。
