## 给用户的摘要

现状：框架已合入 develop，只有匹配 `[guardrails-test]` 的假检测器，没有真实检测能力。做完后：网关能用规则查密钥（D3），用 DeepSeek 判官查有害内容、提示词攻击和管理员写的业务规则（D1/D4/D5）；同阶段多条规则并行跑，一次请求最多多等一次判官调用的时间。配置来自一个 JSON 文件，默认不启用。

拍板项：
1. **期 1 的配置来源用 JSON 文件**（环境变量指路径），管理 API 与数据库留到期 2。利：不引入表和接口，尽快验证检测效果；弊：改配置要重启。
2. **判官请求跳过插件管线**：避免判官自己再被安全插件检查（递归），代价是判官调用不进上游日志与计费。日志与计费留到期 2。
3. **判官返回的理由不写日志**：理由由模型根据对话内容生成，可能复述原文，与框架「日志不含原文」一致。

`起点=fae2fe855`（develop `05db7cea2` + 调研文档），分支 `feat/content-safety-detectors`。

## 2. 现状与约束盘点

- `ee/internal/guardrails/detector.go:22`：`Detector.Detect(ctx, text) ([]Finding, error)`，`Finding` 只有 `Level`（Low/Medium/High）。本期不改此契约。
- `checker.go:66-93`：`Check` 按规则顺序串行执行，遇 Block 停止；`evaluation.go:44-79` 每条规则带 `Timeout`，超时/错误/非法等级按 `OnError` 处置。**并行执行改在 checker 内部**，`CheckResult.RuleEvaluations` 保持配置顺序。
- `plugin/plugin.go`：入口只依赖 `*Checker`，本期不改插件。`plugin.Logger` 只有 `Info`。
- `app/guardrails.go`：现有假检测器装配读 `EE_GUARDRAILS_FAKE`，用 `host.SyncLoadedPlugin` 注册在内置插件之前。本期保留该开关，新增真实装配。
- 判官调用出口：`transports/bifrost-http/server/server.go:230` 的 `host.Client *bifrost.Bifrost`，`core/bifrost.go:801 ChatCompletionRequest`；`schemas.BifrostContextKeySkipPluginPipeline`（`core/schemas/bifrost.go:349`）可跳过插件管线。判官的 provider、key、重试退避全部复用上游 provider 配置（`core/schemas/provider.go:65 MaxRetries`），检测器只做自己的应用层重试。
- 复用盘点：`pricing` 模块已有「嵌入数据文件 + 环境变量指外部文件」的做法（`app/pricing.go:16-24`），密钥规则数据照此组织；无现成 HTTP 客户端可复用，判官也不需要。
- 约束：`ee/AGENTS.md` 根包只用标准库；`guardrails` 根包禁止 `net/http`、`fasthttp`（checklist 禁留标记）；不改上游文件；日志不含原文与命中值；文件超 500 行必拆。
- Gitleaks 规则为 MIT，数据文件随附许可声明；其 TOML 需转换，`ee/go.mod` 无 TOML 库，转换在仓外一次性完成，仓内只放 JSON。

## 3. 目标 / 非目标

**目标**：

1. `detectors/secrets`：密钥规则检测器。
2. `detectors/judge`：判官检测器，含 D1/D4 内置提示词与 D5 模板。
3. `Checker` 同阶段规则并行，遇 Block 取消其余。
4. `app` 按 JSON 配置装配，每个检测项目一个判官实例、每条 D5 规则一个实例。
5. 冒烟脚本覆盖密钥拦截与判官替身；真实 DeepSeek 验证作为独立记录。

**非目标**：管理 API、数据库表、UI；脱敏、代答；输出流；MCP、多模态、Responses；判官调用的日志与计费；提示词效果调优（提示词沿用实验初稿，隐晦样本另开工作）；上游文件改动。

## 4. 接口与数据设计

### 4.1 密钥检测器 `detectors/secrets`

```go
// 规则数据：data/rules.json + data/NOTICE（Gitleaks MIT）
type rule struct {
    ID, Description string
    Regex           string   // Go RE2
    Keywords        []string // 小写；空表示总是执行
    Entropy         float64  // 0 表示不检查
    SecretGroup     int      // 0 取第一个非空捕获组
    Allow           allowlist // Regexes(对 secret)、StopWords
    Level           guardrails.Level // 专用规则 High，generic-* Medium
}
func New(opts Options) (*Detector, error)  // Options: ExtraStopWords []string（管理员忽略词）、内置 sk-bf- 白名单不可关闭
func (d *Detector) Detect(ctx, text) ([]Finding, error)
```

扫描顺序：文本小写 → 关键词命中集合（`strings.Contains` 逐词，244 词，实测再决定是否换 AC）→ 只跑命中规则 → `FindAllStringSubmatchIndex` → 取 secret → 熵过滤 → 全局 + 规则白名单 → 同一 secret 已被专用规则命中则丢弃 generic 结果。每 32 条规则检查一次 `ctx.Err()`。返回每个命中一条 `Finding{Level}`，不返回位置和值。

规则数据来源：Gitleaks v8.30.1 的 222 条去掉纯路径规则与 path 条件；按[密钥格式核实](../../../../product/需求/内容安全/密钥格式核实.md)修正 Gemini `AQ.`、Anthropic 通配、OpenAI 不定长；新增可写专用规则的厂商（Groq、Cerebras、OpenRouter、xAI、Replicate、Azure OpenAI 新版、百炼 `sk-sp-`、MiniMax、千帆、智谱、阿里云 STS、腾讯云、火山、百度新版，钉钉/飞书/企业微信 webhook）；`generic-api-key` 关键词补 密钥、密码、令牌、口令、秘钥、apikey。长度一律「前缀 + 最小长度」。

### 4.2 判官检测器 `detectors/judge`

```go
// 窄接口由检测器定义，app 用 host.Client 适配；根包不依赖 core/schemas
type Model interface {
    Complete(ctx context.Context, system, user string) (string, error) // 返回 assistant 文本
}
type Options struct {
    Model      Model
    Prompt     Prompt        // PromptHarmful / PromptPromptAttack / BusinessRule(ruleText)
    Retries    int           // 应用层重试次数，默认 3，允许 0–5
}
func New(opts Options) (*Detector, error)
```

请求：system = 提示词，user = `{"stage":"input|output","text":...}`（stage 由 Prompt 与规则阶段决定，检测器构造时指定）。响应解析 `{"risk_level":"none|low|medium|high"}`，映射 none→无 Finding，low/medium/high→`Finding{Level}`；非法 JSON 或未知等级算一次失败。失败（错误、超时、非法）按退避 200ms×2ⁿ 重试至 `Retries` 次，仍失败返回 error，由规则 `OnError` 处置（用户已定：拦截）。全部在规则 `Timeout` 内，超时即停。

提示词放 `prompts/*.md`，`go:embed`；沿用[判官实验](../../../../product/需求/内容安全/判官实验/run.py)初稿，拆成有害内容、提示词攻击、业务规则模板三份。理由字段解析但不记录。

app 侧适配器（`app/guardrails_judge.go`）：`host.Client.ChatCompletionRequest`，ctx 设 `BifrostContextKeySkipPluginPipeline=true`，`temperature=0`、`max_tokens=200`、`response_format=json_object`；provider/model 来自配置，必须是网关已配置的 provider。

### 4.3 并行执行

`Checker.Check` 对同阶段规则起 goroutine，共用可取消子 ctx；任一规则得到 Block 立即 cancel；结果按配置顺序写回 `RuleEvaluations`。因 Block 而被取消、未完成的规则**不写入** `RuleEvaluations`，避免把取消记成检测失败；`CheckResult.Action` 与串行语义一致（有 Block 则 Block，否则 Allow）。父 ctx 取消、非法输入仍作为框架错误返回。

### 4.4 配置与装配

环境变量 `EE_GUARDRAILS_CONFIG` 指向 JSON；未设置则不注册插件。

```json
{
  "deny": {"status": 400, "message": "内容未通过安全检查"},
  "max_text_bytes": 65536,
  "judge": {"provider": "deepseek", "model": "deepseek-v4-flash", "retries": 3, "timeout_ms": 10000},
  "secrets": {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block", "timeout_ms": 500, "ignored_keywords": []},
  "harmful":       {"enabled": true, "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "prompt_attack": {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "business_rules": [{"id": "pricing", "rule": "不得透露内部底价……", "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"}]
}
```

校验：阈值/动作/阶段非法、judge 缺 provider、business_rules ID 重复或 rule 为空 → 拒绝启动。每个启用项按阶段生成 `guardrails.Rule`，规则 ID = `<项>:<阶段>`，判官实例 ID = `judge:<项>`。

## 5. 实现步骤

1. `Checker` 并行执行 + 竞态与取消测试（`feat(guardrails): run same-stage rules in parallel`）。
2. 密钥检测器：数据文件转换（仓外脚本，结果与转换记录入 `data/`）、扫描实现、真假样本单测（`feat(guardrails): add secrets detector`）。
3. 判官检测器：提示词、解析、重试；用替身 `Model` 测正常/非法/超时/取消（`feat(guardrails): add judge detector`）。
4. 配置装配与 `host.Client` 适配器，`guardrails-smoke.py` 扩展（密钥拦截 + 判官替身服务），README 更新（`feat(ee): assemble content safety detectors from config`）。
5. 用真实 DeepSeek 跑实验样本，写独立验证记录；预飞；提交候选。

## 6. 测试策略

- 密钥：每类新增规则一真一假样本（假样本为占位串、低熵、白名单词）；中文字段名召回；`sk-bf-` 不命中；40KB 普通文本耗时基准；取消响应。
- 判官：替身返回四种等级、非法 JSON、错误、慢响应；重试次数与总时长断言；`Retries` 越界拒绝构造。
- 并行：多规则中一条 Block 时其余被取消且不出现在结果；无 Block 时结果顺序与配置一致；`-race`。
- 装配：非法配置逐项拒启；配置生成的规则集与预期一致。
- 集成：现有真实插件管线测试增加密钥规则用例。
- 盲区：真实 DeepSeek 的准确率与延迟只在独立记录中体现；判官提示词质量不在本期断言。

## 7. 验收标准 + 检查清单 YAML

见同目录 `checklist.yaml`：EE vet/race/build、gofmt、diff-check、workbench 视图、冒烟脚本；必存 `detectors/secrets/data/rules.json`、`data/NOTICE`、`detectors/judge/prompts/`；必含 `func New` 于两个检测器包。所有 Go 文件 ≤ 500 行。

## 8. 风险与禁止事项

- 判官延迟叠加到每个请求；并行后最多一次调用时长。规则 `Timeout` 默认 10s，超时按拦截，需要在独立验证中记录真实分布。
- 密钥规则的长度多来自第三方，可能误报或漏报；`ignored_keywords` 供管理员止血。
- 禁止：日志含原文、命中值或判官理由；把判官失败当通过；改上游文件；根包引入网络库；默认启用。
