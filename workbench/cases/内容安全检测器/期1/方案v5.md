## 给用户的摘要

现状：框架已合入 develop，只有匹配 `[guardrails-test]` 的假检测器。做完后：网关用规则查密钥（D3），用 DeepSeek 判官查有害内容、提示词攻击和管理员写的业务规则（D1/D4/D5）；每个项目一个判官实例、各自配置；同阶段规则并行，单阶段最坏等待等于判官超时（默认 10s，含重试）。配置存数据库，通过 POST 接口读写并热更新；默认无配置即不检测。

v5 相对 v4：启动时库中配置构建失败改为拒启（与仓内先例一致，不再静默放行）；每个请求在前置钩子固定一份检查器快照，热更新只影响后续请求；其余为评审 4 建议的补充。v4 相对 v3 的变化（Gate 1 用户裁决）：配置从 JSON 文件改为数据库表 + `POST /api/guardrails/*` 接口，热更新；判官送检上限默认与框架总上限一致（64KB）；另订正评审 3 指出的三处口径。判官仍每项目一个实例（用户 2026-09-19 裁决，暂不合并调用）。

已裁决事项（2026-09-19）：配置存库并提供接口；判官调用不进上游日志与计费；判官理由不写日志；判官文本上限默认 64KB 可下调；成本口径（示例配置每请求最多 5 次判官调用；上限 64KB 时按实验单价约 ≤0.125 元）；密钥等级专用 High / 通用 Medium。

## 4. 接口与数据设计

### 4.1 密钥检测器 `detectors/secrets`

```go
type Options struct{ IgnoredKeywords []string } // 管理员忽略词：小写、去重，命中值含任一子串则丢弃
func New(opts Options) (*Detector, error)
func (d *Detector) Detect(ctx, text) ([]guardrails.Finding, error)
```

规则数据 `data/rules.json`（id、description、regex、keywords、entropy、secret_group、allow{regexes,stop_words}、level）与 `data/NOTICE`（Gitleaks MIT）。转换脚本 `ee/scripts/secrets-rules-convert.py`：输入 Gitleaks `gitleaks.toml` 路径 + 本仓 `data/rules.extra.json`（修正与新增），输出 `rules.json`；去掉纯路径规则与 `path` 条件；`generic-*` 规则 level=medium、其余 high；`data/README.md` 记录来源版本与命令。

扫描：小写 → 关键词命中集合（逐词 `strings.Contains`）→ 只跑命中规则（无关键词规则总是跑）→ `FindAllStringSubmatchIndex` → secret 取 `secret_group` 或第一个非空组 → 熵 ≤ 阈值丢弃 → 内置白名单（`sk-bf-` 前缀，不可关闭）→ 全局与规则 allow → 管理员忽略词 → 同一 secret 已有专用规则命中则丢 generic。每 32 条规则查一次 `ctx.Err()`。返回每命中一条 `Finding{Level}`。

规则内容：Gitleaks v8.30.1 去路径规则；修正 Gemini `AQ.`、Anthropic 通配、OpenAI 不定长；新增可写专用规则的厂商（[密钥格式核实](../../../../product/需求/内容安全/密钥格式核实.md)第二节）；`generic-api-key` 关键词补 密钥、秘钥、密码、令牌、口令、apikey。长度写「前缀 + 最小长度」。

### 4.2 判官检测器 `detectors/judge`

```go
type Model interface { Complete(ctx context.Context, system, user string) (string, error) }
type Kind string // Harmful, PromptAttack, BusinessRule
type Options struct {
    Model    Model
    Kind     Kind
    Rule     string // Kind=BusinessRule 时必填
    Stage    guardrails.Stage
    Retries  int    // 3–5，默认 3
    MaxBytes int    // 送检上限；超过返回 guardrails.ErrDetectorTextTooLarge，不重试
}
func New(opts Options) (*Detector, error)
```

请求：system=提示词（`prompts/harmful.md`、`prompt_attack.md`、`business_rule.md`，`go:embed`，业务规则模板以 `{{rule}}` 替换），user=`{"stage":…,"text":…}`。解析 `{"risk_level":"none|low|medium|high"}`：none→空结果，其余→`Finding{Level}`；非法 JSON、未知等级、空响应各算一次失败。失败按 200ms×2ⁿ 退避重试至 `Retries` 次（3 次重试退避合计 1.4s）；每次尝试用传入 ctx，规则 `Timeout` 到期即停并返回 `context.DeadlineExceeded`，框架记 `DetectorTimeout`。理由字段忽略。两个哨兵错误不互相包装。

### 4.3 并行执行与拦截来源

```go
type CheckResult struct {
    Action          Action
    Blocking        *RuleEvaluation // 不变量：Action==Block 且 err==nil 时非 nil，指向 RuleEvaluations 中对应元素；其余情况 nil
    RuleEvaluations []RuleEvaluation
}
var ErrDetectorTextTooLarge = errors.New(...) // 检测器声明文本超过自身上限
const TextTooLarge Failure = "text_too_large"
```

`Check`：先做取消/长度/UTF-8 检查 → 派生 `blockCtx, cancel` → 同阶段规则各起 goroutine 调 `evaluateRule(parent, blockCtx, rule)` → `WaitGroup` 等全部结束后汇总。评估：detect 用 `blockCtx` 派生的 `Timeout` 子 ctx；返回后先查 `parent.Err()`（父取消 → 返回 error，`Check` 返回该 error 与已完成评估）；再查 `blockCtx.Err()`（因 Block 取消且本条未完成 → 丢弃）；否则按失败/阈值逻辑记录，`errors.Is(err, ErrDetectorTextTooLarge)` 记 `TextTooLarge`。任一 goroutine 得到 Block 即 `cancel()`；汇总时 `Blocking` 取配置顺序最靠前的 Block 评估。`RuleEvaluations` 按配置顺序，仅含完成的评估。

`plugin.checkText`：`Blocking.Outcome==Failed` 时按 `Failure` 映射——`TextTooLarge` → `content_safety_text_too_large`，其余 → `check_failed`；`Matched` → `content_safety_blocked`；`err!=nil` 路径不变。

### 4.4 热更新与判官适配器 `guardrails/host`

插件：`checker` 改为 `atomic.Pointer[guardrails.Checker]`，新增 `Swap(*Checker)`；`New` 允许 nil 检查器启动。**每请求一份快照**：`PreLLMHook` 进入后第一件事读取当前指针并以包内未导出零尺寸类型为 key 写入 ctx（`ctx.SetValue`，落在根 ctx），**已存在则不覆盖**（fallback 会重跑前置钩子，`bifrost.go:7920`）；nil 也写入。流式准入与输入检查都用这份快照；`PostLLMHook`（含流式每个 chunk）只读 ctx 快照：**缺失或为 nil 都直接透传**，不回读当前指针，避免 nil→非 nil 的 Swap 让已准入的流中途撞不支持错误。热更新因此只影响 Swap 之后到达的请求，已准入的流不会中途改判。

```go
type Client interface { ChatCompletionRequest(*schemas.BifrostContext, *schemas.BifrostChatRequest) (*schemas.BifrostChatResponse, *schemas.BifrostError) }
func NewJudgeModel(client Client, provider, model string, log Logger) judge.Model
type Builder struct{ client Client; providers ProviderLookup; log Logger }
func (b *Builder) Build(ctx, cfg config.Config) (*guardrails.Checker, error) // 校验 provider 存在，构造密钥与判官实例、规则集
```

`Complete`：`schemas.NewBifrostContext(ctx, deadline)` + `defer Cancel()` + `bifrost.PrepareContextForInternalRequest`；`Temperature=0`、`MaxCompletionTokens=200`、`ResponseFormat={"type":"json_object"}`；取 `choices[0]` 文本；`BifrostError` 转普通 error（不含正文）。每次调用 Info 日志：provider、model、token 用量、耗时、成功或失败类别。若判官 provider `MaxRetries>0`，`Build` 记 Warn。

### 4.5 配置模型 `guardrails/config`（仅标准库）

```json
{
  "deny": {"status": 400, "message": "内容未通过安全检查"},
  "max_text_bytes": 65536,
  "judge": {"provider": "deepseek", "model": "deepseek-v4-flash", "retries": 3, "timeout_ms": 10000, "max_text_bytes": 65536},
  "secrets":       {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block", "timeout_ms": 500, "ignored_keywords": []},
  "harmful":       {"enabled": true, "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "prompt_attack": {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "business_rules": [{"id": "pricing", "rule": "……", "enabled": true, "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"}]
}
```

`config.Parse([]byte)`：`DisallowUnknownFields`；`judge.max_text_bytes` 省略时取 `max_text_bytes`。`Validate` 拒绝：`deny.status` 不在 400–599、数值非正、判官上限大于总上限、阈值/动作/阶段非法、`judge` 缺 provider/model、`retries` 不在 3–5、`business_rules` ID 重复或 rule 空、所有项目未启用。判官类项目 `Timeout` 取 `judge.timeout_ms`；密钥取自身。规则 ID=`<项>:<阶段>`，判官实例 ID=`judge:<项>:<阶段>`。

### 4.6 持久化与接口

`guardrails/persistence`：表 `ee_guardrails`（`id=1` 单例，`config` TEXT、`version` INT、`updated_at`），迁移 ID `ee_guardrails_v1`，顾问锁键与品牌/身份不同，SQLite busy 重试与品牌一致；`Read`（无行返回 `ErrNotConfigured`）、`Update(config, expectedVersion)`（版本不符返回冲突）、`Reset`。

`guardrails/http`：
- `POST /api/guardrails/get` → `{config, version}`；未配置返回 `{config: null, version: 0}`。
- `POST /api/guardrails/update` body `{config, version}` → `Parse`/`Validate` → `Builder.Build`（含 provider 校验）→ `store.Update` → `plugin.Swap` → 返回新版本。校验失败 400，版本冲突 409，provider 不存在 400。
- `POST /api/guardrails/reset` → 删除行 → `plugin.Swap(nil)`。
- routes.txt：`get` 登记 `@ managed Settings.View none ordinary`，`update`/`reset` 登记 `@ managed Settings.Manage none ordinary`；写接口经 `auth` 中间件。

`app`：迁移 → 读库（无行以 nil 启动；有行则 Build，**失败拒启**，日志说明失败原因与恢复方式：修复 provider，或直接删除 `ee_guardrails` 表行后重启）→ `plugin.New` → `SyncLoadedPlugin`（内置插件之前）→ 注册路由。`EE_GUARDRAILS_FAKE` 与库中配置同时存在时拒启；FAKE 模式运行期间 `update` 接口返回 409（不允许在假检测器模式下写入生产配置）。

`version` 约定：未配置时 `get` 返回 0，`update` 须带 0；每次 update 递增；reset 删除行后回到 0。`config` 包是序列化边界（带 `json` 标签的 DTO 与校验），构建出的规则与检测器选项才是根包业务类型，不违反「业务类型不带标签」规则。

## 6. 测试策略

- 密钥：每类新增规则一真一假；中文字段名召回；`sk-bf-` 不命中；忽略词；generic 去重；取消；基准。
- 判官：解析矩阵；重试次数与退避总时长；超时后不再重试；超限返回 `ErrDetectorTextTooLarge` 且不重试；越界拒绝构造。
- 并行：一条 Block 时其余被取消且不在结果；Observe 在 Block 前完成则保留；无 Block 顺序与配置一致；父取消返回 error 并保留已完成评估；`-race`。
- 插件：`Blocking` 三条映射各一断言（Matched / Failed+TextTooLarge / Failed+其他）；`Swap` 期间并发请求无竞态；快照：Pre 后 Swap，Post 仍用旧快照（含流式 chunk）；nil 快照下 Swap 进含输出规则的配置，进行中的流仍透传；fallback 重跑 Pre 不覆盖快照；nil 检查器透传；`plugin_test.go` nil 断言反转；既有集成测试加密钥规则用例。
- 配置与构建：拒绝条件逐项；示例配置生成的规则集断言；provider 不存在拒绝。
- 持久化与接口：迁移幂等；版本冲突 409；FAKE 模式 update 409；update 后新请求生效（冒烟）；reset 后不检测；启动时坏配置拒启（单测）；权限登记经 `VerifyRoutes` 全覆盖守卫。
- 盲区：真实准确率与延迟只在独立记录；提示词质量不断言；provider 自身重试叠加只 Warn。

## 8. 风险与禁止事项

- 判官延迟：单阶段最坏等于 `judge.timeout_ms`（含重试），两阶段叠加；真实分布在独立验证中记录。
- 因拦截被取消的判官调用在 provider 侧仍会跑完并计费（`core/providers/utils/utils.go:355-365`）。
- 密钥规则长度多来自第三方；`ignored_keywords` 止血。
- 启动时库中配置构建失败（如 provider 已删）拒启：网关不可用直到修复，但不会静默放行。
- 权限沿用 `Settings.Manage`：能改常规设置、缓存的人也能关闭内容安全；本期不新增权限模块，列为已接受风险，期 2 随管理页面再评估。
- 禁止：日志含原文、命中值、判官理由；判官失败当通过；改上游；根包与 detectors 引网络库或 `core/schemas`；默认启用；新增 RBAC 模块。
