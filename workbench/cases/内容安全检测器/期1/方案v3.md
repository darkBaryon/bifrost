## 给用户的摘要

现状：框架已合入 develop，只有匹配 `[guardrails-test]` 的假检测器。做完后：网关用规则查密钥（D3），用 DeepSeek 判官查有害内容、提示词攻击和管理员写的业务规则（D1/D4/D5）；同阶段规则并行，一次请求在输入、输出两个阶段各多等一段判官时间，单阶段最坏等于 `judge.timeout_ms`（默认 10s，含重试）。配置来自 JSON 文件，默认不启用。

v3 相对 v2 只订正口径：送检上限的汉字换算、单阶段最坏等待、每请求费用合计、超限的失败路径与日志类别。v2 相对 v1 的变化：判官调用改用上游提供的内部子请求方式（v1 的写法会让判官取不到 key）；适配器从 `app` 移到 `guardrails/host`；并行执行的取消语义和插件错误码判定重新定义；送检文本设上限；转换脚本入库。

拍板项：
1. **期 1 配置用 JSON 文件**，管理 API 与数据库留期 2。利：不引入表和接口；弊：改配置要重启。
2. **判官调用不进上游日志与计费**（内部子请求跳过插件管线）。判官 token 用量本期只写 EE 日志，期 2 再落库。
3. **判官理由不写日志**：理由可能复述原文。
4. **送检判官的文本上限 16KB**（约 5 千汉字，全部历史消息拼接后计），超过记为独立失败类别 `text_too_large`，按该规则 `on_error` 处置（用户已定拦截），客户端错误码 `content_safety_text_too_large`。利：延迟与费用可控；弊：长对话会被拒。也可选「只送最近 N 轮」，本期不做。
5. **成本口径**：每个请求每阶段的判官调用数 = 启用的项目数（示例配置：输入 3 次、输出 2 次，合计 5 次），单次 ≤16KB 文本；按实验单价估算每次 ≤0.02 元、每请求 ≤0.1 元。因拦截被取消的判官调用在 provider 侧仍会跑完并计费（`core/providers/utils/utils.go:355-365`）。
6. **密钥等级映射**：厂商专用规则 High、通用规则 Medium。后果：阈值配 `high` 时「password: <高熵串>」这类通用命中只记录不拦，配 `medium` 则拦。

## 4. 接口与数据设计

### 4.1 密钥检测器 `detectors/secrets`

```go
type Options struct{ IgnoredKeywords []string } // 管理员忽略词：小写、去重，命中值含任一子串则丢弃；与 Gitleaks StopWords 同义
func New(opts Options) (*Detector, error)
func (d *Detector) Detect(ctx, text) ([]guardrails.Finding, error)
```

规则数据 `data/rules.json`（字段：id、description、regex、keywords、entropy、secret_group、allow{regexes,stop_words}、level）与 `data/NOTICE`（Gitleaks MIT）。转换脚本 `ee/scripts/secrets-rules-convert.py`：输入 Gitleaks `gitleaks.toml` 路径 + 本仓 `data/rules.extra.json`（修正与新增），输出 `rules.json`；脚本去掉纯路径规则与 `path` 条件，`generic-*` 规则 level=medium、其余 high，`data/README.md` 记录来源版本与命令，可复现。

扫描：小写 → 关键词命中集合（逐词 `strings.Contains`）→ 只跑命中规则（无关键词规则总是跑）→ `FindAllStringSubmatchIndex` → secret 取 `secret_group` 或第一个非空组 → 熵 ≤ 阈值丢弃 → 内置白名单（`sk-bf-` 前缀，不可关闭）→ 全局与规则 allow → 管理员忽略词 → 同一 secret 已有专用规则命中则丢 generic。每 32 条规则查一次 `ctx.Err()`。返回每命中一条 `Finding{Level}`。

规则内容：Gitleaks v8.30.1 去路径规则；修正 Gemini `AQ.`、Anthropic 通配、OpenAI 不定长；新增可写专用规则的厂商（[密钥格式核实](../../../../product/需求/内容安全/密钥格式核实.md)第二节）；`generic-api-key` 关键词补 密钥、秘钥、密码、令牌、口令、apikey。长度写「前缀 + 最小长度」。

### 4.2 判官检测器 `detectors/judge`

```go
type Model interface { Complete(ctx context.Context, system, user string) (string, error) }
type Kind string // Harmful, PromptAttack, BusinessRule
type Options struct {
    Model    Model
    Kind     Kind
    Rule     string // Kind=BusinessRule 时必填
    Stage    guardrails.Stage
    Retries  int    // 3–5，默认 3
    MaxBytes int    // 送检上限，默认 16384；超过返回 guardrails.ErrDetectorTextTooLarge，不重试
}
func New(opts Options) (*Detector, error)
```

请求：system=提示词（`prompts/harmful.md`、`prompt_attack.md`、`business_rule.md`，`go:embed`，沿用实验初稿，业务规则模板以 `{{rule}}` 替换），user=`{"stage":…,"text":…}`。解析 `{"risk_level":"none|low|medium|high"}`：none→空结果，其余→`Finding{Level}`；非法 JSON、未知等级、空响应各算一次失败。失败按 200ms×2ⁿ 退避重试至 `Retries` 次（3 次重试的退避合计 1.4s，其余预算留给调用）；每次尝试都用传入 ctx，规则 `Timeout` 到期即停并返回 `context.DeadlineExceeded`，由框架记 `DetectorTimeout`。超限不重试。理由字段忽略。

### 4.3 并行执行与拦截来源

```go
type CheckResult struct {
    Action          Action
    Blocking        *RuleEvaluation // 不变量：Action==Block 且 err==nil 时非 nil，指向 RuleEvaluations 中的副本；其余情况 nil
    RuleEvaluations []RuleEvaluation
}
```

`Check`：先做取消/长度/UTF-8 检查 → 派生 `blockCtx, cancel` → 同阶段规则各起 goroutine 调 `evaluateRule(parent, blockCtx, rule)` → `WaitGroup` 等全部 goroutine 结束后再汇总（不提前返回，避免竞态）。评估函数：detect 用 `blockCtx` 派生的 `Timeout` 子 ctx；detect 返回后**先查 `parent.Err()`**（父取消 → 返回 error，`Check` 返回该 error 与已完成评估）；再查 `blockCtx.Err()`（因 Block 取消且本条未完成 → 丢弃，不写入结果）；否则按现有失败/阈值逻辑记录。任一 goroutine 得到 `Action==Block` 即 `cancel()`；汇总时 `Blocking` 取 `RuleEvaluations` 中配置顺序最靠前的 Block 评估。`RuleEvaluations` 按配置顺序，仅含完成的评估。

框架新增 `ErrDetectorTextTooLarge` 哨兵与 `Failure` 值 `TextTooLarge`（`evaluation.go` 用 `errors.Is` 识别），与 `DetectorError` 区分，日志 `failure=text_too_large`。

`plugin.checkText`：`Blocking.Outcome==Failed` 时按 `Blocking.Failure` 映射——`TextTooLarge` → `content_safety_text_too_large`，其余 → `check_failed`；`Blocking.Outcome==Matched` → `content_safety_blocked`；`err!=nil` 路径不变。

### 4.4 判官适配器 `guardrails/host`

```go
type Client interface { ChatCompletionRequest(*schemas.BifrostContext, *schemas.BifrostChatRequest) (*schemas.BifrostChatResponse, *schemas.BifrostError) }
func NewJudgeModel(client Client, provider, model string, log Logger) judge.Model
```

`Complete`：`schemas.NewBifrostContext(ctx, deadline)`（deadline 取 ctx 的）+ `defer Cancel()` + `bifrost.PrepareContextForInternalRequest`；请求 `Temperature=0`、`MaxCompletionTokens=200`、`ResponseFormat={"type":"json_object"}`；取 `choices[0]` 文本；`BifrostError` 转普通 error（不含响应正文）。每次调用 Info 日志：provider、model、token 用量、耗时、成功与否。

### 4.5 配置与装配（`app/guardrails.go`）

`EE_GUARDRAILS_CONFIG` 指向 JSON，未设置不注册；解析用 `DisallowUnknownFields`。

```json
{
  "deny": {"status": 400, "message": "内容未通过安全检查"},
  "max_text_bytes": 65536,
  "judge": {"provider": "deepseek", "model": "deepseek-v4-flash", "retries": 3, "timeout_ms": 10000, "max_text_bytes": 16384},
  "secrets":       {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block", "timeout_ms": 500, "ignored_keywords": []},
  "harmful":       {"enabled": true, "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "prompt_attack": {"enabled": true, "stages": ["input"], "threshold": "medium", "on_match": "block", "on_error": "block"},
  "business_rules": [{"id": "pricing", "rule": "……", "stages": ["input","output"], "threshold": "medium", "on_match": "block", "on_error": "block"}]
}
```

判官类项目的 `Timeout` 统一取 `judge.timeout_ms`；密钥取自身 `timeout_ms`。拒启条件：未知字段、`deny.status` 不在 400–599、`max_text_bytes`/`timeout_ms`/`judge.max_text_bytes` 非正或判官上限大于 `max_text_bytes`、阈值/动作/阶段非法、`judge` 缺 provider/model 或 provider 未在网关配置（经 `host.Config.ConfigStore.GetProviderConfig` 查；`ConfigStore` 为 nil 时拒启）、`retries` 不在 3–5、`business_rules` ID 重复或 rule 空、所有项目都未启用。规则 ID=`<项>:<阶段>`，判官实例 ID=`judge:<项>:<阶段>`（Stage 是检测器构造参数）。`EE_GUARDRAILS_FAKE` 与本配置互斥，同时设置拒启。

## 6. 测试策略

- 密钥：每类新增规则一真一假；中文字段名召回；`sk-bf-` 不命中；忽略词生效；generic 去重；取消响应；基准。
- 判官：解析矩阵；重试次数与退避总时长；超时后不再重试；超上限返回错误；`Retries`/`MaxBytes` 越界拒绝构造。
- 并行：一条 Block 时其余被取消且不在结果；Observe 与 Block 并发时 Observe 若已完成则保留；无 Block 时顺序与配置一致；父取消返回 error 且保留已完成评估；`-race`。
- 插件：`Blocking.Outcome` 两种取值对应两种错误码；既有集成测试加密钥规则用例。
- 装配：拒启条件逐项；示例配置生成的规则集断言。
- 盲区：真实准确率与延迟只在独立记录中；提示词质量不断言；provider 自身重试叠加只做 Warn 提示不测。

## 8. 风险与禁止事项

- 判官延迟：每阶段最多一次调用时长（并行），两阶段叠加；`timeout_ms` 到期即拦截。真实分布在独立验证中记录，超预期由用户决定是否调整阈值或阶段。
- 密钥规则长度多来自第三方；`ignored_keywords` 止血。
- 判官 provider 若自带重试，实际调用次数 = (1+MaxRetries)×(1+retries)；装配时 Warn。
- 禁止：日志含原文、命中值、判官理由；判官失败当通过；改上游；根包与 detectors 引网络库或 `core/schemas`；默认启用。
