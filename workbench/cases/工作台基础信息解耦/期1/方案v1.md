## 4. 设计

### 4.1 后端接口

新增 `POST /api/console/bootstrap`，正文严格JSON空对象 `{}`。响应：

```ts
{ is_db_connected: boolean; is_logs_connected: boolean; env_label: string | null;
  restart_required?: { required: boolean } }
```

前三字段来自宿主已持有的Config；连接布尔保持原语义（对应store是否存在），不额外做数据库探测。空环境标识归null。第四字段是对最初三字段候选的兼容补全：Sidebar已有重启提示需要它；仅白名单投影required，绝不返回内部reason/管理员/认证/代理/连接串等设置。nil或读取错误时省略restart_required，基础响应仍200；失败记录固定诊断原因与request_id，不输出原始存储错误。

handler位于ee/internal/host/console.go，注册到现有AuthAdapter；精确路径在APIMiddleware交给自身处理。新kindConsoleService=console-service登记routes.txt，仅此POST，自行验证，不放宽/api/config。不新增数据库表、权限码或业务服务。

处理顺序：建立诊断上下文和no-store；检查SameOrigin；拒绝非空Authorization；Session.Authenticate个人Cookie；严格对象解码（application/json、16KiB、禁止重复/未知字段、多对象、非对象）；读取并转换基础状态。使用identityhttp的错误结构：身份失效401、来源403、非法请求400、身份存储故障/缺宿主配置503。所有成功/失败响应no-store。该只读端点允许仍使用初始密码的有效会话，不改变其他端点的强制改密规则。

新增identityhttp.DecodeJSONObject(c,*struct{})包装现有decode(...,false)。新增窄ConsoleLogger.Warn接口/WithConsoleLogger，由app已有logger注入；无logger不得影响响应，生产装配必须注入。

### 4.2 前端覆盖

公共类型 `ui/lib/types/console.ts`：ConsoleConfig仅含四个基础字段（restart保留可选reason用于OSS结构兼容）、ConsoleConfigQueryOptions.skip、查询状态合同。`@enterprise/hooks/useConsoleConfig` 导出 useConsoleConfigQuery(options?)、useConsoleAuthEnabled()、CONSOLE_ONBOARDING_ENABLED。

fallback调用useGetCoreConfigQuery({}, options)，auth hook沿用完整config.auth_config.is_enabled，onboarding=true；EE覆盖注入baseApi端点调用POST /console/bootstrap正文{}，复用credentials和既有错误规范，返回同一查询状态结构。端点providesTags:["Config"]复用设置更新的失效通知，确保环境/重启状态更新；不会把bootstrap数据写入getCoreConfig缓存。EE auth hook复用现有useIsAuthEnabledQuery的is_auth_enabled，onboarding=false；不实现新的登录或权限Context。

ClientLayout换用窄hook及窄类型，保留public/临时令牌skip、原加载/出错/重试/日志独立模式；不把403/失败当就绪。EE跳过旧Widget，Sidebar通过已有skip停用向导查询并避免resume入口，普通版行为不变。Sidebar换窄hook保留环境标签与重启提示（EE不提供reason时用现有通用文案）；Topbar只把auth读取换成auth hook，现有账号显示/退出行为保持。

不修改RoutingRules任何业务组件、useRbac或RBAC矩阵。会话切换清缓存/完整登录接入不在本切片中，不声称已解决。
