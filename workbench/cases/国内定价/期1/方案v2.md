## 给用户的摘要

现在通过自定义厂商调用国内模型，费用一律算成零，因为上游按管理员起的厂商名查定价表，对不上。
完成后，ee 启动时读一份随版本发布的国内价格文件，按每个自定义厂商的接入域名认出它是哪家，把该家的价格写成上游的"定价覆盖"，费用立即按官网价计算。
不新建表、不改上游文件、不做页面；价格以美元为基准，人民币价按配置的汇率换算；管理员手工建的覆盖不受影响；内置厂商（如 deepseek）不受影响。
本版按[方案评审 #1](方案评审1.md)修订：删去对内置厂商的识别，补双节点同时启动与删除幂等的失败路径，冒烟脚本改为自建夹具注入环境变量。
**拍板项一条（Gate 1）**：官网阶梯计价与分时段价在上游覆盖表里只能写一个单价，取哪一档——推荐"阶梯取最低输入长度档、时段取标准价"，代价是长上下文请求会少算；备选"阶梯取最高档、时段取高峰价"，代价是短请求多算。产品方案第五节三项决策全部沿用。
本方案未经复核，未开始改业务代码。

## 3. 目标与非目标

**目标**

1. `ee/internal/pricing/` 新模块：价格文件模型与解析、厂商识别、币种换算、覆盖行生成、幂等同步。
2. 价格数据文件 `ee/internal/pricing/data/cn-prices.json` 随二进制嵌入，收录阿里百炼、DeepSeek、Kimi、智谱在售对话模型（产品方案第五节范围）。
3. 启动时（attach 内）执行一次同步：识别**自定义厂商** → 生成覆盖行 → 与表内现状比对 → 增、改、删本功能管理的行 → Upsert 内存。
4. 环境变量 `EE_PRICING_USD_CNY`（汇率，覆盖文件头默认值）、`EE_PRICING_VENDOR_MAP`（手工对应表）、`EE_PRICING_FILE`（用外部文件替换嵌入文件，供冒烟与临时修价）。
5. 冒烟脚本、包 README、`ee/docs/国内定价.md` 使用说明。

**非目标**：人民币基准切换（产品方案第八节）；页面；在线拉价；海外模型修价；**内置厂商**（`CustomProviderConfig == nil`，如内置 deepseek）不识别、不写覆盖；处理 `source_of_truth=config.json` 组合；运行期监听厂商增删；多节点运行期一致性（见 §8）；阶梯计价与时段折扣的精确表达（见 4.2 取价规则）。

### 4.2 价格文件

JSON，字段名对齐 LiteLLM 价格文件，便于日后提 PR。

```json
{
  "version": "2026-09-13",
  "pricing_rule": "lowest-tier-standard-rate",
  "rates": { "CNY": 7.20, "checked_at": "2026-09-13" },
  "vendors": [
    {
      "id": "dashscope",
      "name": "阿里云百炼",
      "endpoint_hosts": ["dashscope.aliyuncs.com"],
      "price_page": "https://help.aliyun.com/zh/model-studio/model-pricing",
      "models": [
        { "model": "qwen3-max", "currency": "CNY", "unit": "per_million_tokens",
          "input_cost": 6, "output_cost": 24, "cache_read_input_cost": 1.2,
          "checked_at": "2026-09-13", "note": "阶梯计价，取 0-32K 档" }
      ]
    }
  ]
}
```

- `currency` 取 `CNY` 或 `USD`；`unit` 固定 `per_million_tokens`；三个价格字段单位随 `unit`。
- **取价规则（Gate 1 拍板项 A）**：上游覆盖表对一个模型只能写一个单价，表达不了官网的输入长度阶梯（阿里、智谱）与分时段价（DeepSeek）。两个候选，文件头 `pricing_rule` 记录采用的那个，每条 `note` 注明取了哪一档：
  - **A1（推荐）`lowest-tier-standard-rate`**：阶梯取最低输入长度档；分时段取标准（高峰）价；限时折扣不取；免费模型写 0。偏差方向：超出最低档的长上下文请求**少算**。推荐理由：多数控制台请求落在最低档，与官网账单差异最小。
  - **A2 `highest-tier-peak-rate`**：阶梯取最高档、时段取高峰价。偏差方向：短请求**多算**，预算偏保守。
  - 无论选哪个，都不改变代码结构，只改数据文件与文档措辞；用户不选时不填数据文件（步骤 4 阻塞）。
- 校验：`vendors[].id` 唯一、`endpoint_hosts` 非空、同一厂商内 `model` 唯一、价格非负、`currency` 在枚举内、`rates` 含所用币种、`pricing_rule` 在枚举内。任一条不过整份文件判无效。

### 4.3 厂商识别（`vendors.go`）

输入：本部署厂商列表（名字、是否自定义、`base_url`）+ 价格文件 + 手工对应表。只处理**自定义厂商**（`CustomProviderConfig != nil`）；内置厂商直接跳过，不记日志。规则：

1. 手工对应表优先：`EE_PRICING_VENDOR_MAP="qwen=dashscope,kimi2=moonshot"`，键为本部署厂商名，值为价格文件 `vendors[].id`。值不存在于价格文件 → 启动失败（配置错误）；键不是本部署的自定义厂商 → 记 warn 并忽略该项（厂商可能已被删除，不因此拒启）。
2. 否则取 `base_url` 的主机名：`NetworkConfig` 为 nil 或 `base_url` 为空 → 视为无接入地址，按未识别处理；地址无 scheme（如 `dashscope.aliyuncs.com/compatible-mode/v1`）先补 `https://` 再解析；主机名与各厂商 `endpoint_hosts` 做**等于或以 `.<host>` 结尾**匹配（`dashscope-intl.aliyuncs.com` 不是 `dashscope.aliyuncs.com` 的子域，不误配）。
3. 命中多个厂商 → 视为配置错误，启动失败；命中零个 → 记 info 日志"未识别厂商 X（主机 Y），可用 EE_PRICING_VENDOR_MAP 指定"（主机名解析结果打进日志便于排查），跳过。

输出：`[]Match{Provider, VendorID}`。

### 4.4 覆盖行生成（`overrides.go`）

| 字段 | 值 |
|---|---|
| `ID` | UUID v5，命名空间为固定常量 `namespaceID`，名字为 `provider + "/" + model`；重启不变，多节点算出同一 ID |
| `Name` | `ee-pricing: <vendorID>/<model>`；前缀常量 `namePrefix = "ee-pricing: "` 是"本功能管理的行"的唯一标记，文档写明为保留前缀 |
| `ScopeKind` / `ProviderID` | `provider` / 厂商名（原样） |
| `MatchType` / `Pattern` | `exact` / 模型名 |
| `RequestTypes` | `chat_completion`、`responses`、`text_completion` |
| `PricingPatchJSON` | `input_cost_per_token`、`output_cost_per_token`，有缓存价时加 `cache_read_input_token_cost`；单位美元/每 token = 价格 ÷ 1e6 ÷ 汇率（USD 时汇率取 1） |
| `ConfigHash` | 空串 |

换算函数 `toUSDPerToken(amount, currency, rates)` 单独成函数并有表驱动测试。

### 4.5 同步（`sync.go`）

```go
type Service struct { overrides overrideStore; catalog catalog; providers providerLister; log logger }
func New(file PriceFile, opts Options, deps Deps) (*Service, error)
func (s *Service) Sync(ctx context.Context) (Report, error)
```

窄接口（根包定义，`persistence` 实现）与两个错误哨兵：

```go
var ErrRowExists  = errors.New("pricing override row already exists") // persistence 由 configstore.ErrAlreadyExists 映射
var ErrRowMissing = errors.New("pricing override row missing")        // persistence 由 configstore.ErrNotFound 映射

type overrideStore interface {
    List(ctx) ([]OverrideRow, error)           // 全表
    Create(ctx, OverrideRow) error             // 冲突返回 ErrRowExists
    Update(ctx, OverrideRow) error             // 上游 Save，兼作 create-or-update
    Delete(ctx, id string) error               // 已不存在返回 ErrRowMissing
}
type catalog interface {
    Upsert(rows ...OverrideRow) error          // → ModelCatalog.UpsertPricingOverrides
    Delete(id string)                          // → ModelCatalog.DeletePricingOverride
}
type providerLister interface { List(ctx) ([]Provider, error) }  // → ConfigStore.GetProvidersConfig；Provider 含 Name/Custom/BaseURL
```

`Sync` 步骤：

1. 期望集 = 对每个 `Match` 展开该厂商全部模型的覆盖行。
2. 现状集 = `List` 中 `Name` 以 `namePrefix` 开头的行，按 ID 索引。
3. 差异：期望有现状无 → `Create`；两边都有但字段不同 → `Update`；现状有期望无 → `Delete`。字段相同 → 跳过。
4. 表操作全部成功后，一次 `catalog.Upsert(期望集...)`，逐个 `catalog.Delete(删除集)`。
5. 返回 `Report{Created, Updated, Deleted, Unchanged, Unrecognized []string}` 并打一行 info 日志 `pricing sync: created=%d updated=%d deleted=%d unchanged=%d unrecognized=%v`。

**并发与幂等**（双节点共库同时首启、或一节点先删）：

| 情形 | 行为 |
|---|---|
| `Create` 返回 `ErrRowExists`（另一节点刚写入同一 ID） | 视为已存在，改走 `Update`（上游 `Save` 收敛到期望值），计入 `Updated`；不中止 |
| `Delete` 返回 `ErrRowMissing`（另一节点已删） | 视为成功，计入 `Deleted`；不中止 |
| 两节点期望集相同 | 表最终一致；各自 Upsert 自己内存，结果相同 |
| 一节点换了新价格文件重启，另一节点未重启 | 表是新价，未重启节点内存仍是旧价，直到它重启或管理员点"重载定价"。本期不处理，文档写明升级时全部节点滚动重启 |

**失败路径**：

| 情形 | 行为 |
|---|---|
| 汇率非法（非正数、非数字） | attach 返回错误，启动失败（配置错误按身份模块惯例）；与价格文件是否有效无关 |
| 价格文件解析或校验失败 | attach 记 error 日志，**不同步、不删除、跳过手工对应表校验**，服务继续启动 |
| 手工对应表引用未知厂商 ID（文件有效时才校验） | attach 返回错误，启动失败 |
| `List`/`Create`/`Update`/`Delete` 任一非幂等失败 | 中止本次同步，记 error，已成功的表操作保留（每行独立提交，非事务；下次启动继续收敛），不 Upsert 内存 |
| 厂商表为空（`nil, nil`） | 期望集为空；现状中本功能的行被删除（config.json 厂商已在 `LoadConfig` 落库，表空即真无厂商） |
| 管理员手工建的覆盖与本功能同作用域同模型 | 不处理，按上游优先级规则叠加（产品方案第四节） |
| 管理员手工建的覆盖名字以 `ee-pricing: ` 开头 | 被视为本功能的行，下次启动会被改写或删除；文档写明该前缀保留 |

不做的事：不在运行期监听厂商增删（管理员加了新厂商需重启一次才补价，写进文档）；不用事务包整批（上游 CRUD 各自提交，粒度按行）。

### 4.6 装配（`app`）

`app/pricing.go`，在 `attach` 中品牌装配之后调用，顺序固定：

1. 读 `EE_PRICING_USD_CNY`（非法 → 返回错误，启动失败）。
2. `pricing.Load(embedded 或 EE_PRICING_FILE)`；失败 → 记 error 日志并 return nil（跳过 3-5，服务继续启动）。
3. 解析 `EE_PRICING_VENDOR_MAP` 并对照文件校验值；未知 → 返回错误，启动失败。
4. `s.Config.ModelCatalog == nil` → 记 warn 并 return nil。
5. `persistence.NewStore(s.Config.ConfigStore, s.Config.ModelCatalog)` → `pricing.New(...)` → `Sync`；`Sync` 返回错误只记 error，不阻断启动。

环境变量常量与读取方式对齐 `app/identity.go`。`app/README.md` 增一段说明本装配。

## 8. 风险、禁止事项与回滚

- **取价规则的方向性偏差**（拍板项 A）：覆盖表只能写一个单价，阶梯与时段模型的费用必然系统性偏离官网账单，方向由 A1/A2 决定，用户在 Gate 1 接受。
- **`source_of_truth=config.json` 且声明 `governance.pricing_overrides`**：上游在 `LoadConfig` 内删掉本功能的行，attach 随即重建，`Start` 才监听，无费用为零窗口；后果只是每次启动日志 `created=N`、`CreatedAt` 重置。写进 `ee/docs/国内定价.md`，不是风险接受项。
- **官网价目变动**：文件带核对日期，费用准确性以该日期为限；无自动手段发现失效。
- **模型名与请求名不一致**（如请求带版本后缀）：exact 匹配不命中则回落定价表或零费用；期 1 不用 wildcard，记为观察项。
- **多节点内存不一致**：见 4.5，靠滚动重启纪律，文档写明。
- **保留前缀**：`ee-pricing: ` 开头的手工覆盖会被接管；文档写明。
- 禁止：改上游文件；用 `SetPricingOverrides`；删除或修改 `Name` 不带前缀的行；在业务根包（含测试）引入 GORM/上游类型；修改 `identity-smoke.py`/`branding-smoke.py`。
- 回滚：删除 `app/pricing.go` 的调用即停止同步；已写入的行可用上游自定义定价页删除，或临时把 `EE_PRICING_FILE` 指向只含 `vendors: []` 的文件重启一次，`Sync` 会删掉全部本功能行。
