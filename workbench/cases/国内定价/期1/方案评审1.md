## 结论

**需修改。** 方案的主干成立：复用 `governance_pricing_overrides` 表、`provider` 作用域按原始厂商名匹配、先写表再 `UpsertPricingOverrides`、在 `attach` 内执行——这四点我逐条在基线源码上核过，与上游 HTTP 创建链路等价，启动时序也不会被 `LoadOverridesFromStore`/`SetPricingOverrides` 冲掉。但有四处必须在 v2 关闭后才能提 Gate 1：

| # | 阻塞项 | 位置 | 最小修正 |
|---|---|---|---|
| 1 | 取价规则（阶梯取最低档、分时段取高峰价、折扣不取）是影响计费金额的业务取舍，产品方案第五节没有这条决策，方案却声明「拍板项：无新增」 | 方案 §4.2、摘要、§9 | 列为 Gate 1 拍板项（给出多算/少算方向），或先回产品方案补决策 |
| 2 | §4.3 第 3 条把**内置厂商**也纳入识别，会给已有定价表价格的内置 `deepseek` 写覆盖行，改变现有费用；产品方案第三节第 3 条只覆盖自定义厂商 | 方案 §4.3 第 3 条、§6 单测「内置 deepseek 按名字匹配」 | 删除该条（只识别 `CustomProviderConfig != nil` 或 `base_url` 非空的厂商），或作为「范围扩大」拍板项单列 |
| 3 | 双节点同时启动时两边算出相同的稳定 ID，后到者 `Create` 触发唯一约束冲突，按 §4.5 失败表「中止、不 Upsert 内存」，该节点在下次重启前费用为零；`Delete` 对已被对方删掉的行返回 `ErrNotFound` 同样中止 | 方案 §4.5 失败路径 | `Create` 遇 `ErrConflict` 视为已存在并继续；`Delete` 遇 `ErrNotFound` 视为成功；或直接用 `UpdatePricingOverride`（上游注释明写它兼作 create-or-update） |
| 4 | 冒烟步 4、5 依赖 `EE_PRICING_FILE`/`EE_PRICING_USD_CNY` 环境变量，但复用的夹具 `identity_smoke.Node.start` 会剥掉子进程环境里所有 `EE_*` 变量，`branding-smoke.Fixture` 也没有覆盖 `start`；按方案现文写不出能跑的脚本 | 方案 §6 冒烟、checklist `pricing-smoke` | 在 §6 写明：`pricing-smoke.py` 自建 `Node` 子类覆盖 `start` 注入本案变量，不改 `identity-smoke.py` |

另有 4 条非阻塞意见（事实修正）与 9 条建议，见下。

### §3 目标与非目标 — 一处范围扩大（阻塞 2）

目标 1-5 与需求报告目标 1-4 对得上；非目标与产品方案一致。但 §4.3 第 3 条「内置厂商同样参与识别」不在产品方案任何一节：第三节第 3 条写的是「自定义厂商的接入地址落在哪家域名下」，第二节明写「内置的 deepseek 调用有费用」（定价表 11/11 有价）。给内置 `deepseek` 写覆盖行，会把它现有的定价表美元价换成「文件价 ÷ 汇率」，是对已正常计费厂商的行为变更，且方案 §6 还专门为它写了单测。这是范围扩大，须删除或列拍板项。

### §4 设计 — 主干成立，两处失败路径与一处业务取舍需补（阻塞 1、3）

- **布局与依赖方向**：符合架构 §7 判定——`configstore.ConfigStore` 接口与 `*modelcatalog.ModelCatalog` 是库类型，不是运行中宿主对象，归 `persistence` 正确；`app` 只做装配。根包三个窄接口由使用方定义、构造注入，符合编码规范。`google/uuid v1.6.0` 已在 ee 模块图中（`go list -m` 核实），升为直接依赖不算引入外部依赖。
- **§4.2 价格文件**：字段设计可用。**取价规则是阻塞 1**——阿里百炼 qwen3-max 等按输入长度阶梯计价，取最低档意味着长上下文请求系统性少算；「分时段取高峰价」则相反。这两个方向都是「业务规则的解释或取舍」（[流程 · Gate 条件触发](../../../规范/流程.md)），产品方案第五节只有三项决策（币种与汇率、四家范围、自动识别+手工兜底——方案摘要写「四项」，笔误），没有这一条。
- **§4.3 厂商识别**：主机名「等于或以 `.<host>` 结尾」的规则正确排除了 `dashscope-intl`。手工表优先、多命中报错、零命中记 info 并提示，与产品验收 7 一致。第 3 条见阻塞 2。
- **§4.4 覆盖行**：UUID v5 以 `provider/model` 命名 → 同一部署重启不变、不同厂商同模型不同，幂等成立；`UpdatePricingOverride` 用 `Save` 且保留 `CreatedAt`（`rdb.go:3104-3116`），比对后只更新变化行即可。`Name` 前缀作为「本功能管理」标记可行，但上游名称校验只做 trim（`governance.go:4848`），管理员手工输入同前缀的行会被当成本功能的行——见建议 6。
- **§4.5 同步**：增/改/删/跳过的差异算法与「先表后内存」顺序正确；`catalog.Delete(id)` 对应 `DeletePricingOverride(id)` 无返回值，接口签名一致。**失败路径缺双节点竞争（阻塞 3）**：ee 的身份冒烟本就覆盖 PostgreSQL 双节点（[身份 checklist](../../身份模块整理/期1/checklist.yaml) `identity-postgres-two-nodes`），两节点同时首启会各自 `Create` 同一 ID，后到者收到 `parseGormError` 映射的唯一约束冲突（`rdb.go:414-417`），按 §4.5 表「中止、不 Upsert 内存」，该节点内存里没有本功能的行，直到重启或管理员点「重载定价」。同理 `DeletePricingOverride` 在 `RowsAffected == 0` 时返回 `ErrNotFound`（`rdb.go:3133-3134`），对方先删就会让本节点中止。「厂商表空 → 删除本功能行」这条我认为成立：`LoadConfig` 已把 config.json 厂商落库，表空即真无厂商。
- **§4.6 装配**：环境变量读法对齐 `identity.go`；`ModelCatalog` 为 nil 时 warn 跳过合理。一处口径不清：文件无效时「不同步、继续启动」，但 `EE_PRICING_VENDOR_MAP` 引用未知厂商要「启动失败」——文件无效就无法校验手工表，方案要写明此时手工表校验跳过还是仍失败。

### §5 实施步骤 — 通过

3. **ee 的 Create/Update/Delete + Upsert 是否与上游 HTTP 链路等价？** 已证实（同一 `ConfigStore` 方法、同一 `ModelCatalog` 方法、`ConfigHash` 空串、`ID` 自生成；上游也不更新 `GovernanceConfig.PricingOverrides` 内存切片）。关闭。

5. **同步失败会不会误删管理员手工行？** 不会：删除集只从 `Name` 以前缀开头的行里算；文件无效时根本不进入 Sync。但反向问题存在——手工行若恰好以该前缀命名会被接管（建议 6）。关闭。
6. **稳定 ID 是否成立？** 成立（UUID v5，命名空间常量 + `provider/model`）。关闭。
7. **`RequestTypes` 三种取值是否合法？** 合法（`bifrost.go:138-142`，`validateRequestTypes` 放行）。关闭。
8. **双节点同时首启会怎样？** 后到者 `Create` 冲突 → 中止 → 内存无本功能行。**未关闭，阻塞 3。**
9. **冒烟脚本能否按 §6 现文写出来？** 不能，`Node.start` 剥掉 `EE_*`。**未关闭，阻塞 4。**
10. **是否重复建设上游能力？** 上游有 config.json `governance.pricing_overrides` 的声明式同步（`config.go:3265-3302`），但它要求改用户的 config.json 且受 `ConfigHash`/`source_of_truth` 语义约束，产品方案已选定「启动导入覆盖表」；方案复用的是上游表与内存入口，没有另建一套。关闭。
11. **是否混入顺手优化？** `EE_PRICING_FILE` 服务冒烟步 4/5 与临时修价，有验收价值；`responses`/`text_completion` 请求类型是覆盖完整性，不是扩张。唯一的越界是 §4.3 第 3 条（阻塞 2）。关闭。
12. **验收是否覆盖产品第六节 7 条？** 覆盖，见 §7 表。关闭。

## 非阻塞意见（v2 应修正的事实）

1. **§8 第一条风险的后果写错了。** `pruneGovernanceConfigToFile` 在 `LoadConfig` 内执行（`config.go:3424`），ee `attach` 紧随其后重建本功能行，`Start` 才开始监听——**不存在「中间窗口费用为零」**。真实后果只是：每次启动本功能的行被删后重建，日志每次都是 `Created=N`，`CreatedAt` 重置。改成这句之后，它就不再是需要用户「接受」的风险，写进 `ee/docs/国内定价.md` 即可。
2. **摘要「产品方案第五节四项决策」应为三项**（币种与汇率；四家范围；自动识别+手工兜底）。
3. **§2 第 1 行补一句**「基础定价表查询经 `normalizeProvider`，覆盖匹配用原始名」，避免实施时把 `ProviderID` 也归一化。
4. **§4.3 补 `NetworkConfig == nil` 的口径**（视为 `base_url` 为空 → 按第 3 条处理，或阻塞 2 修后直接跳过）。

## 建议栏（不立案）

1. **`Delete` 语义**：把「`ErrNotFound` 视为成功」写进 §4.5，与阻塞 3 一起处理。
