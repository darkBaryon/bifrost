## 给用户的摘要

现在通过自定义厂商调用国内模型，费用一律算成零，因为上游按管理员起的厂商名查定价表，对不上。
完成后，ee 启动时读一份随版本发布的国内价格文件，按每个自定义厂商的接入域名认出它是哪家，把该家的价格写成上游的"定价覆盖"，费用立即按官网价计算。
不新建表、不改上游文件、不做页面；价格以美元为基准，人民币价按配置的汇率换算；管理员手工建的覆盖不受影响。
拍板项：无新增，产品方案第五节四项决策全部沿用。
本方案未经复核，未开始改业务代码。

## 3. 目标与非目标

**目标**

1. `ee/internal/pricing/` 新模块：价格文件模型与解析、厂商识别、币种换算、覆盖行生成、幂等同步。
2. 价格数据文件 `ee/internal/pricing/data/cn-prices.json` 随二进制嵌入，收录阿里百炼、DeepSeek、Kimi、智谱在售对话模型（产品方案第五节范围）。
3. 启动时（attach 内）执行一次同步：识别厂商 → 生成覆盖行 → 与表内现状比对 → 增、改、删本功能管理的行 → Upsert 内存。
4. 环境变量 `EE_PRICING_USD_CNY`（汇率，覆盖文件头默认值）、`EE_PRICING_VENDOR_MAP`（手工对应表）、`EE_PRICING_FILE`（用外部文件替换嵌入文件，供冒烟与临时修价）。
5. 冒烟脚本、包 README、`ee/docs/国内定价.md` 使用说明。

**非目标**：人民币基准切换（产品方案第八节）；页面；在线拉价；海外模型修价；处理 `source_of_truth=config.json` 组合；阶梯计价与时段折扣的精确表达（见 4.2 取价规则）。

## 4. 设计

### 4.1 布局与依赖方向

```text
ee/internal/pricing/
├── README.md
├── model.go          价格文件模型（厂商、模型价、币种常量）、覆盖行模型、错误、窄接口
├── pricefile.go      解析与校验价格文件；嵌入默认文件
├── vendors.go        厂商识别：按接入地址主机名匹配；手工对应表合并
├── overrides.go      模型价 → 覆盖行（换算、稳定 ID、命名前缀、请求类型）
├── sync.go           Service.Sync：读厂商、生成、比对、增改删、内存 Upsert
├── data/cn-prices.json
├── *_test.go
└── persistence/
    ├── README.md
    └── store.go      把根包的两个窄接口适配到 configstore.ConfigStore 与 modelcatalog.ModelCatalog
```

依赖：`pricing/persistence → pricing`；`app → pricing + pricing/persistence`。根包只依赖标准库与 `google/uuid`（稳定 ID）。不新增 `host` 代码：本案不触及 `*BifrostHTTPServer`，ConfigStore 与 ModelCatalog 是库类型，按架构 §7 归 `persistence`。

### 4.2 价格文件

JSON，字段名对齐 LiteLLM 价格文件，便于日后提 PR。

```json
{
  "version": "2026-09-13",
  "rates": { "CNY": 7.20, "checked_at": "2026-09-13" },
  "vendors": [
    {
      "id": "dashscope",
      "name": "阿里云百炼",
      "endpoint_hosts": ["dashscope.aliyuncs.com"],
      "price_page": "https://help.aliyun.com/zh/model-studio/model-pricing",
      "models": [
        { "model": "qwen3-max", "currency": "CNY", "unit": "per_million_tokens",
          "input_cost": 6, "output_cost": 24, "cache_read_input_cost": 1.2,
          "checked_at": "2026-09-13", "note": "阶梯计价，取 0-32K 档" }
      ]
    }
  ]
}
```

- `currency` 取 `CNY` 或 `USD`；`unit` 固定 `per_million_tokens`；三个价格字段单位随 `unit`。
- **取价规则**（上游覆盖表达不了阶梯与时段）：阶梯计价取最低输入长度档；分时段取标准（高峰）价；限时折扣不取；免费模型写 0。每条 `note` 注明取了哪一档。
- 校验：`vendors[].id` 唯一、`endpoint_hosts` 非空、同一厂商内 `model` 唯一、价格非负、`currency` 在枚举内、`rates` 含所用币种。任一条不过整份文件判无效。

### 4.3 厂商识别（`vendors.go`）

输入：本部署厂商列表（名字、`base_url`）+ 价格文件 + 手工对应表。规则：

1. 手工对应表优先：`EE_PRICING_VENDOR_MAP="qwen=dashscope,kimi2=moonshot"`，键为本部署厂商名，值为价格文件 `vendors[].id`；值不存在 → 启动失败（配置错误）。
2. 否则取 `base_url` 的主机名，与各厂商 `endpoint_hosts` 做**等于或以 `.<host>` 结尾**匹配（覆盖 `dashscope.aliyuncs.com` 与 `dashscope-intl.aliyuncs.com` 这类子域不误配：只匹配等于或子域，`dashscope-intl` 不是 `dashscope.aliyuncs.com` 的子域）。
3. 内置厂商（无 `CustomProviderConfig`）同样参与识别：内置 `deepseek` 的 base_url 为空时按其名字与 `vendors[].id` 相等匹配，使本功能对内置厂商也能补价。
4. 命中多个厂商 → 视为配置错误，启动失败；命中零个 → 记 info 日志"未识别厂商 X（主机 Y），可用 EE_PRICING_VENDOR_MAP 指定"，跳过。

输出：`[]Match{Provider, VendorID}`。

### 4.4 覆盖行生成（`overrides.go`）

| 字段 | 值 |
|---|---|
| `ID` | UUID v5，命名空间为固定常量 `namespaceID`，名字为 `provider + "/" + model`；重启不变 |
| `Name` | `ee-pricing: <vendorID>/<model>`；前缀常量 `namePrefix = "ee-pricing: "` 是"本功能管理的行"的唯一标记 |
| `ScopeKind` / `ProviderID` | `provider` / 厂商名 |
| `MatchType` / `Pattern` | `exact` / 模型名 |
| `RequestTypes` | `chat_completion`、`responses`、`text_completion` |
| `PricingPatchJSON` | `input_cost_per_token`、`output_cost_per_token`，有缓存价时加 `cache_read_input_token_cost`；单位美元/每 token = 价格 ÷ 1e6 ÷ 汇率（USD 时汇率取 1） |
| `ConfigHash` | 空串 |

换算函数 `toUSDPerToken(amount, currency, rates)` 单独成函数并有表驱动测试。

### 4.5 同步（`sync.go`）

```go
type Service struct { overrides overrideStore; catalog catalog; providers providerLister; log logger }
func New(file PriceFile, opts Options, deps Deps) (*Service, error)
func (s *Service) Sync(ctx context.Context) (Report, error)
```

窄接口（根包定义，`persistence` 实现）：

```go
type overrideStore interface {
    List(ctx) ([]OverrideRow, error)           // 全表
    Create(ctx, OverrideRow) error
    Update(ctx, OverrideRow) error
    Delete(ctx, id string) error
}
type catalog interface {
    Upsert(rows ...OverrideRow) error          // → ModelCatalog.UpsertPricingOverrides
    Delete(id string)                          // → ModelCatalog.DeletePricingOverride
}
type providerLister interface { List(ctx) ([]Provider, error) }  // → ConfigStore.GetProvidersConfig
```

`Sync` 步骤：

1. 期望集 = 对每个 `Match` 展开该厂商全部模型的覆盖行。
2. 现状集 = `List` 中 `Name` 以 `namePrefix` 开头的行，按 ID 索引。
3. 差异：期望有现状无 → `Create`；两边都有但字段不同 → `Update`（`UpdatedAt` 更新）；现状有期望无 → `Delete`（模型从文件移除、厂商被删或不再识别）。字段相同 → 跳过。
4. 表操作全部成功后，一次 `catalog.Upsert(期望集...)`，逐个 `catalog.Delete(删除集)`。
5. 返回 `Report{Created, Updated, Deleted, Unchanged, Unrecognized []string}` 并打一行 info 日志。

失败路径：

| 情形 | 行为 |
|---|---|
| 价格文件解析或校验失败 | attach 记 error 日志，**不同步、不删除**，服务继续启动 |
| 汇率非法（非正数）或手工对应表引用未知厂商 | attach 返回错误，启动失败（配置错误按身份模块惯例） |
| `List`/`Create`/`Update`/`Delete` 任一失败 | 中止本次同步，记 error，已成功的表操作保留（每行独立提交，非事务；下次启动继续收敛），不 Upsert 内存 |
| 厂商表为空（`nil, nil`） | 期望集为空；现状中本功能的行被删除 |
| 管理员手工建的覆盖与本功能同作用域同模型 | 不处理，按上游优先级规则叠加（产品方案第四节） |

不做的事：不在运行期监听厂商增删（管理员加了新厂商需重启一次才补价，写进文档）；不用事务包整批（上游 CRUD 各自提交，粒度按行）。

### 4.6 装配（`app`）

`app/pricing.go`：读三个环境变量 → `pricing.Load(embedded 或 EE_PRICING_FILE)` → 构造 `persistence.NewStore(s.Config.ConfigStore, s.Config.ModelCatalog)` → `pricing.New(...)` → 在 `attach` 中品牌装配之后调用 `Sync`。`ModelCatalog` 为 nil 时跳过并记 warn。环境变量常量与读取方式对齐 `app/identity.go`。

## 6. 验证策略

**单元测试**（步 1-4）

- 价格文件：合法文件通过；缺 `endpoint_hosts`、重复模型、负价、未知币种、`rates` 缺币种各返回明确错误；嵌入文件通过校验。
- 厂商识别：`https://dashscope.aliyuncs.com/compatible-mode` → dashscope；`https://dashscope-intl.aliyuncs.com` → 未识别；手工表优先；手工表引用未知厂商报错；多命中报错；内置 `deepseek` 按名字匹配。
- 换算：CNY 6 元/百万 @7.2 → 8.333e-7；USD 不换；0 → 0。
- 行生成：同输入两次 ID 相同；不同厂商同模型 ID 不同；请求类型三种；无缓存价时 patch 不含该键。
- 同步：假存储下 创建/更新/删除/未变 计数正确；文件无效不调用存储；`Create` 失败中止且不 Upsert。
- 费用闭环：用 `modelcatalog.NewTestCatalogWithDatasheet(datasheet.NewTestStore(nil))` 装入生成的行，对一个假响应算费用，等于 `input×单价+output×单价`。若该测试构造函数不支持覆盖注入，改为直接测 `datasheet.Store.SetOverrides` 后 `CalculateCost`，方案复核时确认。

**冒烟**（步 5，`ee/scripts/pricing-smoke.py`，复用 `branding-smoke.py` 的旧管理员夹具）

1. 临时目录、随机端口，config.json 含厂商 `myqwen`（base_url 官方域名、假 key）与 `mystery`（base_url `https://example.invalid`）。
2. 启动，登录，`GET /api/governance/pricing-overrides`：`myqwen` 有 N 行（N = 文件中阿里模型数），每行 `provider_id=myqwen`、patch 值等于文件值换算；`mystery` 零行；日志含未识别提示。
3. 手工 `POST` 一条覆盖；重启；两类行都在，本功能行数仍为 N。
4. `EE_PRICING_FILE` 指向非法文件重启：进程起来，日志有 error，N 行仍在。
5. `EE_PRICING_USD_CNY=3.6` 重启：patch 值翻倍，行数不变，日志 Updated=N。

**实测验收**（Gate 2，用户环境）：本机 `qwen` 厂商真 key 调一次收录模型，日志费用 = token 数 × 文件单价 ÷ 汇率。

## 8. 风险、禁止事项与回滚

- **风险：`source_of_truth=config.json` 且声明 `governance.pricing_overrides` 时本功能的行会在启动时被上游清掉**，下次 attach 再写回，中间窗口费用为零。本案不处理，写进 `ee/docs/国内定价.md`。
- **风险：官网价目变动**。文件带核对日期，费用准确性以该日期为限。
- **风险：模型名与请求名不一致**（如请求带版本后缀）。exact 匹配不命中则回落定价表或零费用；期 1 不用 wildcard，记为观察项。
- 禁止：改上游文件；用 `SetPricingOverrides`；删除或修改 `Name` 不带前缀的行；在业务根包引入 GORM/上游类型。
- 回滚：删除 `app/pricing.go` 的调用即停止同步；已写入的行可用上游自定义定价页删除，或临时把 `EE_PRICING_FILE` 指向只含 `vendors: []` 的文件重启一次，`Sync` 会删掉全部本功能行。
