**阻塞 2 — 内置厂商。关闭。** `diff` 显示 §4.3 原第 3 条整段删除，输入改为"名字、是否自定义、`base_url`"，规则改为"只处理自定义厂商（`CustomProviderConfig != nil`）；内置厂商直接跳过，不记日志"；§3 非目标、§2 不碰范围、摘要各补一句"内置厂商不受影响"；§6 单测把"内置 `deepseek` 按名字匹配"换成"内置厂商（`Custom=false`）跳过且不出现在 `Unrecognized`"；§4.5 窄接口注释 `Provider 含 Name/Custom/BaseURL`。源码侧：`GetProvidersConfig`（`rdb.go:1281-1320`）逐行把 `dbProvider.CustomProviderConfig` 放进 `ProviderConfig.CustomProviderConfig`；`tables/provider.go:23,40` 用 `CustomProviderConfigJSON` 列 + `gorm:"-"` 虚拟字段持久化，内置厂商该列为空、反序列化后为 nil。`ProviderConfig` 结构见 `clientconfig.go:478-486`，v2 §2 引用的行号准确。区分成立。

**阻塞 3 — 双节点与删除幂等。关闭。** v2 §4.5 新增"并发与幂等"四行表与失败路径改写，根包新增 `ErrRowExists`/`ErrRowMissing` 两个哨兵，`persistence` 负责从 `configstore.ErrAlreadyExists`/`ErrNotFound` 映射；步骤 3 与 §6 各加"冲突继续 / 缺行继续"用例；checklist 加必含符号 `ErrRowExists`。源码亲核：

- `framework/configstore/errors.go:9-10`：`ErrNotFound`、`ErrAlreadyExists` 是包级 `errors.New` 哨兵，行号与 v2 §2 一致。
- `rdb.go:403-490` `parseGormError`：`gorm.ErrRecordNotFound` → 直接返回 `ErrNotFound`；报文含 `UNIQUE constraint failed`（SQLite）或 `duplicate key value violates unique constraint`（PostgreSQL）→ 三个返回分支都是 `fmt.Errorf("… %w …", ErrAlreadyExists)`，`errors.Is(err, configstore.ErrAlreadyExists)` 成立。`CreatePricingOverride`（`rdb.go:3084-3096`）把 `Create` 的错误过一遍 `parseGormError`。表主键是 `ID`（`pricingoverride.go:13`），`Name` 无唯一索引，所以双节点撞的只是 `ID`。
- `UpdatePricingOverride`（`rdb.go:3098-3120`）：先 `Select("created_at").First` 读旧行，`ErrRecordNotFound` 时不报错、直接 `Save`；注释明写"this also serves create-or-update callers"。再往下一层，GORM `Save`（`finisher_api.go:107-111`）先执行全列 `UPDATE`，`RowsAffected == 0` 时以 `SkipHooks` 回落 `Create` + `ON CONFLICT UPDATE ALL`。`BeforeSave` 钩子在前面的 `UPDATE` 阶段已把 `RequestTypes` 序列化进 `RequestTypesJSON`（`pricingoverride.go:36-47`），回落插入的结构体带着已填好的 JSON 列，不丢请求类型。
- `DeletePricingOverride`（`rdb.go:3122-3137`）：`RowsAffected == 0` 返回 `ErrNotFound`。

方案让 `Create` 冲突后改走 `Update`（而不是直接一律 `Update`），保留了 `Created` 计数的语义，可接受。

**阻塞 4 — 冒烟夹具。关闭。** v2 §6 写明 `class PricingNode(identity_smoke.Node)` 覆盖 `start(self, *, pricing_env=None)`，§2 新增事实行（`identity-smoke.py:57-58`、`branding-smoke.py:38-60`），§8 禁止项加"修改 `identity-smoke.py`/`branding-smoke.py`"。可行性亲核：

- `identity-smoke.py:57-76` `Node.start` 在方法体内构造局部 `env`（剥掉 `BIFROST_/EE_/…` 前缀后只加回 `EE_PUBLIC_ORIGIN`、`BIFROST_SETUP_TOKEN`），随后直接 `subprocess.Popen(..., env=env, ...)` 并轮询 `/api/session/is-auth-enabled`。它不是 `staticmethod`/`classmethod`，也没有可挂钩的 `env()` 工厂，所以子类**不能 `super().start()` 之后再注入**，只能整体重写 `start`（复制约 20 行并在 `env.update` 后追加本案变量），或者把 `self.binary` 指向一个 `export … && exec 真二进制 "$@"` 的包装脚本再调父类 `start`（`Node.__init__` 只做 `Path(binary).resolve()`，`stop` 用 `terminate()`，`exec` 后 PID 就是真二进制）。v2 的"先按父类方式构造环境，再注入"应按"复制父类逻辑"理解，两种写法都不碰既有脚本，结论成立；哪种更省维护见建议 3。
- `branding-smoke.py:38-56` `Fixture.__init__` 的旧管理员 config（`governance.auth_config` + 空 `providers`）可照抄；`PricingNode` 需在其上放两个厂商。
- config.json 厂商片段：`keys[].name/value/weight` 对应 `core/schemas/account.go:128-132`（`value` 是 `SecretVar`，明文字符串可解析），`network_config.base_url` 对应 `provider.go:62`，`custom_provider_config.base_provider_type` 对应 `provider.go:537`。`processProvider`（`lib/config.go:1448-1485`）先 `ValidateCustomProvider`（`7402-7430`）：厂商名 `myqwen`/`mystery` 不是标准厂商、`base_provider_type: openai` 受支持、非 Bedrock，放行；key 无 `id` 时自动生成。片段可被上游接受。厂商名会被 `strings.ToLower`（`config.go:1378, 1454`），片段用的都是小写，无影响；对 `EE_PRICING_VENDOR_MAP` 的影响见建议 4。

## 非阻塞意见（在 Gate 1 请求与 §9 记录中按此口径写，不开 v3）

1. **拍板项 A 的时段轴不是区分项，A1 的偏差方向不完整。** A1 写"分时段取标准（高峰）价"，A2 写"时段取高峰价"，二者相同；真正的差别只在阶梯档位。因此 Gate 1 请求应写成："两候选只在阶梯档位上不同（最低档 vs 最高档）；分时段与限时折扣两者都按标准价、不取折扣，折扣时段的请求在两种选法下都多算"。另外"多数控制台请求落在最低档"是推荐理由不是已核事实，请标为假设。DeepSeek 目前是否仍有分时段价本环境无法联网核实，起草者在步骤 4 核对官网时确认；若已取消，时段轴整句删除，不影响 A 的选择。
2. **冒烟步 3 的断言串与 §4.5 日志格式不连续。** 日志行是 `created=%d updated=%d deleted=%d unchanged=%d …`，步 3 写的 `created=0 updated=0 unchanged=N` 中间缺 `deleted=0`，按子串匹配会永远不命中。脚本按完整行 `created=0 updated=0 deleted=0 unchanged=N` 断言即可（`deleted=0` 本身也是验收 3 要证明的事）。

## 建议栏（不立案）

1. **所有权判定加 ID 复算。** 现状集只按 `Name` 前缀识别本功能的行，管理员手工建的行若恰好用了该前缀会被改写或删除（v2 §4.5 已承认）。本功能的行 ID 是 `UUIDv5(namespaceID, ProviderID/Pattern)`，读表时对每条带前缀的行复算一次 ID、不相等的视为"非本功能行、只 warn 不动"，成本一行代码，能把这条风险从"文档提醒"变成"不可能发生"。属于加固，不扩当前方案，由设计职责决定是否并入实施。
2. **`ErrRowExists` 的必含符号位置。** 哨兵按 §4.1 定义在 `model.go`，checklist 却在 `sync.go` 里找它——只要 `sync.go` 写了 `errors.Is(err, ErrRowExists)` 就命中，可用；若实施时把判断挪进别的文件，改 checklist 的 `in` 即可，不必改方案。
3. **`PricingNode.start` 用包装脚本代替复制父类。** 复制 20 行的问题是父类以后改探针路径或超时时子类不跟。包装脚本方案：`__init__` 里在 `root` 下生成 `#!/bin/sh\nexport EE_PRICING_FILE=… \nexec "<真二进制>" "$@"`，把 `self.binary` 指向它，`start` 直接用父类的。每次重启换环境变量（步 4/5）就重写脚本。两种写法方案都允许，这里只是省维护。
4. **`EE_PRICING_VENDOR_MAP` 的键做小写归一。** 上游把厂商名 `strings.ToLower` 后落库（`config.go:1378, 1454`），管理员写 `Qwen=dashscope` 会因大小写不匹配被 §4.3 第 1 条当作"不是本部署厂商"warn 忽略，结果是静默无价。解析时把键小写，或在 warn 里提示"厂商名区分大小写、库内为小写"。
5. **冒烟片段关掉 `list_models`。** `custom_provider_config` 加 `"allowed_requests": {"list_models": false}`（`core/schemas/provider.go:337`），`server.go:1770` 会跳过该厂商的后台模型发现，冒烟不再出网访问 `dashscope.aliyuncs.com`/`example.invalid`；离线或沙箱环境跑 checklist 时少一类偶发 warn。
6. **Gate 1 请求的"最大剩余风险"列全四条**：多节点内存不一致（靠滚动重启）、模型名精确匹配不命中回落零费用、价目时效、保留前缀接管（若不采纳建议 1）。这四条 v2 §8 都有，只是 §9 没有提示它们要随 Gate 1 一起呈给用户。
