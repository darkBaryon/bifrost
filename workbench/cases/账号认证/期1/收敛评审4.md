### 关键保留理由

1. **常量与字面量。** HTTP 方法、状态码、Cookie 删除时间复用 fasthttp；`maxIdentityBodyBytes` 和 `maxJSONDepth` 是适配层容量保护；`LoginRateWindow`、两个尝试次数阈值及 `WSTicketTTL` 是服务/存储/HTTP 协作的业务值。`Retry-After` 和 `expires_in` 从时长换算秒。`application/json`、JSON 标签、固定路由、`Origin`/`Referer` 等协议名称在使用处表达清楚，不需要逐项提升为配置。`ReserveLogin` 中一小时旧桶清理与一分钟计数窗口是两个不同用途，不把它们合并成同一限制。
2. **路由和操作绑定。** `OwnsRoute` 与 `RegisterRoutes` 读取同一张表；匿名和空体能力是显式字段，新旧别名复用 operation，诊断操作名也由 operation 生成。相较原先字符串 action 和路径前缀判断，修改一个别名不再要求推断另一处前缀规则。Go 的命名字符串类型并非封闭枚举，当前默认分支明确失败，因此不能声称编译器保证所有值有效；也不据此新增一套注册校验框架。
3. **控制流与文件组织。** endpoint 的 `p/e/result/code` 都在每次请求的闭包内部，不捕获跨请求可变状态。登录分支有连续解码、签发、读取公开账号和写 Cookie 的嵌套，但步骤按执行顺序集中可读；各分支只负责 HTTP 适配，没有在总 switch 中另写账号业务。状态查询的 GET 与 POST 解码差异、旧接口空体差异均有契约来源。没有仅凭 handler 行数要求拆文件，也不为消灭局部 `if e == nil` 增加通用执行器。
4. **守卫与重复效果。** HTTP 身份识别与服务在事务内重新核验不是同一对象/时点的检查；`SetCookie` 连续写的是新 Cookie 和旧 Cookie 两个名字；`status` 已去掉 endpoint 设置过的 `no-store`。JSON 结构遍历负责重复键/多值/深度，后续结构解码负责类型和未知字段，不是可以直接删除的一次重复解码。
5. **响应出口与抽象成本。** 命名 DTO 固定对外字段，公开 `identity.Account` 自身已定义为可返回投影，不直接返回 `Credential`/`Session`。没有理由为了“HTTP DTO 必须独立”再复制全部账号字段。上游 `SendError` 使用 Bifrost 错误形状，`SendJSON` 的序列化失败路径也不同，不能机械替换本案固定安全错误码/503 降级出口。固定成功消息集中命名可以保留，不继续为它们建立消息目录或国际化机制。

这些理由只覆盖此次已读取代码和当前用途；今后分支承担业务规则、出现新的协议消费方或路由需要更多独立策略时，应重新按实际变更评估，不构成永久豁免。
