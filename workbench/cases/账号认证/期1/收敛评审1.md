### 架构符合性

- 对照架构 §4：`identity` 根包承担凭据/会话/账号规则，`http` 做输入、Cookie、响应适配，`persistence` 执行身份专用事务。本人改密、管理员重置、离线恢复共用 `replacePassword`，未在三个入口复制密码更新/会话撤销/事件写入业务。
- 对照架构 §1、§7：`app.Bootstrap` 只设置宿主 factory 并连接品牌；factory 在宿主依赖就绪、路由注册前调用 `bifrost.NewAuthAdapter`。身份迁移/兼容输入位于跨功能宿主集成包，执行期账号规则仍在 identity。`ConsoleAuthProvider` 与批准方案 §4.5 的方法和时点一致。
- `recovery.go` 只处理命令输入与资源装配，恢复规则由 `Service.RecoverAdmin` 执行；未让 app 修改账号表或实现密码规则。此入口没有理由再拆一个仅转发的命令框架。
- 与既有品牌迁移一致：经 `ConfigStore.RunMigration` 进入外层事务，PG 使用身份独立 advisory lock，`RunSingleMigration` 只承担版本步骤。身份无需照搬品牌图片字段或删表 rollback；本案已明确备份恢复、禁止自动删除生产身份表。
- API 与推理注册链仍由宿主分别装配；EE 未修改 IsEnterprise 来接管认证。WS 回调进入既有 `writeSafely`，不是另造连接管理器。这是结构核对，受保护范围是否真正完整归代码评审。

### 依赖关系

- 对照架构 §5：identity 根包的 import 为标准库，Repository、Tx、PasswordHasher、AccountPolicy 均在使用方定义；HTTP、存储和宿主适配依赖 identity，未反向导入适配包，未将 `*gorm.DB`、fasthttp 或宿主 Server 传入业务服务。
- `NewService` 显式接收依赖和已解析选项；业务未从全局配置/服务容器查询依赖。`AuthAdapter` 持有宿主用于临时令牌和旧配置接缝，属于架构 §7 允许的跨功能集成，不是业务服务绕过窄接口。
- 密码与会话事务由 service 提供 callback，Store 执行并用 transaction 类型持有 DB；没有跨模块直接更新品牌或上游账号表。`SetAccountStatus` 后的公开 Account 读取是已记载的方案偏差，不把这一响应补读误判为另一个业务更新事务。
- 运行期 Store 复用宿主连接且无 Close；离线入口自己打开并 defer 关闭数据库。未增 Redis、第二个网关、全局身份容器或空 audit/rbac 包。共享资源清理是否覆盖全部失败情形仍由代码评审裁决。
