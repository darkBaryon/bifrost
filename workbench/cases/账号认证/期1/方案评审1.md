## 可证伪质疑

### B1（阻塞）：替换认证器后，主管理员的宿主身份如何传给已有通知功能？

方案 4.5 定义 EE Principal 和 WS 回调，却没有定义 `schemas.IsLocalAdminContextKey` 的写入规则。现有 `handlers/notifications.go:161` 在发布通知时直接要求该值为 true，:207 用它决定全量通知可见性；`handlers/websocket.go:153` 将它复制进连接。旧 `AuthMiddleware` 在认证成功时设置该值，新中间件仅放行并不能满足这些 handler。

**可复现输入：**主管理员新 Cookie 调用 `POST /api/notifications`，或读取/接收有角色限制的通知；若只实现方案列出的 Principal/回调，发布将 403，列表/WS 也不具备主管理员可见性。这与“主管理员可操作所有受保护管理路由”冲突。

**关闭条件：**在宿主适配契约明确已验证、非受限 chief 才设置兼容 local-admin 标记；普通成员、临时令牌、公开请求不能得到该标记，不能设置认证绕过标记。验收补通知创建、查询、WS 可见性及会话撤销后的拒绝。无需新增 RBAC。

### B2（阻塞）：配置拒绝规则既使用了错误字段路径，也会阻断现有普通配置保存。

方案矩阵写 `client.whitelisted_routes`，但 `handlers/config.go:306` 的 HTTP DTO 是 `client_config`，`client` 是文件配置口径。同时，`GET /api/config` 仍返回旧 `auth_config`；`ui/app/workspace/config/views/performanceTuningView.tsx:82`、`loggingView.tsx:71`、`clientSettingsView.tsx:191` 用整个 `bifrostConfig` 拼回 PUT。无条件拒绝“含 auth_config”的请求，会让迁移后的主管理员连普通性能/日志设置也保存不了。

**可复现输入：**主管理员先 GET config，将返回的未修改、已脱敏 auth_config 连同一个普通 client_config 设置 PUT 回去；v1 规定得到 409，而已有页面正是这样调用。另以真实 `client_config.whitelisted_routes` 请求可验证预检是否匹配了错误路径。

**关闭条件：**明确真实 HTTP 字段路径，以及未修改脱敏旧字段的兼容处理和“实际修改旧认证”整请求拒绝边界；或者明确该页面行为中断为需要用户接受的兼容取舍，不能继续笼统承诺其他配置照常。以真实回送请求验证允许普通设置、拒绝认证修改且无部分写入；不要求开发新认证页面。

### B3（阻塞）：从干净检出执行清单，品牌 smoke 使用的 HTML 从哪里来？

`git ls-files ee/cmd/bifrost-http/ui` 只有 `.keep`；`ee/cmd/bifrost-http/main.go` 直接嵌入该目录。checklist 的 `ee-binary` 只有 `go build`，没有 UI 准备步骤。既有 `ee/scripts/branding-smoke.py:108–116` 明确要求 SPA fallback 和 `/` 返回 HTML；`ee/Makefile` 的 build-ui 才负责构建及复制 index.html。方案仅说把该 smoke 改为新初始化/登录，未取消其现有 UI 回归。

**关闭条件：**清单补可复现的 UI 构建/嵌入前置条件，并保持所选 Go workspace 口径一致；或明确定义适用的测试夹具和保留 UI 行为回归的执行位置。不能依赖作者本机残留 UI 产物，也不应直接删掉既有断言掩盖问题。品牌 smoke 原来的 Basic/Bearer 成功断言及旧 sessions 表操作也需随已批准的认证兼容规则更新。

## 建议栏（不立案）

1. **独立 profiling 边界补明。** `ee/cmd/bifrost-http/main.go` 在 Bootstrap 前调用 `profiling.Start()`；该实现使用独立 net/http Server、`BIFROST_PPROF_*` 凭据和 `/debug/pprof/`，不是受新管理中间件控制的 `/api/dev/pprof`。可明确本期保留其部署者运维边界、禁止公开代理为控制台入口，并把它纳入升级说明；不必将运维 profiling 改造成账号业务。未设置端口时它不开启，非回环无凭据也拒绝监听，不将其描述为默认公网旁路。
2. **迁移输入失败的口径补测。** `lib/config.go:4390` 附近文件密码哈希失败会记录 warning 并回退 DB AuthConfig。仅读取“有效快照”无法证明文件解析成功。建议加入“已有旧 DB 凭据 + 无法哈希的文件密码”案例，明确首次迁移是接受宿主回退还是启动拒绝；若坚持任何残缺/不可解析文件凭据均拒绝，需要保留输入来源/错误状态，不能仅相信快照。已初始化 EE 后不得因旧文件变化覆盖 EE 密码的规则保持。
3. **公开 POST 与临时令牌优先级。** 品牌读取实际是 `POST /api/branding/get`，注册时不经过管理认证；应在最终 method+route 清单明确其公开/来源策略。TempTokens 原后备只在无常规凭据时尝试；明确普通成员或过期 EE Cookie 携带正确临时令牌时的结果，并验证浏览器登录状态不会意外改变现有 MCP 流程。无需增加新临时令牌用途。
