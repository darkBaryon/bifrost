## 给用户的摘要

现在是一组共享管理员；做完后可以建立个人账号，改密、停用和重置都有完整后端行为。
沿用成熟方案：bcrypt 密码哈希、数据库会话、HttpOnly Cookie；不用 JWT/Refresh，也不新增 Redis。
管理员按你的决定使用默认初始密码建号，也能重置密码；重置记录持久保存并可查询。
建议默认初始密码先用 `123456`，允许部署配置覆盖；初次及重置后强制改密，改密后重新登录。
旧管理员保留用户名密码，只需重新登录；没有管理员的实例由部署者凭初始化密钥创建。
先做后端；本期普通成员只开放本人接口，主管理员管理全局，完整角色权限及页面随后交付。
拍板项：标准级/L3；上述默认密码与会话规则；接受后端先行和旧脚本管理凭据切换。
最大剩余风险：默认密码在用户修改前可以被他人使用；日志能追查管理员重置，不能阻止冒用。
本页已获 Gate 1 批准，进入实施；来源见文末「Gate 决策结果」。

## 3. 目标 / 非目标与交付依赖

**本期白名单：**账号创建/列表/启停；初始化和迁移；登录/登出/本人资料/本人改密；管理员重置；密码操作事件保存/查询；管理路由及 WS 认证接管；测试和接口、恢复文档。

本期不删除账号、不编辑登录名、不调整角色、不提供公开注册/邮件/SSO/MFA，不做设备会话页面、Refresh、API 管理密钥、全量审计引擎。账号删除与多角色管理由角色权限案完善，不重复建身份表。

**暂行授权边界（Gate 1已确认）：**迁移/初始化产生唯一主管理员；所有新账号为普通成员。本期不给出提升/更换主管理员接口，故不存在用户自改角色或删除最后主管理员入口。主管理员可操作所有受保护管理路由，普通成员只可访问本人接口和自己的密码事件；其他管理路由一律 403。RBAC 案随后接入稳定账号 ID、替换这项临时策略，实现已经确认的多角色并集与主管理员保护。

后端先行沿用既有裁决：事件查询 API 可由普通成员查看涉及自己的记录，由主管理员查看全量；工程验收以真实 HTTP 返回为证。现有审计占位页不算实现，前端阶段必须把该数据接到项目操作日志页面，才可宣称“用户可在页面看到改密”。本案不把页面需求取消，也不把后端交付当成整个认证产品已完成。

## 4. 接口与数据设计

### 4.1 产品规则及配置

- 默认密码 `123456`（Gate 1已确认），仅用于管理员建号和重置；部署变量 `EE_INITIAL_PASSWORD` 可覆盖，仅驻内存，用于每次独立加盐哈希，不进入响应或日志。首个管理员初始化必须自行设置新密码，不使用默认值。
- 管理员建号/重置后 `must_change_password=true`；使用该密码登录成功仅得到受限会话，允许本人信息、改密、登出。修改后才能获得普通会话；不把“强制改密”说成能阻止持有默认密码的人抢先登录。
- 本人改密校验旧密码，新密码合法 UTF-8、至少 8 个字符、最多 72 字节，不 trim、不等于当前密码或部署默认密码。建号默认值是显式例外；历史登录不补套新密码长度规则。bcrypt cost=10 复用现有实现，预留算法标识而不新增算法切换配置。
- 本人改密、管理员重置、停用均使该账号**所有会话失效**；本人改密成功返回 200 并清 Cookie，随后重新登录。不保留当前会话，简化原讨论中的轮换方案。启用账号不恢复旧会话。
- 24 小时绝对有效期，`EE_SESSION_TTL_HOURS` 可设 1–168 的整数；无滑动续期。到期、停用、密码版本不匹配统一 401，数据库不可用返回 503 且不放行。
- `EE_PUBLIC_ORIGIN` 配置完整外部 origin，非回环地址必须 HTTPS；只有本机开发允许 HTTP。Cookie 名 `ee_session`，Path=/，HttpOnly，SameSite=Lax，HTTPS 时 Secure，不设 Domain。不信任客户端 X-Forwarded-* 来推断来源或安全属性。
- API 新增部署项由 EE 启动解析，非法配置启动失败；不向上游 `config.json` 偷加字段。初始化密钥复用现有已解析 `Config.SetupToken`，未设置时初始化 403，不在日志生成/打印凭据。

### 4.2 模块、接口和事务所有权

`identity/` 负责账号、会话、密码事件规则；`identity/http/` 负责 DTO/Cookie/来源校验；`identity/persistence/` 负责 GORM、迁移、原子操作；`bifrost/` 负责宿主适配和管理路由策略；`app/` 装配。每个新包按规范有中文 README。业务层仅依赖标准 context 和自有结构，不接收 GORM/fasthttp。

核心业务契约（类型收在实际使用处，不建万能 Repository）：

```go
type Principal struct { AccountID, SessionID string; AuthVersion int64; MustChangePassword bool }
type Account struct { ID, Username, DisplayName, Status string; MustChangePassword bool }
type IssuedSession struct { Principal Principal; Token string; ExpiresAt time.Time }
type PasswordEvent struct { ID, OperationID, ActorID, TargetID, Action, Result, ReasonCode string; OccurredAt time.Time }

// 以下均为 Service 方法；token 仅向 HTTP 适配返回一次，禁止通用序列化。
Initialize(ctx context.Context, setupToken, username, password string) (Account, error)
Login(ctx context.Context, username, password, peerIP string) (IssuedSession, error)
Authenticate(ctx context.Context, rawToken string) (Principal, error)
Logout(ctx context.Context, rawToken string) error
Me(ctx context.Context, p Principal) (Account, error)
ChangePassword(ctx context.Context, p Principal, oldPassword, newPassword string) error
CreateAccount(ctx context.Context, actor Principal, username, displayName string) (Account, error)
SetAccountStatus(ctx context.Context, actor Principal, accountID, status string) error
ResetPassword(ctx context.Context, actor Principal, targetID, operationID string) (PasswordEvent, error)
ListAccounts(ctx context.Context, actor Principal, cursor string, limit int) (AccountPage, error)
ListPasswordEvents(ctx context.Context, actor Principal, targetID, cursor string, limit int) (EventPage, error)
```

identity 消费窄策略接口 `RequireAccountManager(ctx, actor) error` / `CanReadAllPasswordEvents(ctx, actor) (bool,error)`，当前实现由 identity 状态提供 chief_id 比较，后续 RBAC 通过装配替换。受限会话限制在这些服务方法同样生效，不能只靠 HTTP 拦截。账号启停/重置在事务内重新校验 actor 的当前会话及账号，防止失效 actor 继续变更。

密码事件是 identity 自己拥有的业务记录，未来 audit 通过分页查询接口读取，不能反向改 identity 表；本期不新建空 audit 模块、不造消息队列。对已认证且结构合法的重置请求，成功事件必须与改密**同事务**；权限/状态/目标错误记录失败事件。身份未知的请求只给统一错误，不伪造管理员操作。DB 故障导致无法记录失败时返回 503，密码不得提交；不可宣称 DB 不可用时仍有持久化失败记录。

### 4.3 持久化模型

同一 ConfigStore 权威数据库；管理鉴权不查只读副本、不加 Redis/进程认证缓存。

| 表（均 EE 自有） | 关键字段/约束 |
|---|---|
| `ee_identity_accounts` | UUID 主键；username 唯一、不可改；display_name；bcrypt password_hash；status(active/disabled)；must_change_password；auth_version(初始1)；创建/更新时间 |
| `ee_identity_state` | id=1 单例；initialized；chief_account_id；revision。初始化及账号管理事务先锁此行，序列化保护与 actor/target 校验；后续 RBAC 迁移 chief 关联后再淘汰此过渡字段 |
| `ee_identity_sessions` | UUID ID；SHA256(token)唯一；account_id；issued_auth_version；expires_at；revoked_at；created_at。token 为 crypto/rand 32字节 base64url；库中无原 token |
| `ee_identity_password_events` | UUID ID；operation_id 唯一（重置调用方 UUID；其他事件服务端生成）；actor_id、target_id、账号名快照、action、result、reason_code、occurred_at；保留记录，不级联删除 |
| `ee_identity_ws_tickets` | SHA256(ticket)主键；session_id；expires_at；consumed_at。32字节随机，30秒，UPDATE 条件消费确保多节点单次使用；不复用上游各节点重放表 |
| `ee_identity_login_limits` | scope+不可逆摘要唯一；窗口起点、次数。按账号名与真实 TCP peer IP 分别限流，固定一分钟每账号5次/IP30次，原子预占计数，未知账号同样计数 |

用户名建议 `^[A-Za-z0-9][A-Za-z0-9_.@-]{2,63}$`，大小写敏感；迁移的旧用户名保留原值并允许登录，不因新建规则拒绝迁移。display_name 可空，最长128字符。分页 limit 默认20、1–100；cursor 为排序时间+ID的编码，非法400，空列表返回 `items:[],next_cursor:null`。

密码/停用事务顺序：锁 state → 重读 actor 会话、版本与权限 → 锁/读 target → 更新哈希或状态及 auth_version+1 → 撤销目标全部 session → 写密码事件（重置/本人改密）→ commit。SQLite 通过先更新 state.revision 获取写锁，busy 有界重试后503；PG 使用行锁，同一加锁顺序。散列计算在事务外有界执行，进入事务后校验先前读取的版本/hash，变化则409，不拿旧校验结果更新新状态。

登录先限流、取账号快照并 bcrypt 比较；未知账号使用固定虚拟 hash 完成一次比较。每进程最多4个并行哈希运算，队列满429。随后在同一事务重读账号状态/hash/version后签发session；并发重置/停用要么先发生并阻止签发，要么后发生使签发会话立即失效。全流程不记录请求体、Cookie、Authorization、密码哈希或初始化密钥。限流不依赖不可信代理头，反代部署会共享 IP 桶，这是首版已知限制。

### 4.4 HTTP 契约

自有接口遵守本仓 POST 风格；JSON 请求最大16KiB，未知字段拒绝（尤其角色/权限/密码Hash），数据响应仅白名单字段。无凭据401，无权限403，非法输入400，重复用户名/状态冲突409，限流429，存储不可用503；不把内部错误堆栈回给客户端。

| POST 路径 | 请求 / 成功响应 | 权限 |
|---|---|---|
| `/api/identity/status` | `{}` → `{initialized,auth_type:"password",has_valid_session,must_change_password}` | 公开；没有会话不暴露账号信息 |
| `/api/identity/initialize` | `{setup_token,username,password}` → `{account}` 201；不签发会话 | 未初始化+部署密钥；初始化后409 |
| `/api/identity/login` | `{username,password}` → `{account,must_change_password,expires_at}` + Cookie | 公开；错误用户名/密码/停用统一401 |
| `/api/identity/logout` | `{}` → 200；重复/失效也成功并清 Cookie | 持有 Cookie；无 Cookie也200 |
| `/api/identity/me` | `{}` → `{account}` | 本人，包括受限会话 |
| `/api/identity/change-password` | `{old_password,new_password}` → 200并清Cookie | 本人，包括受限会话；旧密码不符400且不改状态 |
| `/api/accounts/create` | `{username,display_name?}` → `{account}` 201；不返回默认密码 | 主管理员 |
| `/api/accounts/list` | `{cursor?,limit?}` → `{items,next_cursor}` | 主管理员 |
| `/api/accounts/set-status` | `{account_id,status}` → `{account}` | 主管理员；禁止停用自己；相同状态200不重复升级版本 |
| `/api/accounts/reset-password` | `{account_id,operation_id}` → `{event_id,result:"success"}` | 主管理员；禁止重置自己，自己用本人改密；目标可为停用账号，重置不启用账号 |
| `/api/identity/password-events` | `{target_id?,cursor?,limit?}` → `{items,next_cursor}` | 主管理员看全部；普通成员缺省限定自己、传别人403；受限会话403 |
| `/api/identity/ws-ticket` | `{}` → `{ticket,expires_in:30}` | 正常主管理员会话；普通成员当前403 |

重置 operation_id 必填UUID：同一 actor/target 已成功的重复请求返回原 event_id，不能再次改变密码/撤销用户后来建立的会话；同ID不同actor/target返回409，不泄露已有事件。失败事件也占用ID，同请求返回原失败码，再次尝试须新ID。变更提交后HTTP断开可安全查询/重试；提交失败不产生 success 事件。

CSRF：控制台来源检查覆盖包括上游multipart写接口的全部Cookie写请求；MCP独立协议及公开读例外见4.5。自有JSON接口（含login/initialize/logout）只接受 JSON，要求 Origin 与 EE_PUBLIC_ORIGIN 精确一致；没有 Origin 必须有同 origin Referer，二者均无403。读取型 POST 同样执行来源策略，脚本可以明确提供 Origin；有效 Origin 不等于已认证。GET /ws 握手须匹配 Origin，不继承 localhost 自动放行。登录/凭据相关响应全部 Cache-Control:no-store。不引入浏览器可读的认证 token。

### 4.5 宿主改动白名单与兼容矩阵

宿主新增可选扩展，不改现有 AuthMiddleware 的OSS语义。拟在 server 包增加：

```go
type ConsoleAuthProvider interface {
    APIMiddleware() schemas.BifrostHTTPMiddleware
    RegisterSessionRoutes(*router.Router, ...schemas.BifrostHTTPMiddleware)
}
// BifrostHTTPServer 的可选字段；默认 nil，OSS 路径保持原样。
ConsoleAuthFactory func(context.Context, *BifrostHTTPServer) (ConsoleAuthProvider, error)
```

执行时点：Config/ConfigStore/旧AuthMiddleware完成后、append管理鉴权和RegisterAPIRoutes之前调用 factory。EE 在 `app.Bootstrap` 调宿主前赋值；factory 迁移并构造identity适配。非nil provider 用其 APIMiddleware **替代**旧管理鉴权，用其 RegisterSessionRoutes **替代**旧SessionHandler注册；inference和TempTokens装配保持不变。provider创建失败必须中止启动，沿用宿主清理workers/tickets路径；启动/停止共享DB仍归宿主所有。品牌写路由改用同一EE管理中间件。

**宿主身份上下文（B1）：**EE适配每次先清除继承的localAdmin/role标记，认证及策略判断后，仅正常且当前仍为chief的会话设置 `schemas.IsLocalAdminContextKey=true`。普通成员、受限会话、公开请求及TempToken不设置true；绝不写 `IsAPIKeyAuthContextKey` 以跳过其他链。EE Principal用自有typed key保存；不把EE UUID塞进上游uint roleID，也不把原始ee_session写入旧session上下文。通知创建/全量列表/带角色限制通知的可见性继续依据兼容localAdmin；WS复制标记后还必须每次写入执行重新校验，失效立即拒绝下一次验证。

WebSocket 只增可选回调能力：在 handlers 包定义 `WebSocketAuthorizeContextKey`，值为 `func(context.Context) error`。EE管理中间件通过验证后写入只捕获session ID的闭包；建连时复制函数到client，禁止捕获/保留fasthttp RequestCtx。`writeSafely` 在每次数据/心跳写入前调用，2秒查询超时，失败关闭；OSS未设置回调走原行为。回调重新读取session/account/chief状态，不将原localAdmin快照当作永远有效。失效定义为变更提交后开始验证的请求/推送均被拒绝，不承诺撤回此前已验证的在途响应。

**配置兼容细则（B2）：**EE的GET `/api/config`仍先调用上游读取完整配置，随后在返回前只替换 `auth_config` 为只读投影：is_enabled=true，admin_username为chief登录名的普通SecretVar，admin_password为普通SecretVar脱敏值 `<redacted>`，不带env/vault引用；`client_config.whitelisted_routes`投影为空数组。空实例的GET仍受管理鉴权保护，由identity/status提供初始化状态。读响应不修改旧表，也不暴露EE哈希。

PUT在调用原handler之前解析原始JSON（沿用上游body限制，不套新identity的16KiB限制），拒绝歧义重复键；auth_config省略可接受，若提供则必须与当前投影按字段语义完全相等，未知字段/凭据引用/新密码/开关变化均409。白名单省略或空数组可接受，非空409。通过后用sjson仅移除auth_config字段，再调用原handler完成其余修改，不自行重写整份配置。缺省client_config的上游语义保持，不为本案修复其他字段的既有更新行为。精确的同值回送不调用UpdateAuthConfig；当前chief状态由权威DB重读。原security页面改旧认证会明确被拒绝，登录/改密改走新接口；普通性能/日志/其他设置整包回送继续工作。

**兼容会话空体：**旧 `/api/session/logout`、`/api/session/ws-ticket` 接受空body并视为 `{}`，同源检查仍必需；logout成功保留 `message:"Logout successful"`。新接口采用4.4的JSON契约；所有兼容路径也由新服务执行服务端撤销，不仅清浏览器Cookie。

**独立运维端口：**`ee/cmd/bifrost-http/main.go:94` 的 `profiling.Start()` 启动独立net/http `/debug/pprof/`，不在本次控制台认证范围。继续使用现有BIFROST_PPROF_*部署凭据、默认不开启/非回环无凭据拒绝监听的约束；部署说明不得把该端口反代成控制台免认证入口。主Router上的 `/api/dev/pprof` 仍由EE账号保护，二者不能混称。

实现先产出完整“method+路由模板→分类”清单，覆盖 RegisterAPIRoutes 及其他独立注册入口，逐个对照本矩阵；若发现无法归类的生产入口，停止集成并修订方案。不得仅以 `/api/*`、`/ws` 的外层前缀包裹来代替宿主接入。

### 4.6 初始化、迁移、恢复

迁移ID `ee_identity_v1`，PG锁键使用独立常量并检查无冲突；表、state单例与迁移版本同事务。后续一次性bootstrap事务锁state：已initialized直接返回；旧AuthConfig有完整有效bcrypt和用户名则复制为chief，`must_change_password=false`，原用户名与hash字节不变；即使旧认证开关关闭，完整凭据仍迁移，EE管理认证强制开启。没有配置才进入待初始化；残缺/不支持hash/未解析外部凭据则启动失败并提供不含密钥的纠正提示，不能当作空实例开放初始化。

旧文件同步发生在factory之前；首次迁移以宿主完成解析后的有效AuthConfig快照为准，遵循原文件优先规则及已有回退行为：文件密码无法哈希但宿主回退到完整、有效的旧DB账号时，允许迁移该DB账号，并记录不含凭据的来源提示；此时以旧DB密码登录，不宣称采用了失败的文件值。快照本身残缺、未解析或hash不支持则失败。factory需核对 `Config.GovernanceConfig.AuthConfig` 与ConfigStore有效状态，不根据warning文本判断成功。加入超72字节文件密码+有效旧DB密码的迁移用例。state一经提交，重启忽略该快照作为身份来源。旧session/ticket不迁移，新cookie及独立表天然不接受旧会话，旧表可留存但EE不可使用。

两节点初始化必须只有一个成功（201），另一个409；旧管理员迁移并发只生成一个账号。缺DB或迁移错误不开监听，不能退到匿名模式。部署升级须停旧实例后整体切换，禁止新旧二进制混跑共库。

恢复不增加常驻后门HTTP接口：提供 `bifrost-http identity recover-admin --app-dir <dir>` 离线子命令，要求停止所有实例；只允许恢复state中chief_id对应账号，不创建任意新chief。新密码从终端隐藏输入或stdin读取，禁止命令行参数承载密码；复用事务修改、auth_version升级、全会话撤销及actor=`operator`/action=`admin_recovery`事件。目标不存在/数据库错误失败退出；恢复完成重新启动。文档说明服务器/数据库权限持有者仍可修改数据，审计不是防篡改存证。
